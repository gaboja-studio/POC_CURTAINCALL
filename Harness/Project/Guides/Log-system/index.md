# 기획자를 위한 로그·설문·대시보드 안내

2026-10-22 기준 · 게임 0.1.0. 개발 지식 없이 화면 순서대로 따라 하는 문서입니다.
**로그**는 게임이 자동으로 남긴 행동 기록, **세션**은 한 번 시작한 게임 진행입니다.

| 하고 싶은 일 | 읽을 문서 |
|---|---|
| 내 PC에서 기록이 쌓이는지 확인 | [내 PC에서 검증하기](local-test.md) |
| 로그·설문을 켜거나 끈 게임 파일 만들기 | [Windows·Mac 빌드 만들기](pc-build.md) |
| 관리자 계정으로 접속·멤버·기록 관리 | [관리자 안내](dashboard-admin.md) |
| 팀원이 재부팅 후 접속 | [팀원 안내](dashboard-member.md) |
| 통계를 읽고 개선할 부분 찾기 | [대시보드 읽기·분석](dashboard-reading.md) |
| 기록 폴더 찾기·설문을 다시 열기 | [Windows·Mac 기록 위치](pc-files.md) |

처음이라면 **팀원 안내 → 내 PC에서 검증하기 → 통계 읽기** 순서로 읽으세요.
빌드는 ‘다른 PC에서도 실행할 수 있는 게임 파일을 만드는 일’입니다. 빌드 담당자만 빌드 안내가 필요합니다.
이미 받은 게임을 플레이하는 사람에게는 cmd·터미널·Unity 설정이 필요 없습니다.

## 꼭 구분할 두 가지

- **검증용 데이터(TEST)**: Unity 재생 또는 Development Build로 만든 게임. 기능 확인에 사용합니다.
- **실제 플레이(LIVE)**: Development Build를 끄고 만든 게임. 실제 이용자 분석에 사용합니다.
- 실제 사람이 플레이해도 Unity에서 실행했다면 TEST입니다. 두 환경을 합산하지 않습니다.
- **게임 버전**은 게임 파일의 버전입니다. 대시보드 배포 번호와 별개입니다.
- 로그 수집·설문은 각각 켜고 끕니다. 둘 다 기본은 꺼짐입니다.

## 현재 확인 범위

로그·통계·설문 연결은 구현되어 있습니다. 실제 두 PC 플레이와 Mac 빌드 실행, 실제 설문 제출까지의 전체 검증은 남아 있습니다.
기록이 없다는 이유만으로 ‘실패 없음’이나 ‘이용자 없음’으로 결론내리지 마세요.
[개발자를 위한 현재 연결 범위](../../../../Docs/Log-system/coverage.md), [남은 확인](../../../../Docs/Log-system/remaining-work.md).
