# Windows·Mac 게임 파일 만들기: 로그·설문 선택

빌드는 다른 사람이 실행할 게임 파일을 만드는 일입니다. 먼저 최신 프로젝트를 담당자에게 준비받으세요.
Unity 메뉴에 **CurtainCall → 테스트 빌드 태그**가 없으면 기능이 들어 있는 프로젝트가 아닐 수 있습니다.

## 1. 이번 게임 파일의 기능 고르기

재생을 멈추고 **CurtainCall → 테스트 빌드 태그**에서 각 항목을 클릭해 체크합니다.

| 로그 수집 | 0.1.0 설문 | 만들어질 게임 파일 |
|---|---|---|
| 켬 | 켬 | 행동 기록 + 설문. 답변과 플레이 기록을 함께 분석 |
| 켬 | 끔 | 행동 기록만 수집 |
| 끔 | 켬 | 설문만 자동 열기. 대시보드에서 행동 비교는 ‘플레이 로그 없음’ |
| 끔 | 끔 | 둘 다 사용하지 않음 |

**현재 설정 확인**에서 버전과 두 체크를 다시 확인합니다. 기본값은 둘 다 꺼짐입니다.
체크는 이번 PC·프로젝트에 저장됩니다. 다른 담당자가 빌드하면 그 PC에서도 확인해야 합니다.
설문은 게임 버전이 정확히 **0.1.0**일 때만 켤 수 있습니다. 다른 버전에서 켜면 빌드를 멈춥니다.
로그를 켜는 빌드 담당 PC는 [최초 전송 설정](local-test.md)을 먼저 마쳐야 합니다. Windows·Mac 준비 방법이 다릅니다.

## 2. 내 PC와 받을 사람의 PC 구분하기

| 받는 사람 | 기본 빌드 방법 | 전달할 파일 |
|---|---|---|
| Windows 사용자 | Windows Unity에서 Windows 빌드 | `.exe`와 같은 폴더의 모든 파일·폴더를 함께 압축 |
| Mac 사용자 | Mac Unity에서 macOS 빌드 | 완성된 `.app`을 압축해서 전달 |

Windows에서도 Mac 대상이 표시될 수 있지만 실행 권한·서명 등 추가 처리가 필요할 수 있습니다. 처음에는 받는 사람과 같은 운영체제에서 만드세요.
Mac은 받는 PC에 맞게 Apple silicon / Intel을 선택합니다. 두 종류에 배포한다면 **Intel 64-bit + Apple silicon**을 선택합니다.
프로젝트의 플러그인이 해당 운영체제를 지원하는지도 빌드 담당자가 확인해야 합니다. 현재 실제 Mac 빌드 확인은 남아 있습니다.

## 3. Windows에서 만들기

1. Unity에서 **File → Build Profiles**를 엽니다.
2. Windows 프로필을 선택합니다. 없다면 **Add Build Profile → Windows → Add Build Profile**.
3. 필요한 경우 **Switch Profile**로 활성화합니다. 설치가 필요하다고 나오면 Unity Hub에서 해당 버전의 Windows 빌드 지원을 담당자에게 설치받습니다.
4. **Development Build**: 검증용이면 체크, 실제 플레이 분석용이면 해제합니다.
5. 씬 목록은 팀이 준비한 것을 유지합니다. 시작 씬이 Start인지 담당자에게 확인하세요.
6. **Build** → 프로젝트의 Assets 밖 새 폴더에 저장합니다. 예: `Builds/0.1.0-Windows-TEST-로그설문`.
7. 완료 후 폴더 안의 `.exe`로 실행해 방을 만들고 [최소 확인](local-test.md)을 합니다.
8. `.exe`만 보내지 말고 **폴더 전체**를 압축해서 전달합니다.

## 4. Mac에서 만들기

1. 로그를 켤 예정이면 Unity를 닫고 [Mac 전용 실행 절차](local-test.md)로 엽니다. 설문만 쓰면 전송 설정은 필요 없습니다.
2. **File → Build Profiles → macOS**. 없다면 **Add Build Profile → macOS**.
3. 필요한 경우 **Install with Unity Hub**로 빌드 지원을 준비받고 **Switch Profile**을 누릅니다.
4. 받는 PC에 맞는 **Architecture**를 선택합니다. 단순 게임 파일 배포라면 **Create Xcode Project**는 끕니다.
5. **Development Build**는 검증용일 때만 체크합니다. 씬 목록은 팀 설정을 유지합니다.
6. **Build** → Assets 밖 새 폴더에 `.app`으로 저장합니다. 예: `Builds/0.1.0-Mac-TEST-로그설문`.
7. `.app`으로 실행해 방을 만들고 확인한 뒤 압축해 전달합니다. Mac 보안 경고나 서명 문제는 담당자에게 화면을 전달하세요.

## 5. 전달할 때 함께 적기

‘게임 0.1.0 / Windows 또는 Mac / TEST 또는 LIVE / 로그 켬·끔 / 설문 켬·끔’을 함께 적어 주세요.
**Development Build 켬 = TEST**, 끔 = LIVE입니다. 로그·설문 태그와 별개인 선택입니다.
받는 플레이어는 게임만 실행합니다. cmd·터미널·인증용 설정값 입력은 필요 없습니다.
로그 태그가 꺼져 있으면 기존 미전송 기록도 보내지 않습니다. 태그 변경은 반드시 **새 빌드**를 만들어야 적용됩니다.

## 설문이 열리는 순간

- 첫날 밤: 본인이 처음 1일차 밤 정비 대기실에 들어왔을 때.
- 종료: 본인이 ESC → 나가기를 확정하고 시작 화면으로 돌아왔을 때.
- 각 PC·사용자 기준으로 설문마다 처음 한 번만 열립니다. 답변 제출 여부가 아니라 **창을 연 적이 있는지**를 기억합니다.
- 창을 닫고 다음 런을 해도 다시 열리지 않습니다. 재검증은 [설문 캐시 초기화](pc-files.md)를 따릅니다.
- Windows는 파일 탐색기, Mac은 Finder에서 기록 폴더를 열고 **SurveyCache 폴더만** 삭제합니다. 자세한 경로와 클릭 순서는 위 캐시 초기화 문서에 있습니다. 게임·Unity 재생을 먼저 종료하세요.
- 폼의 ‘플레이 기록 연결 코드’는 게임이 채웁니다. 답변자가 고치지 않도록 안내하세요.

## 다음 버전으로 바꾸기

Windows·Mac 공통: **Edit → Project Settings → Player → Version**을 예: `0.1.1`로 변경하고 새 빌드를 만듭니다.
현재 0.1.0 설문은 **끄고** 빌드합니다. 새 버전 설문은 폼·연결 작업을 담당자에게 요청해야 합니다.
새 버전 로그가 도착하고 갱신되면 대시보드 버전 목록에 나타납니다. 기존 게임 파일과 과거 기록의 버전은 바뀌지 않습니다.

메뉴 기준: [Unity 6.3 빌드 프로필](https://docs.unity.com/en-us/engine/6000.3/manual/building-and-publishing/build-settings/create-build-profile), [Mac 빌드](https://docs.unity3d.com/6000.3/Documentation/Manual/macos-building.html).
