# 내 PC에서 검증용 로그 남기기

목표: 게임을 해 본 뒤 대시보드에 **이번 기록이 늘었는지** 확인합니다. 혼자서는 방 만들기만 확인해도 됩니다.
공연을 시작하려면 게임에서 요구하는 인원이 필요합니다. 이를 위해 게임 규칙을 바꾸지 마세요.

## 가장 쉬운 방법: 검증용 게임 파일 받기

1. 담당자에게 **‘0.2.0 / 로그 켬 / 설문 끔 / Development Build 켬’** 게임 파일을 요청합니다. M2 버전 기준입니다.
2. Windows는 압축을 풀고 `.exe`, Mac은 전달받은 Mac용 `.app`을 실행합니다. Windows용 파일은 Mac에서 실행되지 않습니다.
3. 시작한 실제 날짜·시간을 메모합니다. 예: ‘10월 22일 14:46, 내가 방장’.
4. **내가 방을 만듭니다.** 방 입장까지 확인하고 30~60초 정도 게임을 켜 둡니다.
5. [대시보드](https://script.google.com/macros/s/AKfycby1UfzhOaNl9ycjKYATPF-b32AkSskzupKQ--Zxj3Z_eIKraOqy9Aw1PYYLkqKewJ_wqw/exec) → **검증용 데이터 / 0.2.0 → 지금 갱신**. 받은 게임이 이전 버전이면 그 버전을 선택합니다.
6. 수집 이벤트가 늘었는지 봅니다. **방만 만들었다면 총 플레이·공연 플레이가 0인 것은 정상**입니다.

참가자 기록은 방장에게 전달되고 방장이 Google로 보냅니다. 시작 화면만 켜고 끝내면 전송 확인이 되지 않을 수 있습니다.

## Unity에서 직접 확인하기

Windows·Mac 모두 이 프로젝트와 Unity 6000.3.25f1이 준비되어 있어야 합니다. 처음 설치는 담당자에게 프로젝트 준비를 요청하세요.

| 단계 | Windows | Mac |
|---|---|---|
| 전송 설정 최초 1회 | 프로젝트의 `Scripts/Telemetry/configure-client.cmd`를 더블클릭. 관리자에게 개인적으로 받은 설정값을 입력하고 Enter | 아래 ‘Mac 최초 준비’를 따른 뒤 매번 전용 파일로 Unity를 엽니다 |
| Unity 열기 | Unity Hub에서 POC_CURTAINCALL 열기 | `configure-client-mac.command`로 열기 |
| 로그 켜기 | 재생을 멈춘 상태에서 **CurtainCall → 테스트 빌드 태그 → 로그 수집** 체크 | 동일 |
| 설문은 따로 | 현재 M2에서는 **설문 사용**을 끔 (M2 설문 연결 전) | 동일 |
| 시작 화면 열기 | Project 검색에서 `Start` 씬을 찾아 `Start.unity` 더블클릭 | 동일 |
| 기록 시작 | 상단 ▶ 재생 → 내가 방 만들기 → 원하는 행동 | 동일 |
| 기록 확인 | 대시보드 **검증용 데이터 / 0.2.0 / 지금 갱신** | 동일 |

Windows 최초 설정 창이 닫히거나 `pwsh` 오류가 뜨면 담당자에게 PowerShell 7 준비를 요청하세요.
설정값은 비밀번호처럼 다루며 채팅·화면 캡처·기획 문서에 붙여 넣지 않습니다. 이 Windows PC는 이미 설정되어 있습니다.

## Mac 최초 준비와 이후 실행

1. 열려 있는 이 프로젝트의 Unity를 종료합니다.
2. Finder에서 프로젝트의 `Scripts/Telemetry` 폴더를 엽니다.
3. **터미널** 앱을 열고 `/bin/zsh `를 입력합니다. 끝에 공백을 하나 둡니다.
4. Finder의 `configure-client-mac.command`를 터미널 창으로 끌어다 놓고 Enter를 누릅니다. 경로를 직접 타이핑할 필요가 없습니다.
5. 안내에 따라 Enter → 관리자가 개인적으로 전달한 설정값 붙여 넣기 → Enter. 입력 내용은 화면에 보이지 않습니다.
6. Unity가 열리면 위 표의 ‘로그 켜기’부터 진행합니다.
7. 다음 실행·재부팅 후에도 **3~4번으로 Unity를 엽니다.** 설정값은 이 프로젝트의 개인 로컬 파일에 저장되어 다시 묻지 않습니다.

Mac에서 Hub만으로 열면 전송 설정을 전달받지 못할 수 있습니다. 재생을 멈추고 Unity를 닫은 뒤 전용 파일로 다시 여세요.
이 Mac 보조 실행 절차는 제공했지만 실제 Mac에서의 실행 확인은 아직 하지 않았습니다.

## 언제 저장되고 언제 보이나요?

**행동 발생 → PC에 저장 → 방장이 Google Drive로 전송 → 시트 적재·통계 계산 → 화면 표시** 순서입니다.
PC에서는 약 15초마다, 씬 이동·런 종료 때에도 기록을 묶습니다. 전송은 게임 실행 중에 이어집니다.
Drive 도착 뒤 **지금 갱신** 또는 **30분 자동 갱신** 때 시트·대시보드에 반영합니다. 마지막 집계 완료 후 5분 안에는 버튼을 눌러도 기존 캐시를 가져옵니다. 새 검증 기록을 반영하려면 상단 ‘최근 완료’에서 5분이 지난 뒤 다시 누르세요.
30~60초 대기는 간단한 확인용 여유 시간이지 전송 시간 보장은 아닙니다. 게임을 강제 종료하면 마지막 묶음 전송이 남을 수 있습니다.
인터넷이 끊기면 대기 기록을 PC에 보관합니다. 다시 켜서 로그가 켜진 게임으로 방장 플레이를 이어가면 재전송할 수 있습니다.
미전송 참가자 기록은 방장에게 다시 전달되어야 합니다. 대시보드 갱신만으로 꺼진 PC의 기록을 가져올 수는 없습니다.

## 안 보일 때 확인할 세 가지

1. **환경·버전**이 맞나요? Unity와 Development Build는 TEST입니다.
2. **새 게임 파일에 로그가 켜져 있나요?** 태그를 바꿔도 이미 만든 게임 파일은 바뀌지 않습니다.
3. **내가 방을 만들고 전송할 시간을 줬나요?** Unity Console에서 `TelemetryPipeline`을 검색해 ‘Drive 저장 확인’ 또는 오류를 담당자에게 알려 주세요.

계속 안 보이면 ‘시작 시각 / 버전 / Unity인지 게임 파일인지 / 내가 방장인지 / 확인한 행동’을 전달하세요.
기록 파일을 지우지 마세요. [기록 위치](pc-files.md)에서 확인할 수 있습니다.
