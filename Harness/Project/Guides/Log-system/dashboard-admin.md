관리자 계정은 **ourhosu@gmail.com / 모호성**입니다. 다른 팀원은 [팀원 안내](dashboard-member.md)를 사용합니다.
Google에서 소유자 계정을 확인할 수 있으면 바로 접속하고, 이메일 인증 화면이 나오면 소유자 이메일로 인증합니다.

## 지금 갱신의 동작

- 실제 집계는 모든 사용자·환경·버전이 함께 **최소 5분 간격**으로 실행합니다.
- 마지막 완료 후 5분 안에 누르면 새 집계 없이 저장된 결과를 가져옵니다.
- 누군가 갱신 중이면 버튼이 비활성화되고 이전 완료 결과를 보여 줍니다. 다른 사용자의 갱신 상태는 화면이 열려 있을 때 15초마다 확인합니다.
- 완료되면 새 결과를 자동으로 불러옵니다. ‘최근 완료’는 화면을 연 시각이 아니라 실제 집계가 끝난 시각입니다.
- 갱신이 실패하면 이전 완료 결과를 유지합니다. 서버가 중단되어도 진행 표시가 영구히 남지 않도록 약 7분 뒤 재시도가 가능해집니다.
- 기록 삭제 시에는 이전 캐시도 무효화합니다. 정리가 끝나기 전에 삭제된 기록을 다시 보여 주지 않습니다.
- PC 재부팅은 Google의 자동 갱신을 멈추지 않습니다. ‘최근 완료’가 며칠째 그대로라면 서버 오류 조사 대상입니다. 게임을 다시 플레이하거나 캐시를 지울 필요는 없습니다.
- 설문은 LIVE/TEST를 구분합니다. 전체 응답 수와 비교할 때는 환경·날짜·세션·플레이어 필터를 확인하세요. 연결 코드가 없는 답변·같은 초대의 중복 제출은 별도로 구분합니다.

## 팀원 추가·이름 변경·접속 중지

1. 관리자 메뉴 → **멤버 관리**.
2. 이메일과 화면에 표시할 이름 입력 → **사용 허용** 체크 → **멤버 저장**.
3. 팀원에게 대시보드 주소와 [팀원 안내](dashboard-member.md)를 전달합니다. 메일함은 각자 사용합니다.
4. 이름 변경은 해당 사람 **편집** → 이름 변경 → 저장.
5. 접속 중지는 **편집 → 사용 허용 해제 → 저장**. 다음 조회부터 차단됩니다.

추가 멤버는 조회 전용입니다. Drive·시트까지 공개할 필요가 없습니다.
이 화면에서는 소유자를 차단하거나 다른 사람을 관리자로 바꿀 수 없습니다.

## Drive 원본이 너무 쌓일 때

원본은 게임이 보낸 기록 묶음이고, 시트는 이를 읽어 펼쳐 놓은 기록입니다.
기본은 **최근 1,000개 보관**입니다. 관리자 메뉴 → **원본 보관**에서 자동 정리·최대 개수를 저장합니다.
다음 수동/30분 갱신 때 **시트에 옮긴 것이 확인된 오래된 원본만** 휴지통으로 보냅니다. 통계는 남습니다.
미적재 파일은 보호하므로 한도를 잠시 넘을 수 있습니다. 한 번에 최대 100개를 정리합니다.
휴지통 파일도 30일간 용량에 포함됩니다. 즉시 용량 확보가 필요하면 소유자가 Drive 휴지통을 직접 확인합니다.
오류 조사 중에는 담당자와 원본 보관을 상의하세요. 원본이 없으면 재조사할 자료가 줄어듭니다.

## 특정 세션·현재 버전 기록 지우기

1. **상단 환경·게임 버전**부터 정확히 고릅니다. TEST를 골랐다면 LIVE는 지워지지 않습니다.
2. 관리자 메뉴 → 여러 세션 체크 후 **선택 세션 삭제**, 또는 **선택 버전 클리어**.
3. 삭제될 버전·환경·세션·기록 건수를 읽습니다. 이때까지는 아직 삭제되지 않습니다.
4. **관리자 이메일로 인증번호 받기** → 소유자 메일의 8자리 번호 입력.
5. 확인 문구에 **삭제**를 정확히 입력 → **확인한 기록 삭제 실행**.

중앙 로그·설문 집계에서 제외하며 같은 기록의 재전송도 막습니다. **Google Forms 원본 답변은 남습니다.**
버전 클리어는 확인 시각 이전 기록을 지웁니다. 같은 버전의 이후 새 플레이는 다시 쌓을 수 있습니다.
잘못 지웠다면 게임과 수동 갱신을 잠시 멈추고 담당자에게 요청하세요. 휴지통 복원만으로 되돌아오지는 않습니다.

## 버전·설문 운영

- 새 버전 만드는 방법은 [빌드 안내](pc-build.md)의 ‘다음 버전으로 바꾸기’를 따릅니다.
- 설문 폼 관리자 페이지는 기획 담당자가 직접 수정합니다. **플레이 기록 연결 코드 (자동 입력)** 질문을 지우거나 이름·연결을 바꾸려면 담당자와 확인하세요.
- 설문은 ‘제출’해야 원본 응답 시트에 쌓이고, 이후 수동/30분 갱신 때 대시보드에 반영됩니다.
- 인증 메일은 무료 발송 한도 때문에 잠시 제한될 수 있습니다. 같은 요청을 반복하지 말고 나중에 다시 시도합니다.
- 비밀 설정값은 개발 담당 PC에만 개인적으로 전달합니다. 시트·문서·일반 팀원 안내에 적지 않습니다.

## 오래된 플레이 기록은 어떻게 되나요?

- 실제 플레이(LIVE)는 마지막 기록부터 30일, 검증(TEST)은 7일이 지나면 상세 타임라인을 정리합니다. 통계와 설문은 남습니다.
- 새 기록을 받은 뒤 48시간, 또는 서버 처리 대기가 남아 있으면 정리를 미룹니다.
- 시트가 커지면 처리된 상세를 Drive로 옮깁니다. `세션 요약` 탭의 상세 파일 링크에서 보관 중인 원문을 찾을 수 있습니다. Events 행 수가 줄어도 통계가 삭제된 것은 아닙니다.
- 상단의 처리 대기가 0이 아니면 아직 반영할 전송 묶음이 있다는 뜻입니다. ‘최소’가 붙으면 전체 개수 확인이 끝나지 않았습니다.
- 처리 상태의 ‘요약’ 세션 수는 상세 보관 기간이 끝나 요약만 남은 세션 수입니다. 0이어도 보관 중인 세션들의 요약은 이미 저장되어 있습니다.
- ‘정리 후 늦게 도착한 기록’ 안내가 보이면 담당자에게 알려 주세요. 이미 정리된 세션에 임의로 더해 수치를 부풀리지 않고 별도로 보존합니다.
- 상세 보관 기간이 지난 세션에서는 위치 도식 대신 요약 보관 안내가 나옵니다. [상세 운영 기준](../../../../Docs/Log-system/session-retention.md).
