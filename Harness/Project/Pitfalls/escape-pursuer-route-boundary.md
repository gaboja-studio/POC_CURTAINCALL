# 추격자 경로 경계와 후발 주자 방치

## 언제 읽나

탈출로 첫 대포 근처에서 추격자가 정지하고 `EscapePursuerRoute.Position` 또는 `Exposed`에 IndexOutOfRangeException이 반복될 때. 예외는 없지만 먼 입구 참가자를 잘못 추적하거나, 반대로 입구 생존자를 오래 방치하고 선두만 계속 공격할 때도 읽는다.

## 원인과 수정

- 사용자가 실제 플레이에서 재현했다. Editor.log의 `Advance → Position` 예외 이후 `CanAttackFromRoute → Exposed`도 반복 실패했다.
- 길이 27.6310005인 구간에서 cursor 0.000449986488을 역방향으로 끝까지 이동할 때 거리 나누기·뺄셈 결과가 -2.91e-11이 된다. FloorToInt는 이를 -1로 바꾼다.
- 도착한 경계는 계산 결과를 누적하지 않고 정확한 정수/목표값을 대입한다. 남은 이동 예산만 차감하고, 경로 조회 인덱스도 범위 내로 제한한다.
- PursuerRouteTests의 경계 도착·음수 잔차 회귀는 편집 모드에서 검사한다. 실제 플레이의 전 구간 추격 성공을 증명하는 검사는 아니다.
- 갱신 예외 때문에 마지막 프레임의 조준선이 그대로 남을 수도 있다. 공격 종료 시 표현을 명시적으로 정리하고, 참조 누락 조기 반환 전에 선을 끈다.

## 예외 없이 봉 앞에서 멈추는 경우

- 2026-11-14 실제 PlayMode에서 첫 서비스 벽 앞 거리2.82639551m로20초 이상 정지했다. 확장 AABB가 이동을 먼저 막고 실제 타격 조건2.8m는 만족하지 않았다. 지상 경로의 각 edge를 실제 몸통 캡슐로 검사하고, 실제 벽의 타격 경계까지 접근한 뒤 파괴를 기다려야 한다. 회전된 벽의 월드 AABB만으로 정지점을 정하지 않는다.
- 위 수정 뒤 첫 봉에 매달린 실제 플레이에서 별도 교착을 발견했다. world(-226,25,65.3)에 이미 도착했으나 cursor0.999999642/desired1이어서 등장 조건cursor>=1을15.54초 동안 만족하지 못했다. 월드 위치가 다음 지상 앵커와 일치하면 cursor를 정수에 정렬한다. 점프 edge나 먼 앵커를 건너뛰는 방식으로 보정하지 않는다.
- 진행률 차이에 고정 epsilon을 두면 긴 edge의 실제1mm 잔차도 영구히 남는다. 남은 이동 예산을 소비하고 도착한 목표값을 정확히 대입한다. 전진·역주행·마지막 앵커·아주 작은 이동 예산을 함께 검사한다.
- 벽 도약 검사는 실제 포물선의 몸통 경로를 사용한다. 발사 위치에서 타격할 수 없는 벽을 미래 공중 표본으로 파괴시키지 않는다. 낮은 벽 위로 정상 통과하는 도약은 지상 직선 검사로 막지 않는다.

- 첫 봉의 발 위치(61,-6,75)는 첫 공격 발판에서 약33~35m다. 봉 탑승자는 경로 진입 뒤에도36m 팔 사거리/외줄 경고를 유지해야 한다. 일반 노출 바닥22m로 줄이거나 복도 접촉 공격으로 분류하면 공격할 수 없다.
- 공중 목표에는 NavMesh 표본이 없을 수 있다. 기존 경로를 매번 지우지 말고 도달 가능한 접근점을 찾는다. 은폐 경로는 플레이어의 소수 진행률 대신 실제 등장 진입점을 목표로 삼는다.
- 같은 구역에 선 플레이어만 기다리지 않는다. 발판의 지지·가림을 검사한 공격 위치를 찾고, 정체4초/노출12초 뒤 확정된 공격을 끝내고 물리적으로 복귀한다.
- 출현 선택과 유지 판정은 실제 공격 가능 위치·사거리를 공유한다. 경로 index 구간만 비교하면 이미 사거리 안의 플레이어를 두고 철수하거나 재방문 쿨다운 때문에 공격 불가능한 발판으로 왕복한다. 진행 중인 파편 경고·비행도 압박 진행으로 세되 최대 노출 제한은 유지한다.
- 재방문 대기시간 만료만으로 이동 중 선택한 출현 지점을 바꾸면 양쪽 사이를 오갈 수 있다. 대상 변경/유의미한 구간 이동 전까지 진입 목적지를 유지한다. EditMode 회귀와 실제 씬 손 소켓 시야·NavMesh를 확인하고, 플레이 성공은 사용자 검증으로 남긴다.
- 높이가 겹치는 미궁에서 최근접 경로의 진행도만 비교하면 먼 입구 참가자를 지하 경로의 선두로 잘못 판정할 수 있다. 3인 연속 진단에서 실제 주자 progress9/거리1.73m보다 미출발 참가자 progress11/거리43.33m가 선택돼 같은 등장·복귀가 반복됐다. 최초 진입8m·현재 표본12m라는 기존 신뢰 범위를 사용하고, 공중에서는 마지막 신뢰 진행도를 유지한다. 실제 StartArea 지상 귀환은 홀 대상으로 돌린다.
- 서비스 경로에서 잘못된 대상을 제외하고 null만 반환하면 해결되지 않는다. Following이면 NavMeshAgent를 꺼 두므로 정지한다. 현재 등장과 도약·포획을 마친 뒤 실제 경로를 Entry까지 역주행하고, 같은 agent type의 연결된 홀 NavMesh에 도착한 뒤 인계한다. 라운드·압박·출발 기록 전체를 Reset하거나 순간 이동시키지 않는다. 목마로 높은 참가자도 기존 접근 탐색8m 범위의 지상 연결을 확인한다. 단위 회귀와 편집 씬 Entry→홀 PathComplete는 실제 전체 귀환 플레이 증거와 구분한다.

## 플레이어 빌드의 등장 클립과 후방 주자

- 에디터에서 재생되는 UnderstageEntrance.anim도 동일 클립을 Animator 없는 루트에서 SampleAnimation으로 호출하면 스탠드얼론에서 멈춘다. 이 클립은 Legacy를 사용하고 Revision7 리그의 다른 클립들은 각자의 재생 경로를 사용한다. 입구에서 추격자 월드 좌표가 실제로 전진하는지 스탠드얼론 호스트와 원격 로그에서 확인한다.
- 일부 주자가 도착하고 주자가 뒤에 남아 있으면 마지막 도약 전 유효한 위협 발판을 먼저 고른다. 전방 등장 지점도 지지와 공격 시야가 유효하면 뒤쪽 주자에게 사용할 수 있다. 접힌 합류교 같은 실제 차폐물은 여전히 공격을 가린다.
- 상승 대포와 양방향 합류교는 마지막 주자가 기존 봉을 직접 잡았을 때 장치가 고정된다. 포획 연출 중인 동료는 투척·탈락 확정까지 남은 참가자로 센다. 단순 접속 인원 수로 계산하면 탈락한 관전자가 장치 진행을 계속 막는다.

## 진행도 점수에 밀려 후발 주자를 무기한 방치하는 경우

- 2026-11-16 연속 4인 실행에서 입구 AFK 참가자가 Normal로 남아 있자 선두의 마지막 주자 고정 조건이 성립하지 않았다. 선두가 helper12에서 기다리다 포획된 뒤에야 추격자가 입구를 다시 골랐다. `EscapeCooperativeLocks.HasOneUnresolvedRunner`가 Normal·EscapeCaptured를 세는 것은 정상 협동 규칙이다. 이 사례를 잠금 장치 고장으로 고치지 않는다.
- 기존 `EscapePursuerRoute.SelectTarget`은 진행도(0..73)에 최근 공격 감점 최대 5, 압박 가산 최대 2를 더했다. 진행도 58인 선두의 최소 점수 53은 입구의 최대 2보다 높다. 시간이 지나 압박이 포화되어도 역전되지 않는다. `Boss.HasRunnerBehindFinale`의 후방 우선은 Chasing 단계 한정이라 이전 구간의 방치를 해결하지 못한다.
- 기존 `SampleProgress`는 먼 투영 또는 inHall을 건너뛰어 입구의 정체 시간도 기록하지 않았다. 현재는 입구를 신뢰 진행도 0으로 최초 관측한다. 기존 최초 진입 8m·현재 표본 12m와 공중의 마지막 신뢰 진행도는 유지하며, 먼 가짜 투영을 전진 기록으로 사용하지 않는다.
- 수정은 GameSettings 값을 바꾸지 않는다. 마지막 유효 전진과 실제 `MarkPressured` 중 더 최근 시각부터 `pressureIdleGrace + pressureRiseSeconds`가 지났으면 우선군에 넣는다. 현재 설정 합은 45+45=90초이며 새 고정 상수나 라운드 전체 제한시간이 아니다. 가장 오래 방치된 후보를 먼저 고르고, 같은 나이는 기존 점수·ID 순으로 비교한다. 우선군이 없으면 기존 선두 우선이 유지된다.
- 선택·캐시 갱신·귀환 이동은 방치 시간을 갱신하지 않는다. 실제 경고/공격의 `MarkPressured` 또는 기존 최장 진행거리보다 `pressureProgressMetres`(현재 4m) 이상 전진했을 때만 갱신한다. 왕복 거리 자체는 전진이 아니므로 필요한 후퇴·재합류 중 압박 체감은 실기에서 확인해야 한다. 사망·포획 표적은 제외하고, 라운드 재시작·시계 역행 때 시간 기록을 초기화한다. 시계 보정으로 경로 위치나 신뢰 공중 진행도를 순간 이동시키지 않는다.
- 입구가 선택되어도 현재 공격·포획 운반을 중단하거나 즉시 홀로 이동하지 않는다. 현재 등장점에서 물리적으로 복귀하고 서비스 경로를 Entry까지 역행한 뒤 연결된 홀 NavMesh로 인계한다. 90초는 재선정 기준이며 공격 도착·포획 완료를 보장하는 시간이 아니다.
- 코드 근거는 `Assets/Scripts/EscapeRoute/EscapePursuerRoute.cs`, 회귀는 `Tests/Editor/PursuerRouteTargetTests.cs`다. `EscapePursuerComplete` EditMode 142/142 통과(기존 120 + 기존 신뢰 진행도/복귀 10 + 신규 방치 12), 컴파일 오류 0. 로컬 증거는 `.harness/local/pursuer-space-20261116/pursuer-neglect-tests.json`과 `pursuer-neglect-verification.json`. 최초 테스트 요청의 연결 종료·상태 조회 실패는 도메인 재로드 중 발생했고, 재로드 후 새 142개 실행 결과를 별도로 확인했다. **기록 시점에 이 AI 수정의 새 게임 빌드·연속 멀티플레이 검증은 아직 없다.**
- 후속 실제 빌드의 `pressure-afk-4-01`은 선두2명 Normal일 때 입구 대기자를106.630초에선택→약120m 밖route15.217에서route0까지역행→140.955초 실제DebrisWarning/142.035초Impact→149.526초선두 재선택을 확인했다. 입구대상은무부상생존하여 포획 검증은 아니다. 같은 빌드3인 마지막 생존자의 입구→24/24→성공 엔딩은 일반 입력 재개를 포함한다. `.harness/local/pursuer-pressure-20261116/pressure-verification-summary.json`에 범위를 구분했다.
- 같은 시점의 geometry audit 경고 272개도 모두 무해하다는 판정이 아니다. 분류·수정 증거는 로컬 `warning-triage.json`에 있고, 보행·캡슐·시선 표본에서 접근 증거가 없다는 것은 모든 공중 묘기로 접근 불가능하다는 증명이 아니다. 정적 검사와 실제 전 구간 플레이 결과를 합쳐 PASS로 쓰지 않는다.

## 컨베이어 외줄과 파괴구

- 0.55m 외줄에서 중심이 0.70m 벗어난 하차장 직진은 줄 고장과 같은 추락으로 보인다. 플랫폼 끝 가이드의 유효 폭을 실제 플레이어 캡슐로 검사하고 양쪽 편차로 진입한다. 줄 입구, 균형 이동, 맞은편 발판 도착을 따로 관측한다.
- 파괴 패널을 비활성화하면 도약 출발점의 숨은 발판은 그대로 남는다. 공용 경로에 추가 바닥을 깔기 전에 열린 틈의 플레이어 역진입과 추격자 도약을 각각 검사한다. 공개 조명은 파괴구 바깥에 고정하고 실제 플레이어 카메라에서도 확인한다.
