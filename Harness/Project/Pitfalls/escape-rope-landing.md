# 탈출로 외줄 착지와 방향 인계

## 언제 읽나

대포·그네에서 외줄로 착지했는데 부상을 받거나, 이어진 꺾인 줄에서 이동 방향이 어긋날 때.

## 원인과 수정

- `HumanCannonLandingZone`의 발 중심 검사는 폭 0.4m 줄 밖의 중심을 거절하지만 몸통은 줄 가장자리에 지지될 수 있다. 안전하지 않은 비행 착지는 `FallCuts=2` 부상으로 이어져 기존 부상이 있으면 사망한다.
- 호스트 착지는 `TightropeCourse.TryGetSupportingRopeAt`으로 요청 좌표와 몸통 크기의 실제 지지줄을 확인한다. 외줄 조작 전환과 같은 표면·법선·높이 검사를 사용한다. 일반 바닥은 기존 착지 구역 규칙을 따른다.
- 후속 오판: 몸통의 90% 반지름으로 탐색하면 실제 캡슐의 바깥 모서리 착지를 놓친다. 실제 `BodyRadius` 전체로 검사하고, 얇은 외줄 모서리의 위쪽 접촉을 허용하되 옆면·아랫면은 제외한다.
- 높이는 최근접 줄 중심선이 아니라 실제 충돌 접점으로 확인한다. 다른 높이의 비활성 줄이 더 가까워도 실제 발밑 줄을 거절하지 않는다. 대포·그네가 이동을 맡는 동안(`Simulated=false`)과 실제 줄 지지 중에는 외줄 깊이 낙사를 적용하지 않는다.
- 줄 위→다른 줄 위는 `onRope` 값이 그대로라 기존 축을 유지하던 문제가 있었다. 독립 줄의 실제 지지 lane에 맞춰 축을 갱신하며 균형과 조작 인스턴스는 유지한다.
- 중앙 보정은 최근접 줄의 진행 거리를 다른 줄에 대입하지 않고 실제 지지줄 자체에 투영한다. 접합부에서 앞뒤 위치까지 튀지 않게 한다.

## 검증

- `TightropeSurfaceControlTests` 29/29 PASS: 중심이 줄 밖 0.24m인 착지와 캡슐 바깥 모서리, 원격 보고 좌표, 다른 높이의 비활성 줄 주변, 외부 이동 인계, 허공/아래/비활성/trigger/덮인 줄 거절, 꺾인 줄 인계와 이전 축 복원, A의 임시 낙사 해제 옵션 범위를 검사한다.
- 정적 접촉·EditMode 회귀는 실제 플레이 감각과 다인 네트워크 검증을 대체하지 않는다.

## A 검토용 옵션과 협동 소실

- 2026-11-02 Start→대기실→탈출로 경로: 캠페인은 개발 자동 실행기를 비활성화하므로 그 컴포넌트의 활성 목록만 확인하면 추락 절단 보호가 빠진다. 대포의 `FallInjuriesSuppressed`는 활성 씬의 `EscapeCampaignContent.IsTraversalActive`와 캠페인 상태도 확인한다. 영속 플레이어가 다른 씬에 속해 있어도 현재 탈출 진행은 보호하며, 균형·낙사 구역·직접 함정 피해 규칙은 별개로 유지한다. 무피해 착지에서는 스프링 신발 반동/소모 분기에도 들어가지 않는다.
- 외줄 소실 시 줄 카메라 요청이 해제된다. 탈출로에서는 이후 남아 있는 1인칭 요청을 선택 후보에서 제외하고 공용 3인칭으로 돌아간다. 요청 자체는 보존해 다른 공간에서 다시 사용할 수 있게 한다. 이 요청 선택 회귀와 실제 벽 충돌 때문에 카메라가 가까워지는 체감은 구분하며, 실제 플레이의 선택 시점/거리 확인은 별도다.
- 입구 접근 카메라는 우선순위75, 줄 카메라는0이다. 계단 끝 영역을 건너뛰면 입구의 근접 구도가 비행 종료/줄 시점 해제 뒤 다시 우선할 수 있다. 실제 대포/외줄 사용을 관찰해 접근 완료를 고정하고 요청을 해제한다. 실제 A의 approachView는 1인칭이 아닌 근접 자유3인칭이다.

- 2026-10-29 사용자 요청으로 A의 `EscapeDevelopmentSession.SuppressFallConsequences`를 켰다. 기본 false이며 지정 개발 씬의 추락 부상·균형 붕괴·낙사 경로만 차단한다. 직접 함정 피해는 유지한다. 원본 씬의 판정을 영구 제거한 것으로 오해하지 않는다.
- `requireCarrierForBounce=true`는 탈출맵에서 추가한 협동 제한이었다. 원본 인간대포처럼 놓인 트램폴린도 반동하려면 false여야 한다. 이동·반동 코드를 복제할 필요는 없다.
- 외줄별 소실은 support 하나와 대응 renderer만 꺼야 한다. `CompletionRope` 시각선/socket은 collider의 자식뿐 아니라 같은 부모의 형제이므로 이름·실제 local box 거리로 매핑한다. 한 줄 제거 전후 실제 지지 여부로 조작을 반환한다.
- 하부 초과 입장자를 되돌릴 때 local pilot만 초기화하면 호스트 비행 상태가 남는다. 원본 `ServerReleaseForInspection` 승인 후 소유자 `PlayerMover.Relocate`로 반환한다. 협동 회귀11/11 PASS, 다인 실행은 별도다. 목마 하차에서도 호스트가 원격 운반자의 공유 공중 상태와 발판 접촉을 확인하고 소유자가 이동한다. `PlayerMover.Simulated`는 소유자에만 검사한다.

## 구조 변경 뒤 남는 메시·좌표 함정

- 3인칭 시야를 열려고 천장/인방을 지우면,그것에 달린 광원/짧은 지지봉도 함께 추적해 벽에 재접합해야 한다. A 공간 폴리싱에서는 조명3개를 벽 직부로 옮기고 이전 부품7개를 제거했다.
- 구조를 맞댈 때 기존 숨은 면을 복구하되 공용 메시를 수정하지 않는다. A 전용 메시에서 현재 인접 체적으로 면을 정리하고,벽 충돌체 체적을 분할한다면 합집합 불변/실제 메시 시야·새 구조 관통을 별도로 검사한다. GlobalObjectId=0인 편집 생성물은 영구 씬 객체 비교에서 제외한다.
- `polished-*` 메시의 숨은 면 제거 결과는 당시 계단·대포 하부 등과의 겹침에 종속된다. 주변 구조를 지워도 잘린 면은 복원되지 않는다. A 첫 대포의 `EscapeBackground/16_VerticalFacility/02_Route_0_to_minus6_to_plus2/진입 캔틸레버`는 `polished-0095`의 윗면이 제거되어 바닥에 투명한 사각형이 남았고, 원본 Cube 메시로 복원했다. 구조 변경 후에는 벽뿐 아니라 바닥의 보이는 면과 Collider 지지면을 함께 확인한다.
- 2026-11-02 수동 삭제 뒤 `남측 하부 외벽_하부`도 같은 잘림이 남았다. 현재 남은 구조 기준으로 A 전용 메시를 복구했고 Transform/Collider는 보존했다. 메시를 `EditorUtility.CopySerialized`로 덮어쓰면 CPU 교차검사와 실제 렌더가 달라질 수 있었다. 기존 Mesh에 Clear/SetVertices/SetTriangles/재계산/UploadMeshData(false)를 적용하고 양쪽 렌더로 확인한다. 맞닿는 면 중복 검사는 역방향 법선도 포함한다.
- `AFusedPole`은 부모 로컬 좌표를 받는 `BMass`에 이동 carriage의 월드 좌표를 전달했다. 천장보와 `FixedDropRod`가 수십 m 떨어져 배치되어 그네 아래 긴 줄처럼 함께 움직였다. 6개 carriage의 잘못된 rod 12개를 삭제하고 각 carriage의 로컬 `(0, 4.25, 0)` 천장보와 `(0, 4.6, 0)` 레일 연결부로 교체했다. 수정 후 각 carrier의 Renderer bounds 크기는 약 `4.5 × 5.02 × 0.7m`, 잘못 배치된 rod는 0개로 확인했다. 이동 부모 아래 장치를 만들 때는 helper의 좌표계와 자식 묶음의 실제 bounds를 확인한다.

## 발밑 표시와 안전 착지 구분 (2026-11-02)
- GroundMarkers.courseFloors는 불안전한 코스 바닥도 포함한다. 투영 성공만으로 초록 안내를 켜지 않고 공용 IsSafeLandingSurface와 발→면 사이 장애물 검사를 함께 사용한다. 미래 궤적의 도착 예측과 구분한다.
- 공중 카메라 프리셋은 벽 충돌 적용 전 구도만 검사하면 안 된다. 실제 스프링 암으로 당긴 뒤 발/목표 가시성도 확인한다. 정적 표본은 실제 조작 체감 검증이 아니다.

## 생성 묘기와 독립 외줄의 공통 방향 (2026-11-02)
- 양방향 진입을 useSceneGeometry/independentSceneRopes 뒤에 두면 원본 생성 묘기에는 적용되지 않는다. 진입 축 보존·좌우 입력 변환·반대 방향 동료 뒤 착지는 공통으로 처리하고, 생성/배치된 줄의 형상 계산만 분리한다.
- LaneLandingShift는 이동기의 진행 축 기준이다. 코스의 authored distance 차이를 그대로 반환하면 역방향에서는 동료 뒤 보정이 반대로 적용된다. 진행 축과 작성 축의 내적으로 부호를 변환한다.
- 기본 조작 복귀를 위해 controller.Scheme만 저장하면 비지정 기본값이 명시적 오버라이드로 남는다. HasAssignedScheme도 반영하고, 조작권을 다시 얻을 때 현재 소유자를 기준으로 갱신한다. 부상 규칙도 맵 종류 대신 실제 외줄 조작/균형 상태에 연결한다.
