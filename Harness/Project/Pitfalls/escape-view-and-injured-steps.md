# 외줄 시선과 부상 단차

## 언제 읽나
외줄에서 카메라를 돌린 뒤 키가 반대이거나, 매달릴 때 1인칭처럼 붙거나, 다리 절단 후 턱을 못 넘을 때.

## 확인할 것
- 줄 진입 축만 시선에 맞추면, 자유 카메라를 반대로 돌린 뒤 W/S·A/D·Q/E가 화면과 어긋난다. 물리 축을 매번 뒤집지 말고 입력 해석·목마 분리 점프·균형 게이지에 같은 시선 부호를 쓴다.90도 부근은 히스테리시스로 부호 떨림을 막는다.
- LocalViewSign을 HasIndependentRopes에만 제한하면 일반 공연/리허설 외줄은 끝에서 반대로 진입할 때 W가 코스 정방향으로 작동한다. 일반 외줄에도 같은 해석을 적용하고 실제 카메라 0/180도·양 끝 W/S 입력으로 확인한다. 도착 완료자의 대기벽은 입력 방향 문제와 구분한다.
- 좁은 줄의 시작 위치를 충돌 간격 확보용으로 옆으로 .45m 옮기면 W로 전진해도 줄 조작으로 전환되지 않는다. 출발 발판 안에서 줄 중심을 유지하는 배치와 4인 길막/복귀를 함께 검사한다.
- A의 1인칭 요청 거절과 ‘벽이 카메라를 몸 안으로 당김’은 다른 문제다. 실제 카메라 충돌 후 거리를 확인한다. 측면 구도도 동일한 벽/메시 검사로 검증하고, 강제 최소 거리로 벽을 통과시키지 않는다.
- 정상 점프80cm를 기준으로 필수 턱70cm를 만들면 두 다리 절단 점프40cm는 넘지 못한다. 하차장 접합은 기존 footprint 안에서23.33cm씩 나눴고 정상/기어가는 캡슐로 걷기 검사를 했다. 부상 상태를 복구하거나 공통 점프 패널티를 없애지 않는다.
- 목마 레버는 주변 난간/기계 위의 단독 접근도 확인한다. 버튼의 원형 거리와 독립 작동은 유지하고 공간 높이/배치로 협동을 만든다. 누적 부상으로 낮아진 목마의 버튼 높이 보정도 보존한다.
- 정적 배칭 Restore 후에는 생성 묶음 객체가 삭제된다. 수정에 쓸 Transform 목록을 다시 조회하고, 최종 Rebuild의 소스/메시 참조와 삼각형 일치를 확인한다.
- 최신 dev 관전은 비활성/풀링 캐릭터를 제외한다. 테스트의 가짜 생존자도 activeInHierarchy 상태여야 하며, 실패를 없애려고 제품 판정을 완화하지 않는다.

## 검사 한계
선별 회귀·캐릭터 컨트롤러 편집 이동·카메라 쿼리 반복은 실제4인 완주나 게임 FPS 검증을 대신하지 않는다. [상세 결과](../../../Tasks/Active/Task-20261027-073-exit-route-space-design/play-feedback-followup.md).

## 2026-11-05 외줄 매달림 카메라 압착
- 서 있는 높이만 검사하면 놓친다. 매달림은 발 위치가 줄보다 1.9m 낮아져 카메라 기준점과 카메라 사이에 보행용 줄 충돌체가 들어온다. 줄을 벽으로 처리하면 SphereCast가 카메라 암을 0까지 줄이고, 가까운 캐릭터 숨김 옵션이 겹쳐 1인칭처럼 보인다.
- 줄 끝에서는 두꺼운 발판·보가 기준점이나 검사 구체와 겹친다. 줄만 제외해도 모든 방향의 검사가 0을 반환할 수 있다.
- 등록된 코스의 줄 지지면만 카메라 충돌에서 제외한다. 플레이어 지지 충돌·실제 벽·발판은 유지한다. 코스 없는 씬에서 충돌체마다 전체 객체 검색을 하지 않는다.
- 매달림에 한해 카메라 검사 기준점을 주변 BoxCollider 밖으로 보정하고, 암이 압축될 때 같은 수직 평면에서 막히지 않는 높이를 찾는다. 입력 yaw/pitch와 캐릭터 위치는 바꾸지 않는다. 일반 보행의 벽 회피는 유지한다.
- A 15줄 × 9위치 × 16방향 × 3피치 × 2높이의 최종 출력 12,960표본에서 몸통 기준 1.5m 이내 0·지형 겹침 0을 확인했다. 편집 모드 물리 검사이며 실제 플레이·전환의 체감 검증은 별도다.
- 회귀: `HangingCameraRegressionTests`, `FeedbackRegressionTests`, `CameraRequestResolverTests`.
