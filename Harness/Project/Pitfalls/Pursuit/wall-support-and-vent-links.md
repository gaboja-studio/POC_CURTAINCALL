# 벽 지지와 열린 환풍구 연결

## 언제 읽나
난간 추격·낮은 환풍구 진입·문 개방 후 추격 경로를 고칠 때.

## 원인과 대처
- 윗면 및 머리 공간만 검사하면 떠 있는 바닥판도 오를 수 있다. `PursuitClimbPath.HasWallSupport`로 발부터 가장자리까지 실제 손이 닿는 벽을 확인한다. 직접 오르기, 자동 생성 링크, 기존 링크 통과에 모두 적용한다.
- 환풍구 베이크 높이는 공통 플레이어 앉기 비율에서 얻은 `CrouchBodyHeight`를 쓴다. 2026-11-16 현재 1.08m, 반경 .24m, voxel .08m이다. 서기 공간과 앉아 착지 공간은 별도로 검사한다.
- 숙소·화장실 환풍구의 `Blocker`는 닫힌 덮개다. 통과 가능으로 무시하지 않는다. `PursuitDoorObstacle` 변경 후 carve를 기다린 뒤 오르기 링크를 재생성한다. 다른 개체가 오르는 동안은 재생성을 미룬다.
- 닿는 경로가 있어도 매우 긴 우회라면 근처의 직접 오르기 후보를 확인한다.
- 착지 방향만 검사하면 화물 난간 입구 옆의 벽을 놓친다. `TryWallSupport`는 옆 방향도 검사하되 출발점부터 착지점까지, 발부터 난간 높이까지 연속 지지를 요구한다. 벽 방향과 착지 방향을 분리해 벽 타기 동안 몸·손 접점은 벽을 향하고 마지막에 착지 방향으로 돈다.
- 에이전트는 링크 시작점의 반경 안에서 진입하므로 실제 transform으로 링크 축을 다시 계산하지 않는다. 검증된 `link.startPos`를 사용한다. 활성 링크 위에서 `ResetPath`하면 즉시 끝점으로 이동하므로, 거부 시 시작점으로 `Warp`한 뒤 경로를 비운다.

## 확인 방법
- `PursuitUpgradeTests`: 허공 바닥판 거부, 연속 벽 허용, 끊긴 벽 거부, 낮은 착지.
- 실제 씬에서 덮개를 열었을 때 숙소 (21.30,.04,71.28) → (22.60,2.32,71.20), 화장실 (18,.04,63.55) → (19.30,2.32,63.55) 경로가 각각 약 3.1m로 연결됨을 확인했다. 검사용 덮개 상태는 복원했다.
- 화물 실제 재현: 추격자 (-57.558,.052,75.195), 플레이어 (-57.558,5.680,75.195). 수정 전 Partial로 바로 아래에 정지. 수정 후 (-59.440,.040,70.250)에서 옆 벽을 타고 (-59.440,5.640,70.800)에 착지하는 Complete 경로. 실제 Play에서 약 4초 Climb 동작과 손발 IK 접점 후 플레이어까지 도착했다.
