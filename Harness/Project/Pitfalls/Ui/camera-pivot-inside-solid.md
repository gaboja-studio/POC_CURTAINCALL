# 고체 안에서 시작하는 카메라 기준점

## 언제 읽나
- 대포 탑승/발사 전환 직후 화면이 구조물 내부로 가려질 때.
- SphereCast/Raycast를 실행했는데도 카메라가 벽 안에 남을 때.

## 원인과 처리
- 검사 시작점 자체가 고체 안에 있으면 거리가0으로 줄거나 내부에서 시작한 광선이 면을 놓친다. 카메라 거리만 줄이면 내부 기준점에 카메라가 남는다.
- CameraViewDirector의 기존 기준점 겹침 보정을 일반3인칭에도 실행한 뒤 카메라 팔 길이를 검사한다. 카메라만 보정하며 플레이어 위치·yaw/pitch 입력 값은 바꾸지 않는다.
- 기존 코드의 HangingCameraPivot은 이전 이름을 유지한다. 매달림 전용 분기는 추가 시점 후보 탐색에만 남는다.
- 0/70/180도 구조물의 합성 검사3건: 수정 전 내부 잔류로 실패, 수정 후 통과. 영상의 정확한 프레임별 카메라 Transform은 미확보이므로 영상과 동일 원인을 실플레이 재현했다고 쓰지 않는다.
- 일반 시점의 우회 후보를 계속 고르면 좁은 복도에서 이전 위치에 붙거나 구도가 마우스 입력과 어긋난다. 일반 시점은 매 프레임 요청된 방향에서 벽 거리로만 제한한다. 벽에서 떨어질 때는 짧게 거리를 유지한 뒤 감쇠 복귀한다. 같은 렌더 프레임에서 거리 복귀는 한 번만 계산한다.
- 배관과 철골에 Renderer만 있으면 물리 검사로 감지되지 않는다. 실루엣이 보이는데 전경이 불투명하다면 `CameraOcclusionFade`의 표시용 메시 검사를 확인한다. 공용 카메라는 렌더러의 로컬 범위 또는 지정된 메시 면을 검사한다.
- 전경을 통째로 끄면 시선 검사 경계에서 깜빡인다. 내 카메라가 그리는 동안만 화면 좌표에 고정된 8×8 Bayer 패턴으로 색상·깊이 픽셀을 함께 자른다. 짧게 스치는 오브젝트는 무시하고, 잠깐 빗나가도 상태를 유지한다. 픽셀 밀도는 시작과 끝에 천천히 바뀌며 가림 상태가 중간에 바뀌면 현재 밀도에서 이어 간다. 다른 카메라에는 원본 재질이 보인다.
