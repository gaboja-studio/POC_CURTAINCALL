# 고체 안에서 시작하는 카메라 기준점

## 언제 읽나
- 대포 탑승/발사 전환 직후 화면이 구조물 내부로 가려질 때.
- SphereCast/Raycast를 실행했는데도 카메라가 벽 안에 남을 때.

## 원인과 처리
- 검사 시작점 자체가 고체 안에 있으면 거리가0으로 줄거나 내부에서 시작한 광선이 면을 놓친다. 카메라 거리만 줄이면 내부 기준점에 카메라가 남는다.
- CameraViewDirector의 기존 기준점 겹침 보정을 일반3인칭에도 실행한 뒤 카메라 팔 길이를 검사한다. 카메라만 보정하며 플레이어 위치·yaw/pitch 입력 값은 바꾸지 않는다.
- 기존 코드의 HangingCameraPivot은 이전 이름을 유지한다. 매달림 전용 분기는 추가 시점 후보 탐색에만 남는다.
- 0/70/180도 구조물의 합성 검사3건: 수정 전 내부 잔류로 실패, 수정 후 통과. 영상의 정확한 프레임별 카메라 Transform은 미확보이므로 영상과 동일 원인을 실플레이 재현했다고 쓰지 않는다.
- 카메라 거리 보정은 Cinemachine의 최종 시점에 적용한다. 완충 범위와 짧은 이동·회전 예측을 감쇠에 사용하고, 현재 위치의 충돌 거리로 매 프레임 제한한다. 같은 렌더 프레임에 파이프라인이 두 번 평가되면 감쇠 시간은 한 번만 소비한다.
- 배관과 철골에 Renderer만 있으면 물리 검사로 감지되지 않는다. 공용 렌더 패스가 내 캐릭터 표면과 화면 깊이를 비교해 가려진 부분을 표시한다. 구조물의 콜라이더와 머티리얼은 그대로 둔다.
- 좁은 복도에서는 팔 길이만 줄이면 카메라가 벽 옆 회전 중 몸 가까이 당겨진다. 공용 카메라는 몸통과 머리 시야를 확인하고 옆이나 아래 후보로 감쇠 이동한다. 렌더 구조물은 `CameraCollisionSurface.VisibilityOnly`를 사용해 시야에만 포함한다. 기존 물리·카메라 충돌 거리 검사는 이 표면을 사용하지 않는다.
