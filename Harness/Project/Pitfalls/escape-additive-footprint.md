# 탈출로 Additive 배치의 전체 공간 침범

## 언제 읽나

큰 시설 두 개를 연결하거나 기존 A 루트를 이동·회전할 때.

## 실패와 원인

- 대기실과 A의 원래 좌표를 그대로 저장하고 캠페인 Awake에서만 A를 이동했다. 두 씬을 동시에 열면 편집 화면에서 시설이 겹쳤다.
- 런타임 위치(-40,-16,118.3)/Y180도도 잘못됐다. A의 큰 외벽이 대기실 서쪽 연습장을 관통했다.
- 문→계단→시작홀 중심선217점 통과는 정상이어도, 두 시설의 물리 충돌은301건이었다. 길만 통과하면 전체 연결이 정상이라는 추론이 틀렸다.

## 수정과 예방

- A 원래 기믹/스폰을 frame 로컬 좌표로 보존하면서 frame을(-100,-16,118.3)/Y180도로 저장했다. 편집 화면과 실제 로드 위치를 일치시켰다.
- 대기실 서쪽 끝 X-83, A 동쪽 끝 X-92: 전체 메시 경계9m 분리. 계단 끝 지하 통로를60m 연장했다.
- 저장/재개방 후 **전체 시설 Renderer 경계 + 모든 활성 Collider 쌍 + 연결부/기존 방 + 보행 경로 + 실제 내부 화면**을 함께 확인한다.
- `PlaceCampaign()`은 루트가 저장 위치에 있어도 함정 경로의 좌표 프레임을 따로 확인한다. 월드 선/루트/함정 경로가 반복 호출로 이중 이동하지 않는 회귀 검사를 둔다.
- A 기존 제작 도구의 절대 월드 좌표를 새 배치에 그대로 적용하지 않는다. frame 로컬 좌표를 기준으로 변환하고 기존 자식 참조를 유지한다.
- 2026-10-31 접합부부터 실제 MPPM4 재검증에서 `HumanCannonHazardCue.origin/destination`은 루트를 따라가지 않는 저장 월드 좌표임을 발견했다. 컨베이어 톱날 경로는 시설에서339.85m, 전체 최대825.02m 벗어나 있었다. 루트 위치만 맞다고 함정 정상으로 판단하면 안 된다.
- 경로의 이전 위치·회전·크기를 별도 직렬화하고 이전→현재 프레임 차이로 비활성 함정도 보정한다. 저장 A의29개 경로 보정 후 최대 오차0.000031m, 반복 배치 불변. EditMode145/145(신규2개 포함). 대기실 씬은 저장하지 않았다. 실제 수정 후 전 구간 완주 여부는 Task 로그에서 확인한다.

- 2026-10-31: 낙사 영역은 시각적 낭떠러지뿐 아니라 그 아래 가장 높은 충돌 바닥과 비교해야 한다. A 전체 심부 local -50(world -66)은 기초 바닥 world -64보다 낮아 추락자가 feet -63.92에서 Normal로 남았다. local -40(world -56)으로 올려 정상 최저 동선(-38)과 기초 바닥 사이에 두었다. 저장 시 좌표 포함/제외 확인, 실제 재추락은 사용자가 이후 일괄 검증으로 보류했다.
- 같은 날 민규 tutorial846ccd79 씬 수신: 전체 W YAML 자동 혼합에는202개 텍스트 충돌이 있었다. 사용자 승인으로 새 W를 기준 삼고 연결 루트만 임시 prefab으로 전송·unpack, 문 개구부를 새 원본 메시에서 파생시켰다. 기존 W 객체 삭제0, 기존 변경은 문 벽 Collider/메시2/루트 목록에 한정. 병합 완료와 실제 플레이 통과는 구분한다.
