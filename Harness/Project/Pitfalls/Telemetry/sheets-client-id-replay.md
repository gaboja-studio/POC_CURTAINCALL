# 동일 로그인데 EVENT_ID_CONFLICT가 발생할 때

- 증상: 원본은 도착하지만 갱신이 IMPORT 단계에서 멈추고 이전 캐시만 보인다. 일부 공연의 시작·결과·사망 기록이 누락되어 보일 수 있다.
- 원인: wire의 networkClientId는 문자열인데 Sheets가 짧은 숫자 문자열을 숫자로 반환한다. Events 적재 후 Batches 영수증이 기록되지 못한 배치를 재시도하면 기존 2와 원본 '2'가 다른 fingerprint로 비교된다.
- 처리: fingerprint의 해당 열만 문자열로 정규화한다. 새 ID 셀은 일반 텍스트 형식으로 저장한다. 빈 ID·0·앞자리 0·큰 정수 ID는 서로 합치지 않는다.
- 실제 내용이 다른 동일 eventId는 계속 거절한다. 오류를 숨기거나 기존 Events·원본을 지워 해결하지 않는다.
- TEST 파일이 많이 밀리면 LIVE 분석도 늦어진다. LIVE 검색 → 전체 폴더 순으로 읽고 25묶음마다 Events → 영수증 순으로 저장한다. 중간 영수증 실패 후에도 재시도로 중복이 생기지 않는지 검사한다.
- 진단: 소유자가 diagnoseDashboardRefresh를 실행하면 IMPORT/STATISTICS/CACHE 등 실패 단계와 허용된 오류 코드만 출력한다. 원본·계정·토큰은 출력하지 않는다.
- 검증: server.test.cjs의 숫자형 변환 후 부분 적재 복구·다른 배치 재전송·다른 ID 거절, refresh-cache.test.cjs의 실패 단계 기록.

## 시트 끝에서 재발한 갱신 정지

- 2026-10-26 Events는 헤더 포함 50,000행이며 43,139건이 INPUT_KEY였다. 새 ID 열 setNumberFormat을 grid 확장보다 먼저 호출해 적재가 멈출 수 있었다. 기존 fixture는 고정 100,000행이라 재현하지 못했다.
- 새 행을 먼저 확장하고 grid 경계 fixture로 검사한다. 원본은 보존하며 계산에서 입력 로그를 제외한다. 운영 보관 한도는 200,000건으로 늘리되 영구 해결로 보지 않는다.
- 설문 동기화는 로그 적재 오류 후에도 실행해 게시한다. 실패한 원본은 영수증 없이 남아 다음 갱신에 재시도되며, 내용 충돌을 무시하지 않는다.

## 세션 요약 저장으로 전환할 때

- v34부터 세션 요약과 상세 파일을 분리한다. LIVE30일/TEST7일, 최근 수신48시간·원본 처리 대기는 기간 정리 유예. 상세가 없어도 누적 통계·설문 연결 요약을 남긴다.
- 첫 전환은 10세션마다 체크포인트, 90초 단위로 이어간다. Events의 처리 위치만 앞당기거나 상세 저장 전에 행을 지우지 않는다. 시트 이동은 저장본 전체 행 재대조 후에만 허용한다.
- 갱신 중단은 기존 완료 화면을 유지한다. 적재90초·상세 대조30초·원본 정리15초로 나누지만 외부 호출의 지연까지 보장하지는 않는다. 실제 한 번의 재시도 성공을 모든 원본 처리 완료로 표현하지 않는다.
- 도식의 앞 400개 사건만으로 참가자를 만들면 사건이 많은 호스트가 다른 참가자를 가린다. 참가자 목록과 표시 사건을 분리하고 플레이어별로 샘플링한다. 원본 시작 인원이 2명인 공연을 임의로 4명으로 늘리지 않는다.
- 기준·제한: [세션 보관](../../../../Docs/Log-system/session-retention.md). 검증: session-store.test.cjs.
