# 원격 플레이어 배치 전 호스트 판정

## 언제 읽나

게임 흐름으로 공연 씬에 들어갔을 때 호스트는 살아 있고 참가자만 시작부터 사망·실격일 때. 새 공연 씬에 위치 기반 호스트 판정(낙하선·영역 사망 등)을 추가할 때.

## 증상

2026-10-17 실제 2인: 줄타기 → 대기실 → 백스테이지 → 인간 대포에서 P2만 시작부터 Fallen, 맵 아래로 계속 낙하. 1인 LAN 자동 검사에서는 재현되지 않았다.

## 원인

- 중간 공간(더미)에는 바닥이 없어 몸이 계속 떨어진다.
- 출발점 이동은 소유자가 한다. 호스트 자신은 같은 프레임에 배치되지만 원격 소유자의 순간이동은 네트워크로 늦게 온다.
- 그 사이 HumanCannonRouteSystem이 호스트에 남은 원격의 옛 위치(-10m 아래)를 보고 ServerKill했다.

## 대처

연결 공연 Entry가 호스트에서 출발점 확인 전 사망을 거절한다(CampaignPerformanceEntry, 줄타기는 CampaignTightropeAdapter의 출발점 확인 후 시작). 새 공연을 연결할 때도 같은 대기 경계를 유지하고, 판정 코드에서 "씬 로드 = 모두 배치됨"으로 가정하지 않는다.

## 확인 방법

1. `RevivalTests/PerformanceEntryJudgeTests` PlayMode 실행(1인 LAN 합성).
2. 실제 2인으로 중간 공간을 거쳐 해당 공연에 들어가 참가자 생존·출발점을 확인한다. 1인 검사로 대체하지 않는다.

## 이동 중 장애물도 두 시각을 섞지 않는다

배치 이후에도 소유자 위치가 호스트에 늦게 도착한다. 호스트의 옛 위치를 현재 톱/불꽃에 대입하면 피해자가 피한 화면과 다른 결과가 나온다. 추격 포획·외줄 톱/불꽃·일반 대포 장애물·별도 대포 톱 관문/불꽃은 피해자가 현재 표시 접촉을 보고하고 호스트가 과거 형상·소유자·라운드/장치 회차·재시작·순서·유효 시각을 검증한 뒤 기존 피해 경로로 확정한다. 원격 host-only 피해를 다시 추가하지 않는다.

피해자의 현재 표시 판정에는 호스트 검증용 저주기 이력을 쓰지 않는다. 별도 톱 관문은 각 렌더 외형의 실제 틈도 유지한다. 접촉 재전송과 초기화 전 보고는 추가 절단을 만들면 안 된다. 관련 프로토콜 변경은 참가자 모두 같은 버전을 사용한다.

같은 씬 재호스팅처럼 서버 시각이 되감기면 형상 이력·다음 샘플 예약·수신 하한도 함께 버린다. 이전 세션의 큰 시각 때문에 새 형상 기록이 멈추지 않게 한다.

실제4프로세스 LAN 지연100ms/지터30ms/유실3% 및 자동 검사 근거와 한계는 [후속 검증](../../../Tasks/Active/Task-20261103-099-pursuit-network-perf/followup-verification-20261104.md)에 있다. 이 결과를4대PC/Relay나 사람의 경계 회피 검사로 대체하지 않는다.
