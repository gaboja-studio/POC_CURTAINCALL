# 원격 위치·낙하 구간의 서로 다른 시각

## 배치 전 판정
- 2026-10-17 실제2인에서 P2만 인간대포 시작부터 Fallen. 더미 공간의 바닥 부재로 낙하한 옛 위치(-10m)를 호스트가 새 공연에서 판정했다. 1인 LAN에서는 재현되지 않았다.
- 소유자 순간이동은 호스트에 늦게 온다. CampaignPerformanceEntry·CampaignTightropeAdapter의 출발점 확인 전 사망/도착 판정 금지를 유지한다. 씬 로드나 고정 대기는 배치 승인이 아니다.
- RevivalTests/PerformanceEntryJudgeTests는 합성1인 검사다. 실제2인 중간 공간→공연 전환은 별도로 확인한다.

## 이동 중 장애물 판정
- 추격 포획·외줄 톱/불꽃·일반 대포 장애물·별도 톱 관문/불꽃은 피해자가 현재 표시 접촉을 보고한다. 호스트는 과거 형상·소유자·라운드/장치 회차·재시작·순서·유효 시각을 검증한 뒤 기존 피해 경로로 확정한다. 원격 host-only 피해를 다시 추가하지 않는다.
- 피해자 표시 판정에 호스트의 저주기 검증 이력을 쓰지 않는다. 렌더 외형의 실제 틈을 유지하고 접촉 재전송·초기화 전 보고가 추가 절단을 만들지 않게 한다. 프로토콜 변경은 모두 같은 버전 사용.
- 재호스팅으로 서버 시각이 되감기면 형상 이력·샘플 예약·수신 하한을 버린다. 옛 큰 시각이 새 기록을 막지 않게 한다.
- 실제4프로세스 LAN(100ms/지터30ms/유실3%) 근거·한계는 [Task099 후속 검증](../../../Tasks/Active/Task-20261103-099-pursuit-network-perf/followup-verification-20261104.md). 4대PC/Relay·사람의 회피 검사로 대체하지 않는다.

## 리허설 회차 전환
- 2026-11-04 Task097: 옛2-2 거리38~38.5m가 새2-3에서35~35.5m로 바뀌어 도착 범위[32,35.5]에 겹쳤다. 배치 승인 전 arrived 등록은 출발 재배치 후에도 도착 벽/강제 복귀를 남긴다.
- 회차별 배치 요청과 호스트 출발 좌표 대조로 도착 판정을 잠그고 승인 전 소유자의 이동을 대기시킨다. 합성 배치 경합·도착 제한/투표 PlayMode2건 PASS는 실제 MPPM2인 입력 검증과 다르다.
- 대포 리허설은 일반 Entry를 안 거치며 새 Route 낙하선이 대기실 위치보다 높다. PracticeMode 준비 predicate로 Route 낙사/개발 복귀/ServerFallDeath를 보호하고 미배치자는 fallen 집합에도 넣지 않는다.
- 대포 합성 원격 배치→위치 수신 검사: 승인 전 사망0회, 승인 후 실제 추락1회 PASS. 실제 별도 클라이언트 검증은 별도다.

## 순간이동·부활과 낙하
- reset RPC가 NetworkTransform보다 먼저 오면 서버 옛 높은 위치를 최고점으로 다시 기록한다. 목적지 pose 전에는 transform 샘플만 보류하고, 유효한 owner 최고점·지지면 착지 보고는 허용한다. 착지 pose도 늦으면 보고된 feet를 새 대기 목적지로 삼는다.
- peak/teleport/landing/ACK/신발 반동/일반 낙하 RPC에 재시작·부활 번호를 검증한다. 부활 때 추적·예약을 초기화하고 Normal이 부활 번호보다 먼저 오면 새 번호 수신 후 최종 위치를 다시 공유한다.
- 서버 CompleteFall과 소유자 LandingMessage 모두 기물 비행 추적을 끝낸다. 옛 revision/segment 응답이 현재 낙하를 초기화하거나 같은 비행을 일반 낙하로 재보고하지 않게 한다.
- Task114 TutorialFallTracking은 합성 검사이며 실제 두 클라이언트 지연 플레이와 구분한다.

## 일반 보행·착지·다음 점프
- 원격 보행 중 서버 보간 위치만 떠 있으면 과거 계단 최고점이 남는다. 현재 생명·승인 착지 순서·실제 지지면을 검증한 owner 접지 보고로 정리한다.
- 재전송은 최초 착지 좌표·최고점을 보존한다. 늦은 ACK는 해당 착지 대기만 해제하고 다음 점프 최고점을 지우지 않는다. 승인된 중복은 피해 없이 ACK만 재발송한다.
- 최고점 RPC에도 다음 착지 순서를 붙인다. 미래 최고점은 과거 착지 피해에 합산하지 않고 다음 구간에 보존한다.
- 호스트 소유자는 최고점 RPC가 없다. 착지 큐 초기화 전에 같은 구간의 실측 최고점을 보존해야2m 초과 낙하도 서버 상한 검사를 통과한다.
- EditMode NetworkFallSegments는 합성 순서·실제 지지면 검사다. 극단적 지연으로 최초 착지가 서버 거리 검증에 거절된 직후 다음 착지가 생기는 경우는 실제 연결 확인 대상이다.
