# Changed 구독자가 런을 진행시킴

## 언제 읽나

`CampaignRun`·`PerformanceRewards`의 `Changed`(또는 `StepChanged`·`ResultConfirmed`) 이벤트를 발생시킨 뒤 같은 메서드 안에서 이어서 공연 종료·정산·전환 처리를 하는 코드를 쓰거나 고칠 때.

## 증상

- 알림을 보낸 직후 종료하려던 공연이 이미 다른 공연(다음 일차·다음 순서)으로 바뀌어 있다.
- 공연 결과가 엉뚱한 공연에 붙거나, 같은 공연이 두 번 종료되려 한다.

## 원인

C# 이벤트는 동기로 호출된다. 구독자(테스트 화면, 더미 공간, 장소 전환 등)가 알림 안에서 `EndPerformance` 같은 진행 함수를 부르면, 알림이 끝나 돌아왔을 때 런 상태가 이미 바뀌어 있다.

## 대처

1. 알림 전에 대상 공연 좌표(세대·일차·공연 순서·공연 Id)를 지역 변수로 잡아 둔다.
2. 알림 뒤 계속 진행하기 전에 현재 상태가 그 좌표와 같은지 다시 확인하고, 다르면 처리하지 않는다.
3. 재진입(콜백 안에서 다시 같은 함수 호출) 경우를 Logic 테스트로 고정한다(031 "콜백 재진입" 회귀 확인 참고).

## 확인 방법

구독자가 알림 안에서 런을 진행시키는 경우를 EditMode/Logic 테스트로 만들어, 결과가 원래 공연에만 기록되고 중복 종료가 거절되는지 본다.
