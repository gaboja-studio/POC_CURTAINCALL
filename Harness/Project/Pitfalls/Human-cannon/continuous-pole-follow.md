# 그네 연속 추종과 도약 보정

- 매달린 플레이어의 연속 추종에서 HumanCannonPilot.Teleport를 쓰면 CharacterController의 활성 토글, 플레이어 충돌 무시 재등록, NetworkTransform.Teleport가 매 프레임 실행된다. 연속 프레임은 Transform 추종, 실제 잡기·놓기 전환은 순간이동으로 구분한다.
- 펌핑에 쓰던 W/S 입력이 도약 직후에도 남는다. 이전의 속도 전체 회전은 짧은 A/D에도 진로를 계속 꺾었다. 현재는 원래 비행 관성을 유지하고 제한된 수평 보정만 더한다(0.1초 지수 응답). 입력 해제 시 보정이 사라진다.
- BeginPoleFlight는 잡고 있던 W/S 방향을 받아 같은 입력만 최대0.15초 유예한다. 새 방향/중립 입력은 유예를 끝내며 A/D는 바로 동작한다. Clear는 프레임 입력만 지우며 지속 보정은 BeginPoleFlight에서 초기화한다.
- 봉별 도약 상한을 추가하면 호스트의 속도 생성, 로컬 시작 속도 제한, 비행 중 제한을 모두 같은 값으로 적용한다.
- 이 경로의 수정만으로 실제 FPS 문제가 해결됐다고 확정하지 않는다. 플레이 프로파일과 멀티플레이 추종은 별도 확인이 필요하다.
- 참가자의 HumanCannonPoleSystem 각도 보간을 `Loop != null`로 제한하면 고정 봉은 20Hz 스냅으로 보인다. 모든 봉에 표시 보정을 적용하며, 최대 100ms 각속도 예측·봉의 각도 상한으로 제한한다. 실제 놓기 위치/속도는 받은 원본 값 그대로 사용한다.
- TightropeSwingPole·Trapeze는 기존 물리 예측값이 패킷 수신 때 튀지 않도록 표시 오차만 100ms에 걸쳐 보정한다. 점유 전환·250ms 초과 끊김·리셋에는 옛 보정을 잇지 않는다. 봉과 탑승자가 같은 각도를 읽어야 한다.
- 공중그네 수신 중 배열·HashSet·Dictionary·FlightState 객체를 매번 만들지 않는다. 재사용 임시 저장소에서 패킷 전체 검증 후 적용하며, 값 형식의 FlightState로 실제 상태와 임시 상태의 별칭을 막는다. 무효 패킷이 실제 상태를 변경하지 않는 회귀와 워밍업 후 수신 경로 할당 0B를 함께 검사한다.
