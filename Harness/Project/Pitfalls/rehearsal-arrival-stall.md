# 리허설 도착 후 진행 정체

## 언제 읽나
외줄/대포 리허설에서 바닥에 도착했지만 다음 단계나 과반 투표가 열리지 않을 때.

## 증상과 원인
- 외줄1단계는 순간 Lane 점프 관찰 비트까지 요구했다. 중간 발판의 원본 자유 이동 점프는 Lane이 아니고, 원격 점프/위치 수신 순서에도 영향을 받는다.
- 인간대포는 중간 발판·반동 기록까지 요구하여 최종 도착자도 누락했다. 바닥 가장자리15cm를 제외하는 판정도 실제 발판과 달랐다.
- 외줄 새 연결에서 이전 호스트의 큰 version을 남기면 새 방 상태를 계속 거절한다.
- 배치 승인 전 몸 충돌로 출발대 밖에 밀리면 이동 잠금 또는 낙사 유예 상태로 멈출 수 있다.

## 대처
- 기획상 실제 도착이 조건인 외줄1단계·대포는 승인된 현재 회차의 정상/비행 종료 도착을 기준으로 한다. 봉·트리거·목마의 필수 학습은 유지한다.
- 메시·충돌체·도착 범위·도착벽은 같은 실제 발판 경계를 사용한다. 리허설 도착대 배율은 런타임2이며 공연 기본값은1이다.
- 확대된 도착대와 겹치는 Base Frame8Boundary는 리허설 중 숨기고 종료 시 이전 활성 상태로 복원한다.
- 새 클라이언트 연결은 이전 버전/회차/진행을 비운다. 배치 대기자는 출발대로 재배치하고 호스트 승인을 다시 기다린다. 넘기기 요청에는 회차를 포함한다.

## 확인 방법
- EditMode `RehearsalArrivalTests`: 도착/투표·배치·재접속 순서와 발판 경계 회귀. 가상 참가자 상태 검사는 실제4인 접속 성공의 증거가 아니다.
- 실제 플레이에서는 네 화면의 동일 단계/도착 인원·넘기기·복구를 별도로 확인한다. 기존 개인 학습 후 텔레포트 검사만으로 다인 완주를 보장하지 않는다.
