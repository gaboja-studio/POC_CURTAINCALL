# 탈출로 리메이크 배치의 스케일과 절단 잔여물

- 기존 `50_ActualRouteReveal`에는 같은 이름의 조명이 여러 개다. `Transform.Find`로 첫 일치만 옮기면 높이 0.4m의 폐기된 함체가 통로에 남는다. 소속·좌표로 대상을 고르고 생성 후 낮은 렌더러와 실제 화면을 확인한다.
- 전시/가공실은 앞 난간만 검사하지 않는다. 측면과 후면의 진입, 목마·점프 높이, 위에서 내려오는 경우에 대한 실체 경계를 확인한다. 서사실 캡슐 표본 검사가 등 지지대 등 다른 공개 통로 소품까지 보장하지 않는다.

## 원인과 대처

- `A optimized chunk`는 원본 renderer를 비활성화한 별도 결합 메시다. 복사 씬에서 원본 난간을 삭제해도 이 메시가 옛 난간을 계속 표시한다. `EscapeStaticGeometryBatch.Restore()`는 production GUID와 공유 메시 삭제를 사용하므로 복사 씬에 우회 호출하면 안 된다. 복사 씬 GUID로 source ID를 재매핑하고 공유 에셋을 보존하는 전용 복원을 사용한다. Task100이 표면 중복을 잘라 만든 chunk55/56/66은 단순 원본 활성화로 과거 겹침이 재발할 수 있어 별도 대조가 필요하다.
- 현재 Prototype의55/56은 원본 화염계단40개가 이미 삭제된 유령이었다.66은 생존한 창틀3개에8개 원삼각형의 절단이 필요해, 수정된 부분을 복사 씬 전용mesh3개로 분리한 뒤 전체85chunk를 제거했다. 단순히 수정된chunk라서 보존하거나, 원본이 없는데 복구하지 않는다. 해당표면의 소유·현재존재·실제삼각형을 확인한다.
- 입구 대포를 복제하면 `HumanCannonSystem.stations` 등록만으로 추격 시작과 입구 복귀가 연결되지 않는다. Route/Bypass의 `additionalFirstCannons`에 명시 참조를 넣고 원본 `firstWire`의 안전 착지만 인정한다. 이름이나 배열 인덱스만으로 임의 대포를 입구 대포로 간주하지 않는다.
- `AimCompletionCannon`은 속도와 참고 착지점만 맞추며 대포 yaw를 돌리지 않는다. 실제 Muzzle/LaunchVelocity 캡슐 탄도와 착지 지지를 별도로 검사한다. 부모를 돌린 뒤 남은 `AuthoredLanding`도 실제 탄도와 달라질 수 있다.
- 착지섬을 넓힐 때는 봉의 아래 좌석 반동 영역을 침범하지 않는다. 반환 direct 섬은 출발측 X64 경계를 유지하고 도착측을 확장했다. 조명 지주도 건강한 선두뿐 아니라 다리 손실/공중 제동의 전체 비행 캡슐을 막을 수 있다.
- 신규 폴더의 봉만 검사하면 기존 봉에 적용된 공용 2인 정원의 아래 좌석을 놓친다. Task136에서 기존 하강/상승/반환 봉 7곳의 아래 몸이 외줄·정비대와 겹쳤다. 저장 씬의 활성 고정 봉 전체를 검사하고 높이 조정 후 정상/외팔 몸이 원래 지지면에서 공용 거리로 잡을 수 있는지도 별도 검사한다. 이동식 공급 봉의 출현 벽/루프 참조는 정지 봉 전용 검사로 안전 판정하지 않는다.
- 의미 없는 낮은 발판을 높은 벽으로 막기 전에 대포 좌석에서 움직이는 봉의 전체 주기를 검사한다. 컨베이어 앞 잔여 기초의 고벽안은 잡을 수 있는 순간을 가리지 않았지만 접근 중659위상 가운데239~241위를 가렸다. 이 안을 적용하지 않고 앞쪽 잔여 체적만 제거해 실제 통로 뒤의 깊은 지지를 보존했다. 포 이름·검사 개수가0인 빈 탄도 검사를 통과로 쓰지 않는다.
- 바닥 삭제 시 NavMesh 굽기 범위 안에 있다는 사실만으로 수집 여부를 추정하지 않는다. 실제 CollectSources에서 삭제 collider를 확인하고 복사 씬 전용 데이터만 다시 굽는다. 삭제한 상판 위치의 보행면 잔존과 원본 씬·공유 NavMesh 해시를 함께 검사한다.
- 현재 EscapeBackground의 lossyScale은 (1.25,1,1.25)다. 월드 위치만 맞추고 localScale에 설계 크기를 쓰면 기물·충돌·벽 조각이 XZ로 커진다. 생성 루트에 역스케일을 적용하고 실제 월드 치수로 검사한다.
- 기존 CompletionMaterials/CompletionRope 생성기는 이전 `Assets/Scenes/Levels/EscapeRouteMaterials`, `EscapeRouteMeshes` 경로를 가정한다. 현재 factory 재질과 기존 씬의 대포 외형을 참조한다. 과거 생성기 호출로 원본 메시 에셋을 덮어쓰지 않는다.
- 벽을 플레이어 머리 위까지 자르는 것으로 낭떠러지가 확보되지는 않는다. 잘린 벽의 아래 조각이 외줄과 같은 높이거나 낮게 남는다. 새 줄의 안쪽 구간에서 같은 높이부터 아래로 검사하고, 벽 잔여물만 절단해 공통 게임 기물과 기존 협동 발판을 보존한다.
- 바닥 면이 같은 높이에서 겹치면 가장자리 깜빡임이 생긴다. 접합부는 동서/남북 경계로 나누고 생성 잔여물과 새 바닥의 겹친 윗면을 제거한다.
- 외줄 끝 거리 배열의 기존 값을 다시 계산해 덮지 않는다. 기존 등록 순서와 길이를 보존해 새 줄만 뒤에 추가한다. 초기 리메이크의 새 줄은 기존 28m 코스 기준 안에 들어간다.
- 추격자 출구 접근점은 공통 2.8m 벽 타격 거리 안이어야 한다. 숨은 보행 경로가 닫힌 패널을 가로지르지 않아야 하며, 파괴 후 플레이어 역진입 가능성도 별도 검사한다.
- 기존 직육면체 벽·분사함도 MeshCollider로 바뀐 인스턴스가 있다. BoxCollider만 골라 개구부를 만들면 벽이 그대로 남는다. 명시적으로 선택한 직육면체 구조물의 실제 충돌 형식을 확인하고, MeshCollider도 처리한 뒤 플레이어 시점과 캡슐로 다시 검사한다.
- RunnerDeck의 바깥쪽은 Z71/85의 직선이 아니라 최대 1.45m 파인 메시 가장자리다. 옆길을 경계 숫자에만 맞추면 틈으로 떨어진다. 복사 씬 전용 메시로 접합부를 펴거나 실제 메시 윤곽에 맞춰 연결하며 공용 메시 원본은 덮지 않는다.
- 장식의 위치 검사는 공개 길뿐 아니라 기존 등장 시작점·서비스 경로·모든 출현점의 도약을 포함한다. 반입장 장식이 등장 중의 몸통을 막고, 가공장 난간이 기존 점프를 가리는 문제가 실제로 확인됐다. 신규 장식에 대한 시작 구간 캡슐 검사와 모든 출현점 왕복 검사를 유지한다.
- 복사한 NavMeshSurface는 원본 NavMeshData를 계속 참조한다. LabyrinthPrototype 전용 에셋으로 굽고 재연결한다. 기존 surface의 Children 수집만 호출하면 형제 계층인 새 배치가 빠지므로 기존 전체 frame 충돌 수집기를 사용한다.
- 최종 바닥을 넓힐 때 보스 arena도 맞춘다. 기존 14m 폭 밖에 새 옆길을 만들면 `InsideArena` 대상 선택에서 살아 있는 플레이어가 빠진다. 리메이크는 문·불꽃의 X 경계를 유지하며 폭을 34m로 맞추고, 양측 작업장 중심과 모서리 10점을 검사한다. 보스는 route 루트의 자식 Actor에 있다.
- 기존 발판 옆에 같은 높이의 새 발판을 붙이면 예전 낭떠러지 난간이 두 바닥 사이를 막을 수 있다. 검사동 대포→컨베이어 합류에서 실제 플레이어가 월드 X=-271.318에 막혔다. 새 관측장과 기존 대포 준비대 사이의 `Launch side guard`만 복사 씬에서 제거하고, 실제 바깥 낭떠러지의 끝 난간은 유지했다. 바닥 연결 검사는 높이뿐 아니라 옛 난간과 몸 캡슐의 수평 통과도 포함한다.

- `Factory static`은 원본 렌더러를 삭제한 더 오래된 결합 메시다. 지지물을 없앤 뒤 공중 플랜지·바닥 선이 남을 수 있다. 삼각형 연결 성분을 월드 위치/현재 지지와 대조하고, 지정한 장식만 복사 씬 전용 메시에서 제거한다. 원본 ThirdParty 메시를 덮어쓰지 않는다. 제거 뒤 사용하지 않는 정점도 재매핑해 renderer bounds에 유령 범위가 남지 않게 한다.
- 벽의 상부 돌출층만 지우면 Y0의 하부층이 새 발판처럼 남는다. 바닥부터 천장까지 전체 단면을 대조한다. 깊은 벽 기초는 삭제만 하지 말고 실제 집수층·상부 벽과 연결된 면으로 맞추되 공개 통로 아래의 새 바닥을 만들지 않는다.
- 계단 중앙선의 지지/몸통 검사만으로 가장자리 낙사를 잡을 수 없다. 화염복도 앞 두번째 계단에서 대각선 점프 후 중간참으로 역주행할 때 열린 서측 가장자리로 MapExit 사망이 재현됐다. 전진·역주행·대각선 조합을 실제 입력으로 검사하고 가드를 기존 벽면에 맞춰 연결한다. 플레이어 낙사 방지 벽이 추격자 도약을 막지 않도록 모든 실제 출현의 왕복도 함께 검사한다.

`EscapeLabyrinthAudit`로 새 충돌체 중복·크기·외줄 아래 방해물·서사 장식의 범위를 검사한다. 추가로 새 대포의 실제 LaunchVelocity 탄도, 줄 위 플레이어 캡슐, 접근 발판, `EscapePursuerNavigation.Clear/Supported/ClearJump` 왕복을 검사한다. 정적 검사 통과는 실제 플레이 또는 멀티플레이 완주 증명이 아니다.

- 외부 노출은 실제 스카이박스를 사용하는 편집 모드 카메라로 확인한다. 검은색 단색 카메라는 외벽 구멍을 가린다. 기존 코스 바깥에서 시야만 막는 외피를 추가할 때는 기물·자세의 이동 공간과 엔딩 전환 시 숨김 참조를 함께 확인한다.
- 벽면 뒤판으로 출현 시야를 막은 뒤 기존 `Concrete remainder`가 앞쪽으로 남을 수 있다. 상하 벽판 사이의 단차와 바닥부터 이어지는 기초 노출까지 검사한다. `Factory static`은 외줄 본체와 폐기된 바닥 표시를 함께 사용하는 이름이므로 삼각형 연결 그룹과 실제 기물 참조를 대조한다.
- 구형 `concrete-uv-*`나 `pursuer-surface-repair-*`에서 이웃 구조에 가려져 잘린 면이 뒤에서 노출될 수 있다. 실제 충돌 박스의 합집합을 사용해 문과 창을 보존하고, 현재 드러난 면만 씬 전용 메시로 복원한다. 렌더 면과 충돌 프록시가 다르면 두 경계를 대조하고 작은 렌더 오프셋을 유지한다.

## 이동 봉 전 주기와 재순환 (2026-11-16)
- 고정 봉 중립 자세만 검사하면 이동 봉 아래 좌석의 공급 벽·하차장·말단 난간 충돌을 놓친다. 모든 carriage를 같은 시각으로 평가한 뒤 두 좌석, 정상/기어가는 몸, 전체 스윙각과 말단 낙하 지지를 검사한다.
- 열린 wallFed 레일의 재순환은 위치 불연속이다. 점유 상태를 유지하면 승객까지 약123m 순간이동한다. 공용 PoleSystem이 첫 경계에서 호스트 낙하 해제를 발행하고 클라이언트는 승인까지 말단 위치를 보존한다. 닫힌 순환 레일에는 이 처리를 적용하지 않는다.
- 재순환 임시 위치를 JoinedRevision으로 식별하면 클라이언트에 그 값이 전달되지 않아 다음 탑승도 얼어붙는다. 실제 상태 패킷의 actor/launch/segment를 사용한다. 로컬 위치뿐 아니라 원격 LateUpdate 표시도 같은 위치 API를 사용해야 한다.
- Task136은 이동 봉6개를 +1.5m 높이고 말단 길이를56→52.4m로 줄였다. 100,464 몸 표본 충돌0, 36 말단 지지 통과, 정상/외팔 대포 접근 표본 보존. 실제 다인 입력 플레이를 수행한 결과는 아니다.
