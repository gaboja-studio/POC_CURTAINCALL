# 휴대 톱 자기 충돌·배선 도달
- 들고 있는 물체를 이동 후 따라오게 하면 큰 CharacterController.Move가 이전 프레임의 자기 물체에 먼저 막힌다.0.05m 입력은 정상이어도0.3m×8 입력은2.4m 대신1.16m만 이동할 수 있다.
- 운반자와 자기 장치 Collider 쌍은 IgnoreCollision하고,놓기/다른 운반자/비활성 시 기존 쌍 상태를 복원한다. 컨트롤러 재활성은 충돌 무시를 지울 수 있어 다시 적용한다. 11/17 운반 중 발사기 본체의 지형 통과 정책은 아래 후속 규칙을 적용한다. 플레이어와 발사된 톱날의 충돌은 유지한다.
- 전선 교차 계산이 맞아도 날이 먼저 벽/분사구에 닿으면 전선까지 못 간다. 실제 배치에서 장애물까지의 원판 궤적과24가닥 각각의 접촉을 함께 확인한다. 벽 관통 허용으로 해결하지 않는다.
- 뱅크를 옆으로만 옮기면 다른 묶음과 선이 교차할 수 있다. 선분 최소 거리와 절연 반경을 비교하며,벽에서 띄우면 분배함 뒤 지지대를 실제 벽에 연결한다. A 최종 최소0.418m/절연 외경0.17m.
- PreviewScene의 Collider가 전역 Physics 쿼리에 잡힌다고 가정하지 않는다. 같은 물리 씬의 알려진 바닥/벽을 먼저 검출하고 실제 Collider로 재현한다.
- [현재 구현·검사](../../../Tasks/Active/Task-20261027-073-exit-route-space-design/swing-saw-upgrade.md). 실제 다인 조작은 별도 검증이다.

- 카메라의 운반 기물 충돌 제외 대상은 관전 중 CameraSpectator.Target, 일반 플레이 중 NetworkPlayer.Local이다. 다른 기물·벽까지 무시하지 않는다.

## 추가 로드·공유 문 (2026-11-16)
- 대기실 발사대 0/1과 탈출로 0/1의 메시지 이름이 같으면 추가 로드/출발 씬 해제 중 수신기를 덮거나 지운다. 씬 이름과 장치 ID를 채널에 함께 넣고 실제 등록 이름으로 해제한다.
- 공유 배선의 최신 회차 절단 합집합은 겉모습뿐 아니라 문 개방 판정에도 사용한다. 실제 탈출로는 ID 0만 문을 구동한다. 다른 발사대의 절단이 먼저 수신돼도 ID 0이 자기 mask만 보면 문은 닫힌 채다. 2/3/4대의 수신 순서 회귀로 확인했다.
- 움직이는 투사체의 주기 스냅샷도 revision을 올린다. 클라이언트의 장애물 예측으로 목록이 달라지면 동일 revision 비교가 호스트의 유효 복구를 거절한다.
- 운반 충돌 때 lastSafeFeet의 Y까지 복구하면 낙하를 취소한다. 수평 충돌만 되돌리고 소유자 교체 시 안전 위치를 새 운반자에게 맞춘다.
- 11/16 사용자 요청으로 공용 클릭 발사 간격 0, 점프 발사 허용. 비행 톱은 충돌까지 유지하며 동시 처리 안전 한도 64발과 분할 신뢰 전송을 사용한다. 실플레이·Relay 검증은 별도다.
- 장치 본체를 숨기면 Ready가 false여도 호스트의 운반자 해제는 실행해야 한다. 이미 발사한 무제한 톱은 숨김 여부와 분리해 계속 갱신한다. 사망·포획·도착·연결 종료와 64발 포화 후 충돌/재발사를 함께 검사한다.

- 호스트가 참가자의 착지 위치를 먼저 받고 점프 상태를 나중에 받을 수 있다. 발사기 획득은 호스트에서 참가자 발밑이 컨트롤러 스킨 폭 이내인지 재검사한다. 소유자의 공중 입력과 실제 떠 있는 참가자는 여전히 거절한다.
- 잡기 후보 안내와 호스트 승인에서 각각 로컬 카메라/원격 몸 방향을 사용하면 장치의 초기 충돌 위치가 달라진다. 공용 발사기에서 현재 손잡이 방향으로 잡기 자세를 검사하고 확정한 다음 카메라 조작으로 전환한다. 실제 요청이 원격 몸 위치보다 먼저 도착할 수 있으므로 짧게 보관해 동일 소유권 회차에서 기존 판정을 다시 확인한다.

## 운반·발사 통합 (2026-11-17)
- PR #408의 수정은 DEV b933060a에 없었다. 이전에 고쳤다는 기록만으로 현재 브랜치에도 반영됐다고 판단하지 않는다. 필요한 파일의 실제 diff와 회귀 검사를 함께 확인한다.
- 발사형 본체는 운반 중 지형에 걸리지 않게 하지만 플레이어 충돌은 유지한다. 잡는 순간에도 본체 빈 공간 검사로 이를 다시 거부하지 않는다. 손잡이 거리·가시선·접지·생존·다른 기물 소유권 검사는 유지하고, 접촉 절단형은 기존 본체 충돌 판정을 사용한다.
- 원격 발사기 추종이 원격 플레이어의 복제된 회전을 덮어쓰면 손 위치가 다시 어긋난다. 본체만 추종하며 로컬 운반자 회전만 조작한다.
- 발사 요청은 LateUpdate보다 먼저 도착할 수 있다. 호스트의 최신 복제 손 위치로 본체를 맞춘 뒤 발사한다. 발사구가 얇은 벽 너머면 플레이어 쪽 빈 위치를 찾아 발사하고 실제 벽 충돌로 소멸시킨다. 빈 위치가 전혀 없으면 벽 관통 생성은 허용하지 않는다.
- 자동 검사와 실제 멀티플레이를 구분한다. 981건 공용·398건 발사기 EditMode 통과는 LAN/Relay에서 모든 참가자의 실제 입력·발사를 완료했다는 뜻이 아니다.
- 최종 발사기는 발사기 정면을 수평으로 투영해 발사한다. 벽 없는 방향으로 빗나간 톱날은 충돌이 없어 64발 슬롯을 영구 점유할 수 있다. 출구 전투 구역에 다시 닿을 수 없는 먼 톱날만 제거하고, 구역으로 향하는 날은 계속 이동시킨다.
- 2026-11-22: 탈출로 A에서 참가자 판정은 보간된 캐릭터와 호스트가 마지막으로 받은 위치·회전을 구분한다. 잡기·발사·놓기가 서로 다른 자세를 쓰면 같은 착지에서 결과가 달라진다. 지연 잡기는 요청 당시 아바타·재시작·부활 번호와 일치할 때만 재시도한다.
