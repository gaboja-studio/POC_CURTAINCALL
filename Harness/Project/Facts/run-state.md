# 런 상태와 장소 전환

## 언제 읽나

런 진행 관리자, 장소 전환, 공간 사이 데이터 전달(CC-108·CC-111)을 설계할 때. 기획 기준이며 구현 상태는 [공통 게임 시스템 지도](../../../Docs/Domains/common-game-systems.md).

## 기획 내용

- 담당: 시스템(@MoHoDu) — 런 상태 관리, 장소 전환, 공간 간 규칙, 잃은 팔다리 수 관리. 각 공간은 필요한 것만 읽고 쓴다.
- 데이터 범위
  - 세션(세대가 바뀌어도 유지): 세대 번호, 가판대(옛 이름: 물려줄 선반) 기물, 이전 세대 기록(이름·사진, 흔적 위치).
  - 런(세대 교체 시 초기화): 일차·현재 단계, 세트리스트(묘기별 난이도 단계), 묘기별 클리어한 최고 단계, 신체 복구 가격 단계(팀 전체 이용 횟수, 부위당 100토큰에서 이용 1회마다 +25, 여러 부위도 1회), 토큰 공동 자금·장부, 대기실 방 배치(런마다 랜덤), 탈출 진행도(열고 해금한 방·문 등), 소품실 기물.
  - 플레이어: 잃은 팔다리 수(0~4), 생존/사망/리타이어, 지닌 기물, 접속 여부.
  - 공연 1회: 참여 명부·난이도, 개인별 호응도·관심 감소 타이머·완주/사망 고정값·도착 여부·정산 토큰, 오브제 최초 성공/회피·추락 중복 방지 기록, 공용 환호 포인트 획득/소멸 상태(팀 개수 인원×2/3/4). 공연 후 정산액은 런의 공동 자금에 합산한다([보상 규칙](../Decisions/reward-rules.md)).
- 장소 전환 계기
  - 런 시작 → 공연장: 도입 컷씬(또는 세대 교체 연출) 종료.
  - 공연장 → 대기실 로비: 공연 종료(자동, 사망자 부활).
  - 대기실 → 공연장: 쉬는 시간 종료 또는 전원 무대 입구 통로 진입. 늦은 인원은 추격, 정리될 때까지 시작 대기.
  - 마지막 공연 → 밤 정비(같은 대기실, 추격자 없음, 전력 차단·철창으로 일부 영역 외 탐색 제한) → 전원이 자기 침대에 누움 → 수면 연출 → 다음 날 아침 쉬는 시간.
  - 대기실 → 탈출로: 전원 탈출로 입구 집결 후 탈출 개시(탐색 제한 시간 정지).
  - 탈출로 → 엔딩: 한 명 이상 도착 / 전원 리타이어(= 런 실패).
  - 4일차 아침 쉬는 시간 종료 → 런 실패 → 세대 교체.
- 전환 때 넘기는 데이터
  - 공연장 → 대기실: 묘기별 종료 계약으로 확정한 성공/실패, 플레이어별 고정 호응도·생존/사망·도착 여부와 정산 토큰(생존 호응×2, 사망 호응½×2 중간 버림 없음, 도착자만 단계별 100/150/200 추가, 실패에도 호응 보상 지급; [보상 규칙](../Decisions/reward-rules.md)), 사망자, 잃은 팔다리 수, 클리어한 단계(묘기별 클리어 최고 단계 갱신). 인간 대포의 1명 실제 목적지 도착 예외는 [최종 구간](../Decisions/Human-cannon/finale-result.md)을 따르며 공용 연결은 별도 소유 Task가 필요하다.
  - 대기실 → 공연장: 출연자 몸 상태·지닌 기물, 다음 묘기·난이도 단계(1일차 1단계 고정), 잡혀 온 인원.
  - 대기실 → 탈출로: 탈출 인원, 몸 상태, 지닌 기물. 탈출로 → 엔딩: 도착·리타이어 목록.
- 부상 데이터는 팔다리 4곳이 아니라 **잃은 팔다리 수(0~4) 하나**로 관리(절단 순서 고정). 인간 대포 추락은 2 증가, 4 이상이면 사망. 절단 기록(누가·언제·원인)은 공연 1회 범위.
