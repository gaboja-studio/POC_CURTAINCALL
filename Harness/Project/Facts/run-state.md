# 런 상태와 장소 전환

## 언제 읽나

런 진행 관리자, 장소 전환, 공간 사이 데이터 전달(CC-108·CC-111)을 설계할 때. 기획 기준이며 구현 상태는 [공통 게임 시스템 지도](../../../Docs/Domains/common-game-systems.md).

## 기획 내용

- 담당: 시스템(@MoHoDu) — 런 상태 관리, 장소 전환, 공간 간 규칙, 잃은 팔다리 수 관리. 각 공간은 필요한 것만 읽고 쓴다.
- 데이터 범위
  - 세션(세대가 바뀌어도 유지): 세대 번호, 물려줄 선반 기물, 이전 세대 기록(이름·사진, 흔적 위치).
  - 런(세대 교체 시 초기화): 일차·현재 단계, 세트리스트, 묘기별 반복 횟수, 공동 자금·장부, 탈출 진행도, 다음 공연 서비스 효과, 소품실 기물.
  - 플레이어: 잃은 팔다리 수(0~4), 생존/사망/리타이어, 지닌 기물, 접속 여부.
- 장소 전환 계기
  - 런 시작 → 공연장: 도입 컷씬(또는 세대 교체 연출) 종료.
  - 공연장 → 대기실 로비: 공연 종료(자동, 사망자 부활).
  - 대기실·백스테이지 → 공연장: 쉬는 시간 종료 또는 전원 무대 입구 통로 진입. 늦은 인원은 추격, 정리될 때까지 시작 대기.
  - 마지막 공연 → 밤 정비(같은 대기실, 문 잠김) → 전원 준비 완료 → 다음 날 아침 쉬는 시간.
  - 백스테이지 → 탈출로: 전원 입구 집결 후 탈출 개시(탐색 제한 시간 정지).
  - 탈출로 → 엔딩: 한 명 이상 도착 / 전원 리타이어(= 런 실패).
  - 4일차 아침 쉬는 시간 종료 → 런 실패 → 세대 교체.
- 전환 때 넘기는 데이터
  - 공연장 → 대기실: 묘기별 종료 계약으로 확정한 성공/실패, 플레이어별 정산액(게이지 구간), 사망자, 잃은 팔다리 수, 묘기 반복 횟수 +1. 인간 대포의 1명 실제 목적지 도착 예외는 [최종 구간](../Decisions/Human-cannon/finale-result.md)을 따르며 공용 연결은 별도 소유 Task가 필요하다.
  - 대기실 → 공연장: 출연자 몸 상태·지닌 기물, 다음 묘기·난이도 단계, 서비스 효과, 잡혀 온 인원.
  - 백스테이지 → 탈출로: 탈출 인원, 몸 상태, 지닌 기물. 탈출로 → 엔딩: 도착·리타이어 목록.
- 부상 데이터는 팔다리 4곳이 아니라 **잃은 팔다리 수(0~4) 하나**로 관리(절단 순서 고정). 절단 기록(누가·언제·원인)은 공연 1회 범위.
