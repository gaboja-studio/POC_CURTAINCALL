# 탈출로 A 추격자 배치

- 좌표는 EscapeCampaignFrame 로컬. 5m 거구는 A에서만 사용한다. 첫 벽은 EscapeBackground/17_BrutalistRoute/01_Understage의 첫 타설 콘크리트 벽 중심(15,1,-1)이다. 대기실 +X 진입의 오른쪽은 -Z. 같은 이름의 (25,7,23) 벽이나 첫 대포 끝막이와 혼동하지 않는다.
- 첫 파괴 모듈은(15,0,-1),Y180°. 선회·첫6m 보행 후 달리기를 유지한다. 가까워졌다는 이유로 보행에 복귀하는 로직은 없다. 실제 낮은 공간의 숙이기와 공격 동작은 유지한다.
- 74개 앵커 중 초반 이동은 콘크리트 뒤를 이용하고12개 PhysicalEncounter에서 접촉→타격→개방→도약→노출 플랫폼 추격을 수행한다. 하강 X52.5, 하부 X16/Z-86, 협동 Z51, 화염 X108이 숨은 이동선이다. 구형 갈색 갤러리/가동 외장/후반 숨은 바닥은 제거했고 대포 판정용 기준점만 남겼다.
- EscapePursuerWalls의13개 파괴구는 추격자 가슴이 벽에서2.8m 이내일 때만 타격을 시작한다. 플레이어 위치로 스스로 열지 않는다. 호스트 시각을 신뢰 전송하며 재시작 시 복구한다. 구형 EscapePursuerScreens 컴포넌트는 현재 프리팹에서 제거했다.
- 컨베이어 플랫폼은 하차장까지, 화염 회랑은 X122.5/Z47~109의 노출 플랫폼으로 이어진다. 후반47~71번은 북측 벽 앞 Z94,72번부터 Z78. 반출기 기초에 실제 통과 공간을 만들고 기존 반출교 기능은 유지한다. 변경 때 점프 곡선의5m 몸통과 착지 지지를 함께 검사한다.
- 원본 벽은 비활성 보존하고 절단 주변 콘크리트 형상은 추격자 프리팹에 둔다. 에디터에서 새 BoxCollider를 만든 직후 bounds를 사용할 때 Physics.SyncTransforms가 필요하다. 벽별 진입/이탈을 한 번 계산해 절단하며 짧은 표본마다 반복 절단하면 불필요한 조각이 폭증한다.
- 실제 대포 비행은 LaunchVelocity와 공통 Gravity로 별도 검사한다. 플레이어 경로 앵커의 직선 보간은 대포 탄도를 나타내지 않는다.
- 튜닝은 GameSettings.EscapeRoute.Pursuer에 있다. 노출 달리기6.6m/s, 벽 뒤24m/s, 노출 공격 범위22m, 최소 노출 체류3초, 복도 예고0.45초, 손 뻗기0.22초. 구간 번호 제한 대신 실제 거리/시야로 포획 대상을 찾으며 숨은 경로에서 새 포획을 시작하지 않는다. 최종 난이도 승인은 아니다.
- A와 UnderstagePursuerPlaytest를 함께 저장한다. dev 갱신 후 원본 A에서 테스트 복사본을 다시 만든다. 새 엔딩/체크포인트를 오래된 테스트 씬으로 덮지 않는다.
- 닫힌 벽의 시야/몸통/공격선/기물 비행은 기술 검사이며 모든 카메라에서의 비노출이나 전 구간 다인 완주를 증명하지 않는다. 원격 파괴 표현·공포감·압박감은 사용자 확인이 남는다.
- 카운트다운은 없다. [내부 연출 시계](escape-route-timer.md)는 유지하며 출구는 필수 배선 절단으로만 열린다.

## Mascot 외형·공격 표현을 수정할 때

- 현재 적용 상태: A/test/프리팹은 기존 회색 외형·Legacy 동작·8부위 히트박스이며 chase의 mascot 참조는 null이다. 사용자 지시로 미사용 Mascot/단면 객체를 제거하고 새 외부 에셋은 돌진·투척 효과음2개와 필수 meta만 제출한다. 아래 실험 자산·제거 전 씬은 로컬에만 보관하며 원격에서 받을 수 없다. 재적용은 사용자 지시를 따른다.

- 외형은 Mascot Horror Pack의 Mascot3 파생본, 기준 높이5m. 원본은 Generic이며 자동 Humanoid 매핑은 별도 Character1_Ctrl 리그를 잡을 수 있다. `Assets/_ThirdParty/Task100/Mascot/Mascot3Humanoid.fbx`는 실제 스킨의 pelvis/spine_01/upperarm_l 등 변형 본에 명시적으로 매핑한 복사본이다. 원본 FBX는 보존한다.
- 몸통과8부위 메시가 원래 나뉜 팩은 아니다. 파생 Part0~8은 원본 삼각형을 본 가중치로 한 부위에만 배정한다. 손·발을 먼저 분리한 뒤 팔·다리를 자른다. 절단면은 보조 마개를 쓰는 시제품이며 제작용 매끈한 절단 토폴로지는 아니다.
- 파생 메시에는 원본의 미사용 정점도 남는다. 절단 파편의 물리 크기는 실제 삼각형이 참조하는 정점만으로 계산해야 한다. 스킨 전체 bounds를 쓰면 손 파편이 전신 크기의 충돌체가 된다. Unity6000.3의 BakeMesh(mesh,true)로 스킨 Transform 스케일을 보정한 뒤 파편에 원래 lossyScale을 적용한다. false는 이번 모델에서 이미2.48배 커진 정점을 반환해 이중 확대가 발생했다. 실제 사용 정점·두 옵션 비교로 확인했다.
- Brute Warrior 보행/달리기·준비·공격·점프/착지와 Human Basic 숙이기를 수동 PlayableGraph로 재생한다. root motion은 끄고 실제 이동 거리로 위상을 맞춘다. 보폭 계산에는 Avatar humanScale과 모델의2.46배 스케일을 함께 반영한다. 현재 보행 주기1.636m, 질주 주기2.084m.
- 신장 팔은 손목과 lowerarm twist 본 위치를 함께 늘린다. 회전된 손 아래에 비균등 스케일과 반대 스케일을 걸면 손가락이 납작하게 찌그러진다. 매 프레임 기준 위치를 복구한 뒤 보정한다.
- 첫6m 보행 후1.15초 대상 응시/준비/포효→질주. 돌/몸통 투척은 조준 예고 후 목표 위치를 고정하고 호스트에서 궤적을 쓸어 충돌을 검사한다. 벽에 막히며 봉·목마처럼 Collider가 꺼진 정상 플레이어도 몸 캡슐로 판정한다.
- 포획하면 봉·줄·목마·대포·운반 기물 점유를 해제한다.1.6초 동안4사지 절단→몸통 운반→28m 이내 다른 정상 플레이어를 우선 조준해 투척한다. 없으면 기존 낭떠러지 투척으로 이어진다. 피해 순서/리타이어는 기존 NetworkPlayer 규칙을 사용한다.
- chase 스냅샷 v7에 준비/파편 궤적과 몸통의 충돌 정지 위치를 포함한다. 원격 전체 플레이 검증과 공포/난이도 평가는 별도로 필요하다.

## 포획 카메라·투척을 수정할 때

- 별도 카메라를 생성하지 않는다. 기존 CameraSpectator/CameraViewDirector가 EscapeCaptured 동안 추격자의 이동 루트+2.5m를 중심으로 기존3인칭 암의1.5배 거리에서 본다. 손·스킨·포획자 Transform을 따라가면 보행/팔 동작이 화면 상하 흔들림으로 전달된다.
- 추격자 자신의 몸 캡슐은 이 구도에서만 카메라 차단 대상에서 제외한다. 실제 벽은 기존 충돌 쿼리로 유지한다. 포획자 위치를±1.5m 흔든30표본에서 카메라 변위0, 벽 차단 PlayMode 회귀 통과.
- Throw 예고 중에는 추격자를 보고, 실제 손 놓기(SwingTime)부터 기존 생존자 관전으로 바꾼다. AttackCue.ThrowTarget이 살아 있으면 그 플레이어를 먼저 본다. 대상 사망/이탈이면 기존 순서로 대체한다. 호스트의 제어된3인 객체 검사에서888 우선→사망 시777 전환 확인.
- 몸통 Throw 동안 extendedForearm/graspingHand는 끈다. 고정 길이 팔을 뒤로 젖혀 빠르게 앞으로 휘두르고 실제 손 위치에서 발사한다. route CannonRelease까지 팔을 늘리지 않는다. 몸통 궤적은 낮은 포물선이며 실제 충돌에서 멈춘다. F6 샘플도 같은 ThrowPitch/ThrowPosition을 쓴다.
