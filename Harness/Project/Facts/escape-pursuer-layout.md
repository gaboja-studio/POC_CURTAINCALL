# 탈출로 A 추격자 배치

- 좌표는 EscapeCampaignFrame 로컬. 5m 거구는 A에서만 사용한다. 첫 벽은 EscapeBackground/17_BrutalistRoute/01_Understage의 첫 타설 콘크리트 벽 중심(15,1,-1)이다. 대기실 +X 진입의 오른쪽은 -Z. 같은 이름의 (25,7,23) 벽이나 첫 대포 끝막이와 혼동하지 않는다.
- 첫 파괴 모듈은(15,0,-1),Y180°. 선회·첫6m 보행 후 달리기를 유지한다. 가까워졌다는 이유로 보행에 복귀하는 로직은 없다. 실제 낮은 공간의 숙이기와 공격 동작은 유지한다.
- 74개 앵커 중 초반 이동은 콘크리트 뒤를 이용하고12개 PhysicalEncounter에서 접촉→타격→개방→도약→노출 플랫폼 추격을 수행한다. 하강 X52.5, 하부 X16/Z-86, 협동 Z51, 화염 X108이 숨은 이동선이다. 구형 갈색 갤러리/가동 외장/후반 숨은 바닥은 제거했고 대포 판정용 기준점만 남겼다.
- EscapePursuerWalls의13개 파괴구는 추격자 가슴이 벽에서2.8m 이내일 때만 타격을 시작한다. 플레이어 위치로 스스로 열지 않는다. 호스트 시각을 신뢰 전송하며 재시작 시 복구한다. 구형 EscapePursuerScreens 컴포넌트는 현재 프리팹에서 제거했다.
- 컨베이어 플랫폼은 하차장까지, 화염 회랑은 X122.5/Z47~109의 노출 플랫폼으로 이어진다. 후반47~71번은 북측 벽 앞 Z94,72번부터 Z78. 반출기 기초에 실제 통과 공간을 만들고 기존 반출교 기능은 유지한다. 변경 때 점프 곡선의5m 몸통과 착지 지지를 함께 검사한다.
- 원본 벽은 비활성 보존하고 절단 주변 콘크리트 형상은 추격자 프리팹에 둔다. 에디터에서 새 BoxCollider를 만든 직후 bounds를 사용할 때 Physics.SyncTransforms가 필요하다. 벽별 진입/이탈을 한 번 계산해 절단하며 짧은 표본마다 반복 절단하면 불필요한 조각이 폭증한다.
- 실제 대포 비행은 LaunchVelocity와 공통 Gravity로 별도 검사한다. 플레이어 경로 앵커의 직선 보간은 대포 탄도를 나타내지 않는다.
- 튜닝은 GameSettings.EscapeRoute.Pursuer에 있다. 노출 달리기6.6m/s, 벽 뒤24m/s, 노출 공격 범위22m, 최소 노출 체류3초, 복도 예고0.45초, 손 뻗기0.22초. 구간 번호 제한 대신 실제 거리/시야로 포획 대상을 찾으며 숨은 경로에서 새 포획을 시작하지 않는다. 최종 난이도 승인은 아니다.
- 운영 A `Assets/Scenes/Levels/escape_route.unity`는 현재 미궁이며 Start 개발 진입과 대기실 캠페인에서 로드한다. 작업 당시의 Prototype/Remodel/UnderstagePursuerPlaytest 씬은 제거했다. 이 문서의 구형 경로 수치는 이전 배치 설명이다.
- 닫힌 벽의 시야/몸통/공격선/기물 비행은 기술 검사이며 모든 카메라에서의 비노출이나 전 구간 다인 완주를 증명하지 않는다. 원격 파괴 표현·공포감·압박감은 사용자 확인이 남는다.
- 카운트다운은 없다. [내부 연출 시계](escape-route-timer.md)는 유지하며 출구는 필수 배선 절단으로만 열린다.

## 낙하 공간과 왕복 경로

- 추격 발판을 외줄의 중심에서 몇 m 옮기는 것만으로 낙하 공간이 확보되지 않는다. 실제 줄 충돌체 폭·발판 폭·다른 높이의 바닥을 함께 확인한다. Task130은 외줄15개에 수평3m 여유 범위를 검사하고, 노출 발판을 벽 쪽으로 좁혔다.
- 벽 뒤 왕복 경로는 동일 X/Z의 높이 다른 바닥끼리 몸통을 막을 수 있다. 상부 우회는 북측 Z145로 분리하고, 짧은 높이 변화는 도약으로 연결한다. 72번 착지는(384,0,78)로 옮겨 방화문 상부 구조물을 넘는다.
- 경로는 생존자를 따라 역주행·역방향 도약하고 등장 구간을 다시 사용할 수 있다. 노출 플랫폼·보스 작업장은 EscapePursuerNavigation의 지지·몸통 검사와 격자 탐색으로 우회한다. 도약 높이·속도는 GameSettings.EscapeRoute.Pursuer.routeJump 계열이다.
- RestoreFallClearance와 RepairTraversalClearance가 운영 A·추격 프리팹·테스트 씬을 함께 저장한다. CSG 수정 뒤 인접 콘크리트 조각을 병합하고, 보행 지지를 마지막에 복구한다. 편집 검사 후 실제 플레이 확인은 사용자가 수행한다.

## 복사본 추격전 공간 실험

- 사용자 요청으로 `Assets/Scenes/Tests/EscapeRoute/Pursuer/EscapeRoutePursuitRemodel.unity`를 만들었다. 추격자 프리팹 연결을 해제했고 메시·이동면도 별도 에셋이다. 원본 A와 기존 테스트 씬, 공용 추격자 프리팹에 새 공간을 전파하지 않는다. 공간 롤백은 원본 A를 여는 방식이다.
- 최신 사용자 지시: 추격자 전용 경로는 전부 벽 안에 숨기고 플레이어 코스와 분리한다. 노출 회랑 실험은 폐기했다. `EscapePursuitRemodel.Apply`는 새로 복사한 씬에서만 실행하며 꺾인 진입부·차폐벽과 10개 벽 파괴/도약 등장을 구성한다. 등장 뒤에는 기존 플레이어 발판을 사용하고 추격자 전용 외부 바닥을 추가하지 않는다.
- 숙인 속도 3m/s와 경로 경계 예외·투척 표현 수정은 공통 코드/공용 설정이므로 원본에도 적용된다. 실험 씬의 `useEntranceSequence`는 운영 A와 같은 진입·도착 절차를 사용하게 한다.
- 공간 참고·구간별 의도는 Task130의 layout.md에 있다. 실제 완주·다인 추격과 체감 난이도는 사용자가 검사한다.

## Revision7 추격자

- 최신 Circus Golem Revision7 look 모델을 공용 EscapeAPursuer 프리팹·운영 A·기존 테스트·실험 복사 씬에 연결한다. 원본 공간은 보존하지만 외형은 함께 갱신한다. 원본 A를 여는 것은 공간 롤백이며 외형 롤백과 구별한다.
- 207본/9스킨과8부위 절단 순서를 유지한다. Humanoid 재매핑 없이25개 원본 모션을 직접 샘플링한다. Roar 기존 슬롯은 ChargeWarning을 참조한다. Legacy 회색 리그는 등장 루트 이동만 담당하고 렌더러는 끈다. 목/머리는 실제 추격 대상의 몸 높이를 따라 회전한다.
- 실제 이동 거리로 Walk/CarryWalk3.24m, Run5.94m, CrouchWalk3.6m 주기를 맞춘다. 원본 숙임 보행과 목 추적을 함께 적용해 기존3.35m 통로를 검사한다. 모델/본 스케일은1이며 두 다리 절단 후에는 MaimedCrawl과 낮은 공격/피격 자세를 사용한다.
- 손 쥠/투척/타격/도약/착지는 animation-manifest의 프레임에서1을 뺀 뒤30fps로 환산한다. 기존 원격 스냅샷의 시간에 맞추며 FBX 이벤트로 피해를 중복 실행하지 않는다.
- 오른팔은6개 외피와145개 접힌 천 본을 이동시켜 펼친다. 손과 손가락 크기를 유지하고 기존 손 타격/포획 위치에 맞춘다. [리그 연결 함정](../Pitfalls/pursuer-doll-unity-rig.md)을 확인한다. 오른손/오른팔 절단 후 새 포획·투척을 시작하지 않는다. 이미 발사된 투사체는 계속 충돌 검사한다.

## 이전 Mascot 외형과 공통 공격

- 이전 Mascot3 실험은 제거되어 chase.mascot은 null이다. Generic 원본과 별도 Character1_Ctrl 대신 실제 스킨의 변형 본을 명시 매핑한 `Assets/_ThirdParty/Task100/Mascot/Mascot3Humanoid.fbx`는 이력용이다. 파생 Part0~8은 삼각형을 본 가중치로 한 부위에만 배정했고 절단면은 시제품 마개였다.
- 파생 메시에는 원본의 미사용 정점도 남는다. 절단 파편의 물리 크기는 실제 삼각형이 참조하는 정점만으로 계산해야 한다. 스킨 전체 bounds를 쓰면 손 파편이 전신 크기의 충돌체가 된다. Unity6000.3의 BakeMesh(mesh,true)로 스킨 Transform 스케일을 보정한 뒤 파편에 원래 lossyScale을 적용한다. false는 이번 모델에서 이미2.48배 커진 정점을 반환해 이중 확대가 발생했다. 실제 사용 정점·두 옵션 비교로 확인했다.
- 이전 PlayableGraph 실험은 Brute Warrior와 Human Basic 클립, root motion 끔, Avatar humanScale×2.46 스케일로 보행1.636m/질주2.084m 주기를 사용했다. 손목과 lowerarm twist 위치를 함께 늘리고 매 프레임 복구했다. 이 수치와 Humanoid 방식은 Revision5에 적용하지 않는다.
- 첫6m 보행 후1.5초 양팔/상체 포효→질주. 대상 지목/바닥 표식은 표시하지 않는다. 돌/몸통 투척은 조준 예고 후 목표 위치를 고정하고 호스트에서 궤적을 쓸어 충돌을 검사한다. 벽에 막히며 봉·목마처럼 Collider가 꺼진 정상 플레이어도 몸 캡슐로 판정한다.
- 포획하면 봉·줄·목마·대포·운반 기물 점유를 해제한다.1.6초 동안4사지 절단→몸통 운반→40m 이내 다른 정상 플레이어를 우선 조준해1.6초 비행으로 투척한다. 없으면 가장 먼 충돌 없는 낭떠러지 궤적을 고른다. 피해 순서/리타이어는 기존 NetworkPlayer 규칙을 사용한다.
- chase 스냅샷 v8은 준비/파편 궤적·몸통 충돌 정지 위치와 실제 시선 대상 LookActor를 포함한다. 원격 전체 플레이 검증과 공포/난이도 평가는 별도로 필요하다.

## 포획 카메라·투척을 수정할 때

- 별도 카메라를 생성하지 않는다. 기존 CameraSpectator/CameraViewDirector가 EscapeCaptured 동안 추격자의 이동 루트+2.5m를 중심으로 기존3인칭 암의1.5배 거리에서 본다. 손·스킨·포획자 Transform을 따라가면 보행/팔 동작이 화면 상하 흔들림으로 전달된다.
- 추격자 자신의 몸 캡슐은 이 구도에서만 카메라 차단 대상에서 제외한다. 실제 벽은 기존 충돌 쿼리로 유지한다. 포획자 위치를±1.5m 흔든30표본에서 카메라 변위0, 벽 차단 PlayMode 회귀 통과.
- Throw 예고 중에는 추격자를 보고, 실제 손 놓기(SwingTime)부터 기존 생존자 관전으로 바꾼다. AttackCue.ThrowTarget이 살아 있으면 그 플레이어를 먼저 본다. 대상 사망/이탈이면 기존 순서로 대체한다. 호스트의 제어된3인 객체 검사에서888 우선→사망 시777 전환 확인.
- 몸통 Throw 동안 extendedForearm/graspingHand는 끈다. 고정 길이 팔을 뒤로 젖혀 빠르게 앞으로 휘두르고 실제 손 위치에서 발사한다. route CannonRelease까지 팔을 늘리지 않는다. 몸통 궤적은 낮은 포물선이며 실제 충돌에서 멈춘다. F6 샘플도 같은 ThrowPitch/ThrowPosition을 쓴다.
