# 피해자 화면을 기준으로 포획하기

## 언제 읽나
피했는데 잡힘·원격 포획 권한·접촉 패킷·포획 후 동기화를 고칠 때.

- AI/경로/대상 선택과 포획 최종 상태는 호스트. 다른 소유자의 플레이어는 피해자 클라이언트가 접촉을 보고해야 잡힌다. 호스트 거리만으로 원격 포획하는 경로와 타임아웃 자동 포획은 없다. 호스트 본인/오프라인은 기존 거리 판정 유지.
- PursuitActor.LateUpdate에서 실제 표시된 추격자 위치와 로컬 소유자의 현재 root를 검사한다. 기존 CaptureRadius/벽 검사를 유지한다. 새 위치 패킷이350ms 이상 없으면 멈춘 복제본으로 보고하지 않는다. 역순 패킷은 이 신선도를 갱신하지 않는다.
- PursuitContact는57B: 캠페인 generation/day/performance/poseEpoch, actor index, sequence, 마지막 신뢰한 pose 시각, 표시 actor/현재 player 위치. 피해자 ID는 패킷에 없고 NGO sender로만 결정한다. 접촉 중150ms 간격 신뢰성 순서 전송, 확정 전 부상·입력 잠금·포획 연출 없음.
- 호스트는 상태/소유자/epoch/순서·최대1.25초 이내 시각·접촉 범위·시야 내 추격 경로·이동 오차·벽을 검증한다. 경로는 실제20Hz로 보낸 좌표와 동일한 시각을64개 고정 버퍼로 보관한다. 표시 보정 때문에 과거750ms 경로에서60cm 이내임을 허용하지만 피해자 화면의 접촉 반경은 넓히지 않는다.
- 검증된 보고만 CommitCapture로 들어간다. 피해자 보고 위치+기존 모델 offset을 포획 anchor로 사용하고 그 위치의 방을 선택해 호스트의 늦은 좌표로 연출/조명을 되돌리지 않는다. 이후 기존 victims/snapshot·절단·외팔·Retired·관전·조명 경로 재사용.
- authoritative Timer가 Pursuit인지도 확인해 타이머 초기화 직후의 이전 active 캐시로 확정하지 않는다. 초기화/런 변경/메시지 재연결 때 이력·순서를 비운다. 이전 epoch/늦은 보고/이미 잡힌 대상/같은 actor 중복 포획은 거부. 프로토콜v4(state/ready/poses/contact), 전원 같은 버전 필요.
- 이는 이미 소유자 권한인 플레이어 이동 보고의 타당성 검사이며 전체 서버 물리 예측/되감기를 구현한 것은 아니다. 자동 지연 재현과 실제 여러 PC의 Relay 검증을 구분한다. 결과는 Task-099의 capture-contact-*-tests.json 및 log를 따른다.
