# 리허설 공연 원본 재사용

- 정상 Start/SpaceLink 경로의 실제 외줄 공연은 `Assets/Scenes/Tests/MainStage/Tightrope/Tightrope.unity`다. Tests 폴더 이름만으로 개발 전용이라고 판단하지 않는다.
- 실제 공연은 일반 Swing=false, 네 봉 Relay=true, 세 봉 Trapeze=true다. 컴포넌트가 있다는 이유만으로 그 기물/표시가 실제 플레이에서 활성이라고 말하지 않는다. 일반 그네의 예측 착지·초록 해제 표시는 휴면 코드에 있지만 정상 공연에서는 생성되지 않는다.
- 작업 씬은 `Assets/Scenes/Tests/WaitingRoom/Base/WaitingRoomBase.unity`다. 사용자 지시로 WaitingRoom 내용을 먼저 복사했고 원본 WaitingRoom 파일과 Base GUID는 보존한다. Dev 시작 선택 Rehearsal 공개 경로를 사용한다.
- 기획서 v19 재반영: **1→2-1→2-2→2-3→3** 순서 유지. 줄 전환, 낮은 봉1개, 낮은 봉2개, 단일 트리거 협동, 목마/공중 봉 학습이다. 3단계는 사용자 답변대로 현행 유지.
- `TightropeCoursePrepared`·`GameSettings.Tightrope.Course.Clone()`과 원본 활성 봉 컴포넌트를 재사용한다. 줄 개수는2/1/1/2/4, 길이는38/32/38/32/34m이며 단계별 발판·배치는 기획서 구조도를 따른다. 전 구간4줄이라는 이전 지시는 대체됐다.
- 2-3은 UseSpots로 원본 봉1개를 위쪽 끝에 두고 잡는 동안 아래쪽12~20m를 연결한다. 원본 복제 점유 상태로 모든 화면의 표시/지지면을 갱신하며 30초 만료는 제외한다.
- 3단계 공중그네는 원본 첫 두 봉의 높이/간격·3번 줄을 사용하고 다음 봉 잡기로 완료한다. 일반 공연의 세 봉은 그대로다. 첫 봉은 목마 위 사람 또는 실제 목마 분리 점프 자격만 허용한다. 단독 진입 예외는 없다. 아래 동료도 별도 F로 몸에 매달린다.
- 호스트가 실제 옆줄 점프, 낮은 봉 도약/다음 봉 잡기, 트리거로 연결된 줄 통과, 높은 봉 사이 비행/잡기를 관찰한다. 도착만으로 학습을 건너뛰지 못한다. 학습 비트는 공유하고 회차마다 초기화한다.
- 원격 목마 해제 RPC는 Jump NetworkVariable보다 먼저 올 수 있다. 해제 프레임에 점프가 없다고 기록을 지우면 정상 원격 도약을 놓친다. 원본 `PiggybackFollow.LaunchTimeout` 동안 실제 앞 방향 점프를 기다리고, 땅에 F 하차/추락/만료 시에는 지운다. 빌드9 실제4인 재현→빌드10 F 하차 거절/원격 도약 성공으로 확인했다.
- 손잡기는 정상 공연에서 활성인 인접 줄 착지 도움(거리1m·충격 감소50%)이다. 수동으로 손을 잡고 걷는 조작으로 안내하지 않는다.
- 목마는 공연처럼 모든 외줄 구간에서 원본 연결 규칙을 쓴다. 이전의 3단계 전용 허용/리허설 2인 상한은 철회했다.
- 연습 모드에서만 해제봉/공중그네의 30초 강제 해제·유지 시간 표시를 제외한다. 원본 `TightropeRun.PracticeMode`가 경계이며 일반 공연의 30초 제한·비행/잡기·네 봉 연결 규칙은 유지한다.
- 사용자 확정: 리허설은 앞쪽 최대 각도의50% 이상에서 Space로 놓으면 다음 봉/건너편 줄에 닿는 출발 속도로 보정한다. 중립0도 기준이 아니다. 원본 중력/높이 상한·공중 조절·F 잡기·호스트 비행 공유는 유지하고 공연에는 적용하지 않는다.
- 공연 씬 프리팹 밖의 PiggybackSystem/Follow, CatchSystem/착지 표현, 균형 자세, 손잡기 범위 표시도 원본을 함께 연결한다. 프리팹 복제만으로 씬 외부 컴포넌트까지 생기지 않는다.
- `TightropeTrapeze`는 준비 프리팹의 `TightropeCourse.Awake`에서 붙을 수 있다. 비활성 복제에 학습 설정을 먼저 주려면 GetComponent의 null을 무시하지 말고 원본 컴포넌트를 붙인 뒤 설정한다. 활성화 후 Awake가 봉을 생성한다.
- HUD는 원본 PerformanceHud/PerformanceSceneBinding과 공용 상호작용/소지품 UI다. 시간·환호·진행도는 숨긴다. 실제 BalanceCanvas 씬 override(Expand·위험 트랙/채움23/15px)도 복사한다. 원본 프리팹 기본값12/4px는 실플레이와 다르다.
- 도착/과반 투표·2-3 한 명 완료·추락1.5초 후 출발대 복귀·선택 재연습·완료 후 집결은 기존 흐름이다. 현재 감사와 검증 한계: [performance-reuse-audit.md](../../../../Tasks/Active/Task-20261102-097-rehearsal-flow/performance-reuse-audit.md).
- 이전 UI/컴포넌트 존재 비교 PASS를 활성 기물 동등성 증거로 쓰지 않는다. 실제 활성 조건/기물 표시/설정까지 비교한다. 실제 2~4인 전체 입력 완주·재접속은 합성 원격 검사와 별도로 확인한다.

## 인간대포 원본과 리허설
- 2026-11-05 최신 사용자 지시로 외줄처럼 도착 전 넘기기/동의 취소를 허용한다. 전체 참가자의 과반수면 이수로 기록한다. 포기는 별도 집계하며 새 이수를 주지 않고, 기존 이수는 보존한다. 같은 사람이 두 선택에 동시에 투표하지 않는다. 위키의 기존 넘기기 금지보다 이 지시가 우선한다.
- 연결을 새로 맺으면 공유 round는1부터 다시 시작한다. `WaitingRoomCannonRehearsal`은 DontDestroyOnLoad이므로 연결 Reset에서 로컬 endingRound/returnedRound/notifiedRound, 페이드·입력 잠금도 함께 비워야 새 방의 종료 이동이 실행된다. 실제 LeaveAsync→새 방→포기 회귀로 확인한다.
- ESC로 커서를 풀면 CommonMenuUI도 열린다. 대포는 같은 씬에서 입구로 돌아오므로 종료 시작에 CloseAll을 호출해야 메뉴 입력 잠금이 남지 않는다. 실제 ESC→넘기기/포기 버튼 클릭→복귀 후 InputGate 해제 회귀로 확인한다.
- 실제 Start 연결 공연은 `Assets/Scenes/Tests/MainStage/HumanCannon/HumanCannon.unity`다. 실제4프로세스의 정상 Performance 진입과 원본 대포10개/트램펄린/운송3개를 확인했다.
- 현행 운송 `CanStart`는 정상 운반자1명, 자기 발의 탑승 범위, 이동/탑승 상태를 검사한다. `HumanCannonTransport.ContainsLoad` 메서드가 있어도 실제 출발에 쓰지는 않는다. 트램펄린 전체가 발판에 들어가야 한다고 추정하거나 발판을 확대하지 않는다. 실제 운반자1인 출발/공유를 확인했다.
- 실제 씬의 운송 `overloadTrap=false`: 과승은 붉은 거부/출발 대기이고 문을 열지 않는다. 위키3.5의 구형 낙하 문구보다 같은 문서의 최신 dev 기준 지시를 따른다.
- 실제 대포에는 준비 프리팹 밖의 바퀴/20% 시각 override가 있다. `RehearsalCannonSourceBuilder`가 실제 씬 기물 루트를 에디터 API로 복사하여 참조용 프리팹을 만든다. 새 메시/이미지/머티리얼은 생성하지 않는다. 배치·학습용 발판 외의 원본 계층/Transform/메시/재질/발사·반동·운송 설정은 비교 검사한다.
- 리허설은 같은 연습실의 두 체크포인트와 최종 전원 도착을 사용한다. 편성 최초 확정 전 이수 여부 패널, 원본 기물 F 진입, 과반 포기/처음부터 재시작, 도착자 벽, 입구 이동/잠금 해제를 별도로 연결한다. 일반 공연 기본값은 유지하고 PracticeMode의 잘못된 착지만 무부상 사망/복귀로 바꾼다. 기존 부상도 늘리거나 치료하지 않는다.
- 실제4인 검사 도구의 균형 보정을 원본 봇의 공중 Posture 위에 덮으면 외줄 착지 방향이 빗나간다. 원본 봇/공중그네 비행 입력은 보존하고 준비 명령·실제 이동/잡기·완주 결과를 구분한다.
- GatherZone 원점 y=0은 실제 통로 바닥 아래라 최근접 NavMesh가 연결되지 않은 하층을 고를 수 있다. 길안내 목표는 StageEntranceGather.GuideDestination(판정 영역 중심)으로 잡는다. ExitRouteSmoke는 현재 Base 씬에서 실제 걸어 집결하는 검사다.
- 인간대포의 원본 HumanCannonUiBinding은 공용 F 안내와 별도로 운송 상태 C15 툴팁을 표시한다. 연습실에서도 CommonPerformanceUI의 실제 Guide/Tooltip 캔버스 전체를 복사하고 같은 바인더의 ConfigurePractice로 연결한다. 해당 루트의 PerformanceSceneBinding은 비활성으로 저장해 대기실 공용 UI 소유권·시간·환호·공연 진행도를 켜지 않는다. 원본 계층/폰트/재질 비교와 운송 툴팁 표시 검사를 유지한다.
- 원본 한글 폰트 정책 UiRuntimeFontFallback은 캔버스 밖 CommonPerformanceUI 부모에 있다. 두 캔버스만 복사하면 한글 네모가 생기므로 부모 정책과 기존 FontSource 참조도 복사한다. TMP 실제 글리프 검사와 UI 포함 캡처로 확인한다. 연습 전용 포기 패널과 겹치는 툴팁은 그 패널 위로 위치만 피하며 일반 공연 경로에는 적용하지 않는다.
- 대포 연습 배치의 주차된 원형 트램펄린은 오른쪽 첫 대포의 무보정 착지까지 피해 둔다. 렌더 윤곽+플레이어 접촉 범위가 단순 halfSize보다 넓을 수 있다. 운반자가 바로 집어 치우는4인 완주만으로는 이 겹침을 발견하지 못하므로, 아무도 운반하지 않는 오른쪽 첫 발사 검사를 따로 둔다. 최종 발판은 원본 운송 진입로를 덮지 않게 분리한다.
