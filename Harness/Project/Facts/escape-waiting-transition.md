# 대기실·탈출로 로딩 연결

## 언제 읽나
합류실·전환 로딩·A 도착 배치·계단 카메라·최종 집계 연결을 수정할 때.

## 현재 구현
- `EscapeEntrance`와 `EscapeAssemblyState`는 W의 인원만 집계한다. 열쇠 문 해제 + 현재 세션 인원 전원(정상 상태, 부상은 허용)이 모이면 뒤 문을 봉쇄하고 `CampaignRun.StartEscape()`를 요청한다. 합류 전용 시계/만료/시간 세팅은 제거했다. 기존 W 시계는 합류 중 그대로이고 Escape 단계에서 기존 규칙대로 정지한다.
- `EscapeSceneTransfer`는 별도 지속 객체로 최초 참가ID와 각 소유자의 합류 공간 상대 위치·회전·시선을 보관한다. 로딩 중 입력과 소유자 이동 물리를 잠시 멈추며, 요청 확인은 호스트가 참가ID/세대를 검사한다. 전송 지연 중 방 밖으로 나간 소유자는 호스트가 집결 시 수락한 방 안 위치를 사용한다.
- `SpaceLinkDirector.Escape`는 기존 `SceneCurtainTransition`의 전원 화면 가림 확인 뒤 NGO Additive로 A를 로드한다. 전원 위치 보관→A 배경/바닥·로컬 배치 완료 확인→W 해제→커튼 열기 순서다. 두 씬은 로딩 중에만 공존한다. 수신 실패 때 완료로 처리하지 않고 이동을 막은 채 재시도한다.
- `EscapeSceneArrival`이 A 도착 공간·계단 접근 근접 3인칭을 담당하고, 계단 끝부터 요청을 해제해 공용 자유 3인칭을 쓴다(2026-11-01, 이전 계단 끝 1인칭). W 소유 카메라만 A로 이전하며 Hub/전역 카메라는 원래 수명을 유지한다. 기존 운반/대포 시점의 높은 우선순위는 보존한다.
- W `BasementEscapeConnection`은 합류실19 Transform으로 축소했고, A `EscapeArrivalStairs`117 Transform에 같은 모습의 합류실·계단·통로를 옮겼다. 대기실 전체 복제가 아니다. 새 A 프레임은(-200,-16,118.3)/Y180. 합류 기준 W(-17.65,-8.2,93.35)→A(-117.65,-8.2,93.35), 카메라 경계(-138,-14,98.8). 시설 좌표 프레임과 함정 경로도 함께 이동한다.
- W의 출발 벽은 계속 닫혀 있고 A의 대응 벽은 전원 배치 완료 뒤 열린다. 닫힌 뒤 문은 양쪽 공간에서 같은 폭/높이로 외부를 가린다.
- `EscapeCampaignContent`의 최종 집계는 해제된 W 객체 대신 지속된 참가자 명부를 사용한다. 전원 도착/리타이어/이탈 후 도착자1명 이상 성공 규칙은 유지한다.

## 확인 범위
- 편집 모드에서 두 씬 저장, 연결 참조6개 누락0, W에 계단 카메라 트리거 없음, A에 대응 트리거 있음을 확인했다. 최초 구현 때는 Play 미실행. 후속 MPPM4는 집결/출발 확인 뒤 보조3개 로딩 중 접속 이탈로 전원 도착 FAIL, 낮은 메모리 재시도는 사용자 중지. 유동 인원 변경 후 Play 미실행. 상세 Task loading-mppm-results.md.
- 이전 원테이크 MPPM 결과는 새 전환의 통과 증거가 아니다. 전환 지연/실패, 카메라 인계, 4인 위치 유지·부상·소지품·최종 집계는 다음 플레이 검증에서 확인해야 한다.
