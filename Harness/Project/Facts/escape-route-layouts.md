## 확인 방법

- Tools/CurtainCall/탈출로의 A 구조 씬 열기 / B 구조 씬 열기 / C 구조 씬 열기 → **Play만 누르면 혼자 시작**. 세 씬은 같은 EscapeDevelopmentSession을 사용한다. A는 시작홀(13.5,0.05,5), B·C는 기존 무대 하부 입구에서 출발한다.
- 방 생성/참가 UI·게임 오버·관전 대기를 넣지 않는다. 1인 실행은 원본 피격/추락/리타이어 후1초 뒤 복구한다.4인 실행은 생존자가 있으면 유지하고 전원 실패 때 복구한다. R은 호스트 재시작이다. Restarted는 기물/카메라와 A 추격 화염/출구 장치를 함께 초기화한다.
- 내부 개발 연결은 loopback·빈 로컬 포트만 사용하며 씬 종료 시 정리한다. 온라인 서비스/Relay·방 코드 없이 실행한다.
- 인간대포가 기본 조작, 외줄 위에서만 외줄 조작.1키는 실제 플레이어와 함께 자유비행하고 현재 위치/시선에서 복귀한다. R은 원래 출발점 재시작.
- 상시 조작 안내 박스는 없다. 사용할 수 있는 기물 가까이의 F 안내/테두리만 유지한다. 혼자 검토할 때 협동 구간의 동료 역할은 대체하지 않으며 1키로 공간을 살펴볼 수 있다.
- A 융합은 편집 상태에서 원본 탄도·연결·외줄 보행/매달림·그네 이동 범위를 확인했다. AuditCurrentFlow와 이전 제작 검사의 옛 기물 수/계단 가정은 새 A 완료 기준으로 쓰지 않는다. 이전 EditMode10/10·1인 시작 결과도 현행 플레이 검증을 뜻하지 않는다.
- 최신 사용자 요청에 따라 AI가 독립 클라이언트4개의 실제 이동/협동/발사 입력을 검증한다. 개발 실행 인수 -escapeHost 또는 -escapeClient와 -escapePort로 원본 LAN 세션을 연결하고4명이 모이면 시작한다. 인수가 없으면 기존1인 실행이다. 검사 위치 이동과 연속 완주는 구분하며 재미의 최종 평가는 사람이 한다. 런타임 선택·대기실·추격 AI·공식 승리 판정은 별도 범위다.
