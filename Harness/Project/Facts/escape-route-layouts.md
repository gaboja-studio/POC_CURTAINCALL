# 탈출로 A/B/C 검토 씬

탈출로를 열거나 수정할 때 읽는다. 좌표·기물 수·편집 위치는 [현재 variants.md](../../../Tasks/Active/Task-20261027-073-exit-route-space-design/variants.md)가 정본이다. 과거 B/C 공간 전용 상태와 옛 도면은 현행 기준이 아니다.

## 현재 구성

- Assets/Scenes/Levels/escape_route{,_b,_c}.unity 기존 GUID 유지. A: 대포2/그네9/외줄5(A03 한 줄+A05 네 줄)/트램폴린1. B: 대포5/그네9/외줄1/트램폴린1. C: 대포3/그네10/외줄2/트램폴린1.
- A 수정→B 완성→C 완성 후 접합부를 보수했다. A의 깊은 브루탈리즘 시설·거친 설비·작업등·밝은 출구를 공유하며 B는 높낮이 대포 연결, C는 꺾인 외줄·대각 대포·낙하 반동·방향 전환 그네다. 실제 조작/다인 검토는 남아 있다.
- 공통04: 8m 폭 하강 계단·단절3곳/그네3개→Y-22 펌프동 우회/회피→원본 대포로05 복귀. 공통06: 북측 Y-8 회랑/마주보는 화염6쌍 교대→상행→07.
- 공통07: X140–400/Z78의260m 질주,22m 그네 단절, 낙하/측면·정면 톱/철퇴/회전 칼날/불/송풍, 외벽 출구/갈대밭.
- 각 맵 원본 HazardCourse 1개, 피해장치29개+송풍1개. 모든 톱의 외형/판정이 날의 평면 안으로 이동한다. 화염14곳은 기존 FX_Flame_Thrower_01 총84 ParticleSystem을 사용한다.
- 원본 HumanCannonSystem/PoleSystem/Trampoline, 독립 TightropeCourse와 조작권 전환을 재사용한다. InteractionSceneBinding이 공통 상호작용 UI의 테두리/안내를 로드한다. 구 Solo 대체 경로는 비활성 보존한다.

## 확인 방법

- Tools/CurtainCall/탈출로의 A 구조 씬 열기 / B 구조 씬 열기 / C 구조 씬 열기 → **Play만 누르면 혼자 시작**. 세 씬은 같은 EscapeDevelopmentSession을 사용한다. 무대 하부 입구(13.5,0.05,6) 출발.
- 방 생성/참가 UI·시간제한·게임 오버·관전 대기를 넣지 않는다. 원본 피격/추락/리타이어 후 1초 뒤 온전한 몸으로 출발점 복구하며 R도 같은 복구를 사용한다. 기물 점유/카메라 복구는 공용 Restarted 이벤트를 쓴다.
- 원본 NetworkPlayer/묘기 시스템 실행을 위한 내부 연결은 loopback·빈 로컬 포트만 사용한다. 온라인 서비스/Relay·방 코드·외부 참가 없이 실행하며 씬 종료 시 정리한다. 기존 제작용 멀티플레이 시스템은 수정하지 않는다.
- 인간대포가 기본 조작, 외줄 위에서만 외줄 조작.1키는 실제 플레이어와 함께 자유비행하고 현재 위치/시선에서 복귀한다. R은 원래 출발점 재시작.
- 상시 조작 안내 박스는 없다. 사용할 수 있는 기물 가까이의 F 안내/테두리만 유지한다. 혼자 검토할 때 협동 구간의 동료 역할은 대체하지 않으며 1키로 공간을 살펴볼 수 있다.
- 현재 정적 검사는 AuditCurrentFlow(내부 ValidateVariantTraversal)다. 이전 제작단계 검사에는 옛 기물 수 가정이 있으므로 현행 완료 기준으로 쓰지 않는다. 이전 EditMode10/10·1인 시작 결과도 현행 플레이 검증을 뜻하지 않는다.
- AI는 이동/발사 입력·불필요한1인 실행을 수행하지 않는다. 실제 손맛·다인 협동·성능/밝기는 사람이 확인한다. 런타임 선택·대기실·추격/탈출 판정은 별도 범위다.
