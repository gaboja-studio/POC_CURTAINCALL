# 인간 대포 기본 조작

## 언제 읽나

1단계 발사·트램폴린 받기·온라인 동기화를 만들 때. 공통 키는 [control-keys.md](../control-keys.md), 경로는 [협동 경로](cooperative-route.md).

## 결정

- 4인 먼저(지상 담당 1 + 비행 3), 2~4인 기본 역할 구조 동일. 시작/쉼터 대포 최대 3대, 인원이 늘어도 필수 역할을 추가하지 않는다.
- 대포 F 탑승 → 탑승 완료 → **새 F 입력으로 발사**. 자동 발사 금지, 발사 전 F hold 취소. 비행 WASD는 수평 조절만, 수직 힘은 대포·트램폴린에서 얻는다.
- 트램폴린 빈 외곽 손잡이 F 잡기 → WASD 운반. Space로 몸과 장치가 짧게 점프하며 그때도 받기 가능. F hold로 놓으면 장치는 그 자리에 멈춘다.
- 무주인 상태에서도 중앙 반동 유지. 여러 사람이 동시에 들어오면 각자 한 번씩 반동, 같은 진입의 중복 반동 금지.
- **비행 중** 일반 바닥·코스 밖 추락은 즉사 대신 **절단 2곳**(M2, 절단 순서대로, 잃은 팔다리가 4가 되면 사망, [부상·함정](injury-hazards.md)). 현재 구현(M2 미반영): 추락 즉사(`ServerKill`). 담당의 정상 몸 점프 바닥, 대포 발판·쉼터·쿠션·목적지의 지정 정상 착지는 구분한다. 유효 역할 인계 잡기를 일반 바닥 추락으로 처리하지 않는다.
- 발사·소유/점유·역할·위치/점프·비행/반동·사망은 4화면에서 일치하도록 동기화한다. 사망 시 점유 해제, 호스트/참가자 모두 담당 역할을 검증한다.
- 1단계는 **첫 받기 위치에서 시작**하는 장애물 없는 테스트. 분리 출발 이동장치는 3단계이며 미리 구현하지 않는다.

## 이유

새 F와 정상 착지 경계를 명확히 하고, 움직이는 담당이 여러 비행자를 받는 핵심 협동부터 검증한다.

## 바꾸려면

공연장 담당·PM이 원문을 갱신하고 해당 소유 Task에서 변경한다. 4인 공동 테스트는 구현 후 실제 실행·기록한다.
