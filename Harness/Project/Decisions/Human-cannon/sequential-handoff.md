# 인간 대포 인계 완료와 순차 실행

## 언제 읽나

integration/main-stage-human-cannon의 Task-20261015-040~044를 시작하거나 다음 단계로 전환할 때.

## 결정

- 2026-10-15 / PM @MoHoDu(현재 사용자): 5개 Task 모두 담당 @RagSpirin에게 작업 인계를 완료했으며, 담당자는 040 → 041 → 042 → 043 → 044 순서로 실행해도 된다. 추가 인계·착수 승인을 반복 요청하지 않는다.
- 같은 날 PM 정정: 각 Task 안에서도 한 기능 구현→사용자 확인→다음 기능 구현 순서를 지킨다. 인계 완료·순차 실행 승인은 내부 기능을 한꺼번에 구현하라는 뜻이 아니다. 기능별 확인과 전체 통합 후 4인 공동 검증은 별개다.
- 기존의 “실제 전달만 완료, 후속 구현 개방 아님”과 단계마다 별도 PM 배정을 기다리라는 조건을 이 확인으로 대체한다. 각 Task의 기획·수정 금지·공용 종료 의존성은 유지한다.
- 040은 PR #93(8293bb9)으로 통합됐고 041 브랜치는 da4747c로 이를 수신했다. PM의 040 완료 확인에 따라 040을 integrated로 기록하고 코드·테스트 구역과 씬 소유를 041에 이관한다.
- Active Task와 Allowed/공용 씬 소유는 항상 현재 단계 하나만 유지한다. 041은 배정 후 working으로 착수했고, 042~044의 scaffolded는 승인 대기가 아닌 기술적 순번 대기다.
- 선행 구현 통합 후 담당자는 이번 PM 승인에 따라 최신 부모 구현을 받고, 이전 Allowed 반환·다음 단계 assigned/Active Task/Allowed/공용 소유 갱신·이관 이력 기록을 수행할 수 있다. 이 통합의 단계 전환 문서 갱신 권한만 위임한다.
- 기존 합의대로 실제 4인 공동 테스트는 전체 기능 통합 후 수행한다. 단계 전환의 선행 PASS 조건으로 요구하지 않으며, 미실행을 PASS로 바꾸지 않는다. 각 plan의 검증 항목과 최종 통합 검증은 유지한다.
- 코드 구역은 Assets/Scripts/MainStage/HumanCannon/, 테스트 구역은 Assets/Scenes/Tests/MainStage/HumanCannon/이다. main_stage.unity·공용 Systems/Resources·외줄 원본의 수정 권한은 확대하지 않는다.
- 브랜치별 최신 구현·문서 수신 여부는 실제 확인해 기록한다. 이 PM 확인 자체를 원격 sync 완료로 표시하지 않는다. 커밋·push·PR 병합은 기존 사용자 요청 규칙을 유지한다.

## 적용

- Task 기본 문서와 Integration meta/checklist/result에서 이 결정을 참조한다. 일반 Core 절차와 충돌하는 이 통합의 인계 재확인·단계별 4인 PASS 조건에는 현재 PM 지시를 우선한다.
- 기존 assign-task/start-work 스크립트는 원격 문서와 옛 공동검증 조건을 검사한다. 현재 승인과 다른 차단은 기술 상태로 보고하고, 승인된 전환 문서를 정리한다. 이를 PM 미인계로 해석하거나 검사 통과를 꾸미지 않는다.

## 이유

한 담당자에게 이미 완료한 5개 작업 인계를 반복 요청하지 않고, 공유 코드·씬은 한 단계씩 안전하게 이어서 구현한다.

## 바꾸려면

PM이 담당자·순서·구역·검증 시점을 변경할 때 이 결정과 해당 Task/Integration 문서를 함께 갱신한다.
