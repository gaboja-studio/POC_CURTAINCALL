# 기획과 달라진 수치 다루기

## 언제 읽나

기획 문서의 수치(간격·시간·속도·배율 등)를 구현하다가 다른 값을 쓰거나, 기획에 없는 값을 새로 정할 때. 구현 Task를 마무리해 보고할 때.

## 결정

- 2026-10-02 / @MoHoDu: 기획과 다른 수치(기획에 없어 새로 정한 값 포함)는 코드에 박지 않고 **항상 인스펙터 등에서 다시 바꿀 수 있게** 둔다.
- 2026-10-02 / @MoHoDu: 작업을 마치면 기획과 달라진 점을 `- 어떤 기획: 어떤 변경` 형식으로 나열해 **핵심만** 보고한다. 바꾼 값이 있는 위치(컴포넌트·필드)도 함께 적는다.

## 이유

프로토타입은 테스트로 값을 계속 맞춘다. 다시 빌드하지 않고 바꿀 수 있어야 하고, 기획 문서와 실제 값의 차이를 사람이 바로 알아야 기획을 고칠지 값을 되돌릴지 정할 수 있다.

## 바꾸려면

PM이 이 파일을 갱신한다. 큰 규칙 값(게임 규칙·밸런스)은 `Harness/Core/Policies/human-decision.md`도 따른다.
