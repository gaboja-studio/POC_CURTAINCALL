# 런 공통 규칙

## 언제 읽나

런 진행 관리자·쉬는 시간 타이머·공연 종료 판정·접속 처리를 만들거나, 공통 게임 시스템 Task(CC-108~111)의 범위·더미를 정할 때. 기획 요약은 [game-flow.md](../Facts/game-flow.md).

## 결정

- 2026-10-14 / PM(@MoHoDu):
  1. **쉬는 시간 타이머는 B안**(대기실에서 백스테이지로 나온 뒤부터 5분, 복귀는 무대 입구 통로만)을 기본으로 한다. 나중에 A/B 테스트를 하도록 **A안(쉬는 시간 시작부터, 대기실도 복귀 지점)도 구현해 세팅에서 고를 수 있게** 한다(공통 세팅, [game-settings.md](game-settings.md)).
  2. **생존 2명 미만이면 묘기 실패**(모든 묘기 공통 판정). 공연 중 생존자가 1명 이하가 되면 실패로 끝내고 대기실로 복귀한다. 생존자는 부상 그대로, 사망자만 외팔 상태로 부활해 다음 쉬는 시간을 맞는다. 실패이므로 보상은 전원 박탈(게임 흐름 3-3).
  3. **게임 시작 후 재접속 비허용**: 게임(런)이 시작된 뒤 나가면 그 세션에는 다시 들어올 수 없고, 다시 하려면 방을 새로 만든다. **로비(시작 전)에서는 나갔다 다시 들어올 수 있다**(2026-10-14 확인). 현재 구현(진행 중 참가만 거절)과 같다.
  4. **더미 우선**: 공통 게임 시스템 통합에서는 묘기·탐색·대기실·탈출로 로직과 씬을 "게임 시스템이 돌아가고 설정대로 바뀌는지 볼 수 있는" 수준의 더미로 만든다. 실제 공간 로직·씬은 각 공간 담당이 만든 뒤 나중에 교체·연결한다. 더미 위치·이름은 Task `setup.md`에서 PM이 배정한다.
  5. **최소 인원 2명**(기획 변경, 기존 테스트값 1 대체). 1인 테스트는 **개발자 모드**로 한다: #2·최소 인원 같은 인원 규칙을 예외 처리하는 개발용 스위치(빌드 기본 꺼짐). 협력을 보려면 **테스트용 AI 동료**가 더 좋으므로 가능성을 검토해 별도 Task로 하고, 어렵다면 개발자 모드만 둔다.

- 2026-10-14 / PM(@MoHoDu), Task-028 확인 사항:
  6. **B안 타이머는 팀 공용 하나**이고, **누군가 처음** 대기실에서 백스테이지로 나온 순간 시작한다. 아무도 나오지 않으면 흐르지 않는다(4일차 마지막 아침 포함) — 대기실에서 나와야 진행된다.
  7. **시간대 전환 신호**: 공간은 호스트에서 `CampaignRun` 메서드(`EndIntro`·`EndPerformance`·`NotifyLeftWaitingRoom`·`NotifyAllAtStageEntrance`·`StartEscape`·`EndEscape`)를 부르고, 시간대 시작은 `StepChanged` 이벤트로 받는다. 2단계 Task는 테스트 씬 디버그 버튼으로 상대 쪽을 흉내 낸다.
  8. #5 재확인: 최소 인원 2 유지, 1인 시작은 개발자 모드(Task-034)를 2단계에서 먼저 병합해 해결한다.

## 아직 정하지 않은 것

- #6: 플레이테스트 후 B안에서도 바로 제한 시간을 시작할지(특히 마지막 아침) 다시 논의할 수 있다. 바꾸면 `RunState.EnterRest`의 타이머 시작 조건만 고친다.
- #5: 개발자 모드가 예외 처리할 규칙 목록과 켜는 방법, 테스트 AI의 범위(더미 묘기만 / 실제 묘기까지)는 해당 Task에서 제안 후 확정.
