# 최초 리허설과 첫날 연결

## 최종 사용자 승인 (2026-11-03)
- 모든 단계/소구간: 1명 도착 후 연습 지속, 접속 참가자 과반수 동의 또는 전원 도착 시 즉시 전환. 각자 동의 체크 취소 가능, 4명3표/3명2표/2명2표. 단, 2-3 트리거 그네는 1명 도착 즉시 전환(사용자 2026-11-04).
- 도착자는 도착대 안 이동만 가능. 조작 퀘스트 제거 후 동료 진행·투표 상태 표시.
- 기물 이용 직전 안전 위치에 개인 체크포인트. 비상호작용 기물 끝나기 3m 전 기준, 공중/끊김이면 안전 지점으로 조정. 추락 1.5초 후 마지막 유효 지점 복구.
- 기존 공연 발판으로 중간 지점을 구성한다. 인간 그네 F→W/S→Space·연속 공중 F 학습 동작을 유지하며 원본 장치 재사용.
- 최초 교육 포기 불가, 이수 후 단계 선택 재연습·자유 종료. 둘째 공연은 안내 완료 후 호스트가 스케줄표에서 선택·확정.
- 가이드 패널은 기획서대로 구현, 인간대포는 후순위. 현재 실행 기준: `Tasks/Active/Task-20261102-097-rehearsal-flow/approved-rules.md`, Jira CC-199.
- 아래 이전 결정/미정 표기는 이 승인과 다르면 대체된다. 체크포인트 실제 배치 안전성은 아직 구현 검증 대상이다.

- 사용자가 [공연 리허설 시스템 기획서](https://docs.google.com/document/d/1ajABs87srd4A6vjaKxfzkIjxC7fr8t_6Hvw2KjJzhWQ/edit)를 최종 규칙으로 지정했다. 기존 Confluence·아래 이전 결정과 다르면 새 문서가 우선한다.

## 언제 읽나
첫날 캠페인·대기실 출입 제한·안내 완료·임시 퀘스트를 수정할 때.

## 확정 결정
- 서명 → 연습실 리허설 → 완료 후 무대 입구 전원 집결 → 첫 외줄 공연 → 대기실 튜토리얼 → **1일차 두 번째 공연** → 밤 정비 튜토리얼 순서다.
- 최신 사용자 정정: 신규 대체 구현은 기존 외줄 공연 프리팹·조작·HUD로 교체한다. 세 단계를 같게 만들지 않는다. 1단계 두 줄·중간 지점, 2단계 기본/연속 그네/릴레이 세 소구간, 3단계 나란한 네 줄·짝 트리거를 유지한다. 추락하면 해당 소구간 출발 위치로 복귀한다.
- 기능 연결을 먼저 마치고 검증과 대기실 버그 수정을 한다.
- 리허설 중 연습실 입구는 닫힌다. 완료하면 열고 전원이 나온 뒤 다시 잠근다. 첫 공연 전 다른 구역·상호작용 제한은 첫 공연 뒤 대기실 튜토리얼 때 해제한다.
- 전원이 대기실 연계 안내를 마치기 전 탐색 타이머와 집결에 의한 다음 공연 전환을 막는다. 임의의 120초 자동 완료는 제거한다.
- 최초 리허설 포기 투표는 제거한다(과반수 카운트다운은 인간 대포 리허설 규칙).
- 실제 공연에는 퀘스트를 추가하지 않는다. 기존 공연 UI만 사용한다.
- 이번 대기실 기능 연결 범위에 임시 퀘스트 패널을 허용한다. 패널·퀘스트·내용은 사용자가 나중에 편집할 수 있어야 한다.

## 편집 위치
- `Assets/Resources/Settings/WaitingRoom/WaitingRoomTexts.txt`: 리허설 `rehearsal.*`, 첫날 연결 `first-day.quest.*`, 우측 패널 수치 `first-day.panel.*`.
- 좌측 대기실 튜토리얼은 기존 `WaitingRoomTutorialTexts.txt`와 `WaitingRoomTutorialPanel.txt`를 쓴다.
- 수치는 플레이를 다시 시작할 때 읽는다. 임시 퀘스트는 실제 상태를 표시하며 별도 완료 버튼·보상 규칙은 추가하지 않는다.

- 최신 사용자 정정: 중간 지점을 임의 발판으로 구현하지 않는다. 리허설 전용 받침·틀·점선 도형 생성은 철회한다. 인간 그네는 직접 반동·놓기로 이동, 트리거 그네는 동료 줄 연결 역할이며 공연 원본 장치를 연결한다. 모호한 추가는 사용자 확인 뒤 진행한다.
