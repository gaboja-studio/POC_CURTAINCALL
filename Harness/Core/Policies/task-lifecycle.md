# Task Lifecycle

Task 하나는 담당자 한 명이 이어갈 수 있는 목적 단위다. 계획과 할 일은 작업 중 바꿀 수 있다.

## 위치와 식별

- `Tasks/Active/Task-YYYYMMDD-NNN-slug/`에서 진행하고 완료하면 `Tasks/Done/`으로 옮긴다.
- 별도 Status·배정·실제 인계 여부를 관리하지 않는다.
- 누구나 `Scripts/new-task.ps1`로 번호와 3개 문서를 만든다. ID는 현재 작업 트리·로컬/원격 ref에서 중복을 확인한다.
- Task별 작업 브랜치와 담당자를 plan에 적는다. 번호 발급은 현재 확인 가능한 ref 기준이며 공유 시 중복이 발견되면 수정한다.

| 파일 | 내용 | 읽는 시점 |
|---|---|---|
| plan.md | 제목·담당·브랜치·공유 대상, 목적과 현재 계획 | 시작·이어 하기 |
| todo.md | 지금 할 일·완료 항목 | 시작·이어 하기 |
| log.md | 특별한 문제·검사 결과·다음 할 일·PR 링크 | 필요한 때 |
| History/ | 이전 기록 원문 | 필요한 때 |

## 흐름

1. 목적·담당·브랜치를 기록한다. 상세 계획을 PM이 미리 채울 필요는 없다.
2. 담당자가 조사하면서 plan·todo를 작성하고 변경한다. 구역 배정·Jira·앞 Task 상태를 기다리지 않는다.
3. 기능 연결과 관련 버그 수정도 목적 안에서 진행한다. 별도 Task는 담당이나 목적을 실제로 나눌 때만 만든다.
4. 개발·수정 묶음 완료 또는 사용자 요청 시 필요한 검사를 한 번 한다. 결과는 log에 적는다.
5. 요청 시 저장·제출한다. dev 반영은 PR과 지정 팀원 검토로 한다.
6. 실제 완료된 Task만 Done으로 옮긴다. 씬·에셋 자동 삭제는 하지 않는다.

## 기존 작업 이관

- meta·setup·handoff의 원문은 같은 Task의 `History/Harness-v1/`에 보존한다. 권한·인계·세부 상태는 과거 기록이며 현재 제한으로 적용하지 않는다.
- 현재 목적·담당·브랜치·미해결 사항은 plan/todo/log와 원문 링크로 이어 간다. Done 작업은 원래 기록을 보존한다.
