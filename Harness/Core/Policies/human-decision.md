# Human Decision Gate

## 목적

AI는 승인된 Task 범위 안에서 일반적인 기술 세부사항은 고를 수 있지만, 플레이어가 체감하는 의도를 지어내면 안 된다.

## 사람 결정이 필요한 것

다음을 바꾸는 선택이면 해당 작업을 멈추고 Open Decision으로 기록한다.

- 게임 규칙, 난이도, 밸런스, 진행도, 보상, 실패 조건
- 조작, 상호작용 흐름, 확인 동작, 접근성, UX
- 씬 구성, 하이어라키 의미, 프리팹 구조, 공용 UI, 조명, 카메라, 시각 피드백
- 아트, 애니메이션, 사운드, 문구, 현지화, 내러티브
- 제품 범위, 우선순위, 완료 조건, 되돌리기 어려운 마이그레이션

요청할 때는 현재 근거, 추천안 1개, 실질적으로 다른 대안, 각 선택의 영향(바뀌는 파일/에셋)을 제시한다.
답을 기다리지 않아도 되는 다른 작업은 계속한다.

## AI가 정해도 되는 것

- 지역 변수명, 작은 리팩터링, 에러 처리, 테스트 구조
- 저장소에 이미 있는 패턴 재사용
- 도구 호출 순서, 검증 순서
- 되돌리기 쉽고 플레이어에게 보이지 않는 구현 세부사항

단, 되돌리기 비싸거나, 여러 도메인에 걸치거나, 공개 계약을 바꾸거나, Unity 직렬화 데이터에 영향을 주는 기술 결정은 올린다.

## 기록

- 미해결: Task `meta.md`의 `Open Decisions`
- 해결됨: Task `meta.md`의 `Decisions`에 날짜·결정자와 함께 기록
- 프로젝트 전체에 오래 유효한 결정이면 `Harness/Project/Decisions/` 또는 `Harness/Engine/Unity/Decisions/`에 파일로 옮긴다(`knowledge-routing.md`).
- 침묵, 백그라운드 알림, 관련 없는 이전 승인을 허락으로 간주하지 않는다.

## 확인 중 새 요구가 나오면

사람 확인 도중 요구사항이 바뀌거나 늘어나면 현재 Task에 붙이지 않고 **새 Task로 분리**한다.
현재 Task는 원래 합의한 확인 항목만으로 완료 여부를 판단한다.
