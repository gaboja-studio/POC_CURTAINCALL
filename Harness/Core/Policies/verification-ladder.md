# Verification

개발·수정 묶음이 끝났을 때 또는 사용자 요청 시 필요한 검사를 한 번 한다. 중간 수정마다 전체 검사·공동 플레이를 반복하지 않는다.

| 변경 | 기본 확인 |
|---|---|
| 문서·하네스 도구 | 변경 안전성·문서 규칙, 도구를 바꿨다면 관련 회귀 검사 |
| Unity 코드·씬·설정·에셋 | 변경 안전성·문서 규칙·Unity 컴파일 |
| 버그 재발 위험이나 중요한 로직 | 관련 자동 테스트를 선택 실행 |
| 재미·조작감·방향성·최종 플레이 경험 | 사람이 판단. 사용자가 원하는 시점에 확인 |

- `pwsh -File Scripts/check-work.ps1`: 필요한 기본 확인 후 log 기록. Task가 없는 수정도 가능하다.
- 자동 테스트는 `-RunTests [-Mode EditMode|PlayMode]`로 요청한다. 기존 테스트를 활용하며 사소한 변경마다 테스트 구조를 만들지 않는다.
- `verify-scope`는 과거 이름의 호환 명령이다. 구역·PM 권한을 검사하지 않고 미해결 충돌·비밀 파일·Unity `.meta` 누락을 확인한다.
- 파일이 바뀌지 않았으면 같은 검사를 반복하지 않는다. 이전 결과를 재사용할 때 변경 내용이 일치하는지 확인한다.
- 문서·도구 작업에 Unity 에디터를 요구하지 않는다. Unity 변경이 있는데 `-SkipUnity`면 생략으로 기록하고 컴파일 성공으로 처리하지 않는다.
- 해당 검사가 실패하면 의존하는 다음 검사는 생략한다. 독립적인 확인은 계속할 수 있다.
- 결과는 `PASS`, `FAIL`, `SKIPPED(이유)`, `NO_PROJECT_TESTS`, `ENV_BLOCKED(이유)`로 정확히 남긴다.
- 실제 입력·다인 플레이를 하지 않았다면 자동 로직 테스트 통과와 구분한다. 사람 검증을 실행하지 않고 통과로 쓰지 않는다.
- 고정된 공동 테스트 항목·인계 검사·세부 상태는 착수나 다음 작업의 조건이 아니다.
