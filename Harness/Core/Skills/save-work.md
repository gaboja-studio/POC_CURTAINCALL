# Save Work

1. Unity에서 저장(Cmd+S / Ctrl+S)했는지 확인한다.
2. 외부 에셋 변경이 있으면 프로젝트 `third-party-assets.md`의 담당 권한을 확인한다. 지정 관리자에게 승인된 외부 에셋 저장 요청은 private 저장소 저장·push와 공개 포인터 저장까지 포함한다.
   - private 저장소 변경·브랜치·gh 작성자·`.meta`를 확인하고 해당 에셋만 커밋·main에 반영·push한 뒤 공개 저장을 진행한다. detached HEAD·충돌·미승인 변경이 있으면 먼저 해결한다. root 저장 스크립트는 private 내부 파일을 저장하지 않는다.
   - 다른 구역 밖 변경은 섞지 않는다. 검사 실패나 Unity 미연결을 통과로 처리하지 않는다.
3. Task 브랜치면 `todo.md`가 실제 진행과 맞는지 확인하고, 끝났는데 `[ ]`인 항목을 `[x]`로 고친다(`implement-code` 8번).
4. 이번 변경을 한 줄로 요약해 커밋 메시지를 만든다: `<종류>: <요약>` (예: `feat: 커튼 3초 열림 연출`).
5. 먼저 미리보기: `pwsh -File Scripts/save-work.ps1 -Message "<메시지>" -DryRun`
   - 스크립트가 하는 일: 작성자 확인 → 현재 변경에 일치하는 검증 증거 확인(없으면 구역·문서/규칙·컴파일 순서로 검사) → 변경 파일 목록 출력. 실패나 필수 에디터 차단 뒤에는 저장하지 않는다.
6. `[위반]`이 나오면 **저장하지 않는다.** 원인별로 쉬운 말로 알린다.
   - 구역 밖 파일: "○○는 이 Task 구역이 아니에요. 되돌릴까요, PM에게 요청할까요?"
   - `.meta` 없음: "Unity에서 해당 폴더를 한 번 열면 생겨요."
   - 문서 크기 초과: `compact-docs` 절차로 줄인 뒤 다시 시도한다.
   - 사용자 동의 없이 파일을 되돌리거나 지우지 않는다.
7. 문제가 없으면 `-DryRun`을 빼고 실행한다(현재 파일·인덱스가 검증 증거와 일치하고 에디터 상태도 유효하면 재사용하고, 달라지거나 증거가 없으면 다시 검사한 뒤 커밋 → push). 검사 도중 파일 내용이 달라져도 중단한다.
8. 무엇을 저장했는지 1~2줄로 보고한다.

`tests/*` 브랜치에서는 구역 검사를 하지 않는다. Task 없는 `resource/*`는 `Assets/Resources/`와 지정 관리자의 `_ThirdParty` 포인터만, 급한 `fix/*`는 PM 전용·다른 Task 구역만 아니면 통과한다. `dev`, `integration/*`, `builds/*`에는 이 Skill로 저장하지 않는다.
