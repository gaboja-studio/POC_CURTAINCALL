# Implement Code

1. `setup.md`의 작업 구역과 `Harness/Engine/Unity/Policies/code-folders.md`를 확인한다.
2. 요청이 모호하면 결과를 구체적으로 한 번 되묻는다(예: "몇 초 동안 열릴까요?"). 게임 규칙·UX 판단을 지어내지 않는다.
3. 코드는 **내 스크립트 폴더 안에만** 만든다. 진행 중인 다른 Task의 폴더, 공용 씬·프리팹은 수정하지 않는다.
   - 필요하면 멈추고 "PM에게 요청이 필요해요"라고 알린다.
4. 기존 코드·패턴을 재사용하고, 가장 작고 되돌리기 쉬운 방식으로 만든다.
5. 다른 기능이 쓸 수 있게 공개 진입점(public 메서드, 이벤트)을 한 곳에 모은다.
6. 게임 로직은 가능한 한 `MonoBehaviour`와 분리하고, 새 로직에는 EditMode 테스트를 함께 둔다(테스트 폴더도 작업 구역 안).
7. 씬·프리팹 배치가 필요하면 `integrate-editor` Skill을 따르거나, 사람이 Unity에서 직접 하도록 안내한다.
8. 한 번에 한 가지를 구현하고, 끝나면 무엇이 바뀌었는지와 Play로 확인할 방법을 쉬운 말로 알린다.
9. 사용자가 원하면 `save-work`, `check-work`로 이어 간다.
