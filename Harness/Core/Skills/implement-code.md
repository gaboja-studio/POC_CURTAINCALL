# implement-code

1. plan·todo와 관련 지도·기존 구현을 확인한다. 폴더 경계로 읽기·사용·수정을 막지 않는다.
2. 게임 의도가 미정인 부분만 묻고 이미 요청한 내용과 기술 구현은 직접 진행한다.
3. 기존 패턴·공개 진입점을 활용하고 필요한 관련 기능 연결도 같은 Task에서 고친다.
4. 작업에 따라 plan·todo를 수정한다. 담당이나 목적을 나눌 필요가 있을 때만 새 Task를 만든다.
5. 다른 사람 미저장 변경을 보존한다. 겹치는 수정은 담당자에게 알릴 내용을 기록한다.
6. 씬·프리팹 변경은 integrate-editor를 따른다. 큰 에셋 수정·삭제는 PM·에셋 관리자가 관리한다.
7. 개발·수정 묶음이 끝났을 때 필요한 검사를 한 번 한다. 사소한 변경마다 테스트를 만들거나 전체 검사를 반복하지 않는다.
8. todo와 log를 갱신하고 기획자가 이해할 수 있게 바뀐 점·남은 확인만 짧게 알린다.
