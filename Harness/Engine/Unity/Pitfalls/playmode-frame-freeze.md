# Play Mode 프레임 멈춤

## 언제 읽나

AI가 CLI/MCP로 Play Mode에 들어가 시간 경과가 필요한 동작(코루틴, 애니메이션, 타이머)을 확인하려 할 때.

## 증상

Play Mode에 진입했지만 `Time.frameCount`가 거의 오르지 않고, 코루틴·애니메이션이 진행되지 않는다.

## 원인 (추정)

에디터 창이 포커스를 잃었거나 백그라운드 상태여서 플레이어 루프가 거의 돌지 않는다. 정확한 조건은 아직 확정되지 않았다.

## 대처

1. 시간 흐름이 필요한 검증은 가능하면 **PlayMode 테스트**(`unity test --mode PlayMode`)로 작성한다. 테스트 러너는 프레임을 직접 진행시킨다.
2. 로직은 시간 값을 주입받게 설계해 EditMode 테스트로 확인한다.
3. 수동 Play Mode 확인이 꼭 필요하면 우회로를 찾느라 오래 헤매지 말고 사람 확인(5단계)으로 넘긴다.
4. 확실한 우회법을 찾으면 이 파일을 갱신한다.
5. (Task-20261014-037) 일시정지한 뒤 eval 안에서 `EditorApplication.Step()`을 부르면 프레임이 동기로 한 칸씩 진행된다. 단 큐에 넣은 키보드 이벤트는 Game 창 포커스·입력 설정을 바꿔도 플레이어 입력에 닿지 않으므로, 입력 검증은 PlayMode 테스트나 사람 확인으로 한다.
6. (Task-20261013-032) 단계 진행을 공개 함수 eval 호출로 하면, 호출 사이에 에디터가 프레임을 돌려 씬 전환·코루틴이 끝나 있는 경우가 많다. 전환이 끝났는지는 상태(예: `IsTransitioning`)를 다시 조회해 확인한다. Play 진입 직후 첫 eval은 도메인 리로드로 끊길 수 있으니 결과를 확인한 뒤 다음 단계를 보낸다(한꺼번에 병렬로 보내지 않는다).

## 확인 방법

Play Mode 진입 후 몇 초 간격으로 `Time.frameCount`를 두 번 조회해 증가하는지 본다.
