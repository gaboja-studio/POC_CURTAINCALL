# Plan

## Context

041은 040 다음 예약 단계다. 폴더·빈 씬(root 0)만 준비됐으며 인간 대포 기능은 구현되지 않았다. 아래는 실행 근거가 아닌 예정 계획이다.

## Activation

1. PM이 040 integrated·실제 4인 공동 테스트 근거·소유권 반납·실제 JIRA URL을 확인한다.
2. 다음 1개인 041에만 Active Task/Allowed를 부여하고 승인된 준비 브랜치에 배정 문서를 Merge commit으로 sync한다.
3. 기존 feat 브랜치는 앞 단계 완료 후 최신 부모 이력을 받는다. 실제 전달 PM 확인 이후만 start-work한다.

## Approach

1. 봉 F 잡기→W/S 반동→F hold 취소·손 놓기 도약을 연결한다. 정지 봉은 잡는 동안 연결 톱 자동 수납(별도 hold 유지 불필요).
2. 봉 제한시간을 적용하고 놓기/시간 끝/사망 시 예고 뒤 톱을 재동작시킨다. 일반 봉은 밝은 금속, 연결 봉은 노랑/검정·케이블로 대상을 표시한다.
3. 비행자가 위 봉으로 관문 열기→지상 담당 아래 통과→너머에서 다시 받기를 필수화한다. 지상 점프·옆 우회·연속 봉·중계·정지 장치 반복으로 건너뛰지 못하게 한다.
4. 외팔에게 다시 받을 시간·공간을 확보한다. 지상 사망 시 장치는 제자리에서 반동 계속, 생존 비행자가 중앙 반동→반동 중 외곽 F 손잡이로 인계한다. 놓치면 재반동 재시도; 부활 아님, 함정·불꽃은 계속한다.

## Files / Boundaries

- 예정 파일은 setup의 예약 구역만 참조하며 현재 수정 권한은 없다. 공용 부상·관전은 읽기/재사용만 한다.
- main_stage.unity는 025 소유, 외줄 원본은 읽기/재사용만 허용. 공용 부상·관전·종료 수정은 별도 소유 Task다.
- 지상 2명 규칙·중계 대포·호응/보상 수치·2~3인은 미정/후속이며 구현 목표에 넣지 않는다.

## Auto Verification

- 구역: 예약 — 미배정. PM 준비 문서·컴파일·기존 EditMode 결과는 handoff의 Verification 참조.
- 이 단계 기능 자동 테스트·실행 로그·실제 4인 검증: 미실행.
- 활성화 후 `pwsh -File Scripts/check-work.ps1 -Mode PlayMode`로 검사하고 구역→문서→컴파일→PlayMode 테스트→실행 결과를 사실대로 기록한다. 테스트 부재는 NO_PROJECT_TESTS, 실제 플레이 PASS가 아니며 공동 플레이를 대체하지 않는다.
- PM 준비의 기존 EditMode 5/5 검사와 이 단계 PlayMode/실제 4인 검증은 별개다.

## 공동 테스트 항목

합의·실행 전 계획이다. 모든 묶음은 실제 4인 플레이로 수행하며 실제 결과는 handoff에 따로 기록한다.

1. 봉 조작·톱 수납/재동작

- 씬: HumanCannon.unity (setup 예약 테스트 씬, 현재 040 소유; 이관 후 실행).
- 인원: 4인(호스트 1·참가자 3). 지상 담당을 호스트→참가자로 교환하고 같은 순서를 반복한다.
- 재현: 일반/연결 봉 F 잡기→W/S→F hold 취소·놓기 도약→다시 잡기→제한시간 만료→봉 이용자 사망을 별도 회차로 재현한다.
- 예상: 잡는 동안 해당 톱만 자동 수납; 놓기/시간 끝/사망 뒤 예고 후 재동작. 입력·봉 표시·톱 상태가 네 클라이언트에서 일치한다.
- 실제 기록 방법: 일시·4인 이름/역할·브랜치/commit·입력 순서·수납/예고/재동작 시각·영상/로그·예상 대비 실제를 handoff에 남긴다. 현재 미실행.

2. 필수 관문·우회 방지·외팔 다시 받기

- 씬: HumanCannon.unity (setup 예약 테스트 씬, 현재 040 소유; 이관 후 실행).
- 인원: 4인(호스트 1·참가자 3). 지상 담당 호스트/참가자 교환 후 외팔 비행자 조건도 반복한다.
- 재현: 비행자 위 봉→지상 아래 통과→너머 다시 받기; 지상 점프/옆길/연속 봉/정지 장치 반복 우회 시도→외팔로 정규 순서 재시도한다.
- 예상: 비행자 봉 협동 없이는 통과 불가; 정규 협동은 외팔도 시간·공간 여유 안에서 완수하고 다시 받기가 동기화된다. 중계 우회용 장치는 추가하지 않는다.
- 실제 기록 방법: 일시·4인 이름/역할·commit·부상 상태·각 우회 시도/정규 경로·받기 시각·영상/로그·실제 성공/실패를 handoff에 남긴다. 현재 미실행.

3. 지상 담당 사망·반동 중 인계

- 씬: HumanCannon.unity (setup 예약 테스트 씬, 현재 040 소유; 이관 후 실행).
- 인원: 4인(호스트 1·참가자 3). 지상 담당 호스트 사망과 참가자 사망 회차를 교환한다.
- 재현: 봉 이용자 생존 상태에서 지상 담당 사망→장치 위치/반동 확인→중앙 반동→외곽 F 손잡이 인계; 놓친 회차는 중앙 재반동으로 재시도한다.
- 예상: 장치가 제자리에서 계속 반동하고 생존 비행자만 새 담당이 된다. 사망자 부활·함정/불꽃 정지 없이 인계와 재시도가 네 화면에 일치한다.
- 실제 기록 방법: 일시·4인 이름/역할·commit·사망/반동/F 인계 타임라인·장치 위치·영상/로그·실제 인계/재시도 결과를 handoff에 남긴다. 현재 미실행.
