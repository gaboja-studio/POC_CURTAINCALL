2026-10-29: 사용자 요청에 따라 현재 A의 원본 외줄2개·그네6개·트램폴린1개 전체를 연결했다. A03 사용자 검토 대기는 더 이상 구현의 선행 조건이 아니다. 실제 횡단은 사용자가 검토한다.

- 외줄 조작 진입 시 해당 플레이어의 원본 HumanCannonControlScheme 인스턴스와 이동축/줄 간격을 보관하고 이탈 시 복구한다. 대포 점유·비행 중에는 빼앗지 않는다. 카메라·부상 정책·줄 아래 추락 검사는 외줄 조작 범위에 한정한다. 공동 하부를 걷는 사람에게 A03 높이 기준 사망을 적용하지 않는다.

- 입력 없는 검증: EditMode 연결 회귀3/3, A03 참조/지지면31/31, 대포 정적 탄도/참조 검사. 실제 LAN Host의 Player1/최소1/게임 시작/인간대포 조작/공용 카메라 연결/외줄 Run Running 확인. 자동 이동·발사·완주 없음. Vivox Editor 인증403은 별도 환경 오류이며 LAN 시작은 성공했다. 사용자 통과와2–4인 협동은 미검증이다.

## 코드로 확인한 통합 쟁점

1. 외줄 좌표는 현재 `Forward/Right/GetDistance/GetLanePosition`, 플레이어는 `CourseForward/CourseRight`를 제공한다. 기존 문서/주석과 Rebuild 경고에는 월드+Z 설명이 남아 있다. 따라서 회전 불가로 단정하지 않고 대각 코스의 입력·스폰·착지·카메라 전체 경로를 확인한다.
2. TightropeCourse는 정적Current, 공용 Shape, Awake의 지형 생성/지원 컴포넌트 자동 추가, 스폰 재배치가 있다. 여러 구간에 원본 코스를 그대로 복제하면 충돌할 수 있다. 구간별 배치/활성 코스 선택과 공연 지형 생성의 분리가 실제로 필요한지 조사한다.
3. 기본 조작권은 인간대포가 갖는다. 외줄 위에서만 외줄 조작/균형을 적용하고 외줄 이탈 후 반드시 인간대포 조작으로 복귀한다. CourseControlSwitcher의 플랫폼 복귀 경로도 이 기준에 맞춘다. 외줄 추락/매달림·대포 비행·봉 점유 상태를 전환 중 초기화하지 않는다. 별도 키 매핑·이동 물리를 추가하지 않는다.
4. PoleSystem.FindGrabbable은 HumanCannonSystem의 비행 상태를 요구한다. A07에서 일반 달리기 점프만으로 봉을 잡을 수 있다고 가정하지 않는다. 기존 그네 진입/공중 전환 경로를 찾아 사용하고, 필요하면 기존 시스템의 진입 어댑터만 추가한다.
5. GroundBounce는 점프뿐 아니라 반동 면 위에서 내려오는 공중 낙하도 허용한다. 기존 호스트 요청/중복 방지·운반 소유권을 유지하며 외줄 추락 판정이 반동 전에 확정되는지 확인한다.
6. 공연용 Run/Bridge의 도착 정산·실패 재시작이 탈출로에서 임의로 시작되지 않아야 한다. 묘기 메커니즘과 공연 한 판의 수명 관리를 구분한다. 기존 손상/죽음/재시작 규칙을 로컬 즉시 리셋으로 바꾸지 않는다.
7. 1인 시작 API는 이미 있다. 원본 HumanCannonTestHud는 Editor에서 봇을 추가하므로 그대로 이식하지 않는다.1인 검토가 실제 협동 완주 가능성을 증명하지는 않는다.
8. 모든 그네는 인간대포 시스템으로 통일한다. TightropeCourse.Awake가 자동 추가하는 TightropeSwingPole/TightropeTrapeze 등 외줄 전용 그네가 탈출로에서 함께 활성화되지 않도록 연결 방식을 조사한다. 외줄 옆 그네·A05·A07 모두 같은 잡기/반동/놓기 경로를 사용한다.

## 실행 순서와 통과 기준

1. **원본 씬 구성 조사:** 두 씬의 실제 프리팹/컴포넌트/세팅/상태 전이/장애물 변종 표 작성. 제작 스크립트의 초안이나 오래된 문서만으로 현재 동작을 단정하지 않는다. AI 자동 플레이 대신 정적 참조 조사와 사용자 실제 조작 기준을 사용한다.
2. **현재 A의 실제 플레이 진입:** 별도 Solo 대체 경로를 비활성화하고 공용 플레이어·세션·카메라/기존 입력 복구.1인 호스트로 시작 가능, 임시 봇 없음, 원본 조작과 같은 이동/점프/부상임을 확인.1키는 검토용 비행 전환만 담당하고 실제 메커니즘을 대체하지 않게 한다. 비행 중 점유/낙하·복귀 처리를 함께 확인한다.
3. **A03 한 구간 연결:** 인간대포 기본 조작→대포 발사/안전 착지→외줄 조작→인간대포 기본 조작 복귀. 착지/외줄 진입 시 조작권 충돌·부상 초기화·전역 재시작 없음. A05/A07까지 연결한 상태에서 사용자가 실제 플레이를 확인한다.
4. **A05 융합:** 원본 외줄 이탈→원본 트램폴린 접촉/반동→원본 봉 잡기/놓기→안전 착지. 실제 사거리·잡기 범위·진자 궤적에 맞춰 작업대/그네 좌표 조정. 마지막 사람과 운반자의 탈출 경로까지 검토한다.
5. **A07 종합 질주:** 원본에 존재하는 좌우/정면/바닥 톱·철퇴·회전 칼날·불·바람·그네를 기존 판정으로 배치한다. 낙하물은 원본 기능 존재 여부를 먼저 확인하며 없으면 기존 호스트 피해 경로에 연결할 신규 동작으로 명시한다. 구간 진입 예고→작동→해제만 탈출로 동선에 맞춘다. 전폭 동시 봉쇄를 피하고 기존 속도로 회피 가능한 시간/폭을 맞춘다.
6. **검사·사용자 검토:** 원본 씬의 컴파일/참조 회귀, A 저장/재개방, 실제1인 진입, 사용자 A03→05→07 통과 확인.2–4인 동시 점유·판정·후발 주자와 공용 손상 회귀는 별도 기록한다. 정적 검사 통과를 재미/실제 통과 완료로 보고하지 않는다.

## 계속 지킬 경계

별도 씬 생성, 공용 파라미터 임의 변경, 별도 묘기 입력 체계, AI 자동 이동/발사/완주, 요청 없는 커밋/푸시는 하지 않는다. 현재 요청으로 A05/A07 장치를 함께 연결한다. 사용자 검토는 최종 플레이 경험 확인이며 구현 허가를 다시 받는 단계가 아니다.

## 2026-10-29 전체 장치 연결과 비행 동기화

- 한 TightropeCourse에 독립 지지면 두 개를 등록한다. 줄 번호는 A03=0/A05=1이며 각 줄의 위치·길이·높이·진행 방향을 사용한다. 서로 떨어진 줄 사이 옆점프/매달림 이동은 허용하지 않는다.
- A05 기존 원형 트램폴린 외형에 원본 HumanCannonTrampoline과 실제 Handle/Grip을 연결했다. 반동12m/s·운반/공중보정4.5m/s 등 원본 씬 값을 복사했다. A05 그네3개와 A07 그네3개는 모두 원본 HumanCannonPole이며 실제 천장 고정점과 움직이는 케이블/손잡이를 연결했다.
- A07은 일반 점프 중 F로 원본 PoleSystem에 진입할 수 있도록 씬에서만 allowPlatformJumpGrab을 켠다. 호스트가 원래 거리·공중 상태·점유를 검증하고 이후 원본 반동/놓기/비행 번호를 사용한다. 원본 묘기 씬의 기본값은 꺼짐이다. 첫 그네는 원본 점프 사거리에 맞춰 X281→279로 이동한다.
- EscapeInspectionSession은 호스트 승인 및 기존 대포/봉/트램폴린/외줄 매달림/목마 점유 해제만 맡는다. 카메라는 실제 소유자 Player를 이동시키고 기존 NetworkTransform으로 위치를 공유한다. 비행 종료 시 현재 위치·시선과 물리/원본 조작을 복구한다. 재시작/연결 종료 때 이전 비행 좌표를 새 스폰에 덮어쓰지 않는다.
- 확인: 격리 EditMode6/6. 자동 입력·발사·주행은 하지 않았다. 장치 연결·접촉·사거리 정적 검증과 실제 플레이 경험을 구분한다. 다인 실기기 검토는 남아 있다.
