# A 기반 B/C 공간 검토 (2026-10-28)

최신 사용자 방향은 **A의 경험과 공통 마지막 탈출 복도를 유지하면서 03/05의 공간을 다르게 만드는 것**이다. 이전 B/C의 별도 진행 축과 묘기 순서안은 아래 현행 구성으로 대체했다. 지금은 맵을 먼저 구성하며, 구체적인 묘기 융합은 후속 개발한다.

A의 기준은 [브루탈리즘 확장](a-brutalist-route.md)과 [260m 마지막 질주](a-runner-route.md)다. B/C는 폴리싱된 최신 A에서 복제했으며, A 원본과 각 씬 GUID를 유지한다. [이전 폴리싱 기록](polish-pass.md)의 B/C 고유 동선·외부 오프셋은 이전 구조의 기록이다.

## 현재 씬과 차이

| 세트 | Unity 씬 | 03/05 내부 공간 |
|---|---|---|
| A | `Assets/Scenes/Levels/escape_route.unity` | 최신 수직 설비실·전이 공동을 기준으로 유지 |
| B | `Assets/Scenes/Levels/escape_route_b.unity` | 높낮이와 간격이 다른 넓은 발판 6개. 향후 점프·착지가 중심이 될 공간 |
| C | `Assets/Scenes/Levels/escape_route_c.unity` | 좁은 정비 선반, 회복 정비대 4개, 하강 계단 69개. 향후 외줄·균형 횡단을 넣을 공간 |

- 공통 구간은 A의 01 무대 하부, 02 압축 갤러리, 04 깊은 수로, 06 상행 구간, 07 마지막 탈출 복도와 08 밝은 외부다. 03/05도 A의 큰 외피·주 설비·입출구를 유지한다.
- 공통 마지막 복도는 `19_RunnerEscape`, X140–400 / Z78 중심의 260m 구간이다. 그 뒤 외벽 출구와 갈대밭도 A 배치를 공유한다.
- 중성 회색 콘크리트, 깊은 하부, 작업등·배관·사용 흔적과 내부/외부의 밝기 대비는 A 기준을 이어 간다.
- 최종적으로 각 맵에 네 묘기를 포함할 방향이지만 모든 구간을 네 묘기의 연속 체인으로 만들지는 않는다. 대포+외줄, 트램폴린+외줄 등 구간별 조합과 낙하를 받아 올리는 융합은 이후 설계한다.
- 현재 발판 간격·높이·`Reserve_` 지점은 공간 배치다. 실제 사거리, 묘기 설치 순서, 트리거, 다인 운용이나 통과 가능성을 확정한 값이 아니다.

## 03 수직 설비실

- 공통 외피는 X22.5–72.5 / Z62.5–112.5m, Y-90–44m다. 지름 12m·높이 120m 주 설비와 주변 콘크리트 구조를 유지한다.
- 공통 입구는 Y0, 도착부는 Y-6, 기존 40단 계단은 Y+2의 04 연결부로 올라간다. B/C는 중간 고립 발판과 이전 설치 가이드를 비활성 보존하고 새 공간을 배치했다.
- B: Y+2 / +5 / +0.5의 발판 3개를 엇갈리게 배치한다. 넓은 착지면 사이의 빈 공간은 이후 묘기 연결을 위한 여유다.
- C: Y0 상부 정비대에서 30단을 내려가 Y-6 하부 정비대에 닿고, 폭 1.6m의 꺾이는 정비 선반이 기존 도착부로 이어진다. 하강 계단 폭은 1.8m다.

## 05 전이 공동

- 공통 외피는 X77.5–127.5 / Z7.5–45m, Y-100–48m다. A의 Y0 입구와 Y-8 도착부를 유지한다.
- B: Y+2 / -2.5 / -5.5의 발판 3개를 두어 높낮이와 착지 방향을 바꾼다.
- C: 진입 선반과 Y0 정비대, 20단 하강 후 Y-4 중간 정비대, 마지막 19개 계단으로 구성한다. 마지막 0.2m 하강은 기존 Y-8 도착 바닥이 받아서 같은 높이의 계단 면을 중복 생성하지 않는다.
- C의 새 계단은 03의 30개와 05의 20+19개를 합쳐 69개다. 선반과 계단은 현재 일반 구조물이며 외줄 소멸·트램폴린 반동 같은 동작은 없다.

## 제작·검사 기준

- 새 공간 그룹: `23_TraversalSpaces_B` / `23_TraversalSpaces_C`.
- 제작: `EscapeVariantASpaces.cs`의 `BuildVariantFromCurrentA("B" 또는 "C")`, C 배치는 `EscapeVariantCSpaces.cs`.
- 정적 조회: `EscapeVariantSpaceValidation.cs`의 `ValidateASharedVariant()`. `ValidateCurrentVariant()`도 새23 그룹이 있으면 이 검사로 자동 연결한다.

| 확인한 정적 항목 | B | C |
|---|---|---|
| 바닥·계단 높이 표본 | 133/133 일치 | 180/180 일치 |
| 공통 연결부, 반경 0.3m SphereCast | 5/5 막힘 없음 | 5/5 막힘 없음 |
| 공통 마지막 복도 `ValidateRunnerEscape()` | 394/394 통과 | 394/394 통과 |
| 공통 구간 서명 | A와 일치 | A와 일치 |
| 축 정렬 삼각형의 동일 방향·동일 평면 중첩 | 12,290개 대상, 0.005㎡ 이상 0건 | 13,070개 대상, 0.005㎡ 이상 0건 |
| 저장 후 재개방·편집 화면 확인 | 재개방 검사 및 8시점 확인 | 재개방 검사 및 8시점 확인 |

저장 후 재개방한 씬에서 위 결과를 확인했으며 A 원본 파일 해시도 변경 전과 일치한다. 공통 서명은 01/02/04/06, `19_RunnerEscape`, `08_Reeds_30x37.5`의 계층·배치·메시·재질·조명 기록을 비교한다. 씬 전체나 실제 묘기 통과를 보증하는 검사가 아니다. 면 검사는 축 정렬 삼각형과 0.005㎡ 이상 중첩을 대상으로 하며 모든 형태의 화면 깜박임을 보증하지 않는다. 이번 묶음의 `check-work`는 안전성·문서/규칙·컴파일 PASS, 자동 테스트 SKIPPED이며 결과는 `log.md`에 기록했다. AI 이동 입력·자동 플레이는 하지 않는다.

## 이전 구조도

- [B PNG](Layout/b-plan.png) · [B SVG](Layout/b-plan.svg), [C PNG](Layout/c-plan.png) · [C SVG](Layout/c-plan.svg)는 **구안**이다. 별도 진행 축·묘기 순서와 이전 외부 배치를 보여 주며 현재 씬의 구조도로 사용하지 않는다.
- 이전 `ValidateCurrentVariant()`의 연결 9곳·바닥 11곳·단절 3곳 결과와 이전 Play Mode 기동 확인은 당시 구조의 기록이다. 현행 A 기반 B/C 검증으로 재사용하지 않는다.

## 둘러보기와 후속 확인

1. 플레이를 종료하고 `Tools/CurtainCall/탈출로/A·B·C 구조 씬 열기`에서 원하는 씬을 연다. 일반 검토에는 재생성 메뉴를 쓰지 않는다.
2. Play를 누르고 Game 화면을 클릭한다. WASD 이동·마우스 시점, Space 상승·Ctrl 하강, Shift 가속, Esc 커서 해제.
3. `Label_` 제작 라벨은 편집 화면에 남고 Play에서 숨겨진다. `Wayfinding_` 현장 표식은 유지한다.

사용자는 A의 공통 분위기·규모가 유지되는지, B의 높낮이와 C의 좁은 횡단·회복 공간이 적절히 다른지 확인한다. 실제 묘기 융합, 치수·속도·사거리·병목 조정, 최종 밝기와 성능은 후속 구현 및 직접 플레이로 확인한다. 런타임 A/B/C 선택, 대기실 연결, 추격·탈출 판정은 이번 범위에 포함하지 않는다.
