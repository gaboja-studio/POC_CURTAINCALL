# 대포대 착지 후 리타이어 조사 — 2026-10-31

## 범위와 결론

사용자 요청대로 Play/MPPM 재실행 없이 기존 run-3 로그와 소스를 읽었다. 대기실·공용 시스템·A 씬과 게임 코드는 수정하지 않았다.

가장 유력한 원인은 **원격 위치 동기화가 착지 요청보다 늦어 안전한 착지를 추락 부상으로 처리하는 경로**다. 기록된 좌표로 해당 거부 조건이 성립함을 확인했다. 다만 당시 착지 요청 수신 시각·인자와 LandingConfirmed/ServerFell 이벤트를 수집하지 않아 이 사건의 호출 경로를 최종 확정할 수는 없다.

## 관측 사실

- 실제 MPPM run-3의 슬롯3/네트워크 ID3. 세 번째 공동 봉에서 컨베이어 앞 대포대로 이동했다.
- 클라이언트 공통 시계418.902598: 발 `(-168.499985, -37.920002, 107.214607)`, Normal, 비행 착지 응답 대기.
- 호스트 공통 시계418.898970: 같은 사람의 발 `(-168.499298, -33.383514, 104.084694)`, 이미 Retired. 호스트에는 더 높은 이전 비행 위치가 남아 있었다.
- 클라이언트418.996887에 Retired 복제 도착. 두 기록의 위치 차이는 **5.5114497m**, 제곱 약30.38로 허용치25보다 크다.
- 직전 실행 중 읽기 전용 검사에서 `대포 포획 준비대.SupportsLanding(실제 착지점) == true`. Collider 중심(-167,-38.4,104.800011), 크기(8,0.800003,9). 윗면 약-38에 skin 여유0.08을 더한 정상 착지다.
- 컨베이어 낙사 영역과 새 심부 낙사 영역 모두 이 착지점 Contains=false. 위험물 ContactResolved 로그도 해당 실행에서 생성되지 않았다. 이 사실만으로 모든 다른 사망 경로를 배제하지는 않는다.
- 조사 직후 ID0/1/2는 LostParts=None, ID3는 팔다리4개 손실/Retired. 이전 부상 시점은 기존 스냅샷에 없다.

## 코드상의 경로

1. `HumanCannonPilot.SimulateFlight()`는 바닥 충돌 시 실제 착지 좌표를 `RequestLanding`으로 보낸다.
2. `HumanCannonSystem.Landing.cs:58`의 safe 판정은 호스트의 현재 플레이어 좌표와 요청 좌표의 제곱거리가25 이하이고 안전 지지면이어야 한다.
3. 위치 차이가5m를 넘으면 안전 지지면이어도 safe=false다. 요청을 보류·재검증하지 않고 비행을 종료하며 `ServerFallInjury`로 이어질 수 있다.
4. 해당 부상은 팔다리2곳을 절단한다. `NetworkPlayer.ServerApplyCut`은 누적4곳 손실 시 탈출로에서 Retired를 확정한다. 다만 이 사건에서 앞선2곳 손실이 언제 발생했는지는 확인되지 않았다.

따라서 **판정식의 문제 조건은 확인, 실제 사건의 정확한 호출/누적 부상 이력은 미확정**이다. 단순히 바닥을 넓히거나 낙사 높이를 낮추는 수정은 현재 증거와 맞지 않는다.
