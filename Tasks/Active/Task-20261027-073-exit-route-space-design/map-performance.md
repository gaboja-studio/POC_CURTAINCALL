## 조사

- 활성 Renderer2,989개, 그림자 투사 Renderer2,631개.
- 실시간 조명146개 중 그림자 조명111개. 구성은 주광1개와 Soft Spot110개였다.
- 활성 재질에서 참조한 텍스처55개, 에디터 런타임 메모리 추정146.9MiB. 실제 빌드/VRAM/플레이 프로파일 값은 아니다.
- 기계 LOD0 중65,945삼각형인 개체가 반복 사용된다. 멀리 보이는 기계의 LOD, 구역별 가시성, 반복 장식 렌더러는 후속 최적화 후보다.

## 적용

경로의12개 기준 위치에서 주요 그림자 조명을 선정해 Spot 그림자110→11개, 주광 포함111→12개로 줄였다. 나머지 조명의 직접광은 사용한다. A 씬에 저장했다.

작은 장식의 그림자 제외도 검토했으나 동적/로직 부모 제외 조건 때문에 실제 변경은0개다. 이번 결과에 렌더러 묶음·LOD 최적화는 포함하지 않는다.

편집8구도에서 조명 전후를 캡처했다. Collider/MonoBehaviour2,142개 직렬화 SHA256이 동일하고 위치/판정은 동일하다. 백업과 조명 원래 값, 측정 기록은 .harness/local/map-performance/에 있다.

## LOD·정적 렌더 묶음·화염 후속

- 기계11개에 원본의 LOD1을 연결했다. 화면 높이20% 아래에서는 저해상도 메시를 사용한다. 해당11개 메시의 합계486,750→243,366삼각형. 가장 먼 단계도 화면 크기0까지 유지한다.
- 정적인 MeshRenderer617개를 재질·그림자 설정·레이어와16m 공간 구역에 따라78개 묶음으로 만들었다. 활성 MeshRenderer 항목2,700→2,161. 원본과 묶음의 합계 삼각형은 모두76,177개다.
- 원본 오브젝트는 편집 복원을 위해 보관한다. 추가 묶음 메시 파일은 private Task073/StaticOptimized에 약12.9MiB다. LOD 메시 추가도 있으므로 이번 단계가 메모리 사용 감소를 의미하지는 않는다.
- 화염 ParticleSystem266개를 Automatic culling으로 변경했다. 추격 불의 지속 연소 배율을 .45→.35로 조정했다. 한 구간14효과의 같은 시드/3초 시뮬레이션에서140→112입자였다.
- 실제 장치의 Collider1,648개 직렬화 동일. 기존 MonoBehaviour/Collider2,142개의 변경은 추격 불 steadyEmissionMultiplier 한 필드다.
- 복원→재생성 시 활성 메시 항목은2,161→2,700→2,161이었다. 복원 레코드의617개 원본 참조가 모두 해석됐다.

### 편집 시 사용

1. Unity 메뉴 CurtainCall/Escape/Optimization/Restore editable geometry로 원본 렌더링을 복원한다.
2. 벽·장식의 위치·재질·에셋을 편집한다.
3. Rebuild static geometry chunks로 묶음을 재생성한다.

원본을 수정한 뒤 재생성해야 묶음에도 반영된다. 이 도구는 A 씬 Edit Mode에서 동작한다.

### 후속 측정

동일 편집 카메라의 원본/최적화/최적화/원본 교차 측정에서 입구 평균6.56→6.14ms, 컨베이어2.53→2.25ms, 출구2.61→2.64ms였다. 출구는 변동이 커 개선으로 판정하지 않았다. 최초 그림자 최적화와 측정 시점이 달라 앞 표의 절대 시간과 직접 비교하지 않는다.
