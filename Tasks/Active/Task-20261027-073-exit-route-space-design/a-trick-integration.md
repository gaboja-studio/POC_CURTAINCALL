# A 묘기 연결 준비

> 최신 상태: [A 융합 레벨 디자인](a-fusion-layout.md)이05 좌표와 플레이 방식보다 우선한다. 아래는 최초 준비 조사다. 현재 A에는1인 검토와1키 공중 전환을 연결하며 별도 씬을 만들지 않는다. 공용 네트워크 묘기 통합은 후속이다.

2026-10-28 사용자 요청: dev 최신 변경을 전부 통합하고 A부터 묘기를 넣을 준비를 한다. 현재 묶음은 기준점과 기존 기능 재사용 조사이며 실제 기믹 설치/플레이 완료를 뜻하지 않는다.

## 기반

- 작업 브랜치 `feat/exit-route/design-map`, dev `8f111b5`를 병합한 기록 `95a771f`.
- 최신 보상·추락/매달림·설정5탭·외줄 위험 표현·월드 폰트 변경 포함. private 지정 버전 `9cc40f2`와 LFS 준비.
- A 원본 `Assets/Scenes/Levels/escape_route.unity`에서 시작한다. B/C 묘기 연결은 A 검증 이후 진행한다.

- A03/05는 `EscapeTrickSetup_A` 하위 빈Transform으로 남긴다. Feet는 발바닥, Base는 장치 바닥, Grip/Pivot은 손잡이/회전 중심이다. 발사구·캐릭터 탑승 높이와 혼동하지 않는다.
- 편집 메뉴: `Tools/CurtainCall/탈출로/A 묘기 연결 기준점 준비`. 최초 생성 후에는 씬의 기준점을 직접 편집한다. 재실행은 기존 기준점을 덮어쓰지 않는다.
- 기존 대포/트램폴린 회색 설치 가이드는 실제 기물 설치 시 중복 충돌을 제거할 대상이다. 준비 단계에서는 보존한다.

## 연결 시 필요한 작업

1. **플레이 진입:** 현재 `EscapeRouteFlyCamera`는 Play에서 기존 미리보기 플레이어를 정지한다. 실제 시험은 비행 모드와 구분해 `NetworkSessionManager`/`NetworkPlayer` 및 묘기 입력을 연결해야 한다. 배경 미리보기 Player만으로 네트워크 점유/발사를 시험할 수 없다.
2. **대포:** `HumanCannonSystem`은 씬에 하나, stations 배열 순서는 모든 클라이언트가 동일해야 한다. `HumanCannonStation`의 탑승/좌석/발사구를 기준점에 맞춰 조립한 뒤 착지 영역과 속도를 조정한다. 원래 공연용 코스 전체를 복제하지 않는다.
3. **외줄:** `TightropeCourse`는 공연용 코스 생성·공용 세팅·플레이/추락 판정에 연결돼 있다. 현재 코드 주석은 월드+Z 이동을 전제로 하므로 A03의 대각선에 단순 회전 배치하지 않는다. 좌표 변환과 탈출 중 활성 범위를 먼저 분리하고 배경 재생성을 피한다.
4. **트램폴린/그네:** 두 기능은 HumanCannon 폴더에 이미 존재한다. 트램폴린은 손잡이/운반·호스트 반동 판정을 재사용한다. 그네는 `HumanCannonPoleSystem`의 봉 배열과 점유/반동을 사용한다. `TightropeSwingPole`은 `TightropeCourse`와 `TightropeRun` 상태에 종속되므로 그대로 붙이지 않는다.
5. **마지막 질주:** 측면/낙하 위험물과 그네 타이밍은 실제 달리기 속도에 맞춰 후속 조정한다. 22m 단절·천장/손잡이 높이는 공간 예약이며 통과가 검증된 물리 수치가 아니다.
6. **공용 규칙:** dev의 최신 신체 손상·추락/매달림·설정·보상 규칙과 연결한다. 공연 결과용 `CampaignTightropeAdapter`를 탈출 구간에 그대로 붙여 공연 정산을 시작하지 않는다.

## 검사 범위

- `EscapeTrickPreparation.cs`의 `ValidateATrickPreparation()`는 설치 기준점14개, 발 위치의 바닥, 기믹/충돌체를 추가하지 않은 상태와07 기존 앵커를 확인한다.
- 공간 구조 검사는 기존 `ValidateBrutalistRoute()`를 함께 사용한다. 자동 플레이·이동 입력은 하지 않는다.
- 실제 발사/외줄/반동/그네·협동 네트워크·밸런스 검증은 기능 연결 후 별도로 수행한다.
