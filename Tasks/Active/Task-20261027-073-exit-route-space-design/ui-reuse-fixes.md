사용자가 ui-reuse-audit.md의 차이 보수와 UI 외 조작·기능 차이 추가 조사를 요청했다.

## 반영

| 조사 ID | 결과 |
|---|---|
| U01/U02 | A 타이머·장치 알림 CanvasScaler를 원본과 같은 Expand로 저장. 기존 균형 UI를 포함해 A의 세 Canvas가 모두 같은 방식 |
| U03 | 원본/A 균형 UI와 관전 키 표시를 PlayerInputReader.BindingPartLabel에 연결. 긴 균형 키 이름은 기존 칸 안에서 글자 크기를 조절 |
| U04 | PerformanceSceneBinding에 표시 전용 모드 추가, A에 연결. 공용 관전 C11 로드/표시를 재사용하고 직접 A 실행의 CameraSpectator도 활성화 |
| U05 | 기존 A 장치 알림 C8에 외줄 조작 안내 연결. Escape/직접 A에서도 외줄에 진입하면 이동·균형, 점프·목마·구조 설명을 순서대로 각 시도에 한 번 표시. 원본의 첫날 공연 설명은 그대로 유지 |
| U06 | A에 공용 HumanCannonUiBinding 연결. C6가 있으면 중복 안내를 숨기며, 없으면 C7/C15 보조 안내를 제공. 원본 리프트/구간 설명은 표시 전용 A에서 사용하지 않음 |
| U07 | 장치 토스트 폰트 참조를 원본 Notifications/Pretendard-Medium으로 통일. 긴 한글 문장용580px 폭과 런타임 글리프/레이아웃 보완은 유지. 이전 생성 폰트 에셋은 삭제하지 않음 |
| U08 | 타이머 저장 글자 크기를 원본40으로 맞추고 자동 크기28~40 범위를 유지 |

표시 전용 모드에서는 공연 점수/호응/진행 HUD를 숨기고 보상 이벤트를 구독하지 않는다. 공용 결과 씬을 새로 로드하지 않으며 이미 남아 있던 공연 결과 표시도 A에서 정리한다. 기존 공연은 기본 모드이므로 결과·보상 흐름을 유지한다. ESC 메뉴 문구도 A를 공연으로 오인하지 않게 구분한다.

대포 보조 툴팁·운반 키와 외줄 설명의 키 문구도 실제 바인딩을 사용한다. 툴팁이 열린 채 바인딩이 바뀌면 내용 갱신 대상으로 인식한다. 설명을 이미 본 뒤에는 글리프 보완을 매 프레임 반복하지 않는다.

## UI 외 추가 조사·수정

| 항목 | 원인·수정 |
|---|---|
| 자유비행 중 리타이어 | EscapeInspectionSession은 Fallen/Arrived만 차단해 Retired 상태가 통과할 수 있었다. 검사 중인 참가자는 Retired도 차단하고 정상 플레이 중의 리타이어는 유지 |
| 메뉴 중 관전 대상 전환 | CameraSpectator는 원시 Posture 입력을 읽으면서 InputGate 차단을 확인하지 않았다. 메뉴·설정에서 게임 입력을 막으면 관전 대상 변경도 멈추도록 보수 |
| 편집 저장 후 검사 대기 | Undo 기록이 씬 저장 다음 프레임에 반영돼 Unity Test Runner의 저장 확인 창이 나타났다. 수정은 저장 버튼으로 보존했고 A 편집 도구는 Undo.FlushUndoRecordObjects 이후 씬을 저장하도록 보완 |

다음 경로도 추가 대조했다:

- 운반 중 공중 조작 가설: 봉 접근 자체가 HumanCannonCarry.Held를 검사하며 운반자의 일반 점프는 PlayerMover 경로다. 운반 중 Pilot 입력 조기 반환만으로 제어 결함이라고 단정하지 않고 기존 이동을 유지했다.
- 발밑 표시의 장식 통과: 원본 검사에서 비착지 장식과 트리거를 건너뛰고 등록된 코스 바닥만 표시하도록 명시돼 있다. 일반 기계 표면을 새 착지면으로 바꾸지 않았다.
- 인원 조건: 합류 출발은 Session.PlayerCount, 협동 잠금은 현재 인원에 맞춘 최소값 경로를 사용한다. 고정4인 출발 조건으로 되돌리지 않았다.
- 외줄/대포 이동·부상/장비: 같은 공통 컴포넌트·GameSettings/Reader·PropCarry API 연결을 유지한다. 맵별 위치·잡기 거리·반동·좌석/길이·추격 즉사/복도 절단 규칙은 복사하지 않았다.

## 저장·검증

- A 편집 도구 EscapePresentationUpgrade 추가: 같은 연결을 다시 적용할 수 있다. 이전 A03/개발 환경 작성 도구도 관전을 다시 끄지 않도록 보완했다. B/C 실행 설정은 이전대로 유지한다.
- A에 표시 바인딩/조작 설명 컴포넌트4개 추가. 변경 전후 이동 경로 Transform과 Collider 문서는 동일. 원본 묘기 씬·공용 UI 씬·대기실 씬·Build Settings는 변경하지 않았다.
- native verified.json: 표시 전용 모드/균형/보조 안내/배너 연결 유효, Canvas 세 개 Expand, 관전 활성, 개발 환경 검사8항목 모두 통과.
- 신규 표시 연결/관전 입력3개와 자유비행 상태를 포함한 원본 연결7개, 안내/배치/문구/키 재지정/대포/부상/트램폴린/협동/타이머/버튼까지13개 필터177/177 통과. 필터별 결과는 test-summary.json. 최종 check-work는 log.md 참조.
- 여러 필터를 한 문자열로 묶은 최초 실행은 리터럴 부분 일치여서0개였다. 이를 검사 통과로 세지 않고 필터별 재실행한다. 첫 원본 회귀는 저장 확인 창에서 대기했으며 저장 후7/7로 완료됐다.
- 실제 Play/MPPM은 실행하지 않았다. 테스트·네이티브 편집 검증과 실제 화면/네트워크 체감 검증을 구분한다.

변경 전 A, 참조 감사와 검사 증거는 `.harness/local/reuse-fix/`에 있다.
