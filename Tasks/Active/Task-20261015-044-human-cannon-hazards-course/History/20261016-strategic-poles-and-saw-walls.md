# 전략 봉·함정 밀도·중앙 전기톱 관문 후속 조정

## 최신 사용자 결정

- 봉은 반동 최고점보다 살짝 낮게. 연속6m 격자16개는 폐기하고 한 구간2~3개의 전략 선택 위치로 분산한다.
- 전기톱/장애물 수를 두 배로 늘리고 바람이 잘 보이게 한다.
- 통과를 막는 관문 장벽 전체를 전기톱으로 교체해 구간 중간에 둔다. 해제봉을 잡으면 톱이 제자리에서 멈춰 안전하게 통과한다. 사용자가 범위를 명확히 하여 코스 양옆 긴 벽은 제외했다.
- 가장 마지막 지시로 봉 자체도 플레이어 반동에 맞춰 앞뒤로 흔들린다. 상부 고정점은 유지한다. 이는 앞선 '봉 고정' 요청을 수정한다.

## 배치/동작

- 봉16→6개: 구간마다 일반2·해제1. 첫 구간(x,z)=(-7,31)/(0,44)/(7,61), 둘째(7,107)/(0,120)/(-7,137). 기존 봉 인덱스0~3/관문 연결은 보존한다.
- 정지 그립 높이는 구간 바닥+반동 면0.5m+12²/(2×9.81)-0.5m. 첫 구간7.34m/둘째13.34m, 구간별 반동 정점보다0.5m 아래다. 트램폴린 반동 힘/물리 중력은 변경하지 않는다.
- 위쪽 빔/앵커를 고정하고 보이는 봉/케이블이 공유 반동 각도에 맞춰 움직이도록 연결한다. 물리 계산용 Grip 기준점을 보존해 표시 갱신이 반동 위치를 반복 가산하지 않게 한다.
- 일반 함정8→16(가시추4·회전 날개4·지상 톱8), 기존 함정 사이/뒤로 추가 분산하고 속도·반경은 유지한다. 송풍4→8(공중4·지상4), 난도별 실제 세기 유지.
- 최종 가로톱2→4: 포구 뒤7/10/13/16m, 수직톱1→2: 서로8m 떨어진 레인으로 동일 예고/공유 주기/실제 피해 판정. 4개 레인 중2개는 수직 톱이 비어 있다.
- 전기톱 관문은z47/123, 해제봉은3m 앞z44/120. 노란 벽 외형 대신 관문당13개 원반 톱을 폭30m에 배치한다. 해제 중초록·정지·통과 허용, 해제 종료 후 예고 동안 정지/점멸, Active에서 회전/접촉 재개.
- 지상 담당 통과 뒤 비행 진행 허용 규칙은 유지한다. 안전 통과는 원래 관문 충돌체를 비활성화하는 방식이며 톱을 땅속으로 숨기지 않는다.
- 송풍마다 큰 청록 화살표3개·움직이는 바람줄기16개·범위 테두리를 표시한다. 전용 Unlit 재질로 조명에 묻히지 않게 한다. 표시 속도는 실제 밀림 속도를 변경하지 않는다.
- 기존60m 연장·10분 목표·부상/시점·독립 대포 유지. 별도 테스트 코스 추가 없음.

## 검증

- Unity Editor API 빌더로 현재 소유 씬에 적용/저장. root15·봉6·일반 함정16·송풍8·최종 톱6. Scene View에서 중앙 전기톱 열/분산 봉/청록 바람 표시를 확인했다.
- 최종 컴파일 PASS·EditMode350/350(0.74초)·실제 LAN호스트 PlayMode9/9(25.67초) PASS. 봉 추종/케이블 끝점/상부 고정/무드리프트/복귀·관문 정지/재회전·최종톱쌍·기존 부상/바람/대포 회귀를 확인했다. 실제4인/실입력/전략성·완주시간은 사용자 확인 대기다.
- 최초 증설 검사에서 Transform의 자식 열거 때문에 NUnit 유일성 비교가 같은 빈 목록으로 처리된1건을 발견했다. InstanceID 유일성 비교로 수정했으며 배치 데이터는 정상이다.
- 커밋/push/PR 없음. PM 위임 전환 문서8개의 기존 scope FAIL은 별도 보고한다.

## 사용자 확인

1. 구간마다3개의 봉 위치/높이를 보고 트램폴린 반동으로 잡는다. W/S 반동 때 봉과 케이블이 같이 움직이며 상부 고정점이 유지되는지 확인한다.
2. 중앙 해제봉을 잡아 전기톱이 제자리 정지/초록으로 바뀌는지, 지상 운반자가 안전하게 통과하는지, 놓은 뒤 예고/재회전되는지 확인한다.
3. 청록 바람 범위/흐름 방향과 몸 밀림을 비교하고 증가한 일반/최종 톱을 통과한다. 실제4인으로 역할 교환·외팔 완주와 목표10분 대비 시간을 측정한다.
