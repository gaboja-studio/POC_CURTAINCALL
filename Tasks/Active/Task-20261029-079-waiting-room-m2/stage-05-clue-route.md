# 5단계 — 조사·힌트 경로 연결 코드

## 구현
- StructureAClueRoute: 낙서1/2/4, 낡은 노트, 공연 기록, 신문, 압수 노트, UV1/암호 앞쪽UV, 각각의 조사 내용, 모니터, 숨겨진 낙서3의 참조/고유 ID를 연결한다. 위치·문구·암호 값을 만들지 않는다.
- 일반 단서 ConfigureIdentity는 기존 제목/설명·공개 조건을 보존한다. 앞2자리 UV와 뒤2자리 압수 노트는 역할을 식별할 뿐 실제 숫자 설정/자동 조합/패드 해제는 하지 않는다.
- UV RevealWhenFound는 기존 표시 목록에 조사 대상을 추가한다. 발견 전에는 조사 내용을 숨기고 직접 조사 요청도 거절한다. 최초 발견 때만 기존 내구도1 소모, 마지막 사용 후 기물이 없어져도 이미 발견한 단서는 별도 F 오버뷰로 재열람 가능하다.
- 모니터는 Monitor 타입을 검사하고 기존 열람 조건·내용을 보존한다. 발견 상태와 각자 패널/입력 잠금은 분리되어 재열람 때 발견을 중복 처리하지 않는다.
- 숨겨진 낙서3은 명시적인 기존/새 공개 조건을 존중한다. 둘 다 없으면 RevealPending으로 숨겨 두며 UV·모니터 등을 실제 조건으로 임의 지정하지 않는다. 등록된 루트가 공개 상태에 따라 활성화를 갱신한다.
- 단서의 공개 조건이 다시 미충족되면 열어 둔 오버뷰를 종료하고 입력을 복원한다. 중복 참조·잘못된 모니터·없는 UV 발견 대상·UV/숨김 대상의 잘못된 계층은 적용 전에 거절한다.

## 검사
- 일반 단서7개 개별 F열람/발견/입력복귀·기존 제목 보존·재열람 중복발견 없음.
- UV 발견 전 직접 열람 거절, 두 UV 단서 발견과 마지막 기물 소진, 발견 후 재열람/재활성화 상태 유지.
- 모니터 기존 조건 보존·재열람 발견1회, 낙서3 조건 미정 비공개와 명시 조건 지정 후 공개.
- 로컬 발견 상태 초기화 시 UV/숨은 단서 공개 해제·오버뷰/입력 복원. 실제 Campaign 세대 교체나 실제멀티 통합 검증 완료를 의미하지 않는다.
- 잘못된 참조 적용 시 기존 ID/조건을 보존한다. 테스트의 모니터→숨긴 낙서 조건·UV2회·문구는 테스트 입력이며 실제 기획을 확정하지 않는다.

## 제외·남음
정식 맵/씬 참조 저장·에셋·상세 텍스트·실제 암호 값·숨겨진 낙서3의 실제 공개 조건 확정은 하지 않았다. 실제멀티는 후순위·최대2인. 다음은6단계 숨은 경로·패드·탈출로 문 전체 연결 코드다. 최종 결과는 log 참조.
