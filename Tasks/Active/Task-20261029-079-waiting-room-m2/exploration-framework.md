# 탐색 기능 프레임워크 — 2026-10-29

현재 사용자 요청: 기존 구현과 내구도 유지, 기능 코드만 추가. 맵 배치·에셋·상세 텍스트·엔딩 연결 제외.

## 조립

- `ExplorationGate`: 기존 `ShopReach` F 선택, `ExplorationState` 호스트 판정·스냅샷 사용. TargetId는 런 전체에서 고유해야 한다.
- `requiredTargets`: 모두 완료돼야 개방. 열쇠는 Open 대상의 F 획득 완료 상태로 팀 공유한다(새 기물/슬롯 체계 없음). 선행 순서 무관, 소모하지 않는다. 두 열쇠+패드 대상 ID를 협력 문 조건으로 연결할 수 있다.
- `revealTarget`: UV/모니터 등 완료 전 안내와 상호작용 숨김. hiddenVisuals에는 표시할 자식만 지정. 문 콜라이더는 미발견 상태에서도 차단 유지.
- Open: 무도구 F 또는 toolId 지정. Breakable: requiredHits 이후 파괴 완료. blocker 해제, hideOnOpen 숨김, showOnOpen 표시. 기존 머리핀/UV/벽은 그대로 사용.
- Monitor: F로 이동 입력을 막고 텍스트 패널 열람, ESC/F/닫기/거리 이탈로 종료. 완료는 팀 공유, 재열람 가능. 상세 내용은 비워 둠.
- Keypad: F로 패널, ASCII 숫자 4개(앞 0 허용) 입력/확인. 정답은 호스트 컴포넌트에서 검증. password는 정식 배치 때 설정(기본 0000은 예시). 잘못된 입력·실패는 내구도/진행 변경 없음.
- Cooperative: 서로 다른 클라이언트 두 명이 가까이서 F. 두 번째 입력 시 첫 사람의 접속·거리·필요 도구도 재검사. cooperationWindow 기본 0.75초는 조정 가능한 구현 기본값이며 확정 기획 수치 아님. 키를 누르고 유지하는 방식이 아님.
- `ExplorationDrops`: 기존 ToolTarget/BreakableWall/새 Gate에 부착 가능. 지정 목록, 빈 목록은 보상 없음. 미부착 대상은 기존 단일 rewardItemId 사용. 미정 랜덤 확률표는 추가하지 않음.
- 발견품 UID offset은 기존 FoundItemSpot 및 모든 보상과 중복 없이 1~99 지정(기존 기물 UID 규약 유지). 아이템 내구도는 ItemCatalog.FoundUses 재사용.
- 열린 대상의 보상 지급 실패는 기물 시스템 준비 후 재시도. 지급 완료 표식을 탐색 스냅샷에 보존해 획득·소모 후 재지급 방지. reward: 접두사는 내부 지급 표식용으로 예약.
- 단서: ClueInspectable 기존 회전·확대 유지. 발견만 같은 탐색 채널로 공유. targetId 명시 권장, 이전 배치에는 씬/계층 경로 fallback.

## 남은 검증/제약

실제 2인 동시 입력·늦은 상태 수신·이탈(사용자 지시: 후순위, 최대2인), 씬 재진입 및 세대 초기화의 네트워크 플레이 확인 필요. 맵 배치를 하지 않아 신규 컴포넌트는 정식 오브젝트에 아직 연결되지 않음. 열쇠/드랍 ID, 비밀번호, 모니터 내용·숨김 자식·충돌체 참조는 후속 배치 작업에서 지정. 현재 세대/런 유지 범위와 기물 카탈로그 수치 변경 없음.
