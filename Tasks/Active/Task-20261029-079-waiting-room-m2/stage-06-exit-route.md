# 6단계 — 숨은 경로·패드·탈출로 문 연결 코드

## 연결
- StructureAExitRoute는 기존 화장실 파괴 벽 참조와 기계실용 열쇠2/숨은 문, 탈출로 패드/협력 문의 참조를 연결한다.
- 화장실 벽은 기존ID·빠루6타·진행/균열/충돌/성공1회 내구도 차감·공유 상태를 유지한다. 잘못된 도구/타격 수 참조는 적용 전에 거절하며 수정하지 않는다.
- 기계실용 열쇠2(structure-a:key-2)는 탈출 열쇠2와 별개다. 획득처나 배치를 생성하지 않고 기존 획득/공개 조건을 보존한다.
- 기계실 숨은 문에는 열쇠2 조건을 추가한다. 명시된 기존/새 공개 조건을 존중하고 둘 다 없으면 RevealPending으로 상호작용/표시를 보류한다. 루트는 활성 상태로 유지해 미발견 상태에도 막음 충돌체를 끄지 않는다.
- 패드에는 명시적4자리 정답 또는 ConfigurePassword API로 지정한 정답을 사용한다. 프로파일의 값이 비어 있고 명시적 지정도 없으면 PasswordPending으로 두며 일반 Gate의 기본0000을 게임 정답으로 승인하지 않는다. 명시적인0000은 허용한다.
- 탈출로 협력 문에는 기존 두 탈출 열쇠와 패드 성공을 모두 요구한다. 기존 추가 조건·공개 조건·협력 입력 간격을 보존한다. 같은 대상에3단계 키 경로를 다시 적용해도 패드 조건을 지우지 않는다.
- 문 개방 상태는 기존 호스트 판정/탐색 스냅샷·열림 표현·충돌 전환을 사용한다. Campaign 탈출 진행·엔딩·씬 전환을 연결하지 않는다.

## 검사
- 미정 암호의0000/틀린 코드 거절, 명시 정답 설정 후 패드 성공, 기존 추가 조건 보존.
- 열쇠2만 있어도 미정 공개 조건을 임의 해제하지 않음. 명시 조건 후 기계실 문 개방·충돌체 해제·중복 요청 진행 증가 없음.
- 패드/두 열쇠/기존 조건 충족 후에도 혼자 F연타로 협력 문은 열리지 않음. 실제2인 성공 검사가 아니다.
- 잘못된 참조·정답 설정은 적용 전에 거절. 명시적으로 지정한0000은 빈 프로파일에도 보존.
- 개방 스냅샷을 로컬로 적용/초기화해 문 충돌체 상태와 Night/세대 상태 유지 확인. 실제 네트워크 수신이나 Campaign 세대 교체 검사로 보고하지 않는다.
- 실제 암호0123·공개 조건·추가 잠금은 검사용 입력이며 기획 확정 값이 아니다.

## 제외·남음
정식 맵·씬 참조 저장·에셋·상세 텍스트·실제 암호/열쇠2 획득처/문 공개 조건 확정·탈출 엔딩은 제외. 모든 화면에 동일한 참조/설정을 적용해야 한다. 실제멀티는 후순위·최대2인.7단계 정식 배치는 현재 범위 제외이며, 다음 가능한 작업은8단계의 임시 대상 전체 흐름 검사다.
