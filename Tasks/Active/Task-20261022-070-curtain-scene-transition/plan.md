# Plan

## Context

참가자는 NGO Load 통지를 받은 뒤 커튼을 닫으므로 씬 변경이 닫힘보다 먼저 보일 수 있다. 전환 UI가 아직 생성되지 않았으면 수신 구독 자체도 없다.

## Approach

1. 씬 수명과 독립적인 커튼 조정자를 시작 시 생성하고 네트워크 시작 때 수신기를 연결한다.
2. 호스트가 닫힘 요청을 보내고 현재 참가자 ACK를 기다린 후 기존 로더를 호출한다.
3. 로컬 NGO 작업·UI·배경 준비 후 열고, 이전 열림 코루틴이 새 닫힘을 취소하지 못하게 한다.
4. 닫힘 확인 실패 시 로드를 취소하고, 접속 종료 시 입력·커튼을 정리한다.

## Files

- setup.md의 다섯 파일만 코드 변경. 씬·프리팹·설정은 유지.
- 추가 승인: CommonWaitingRoomUI의 방송을 기존 상단 배너로 통일하고 해당 배너만 최고 sorting layer/order로 표시. 알림 발생 시점은 유지.

## Risks

- 다른 Task와 겹치는 경로는 PM 채팅 승인을 기록. 기존 담당자의 병합 후 재검토 필요.
- 전환 중 새로 참가하는 사람의 초기 NGO 동기화는 현재 접속자 장벽과 별개이며 보장하지 않는다.
- 실제 네트워크 지연·다중 화면은 자동 합성 테스트로 대체하지 않는다.

## Auto Verification

- 구역·문서 → 전용 Unity 컴파일 → 커튼 회귀·로비·묘기 PlayMode.
- 초기 구역 실패는 PM 승인과 Task setup으로 정식 기록한다. 실패한 검사를 숨기지 않는다.
- 추가 UI는 사용자 최소 검증 요청에 따라 구역·문서·컴파일 + 합성 표시 경로 PlayMode 1건만 실행. 기존 커튼 4건·전체 스위트 재실행은 생략.

## 공동 테스트 항목

사용자 제보의 기대 순서 기준. 실제 확인은 미실행이며 제출 전에 확인 범위를 명시한다.

1. 호스트·참가자 두 화면에서 로비→공연→대기실 이동: 둘 다 완전히 닫힌 뒤에만 공간이 바뀐다.
2. 참가자 배경 로드를 늦춰 확인: 해당 PC의 배경·UI 준비 뒤에만 커튼이 열린다.
3. 닫히는 동안 호스트 접속 종료: 참가자 시작 화면 복귀 및 입력·커튼 잔류 없음.
