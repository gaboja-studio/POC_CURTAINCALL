## 설정 확장 후속 묶음 (2026-10-28, 구현)
- 목적/담당/브랜치: 대기실 런 포기와 로컬 그래픽 설정 추가 / MoHoDu / `feat/game-system-m2`. 계획 준비 후 사용자가 호스트 전용 런 포기를 확정하고 구현을 요청했다. commit/push는 하지 않는다.
- 요청 확정: 대기실 ESC 메뉴의 설정에 `런 포기` 추가 → `정말 현재 런을 포기하고 새로 시작하겠습니까?` 확인창 → `예`일 때 현재 런 즉시 실패·다음 런 1일차 시작. `아니요`/ESC는 취소. 화면 모드·해상도·FPS는 `그래픽` 분류에 둔다. 기본 FPS는60.
- 구현 순서: ① 정식 런 포기 판정·회귀 테스트 → ② 설정 버튼/확인창·입력 소유 연결 → ③ 로컬 화면/FPS 저장·단일 적용 경로 → ④ 그래픽 선택 UI → ⑤ 묶음 검사·사람 확인 목록 갱신.
- 런 경로: `CampaignRun` → `RunState`에 정식 포기 API를 추가하고 `RunEndReason` 끝에 포기 사유를 추가한다. `DebugRestartRun`은 실패를 기록하지 않고 개발 모드 제한이 있으므로 재사용하지 않는다. 기존 `FailRun`의 세대 증가·1일차 첫 공연 경로와 `RunEnded`/`StepChanged`를 활용한다. 방·접속은 유지하며, 세대 변경 구독자가 자금·소지품·부상·난이도·복구 비용을 초기화하는지 실제 연결을 확인한다. 세션 범위 데이터는 유지한다.
- 안전성: 대기실의 진행 중인 런에서만 허용하고, 공연/로비/탈출/전환 중에는 거절한다. 확인창을 연 세대·상태를 재검증하고 중복 클릭·오래된 확인 요청으로 새 런까지 포기되는 것을 막는다. 확인 취소·전환 때 UI/커서/`InputGate`를 정리하며 온라인 게임 시간을 임의로 멈추지 않는다.
- 사용자 확정: 온라인 런 포기는 호스트 전용. 참가자에게 비활성 버튼·호스트 전용 안내를 표시하며 포기 요청을 호스트로 전달하지 않는다. 오프라인 판정 화면은 허용한다. 대기실·전환 상태와 확인창의 세대/일차/시간대/공연 순번을 실제 API에서도 검사한다.
- 그래픽 제안: 화면 모드 `전체 화면(ExclusiveFullScreen)` / `전체 화면 창(FullScreenWindow)` / `창 모드(Windowed)`, 해상도 선택, FPS `30 / 60(기본) / 90 / 120 / 144 / 165 / 240 / 제한 없음`. 60 초과의 구체 목록은 구현 기본안이며 확정 기획 수치가 아니다. 전체 화면 창은 데스크톱 해상도를 따르고 해상도 선택은 비활성·안내한다. 독점 전체 화면은 플랫폼 지원/실제 적용 모드를 확인한다.
- 로컬 설정: `ClientSettings`의 PlayerPrefs에 모드·해상도·FPS를 저장한다. 기존 Fullscreen 키의 창/전체 화면 창 의미를 이관하고, 지원 해상도를 중복 제거·정렬하며 저장 해상도가 현재 모니터에서 유효하지 않으면 안전한 값으로 복구한다. 설정 열기·탭 이동은 미리보기 편집만, `적용`에서 저장/반영, 취소는 편집 폐기한다. 재실행·씬 전환 뒤 유지한다.
- FPS 충돌 방지: 기존 `FrameRateController`가 `GameSettings.Base.FrameRate`를 매 프레임 덮어쓰므로 로컬 선택값 우선·미설정 시60의 단일 적용 경로로 정리한다. 공통 FPS 세팅/개발용 조정의 역할도 명시하고 기존 `FrameRateSettingsTests`를 새 계약에 맞춰 갱신한다. `vSyncCount=0`, 제한 없음=-1로 요청하되 실제 FPS 보장은 하지 않는다.
