## 원문에서 정리할 충돌·공란

아래는 예전 기획과의 충돌이 아니라 새 최종 문서 내부의 충돌이다. 개발자가 임의로 확정하지 않는다.

1. **단계 완료 시점:** 2·3단계 표/본문은 1명 도착 시 전체 완료, 공통 규칙은 1명 도착 후 단계 넘기기 투표 가능. 전원 도착 시 자동 전환인지, 한 명 도착 즉시 전환인지, 투표가 필수인지 구분이 필요하다. 1단계에는 전원 자동 완료+과반 조기 전환이 명시되어 있다.
2. **포기와 단계 넘기기:** 3.3의 외줄 리허설 포기 불가를 보존하면서 3.4.5 포기/재진입 문장의 적용 대상을 선택 연습·인간대포로 한정할지 확인. 단계 넘기기 투표는 포기 투표와 다른 기능이다. 임시값 표의 '최초 포기 투표 없음'을 단계 넘기기 금지로 해석하지 않는다.
3. **도착 패널:** 공통 규칙은 도착 시 개인 퀘스트 제거, 4.4는 도착 후 대기/곧 전환 퀘스트 표시. 원래 조작 퀘스트만 제거하고 상태 패널은 유지하는지 확인.
4. **실제 그네:** W/S·Space·공중 F 학습 구조와 실제 활성 2인 Trapeze의 3봉/몸 교대 규칙을 어떻게 맞출지 결정. 기존 공연 규칙을 임의 변경하거나 리허설용 대체 장치를 새로 만들지 않는다.
5. **공간·체크포인트:** '전용 발판 없음'과 도면의 '중간 발판'이 병존한다. 기존 공연 발판 재사용 여부 확인. 비상호작용 기물 끝 '3m'는 전방/후방과 안내 발생점/복구점 의미가 불명확하다. 1단계 정확한 위치는 빈칸인데 4.4에는 14m가 있으므로 안내값과 복구 좌표를 분리한다.
6. **신규 범위:** 2-1/2-2 통과 인원·투표 분모/동률/이탈/동시 완료·2인 미만 협동·선택 연습 진입/퇴장·재접속 저장 범위·인간대포 코스/단계는 여전히 공란. 두 번째 공연 선택 시점·권한과 미이수 대포 선택 처리는 연결 계약에 추가한다.

본문에 목마 안내가 명시되어 있으므로 임시값 표의 '미포함'보다 신규 요구로 다룬다. 끝의 '현재 연결되지 않은 길안내' 3종은 현황 목록이며 이번에 모두 추가하라는 확정 요구로 승격하지 않는다. 대포 6단계 등 옛 Confluence의 상세도 새 문서에 없는 상태로 자동 승계하지 않는다.

## 개발 단계와 완료 기준

### 0. 기준 고정·판정 계약

- 새 원문을 유일한 최신 기획 근거로 연결하고 위 충돌을 결정 목록으로 유지한다.
- 도착·투표·체크포인트·장치 선택·둘째 공연 선택 계약을 정한다. 서로 독립적인 문구/연출 작업은 이 결정과 병행할 수 있다.
- 완료 기준: 단계/소구간별 통과 인원·투표 허용·자동 전환·포기 적용 범위가 표 하나로 설명되고 미정값이 식별됨.

### 1. 개인 진행·팀 전환·앱 세션 이수 상태

- 위치를 매 프레임 세는 방식에서 도착 확정 기록/이탈 제한/개인 기물 체크포인트/단계 기록으로 보강한다.
- 합의된 단계 넘기기 투표를 호스트 판정·공유에 연결하고 중복 입력/이탈/단계 변경으로 옛 투표가 재사용되지 않게 한다. 기존 호스트 즉시 클리어는 별도 경로로 유지하되 공통 전환을 사용한다.
- 강제 교육의 완료, 선택 연습의 진행, 앱 종료 전 이수 여부를 분리한다. 최종 완료 때 바닥 복귀를 보장한다.
- 완료 기준: 1단계 도착자 이탈 차단, 통과자 기록 유지, 합의한 전환 1회, 추락 1.5초 후 마지막 유효 지점 복구, 같은 방 다음 런 교육 재출력 없음.

### 2. 실제 공연 장치 재사용·학습 코스 정합성

- 결정된 실제 공연 장치에 단계별 배치 입력을 제공하고 코스/HUD·입력·물리를 재사용한다. 그네 고정 3봉/현재 유효 코스 길이 제약과 1개/2개 배치 요구를 먼저 검토한다.
- 1단계 두 줄, 2단계 세 구간, 3단계 네 줄 짝 연결을 각각 보존한다. 예전 길이·간격은 원문의 임시값으로 유지한다.
- 완료 기준: 실제 입력으로 줄 진입·균형·양 방향 옆줄 점프·단일/연속 그네·트리거 유지/해제, 다인 통과 가능. 상태 강제 변경만으로 조작 성공을 판정하지 않는다.

### 3. 가이드·퀘스트·단장 연출

- 확정 문구, 체크포인트/목마 근접 안내, 패널 우선순위·색·새 알림, 개인 도착 시 표시 정책을 적용한다.
- 통로 진입 판정·얼굴 3초 종료·리허설당 1회 재생 상태를 분리하고 늦게 관측한 클라이언트도 같은 재생 시각을 사용한다.
- 기존 길안내를 유지하고 목표 끝 화살표·집결 출입 시 숨김/재표시를 검증한다.
- 완료 기준: 소개/단계/완료 10초·추락 4초, 조작/통과에 따른 개인 퀘스트, 얼굴 3초 후 꺼지고 재진입해도 다시 켜지지 않음. 기존 대기실 안내 원형 유지.

### 4. 둘째 공연 선택·대포 리허설 진입

- 첫날 첫 외줄 고정을 유지하며 두 번째 슬롯을 선택/공유/확정하는 경로를 연다. 첫날 전체 편성 변경 금지 로직과 UI도 함께 조정한다.
- 대포 해금 후 선택 시 리허설 확인, 아니오 복귀, 예 진입, 이수 후 편성 재개를 연결한다. 코스 상세는 새 3.5 결정 후 구현한다.
- 완료 기준: 미해금 공연 선택 불가, 선택한 둘째 공연으로 실제 진입, 미이수 대포 선택 경로 일관성, 기존 밤 편성·취침·2일차 연결 유지.

### 5. 선택 재연습·회귀 검증

- 선택 연습의 진입/종료/단계 재선택을 확정 범위만 구현한다. 강제 최초 교육 이수를 덮어쓰지 않는다.
- 관련 상태 판정 검사는 투표·도착·복구·편성 중심으로, 플레이 검사는 실제 호스트/클라이언트 입력과 첫날 전체 흐름 중심으로 수행한다.
- 완료 기준: 2~4인 도착·이탈·투표·협동, 중도 접속, 같은 방 재시작/다음 런/앱 재시작, 공연 중 퀘스트 없음, 원본 대기실/밤 안내 유지. 재미와 최종 조작 체감은 사람이 확인한다.

## 검증·환경 제약

- doctor -SkipEditor 1회: third-party dirty, Task 중복, Unity 설치 탐지 실패, gh 미로그인 경고. 지정 Unity 프로세스는 실제 실행 중이므로 '미설치'를 사실로 확정하지 않는다. 이번은 문서·코드 대조이며 Unity 실행 검증을 추가하지 않는다.
- origin/dev fetch 완료, 현재 HEAD에 포함 확인. Unity 실행 중이므로 브랜치/씬/코드 병합 없음. 기존 변경 보존.
- 이전 기록의 성공 결과와 interruption-audit의 최신 원본 밤 안내 회귀 완료 미확인을 구분한다. 이번 정적 대조로 과거 running 결과를 PASS로 바꾸지 않는다.
- 수정 묶음 끝에 check-work -SkipUnity -NoRecord 1회와 record-knowledge 요구 검사 결과를 log에 별도 기록한다. 기존 작업 트리의 코드 변경도 검사 대상이라 문서 변경만으로 Unity PASS를 주장하지 않는다.
