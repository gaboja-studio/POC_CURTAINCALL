# Task-20261112-117

- **Title:** 추격자 트램펄린 운반·탑승 플레이어 포획 불가 수정과 규칙 기반 오르기
- **Type:** fix
- **Assignee:** @MoHoDu
- **Branch:** fix/pursuit/trampoline-capture
- **Base:** dev

## Context
추격자가 트램펄린을 잡고 있거나 타고 있는 플레이어 바로 앞에 있어도 잡지 못한다(2026-11-12 사용자 보고).
3·4단계 추격자는 대기실 오브젝트 위의 플레이어에게 올라오지 못한다.

## 계획
1. 포획 판정: 발끝 3D 거리 → 수평 `CaptureRadius` + 높이 범위(GameSettings 신규 값). 호스트 AI·피해자 보고·호스트 검증 3곳 공통 규칙.
2. 시야각: 3D 각도 → 수평 각도. 머리 위 플레이어를 시야 밖으로 놓치지 않게.
3. 리허설 길안내 임시 NavMesh: 추격자와 같은 에이전트 종류(0)라 추격 경로에 섞인다 → 전용 에이전트 종류로 굽기.
4. 호스트 접촉 기록의 추격 판정: 달리기 동작(Run) → 추격 행동(Chase). 끊긴 경로 끝에서 노려보는 추격자 옆도 포획.
5. (2026-11-12 사용자 허용) 쫓는 대상이 아니어도 포획 범위 안에서 가로막히지 않은 플레이어를 잡는다(시야각 무관, 닿음 기준).
6. 규칙 기반 오르기(2026-11-12 사용자 조건: 대기실 씬·오브젝트 수정 금지, 규칙으로 구조 변경에 대응). 씬·오브젝트 수정 없이 실행 중 로드된 NavMesh 가장자리를 GameSettings 규칙(최대 높이·간격·여유 공간)으로 검사해 오르기 링크를 만들고 3단계 이상에서만 사용.

7. 전용 오르기 애니메이션(2026-11-12 사용자 요청): 실제 추격자 베이스 모델·리그에 근거한 4방향/6방향 키포즈 원화를 먼저 제작·보존하고, 그 원화로 Blender MCP에서 애니메이션을 만든 뒤 현재 추격자 전종에 연결한다. 원본 모델/결손/재질·기존 클립과 씬 배치는 보존한다. 새 파생 에셋과 제작 원본은 private 서브모듈의 `resource/pursuit-climb-animation` 브랜치에 둔다.

8. 접점 IK 및 후속 검증(2026-11-12 추가 요청): 기존 Blender 클립 위에 런타임 2본 IK를 적용해 손은 소품 가장자리, 발은 출발/착지 표면에 고정한다. 유효한 실제 콜라이더·도달 가능 거리에서만 적용하며 결손 사지는 제외한다. 접점·본 보정은 시각 전용이고 GameSettings에서 제어한다. 호스트의 통과 구간/진행률을 스냅샷으로 전달하여 원격도 동일 구간을 검사한다. 대기실 에셋 대신 임시 지형/격리 테스트로 실제 OffMeshLink 통과·단계 제한·전종 접점·종료 복원을 검증한다. 실제 2인 플레이와 최종 미술 판단은 자동 검증과 구분한다.

9. 소품 위 오르기 실패 수정(2026-11-12 사용자 보고: 3·4단계에서도 드럼통 위로 못 올라옴). 1~4단계 모두 오르기(ClimbFromStage=1, 사용자 결정). 좁은 윗면은 NavMesh가 없어 링크가 생기지 않으므로 충돌체 검사 직접 오르기를 추가하고 최대 높이를 2.5m로 올린다. 씬·NavMesh 에셋은 여전히 수정하지 않는다.

10. 앉아 숨기(2026-11-12 사용자 요청): 앉은 플레이어 몸이 장애물에 GameSettings `CrouchHiddenCoverage`(기본 80%) 이상 가려지면 추격자 시야에 보이지 않는다. 앉은 캡슐을 3×5 지점으로 나눠 눈에서의 가림 비율을 잰다. 벽 너머 탐지·최인접 단계는 단계 규칙 우선.

## 미정·주의
- 대기실 구조·배치는 다른 작업자가 고도화 중: 씬·오브젝트·NavMesh 에셋을 수정하지 않는다(2026-11-12 사용자 지시).
- 트램펄린 운반자 미포획의 확정 원인은 에디터 실측(`LastContactRejection`) 전까지 추정. 위 1~5는 알려진 원인 후보를 모두 막는다.
