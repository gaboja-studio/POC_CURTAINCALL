# Plan

## Context

CC-124의 첫 단계만 구현한다. 4인 지상 담당 1 + 비행 3으로 이동하는 받기와 발사 입력을 먼저 검증한다.

## Approach

1. 배정 문서 수신·실제 전달 확인 후 setup 구역 안에서 장애물 없는 장치를 구현한다.
2. F 탑승 완료 뒤 새 F 발사, F 홀드 취소, 공중 WASD 수평 조절을 구분한다.
3. 트램폴린 F 잡기·WASD 운반·Space 몸/장치 짧은 점프·F 홀드 놓기, 다인/무주인 각 1회 반동을 만든다.
4. 역할별 정상 착지와 비행 추락 사망, 점유 해제·상태 초기화·네 화면 일치를 검증한다. 같은 공연의 부활은 추가하지 않는다.
5. 공용 인터페이스가 부족하면 별도 소유 Task를 PM에게 요청한다. 분리 출발 장치는 3단계로 남긴다.

## Files

- 수정 예정: setup의 HumanCannon 스크립트·테스트 씬·테스트 전용 Prefabs와 이 Task 문서.
- 읽기 전용: `Harness/Project/Decisions/Human-cannon/basic-control.md`, 공용 입력·부상/관전 계약.

## Risks

- 동시 진입 중복 반동, 사망자 점유 잔류, 호스트만 가능한 지상 담당, 정상 점프의 잘못된 추락 판정.
- 테스트 조정값은 최종 밸런스 확정값이 아니다. 미정 역할/보상·2~3인 범위는 추가하지 않는다.

## Auto Verification

- 구역 → 문서 → 컴파일 → 자동 테스트: `pwsh -File Scripts/check-work.ps1 -Mode PlayMode` (구현 후 플레이 동작 검증).
- PlayMode 테스트가 없으면 NO_PROJECT_TESTS. 실제 입력 실행 로그·오류·생략은 handoff에 기록하며 자동 테스트로 공동 검증을 대체하지 않는다.
- 준비 검증은 기능 검증이 아니다. PR은 integration/main-stage-human-cannon 대상으로 제출한다.

## 공동 테스트 항목

공통 씬: `Assets/Scenes/Tests/MainStage/HumanCannon/HumanCannon.unity`. 각 묶음은 4인(호스트 1·참가자 3), 지상 1·비행 3으로 실행하고 호스트/참가자 지상 역할을 교환해 반복한다. handoff에 일시·참여자/역할·씬·재현·예상·실제/로그를 기록한다. 현재 전부 미실행이다.

1. 탑승/발사: F 탑승 → 자동 발사 없음 확인 → 탑승 뒤 새 F 발사 → 발사 전 F 홀드 취소 → 공중 WASD. 예상: 수평만 조절되고 점유/발사/취소가 네 화면에 일치한다.
2. 연속 받기: 발사 간격·착지 위치 변경 → 지상 이동/점프로 연속 받기 → 동시 진입 → 장치를 놓고 무주인 받기. 예상: 점프 중에도 유효하며 모든 진입자는 각각 1회 반동, 중복 없이 네 화면 위치·결과 일치.
3. 실패/초기화: 고의로 받기 놓치기 → 비행 추락 사망 확인 → 담당 정상 점프 착지 → 점유자 사망/새 시도 → 역할 교환 반복. 예상: 정상 몸 점프는 생존, 비행 추락은 사망·점유 해제, 같은 공연 부활 없음.
