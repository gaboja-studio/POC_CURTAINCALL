# 3·4인 탈출 조합 시나리오

복사 씬 `EscapeRoutePursuitRemodel`을 개발 빌드로 만들고 NGO 호스트 1명과 별도 로컬 프로세스 참가자 2~3명을 연결한다. `setup`으로 시작 위치, 호스트의 기존 절단 API로 지정 부상을 준비한다. 걷기·균형·F·점프·달리기·앉기는 참가자 자신의 게임 입력으로만 실행한다. 부상 설정은 연속 플레이에서 금지한다.
개발 빌드 씬은 복사 씬, `CommonPerformanceUI`, `CommonInteractionUI`, `CommonMenuUI`, `Lobby`를 포함한다.

| 시나리오 | 역할과 행동 | 통과 기준 |
|---|---|---|
| InjuredWire (3인) | 한쪽 다리, 양쪽 다리, 한 팔만 남은 세 사람이 하차장에서 출발 | 각자 외줄을 건넌 뒤 추격자가 뒤따라와 유효한 공격을 하고, 첫 탈락 뒤 살아 있는 팀원을 다시 선택 |
| StackAndPole (4인) | 다리 부상 운반자, 팔 부상 승객, 양다리 부상 봉 사용 주자, 별도 주자 | 목마와 봉을 동시에 점유하는 상태에서 추격자가 접근·조준. 포획된 플레이어의 기물 점유는 모든 화면에서 해제되고 다른 생존자가 새 목표가 됨 |
| TrampolineHandoff (3인) | 외팔 운반자, 다리 부상 점퍼, 인계 받을 주자 | 반동은 실제 접촉으로 발생. 추격자의 실제 운반자 포획 뒤 점유가 풀리고 재획득이 다른 화면에도 반영 |
| ConveyorQueue (4인) | 서로 다른 부상의 주자 세 명이 동일한 대포에 접근, 별도 주자는 입구에 남음 | 대기 창은 플레이어별로 계산. 두 주자가 차례로 봉을 잡고, 남아서 대기가 끝난 주자는 추격자가 포획할 수 있음 |
| LowPosturePursuit (3인) | 부상자가 앉아서 추격을 받고 두 동료는 걷기·달리기·점프를 사용 | 호스트가 앉아 있는 플레이어를 실제 공격·포획한다. 탈락 뒤 다른 생존자를 직접 공격해야 함 |
| 추가 변형 | 잡히는 역할 교대, 외줄 매달림과 구조, 합류교, 장비 운반자 사망 후 최종 탈출 | 준비 상태·판정 원인·관전 전환과 입구부터 연속 재현 여부를 별도로 기록 |

```powershell
pwsh -File scenario-play.ps1 -Build <개발 빌드 exe> -Evidence <새 결과 폴더> -Scenario InjuredWire
```

`milestones.jsonl`에는 각 단계가 성립했을 때 모든 프로세스의 상태를 기록한다. `trace.jsonl`에는 호스트가 고른 목표·등장구·공격 단계와 원격 입력 소유자의 자세·점유를 남긴다. 실패 시 `failure-state.json`과 실제 입력 `actions-*.jsonl`을 보관한다. 시간 초과는 세팅·입력 문제와 게임 버그를 구분하고 재현 결과를 추가한다.

## 수정 전 실제 LAN 결과

- `InjuredWire`: 서로 다른 부상의 세 명이 외줄을 건넜다. 68.83초에 4번 파괴구에서 파편 예고를 시작했다. 107.86초에는 첫 추격 탈락이 확정됐고, 다른 생존자를 목표로 삼았다. 이 검사는 외줄을 건넌 직후의 공격을 확인했다.
- `StackAndPole`: 목마와 상승 봉을 동시에 사용했다. 한 시도에서 추격자의 파편이 양다리 부상 봉 이용자를 맞혀 봉 점유를 풀었고, 이어 목마 승객이 포획됐다. 더 엄격한 재실행에서는 103.43초에 공격·봉 해제 및 실제 포획, 110.71초에 해당 묘기 그룹 내 탈락 이후 살아 있는 목표 선정을 확인했다. 네 화면에서 포획자의 점유는 해제됐다.
- `TrampolineHandoff`: 5번 파괴구에서 실제 추격으로 81.36초에 외팔 운반자가 포획됐고, 트램펄린은 바로 해제됐다. 82.79초 다리 부상 원격 주자가 반동, 86.07초 세 번째 주자가 다시 잡았다. 최초 포획자의 투척 연출이 끝나기 전에 팀이 진행할 수 있었다.
- `ConveyorQueue`: 19.75초에 세 부상자가 각각 대기 창을 가지고 있었다. 23.67초와 34.55초에 첫째·둘째 주자가 같은 대포에서 차례로 발사해 이동 봉을 잡았다. 둘은 하차 입력을 주지 않은 채 지나가 환경 낙사로 탈락했다. 대기 창이 끝난 발판의 세 번째 주자를 95.99초에 2번 파괴구에서 실제 포획했다.
- `LowPosturePursuit` 수정 전: 저층 문틀의 실제 손 경로가 막혀, 숙이고 있던 부상자를 목표로 잡고도 약 1.8m 앞에서 수십 초 동안 공격하지 않았다. 몸통 높이에서 목표로 가는 검사에는 충돌이 없었고, 애니메이션의 손에서 같은 위치로 검사할 때 두꺼운 오른쪽 문틀이 막았다.

처음 부상 테스트에서 비순차 손실 예외가 난 원인은 개발 세팅이 팔을 먼저 자른 것이었다. 실제 게임과 같은 호스트 공통 절단 순서로 변경했다. 트램펄린 하부의 한 명 제한도 재현되어, 도약·인계를 하는 두 주자는 위층에서 시작하게 했다.

## 문틀 정지 수정과 재검증

- 정지 반경만 줄인 시도는 추격자가 0.6m 더 이동했지만 문틀이 같은 손 경로에 걸려 실패했다. 최종 수정은 통로 근접 공격에 한해, 방향을 바꾼 실제 손에서 공격할 수 있고 같은 층 이동면으로 완전히 연결된 후보를 고른다. 이동 중에는 고른 위치를 유지하고 목표가 바뀌거나 충분히 이동하면 다시 찾는다. 실제 팔 충돌은 유지했다.
- 원래 정지점에서 실제 손과 몸통 검사에 모두 통과하고 완전한 이동 경로가 있는 위치 8곳을 복사 씬 편집 물리 검사에서 찾았다.
- 같은 장소와 부상 조건의 3인 재실행에서 몸통 위치가 문틀 옆으로 바뀌었다. 36.58초 앉은 주자에 대한 손 공격 예고, 37.29초 실제 포획, 최초 주자 탈락 뒤 44.93초 다른 생존자에 대한 새 공격 예고를 확인했다.
- 수정된 빌드의 4인 목마·봉 재실행에서는 101.41초 두 기물 상태가 유지된 동안 공격 예고가 나왔고, 104.29초 실제 포획과 점유 해제를 확인했다. 해당 그룹의 피해자 탈락 후 111.89초 다른 생존자에 대한 공격 예고가 나왔다.
- 로컬 증거: `.harness/local/pursuer-campaign-20261115/scenario-v2`의 외줄·대포, `scenario-v3`의 목마·봉·트램펄린 및 수정 전 앉은 자세, `scenario-after-angle-v2`의 수정 후 재현. 체크포인트 구간 실기이며 입구→엔딩의 연속 실행과는 구분한다.
