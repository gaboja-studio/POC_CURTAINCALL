# Plan

## Context

프로젝트 개요와 내용을 팀원이 찾아볼 수 있는 문서로 정리한다. 현재 게임 개요는 TBD이므로 확정된 사실과 미정 사항을 분리한다.

## Approach

1. setup.md 작업 공간 확정 후 현재 프로젝트 사실과 사용자 확정 정보를 확인한다.
2. 목적·POC 범위·현재 상태·주요 내용·미정 사항을 작성하고 관련 문서로 연결한다.
3. 근거가 없는 게임 규칙·일정·밸런스를 만들어 넣지 않는다.
4. 문서 검사와 공동 리뷰 후 integration/document-project로 제출한다.

## Files

- 수정 예정: setup.md에 PM이 지정한 문서 파일 및 이 Task 문서.
- 읽기 전용 참고: AGENTS.md, Harness/Project/Facts/overview.md 및 관련 사실 문서.
- Assets 폴더 규칙은 Task-20260930-002의 소유이며 중복 작성하지 않는다.

## Acceptance Criteria

- 확정 정보·TBD·확인 필요 사항이 명확히 구분된다.
- 프로젝트 목적·범위·현재 상태·내용과 참고 문서 링크가 제공된다.
- setup.md 범위 밖 변경이 없고 링크·문서 검사가 통과한다.

## Dependencies

- 선행 Task 없음. Task-20260930-002와 독립 구현 가능.
- 공용 문서 링크를 수정해야 한다면 PM이 Integration 소유 표에 배정한다.

## Risks

- 미정 정보를 확정 사실로 쓰는 오류, 기존 사실 문서와 중복·불일치.

## Auto Verification

- 구역 검사: 작업 공간 확정 후 Scripts/verify-scope.ps1.
- 1 문서/규칙: Scripts/verify-fast.ps1 및 링크·근거 수동 점검.
- 2 컴파일: 문서만 변경하면 생략하고 사유 기록.
- 3 테스트: Unity 테스트는 문서 작업에 해당 없음. 미실행을 PASS로 표기하지 않는다.
- 4 실행 로그: 게임 실행 불필요. 문서 검사 결과를 handoff.md에 기록.

## 공동 테스트 항목

1. 처음 읽는 사람이 프로젝트 목적·범위·현재 상태를 설명할 수 있는지 확인한다.
2. 확정 정보와 TBD를 구분하고 근거·관련 문서 링크를 따라갈 수 있는지 확인한다.
3. Assets 규칙 문서와 책임·내용이 중복되지 않는지 통합 후 확인한다.
