# 2단계 — 기존 로비 복제·배치

- 기준: CC-159, WaitingRoomBase.unity / WaitingRoomGreybox.
- 새 로비: WaitingRoom_LayoutA/S01_Lobby. 기존 20×18m 바닥, 천막과 소품, 천장·벽·조명·일정판·전용 카메라·스폰을 복제. 총 668개 오브젝트(활성 계층 583개).
- 중앙 천막 묶음을 중심으로 재배치하고 상단 생활/연습, 우측 공연, 하단 물류, 좌측 작업/지하 방향을 설정했다. 9개 출입 예정 위치에 임시 차단과 표지 배치. 휴게실은 위치만 예약.
- 스폰 4곳은 로비 남쪽에 배치. 활성 스폰 제공자 1개, WaitingRoomSpawn 1개. 일정판 카메라 참조 1개 재연결. 바깥 공용 관리자 추가·변경 없음.
- 상세 복제 경로: stage-02-copy-manifest.md. 재실행으로 중복 생성되지 않도록 구성 도구에 기존 로비 검사와 실패 시 Undo 복원 적용.

## 검증

- 원본 6,035개 하위 오브젝트의 ID·이름·활성값·변환·컴포넌트 직렬화 문자열 동일 확인. 저장 파일을 HEAD와 ID별 비교: 삭제된 기존 블록 0개, 기존 변경 블록 2개(원본 루트 비활성, 씬 루트 목록에 새 맵 추가). 씬 파일의 큰 줄 차이는 새 복제 객체 삽입과 저장 순서 변경이다.
- 스폰 4곳의 바닥 지지와 캡슐 여유 공간 통과. 미완성 출입구 차단 충돌 9/9 확인.
- 실제 Play Mode에서 PlayerMover가 설정한 CharacterController(반경 0.3m, 높이 1.5m)로 로비 순환과 9개 출입구 접근 경로를 이동. 25/25 경유점 통과, 1,433프레임 진행, 발 높이 0.080~0.100m, 막힘·낙하 없음. 임시 검증 객체는 종료 후 제거.
- 컴파일된 프로젝트 타입으로 Validate 실행 성공, compilationFailed=false, compiling=false, Play Mode 콘솔 오류 0개. 공용 UI Pretendard 글꼴의 ‘잠’, 캡처 시 ‘칸’ 누락 경고는 존재한다.
- 평면/플레이어 높이 이미지 검토: Temp/Task075/stage02-top.png, stage02-eye.png. 평면 이미지는 천장만 임시로 숨겨 촬영 후 복원했다. 플레이어 높이 이미지는 임시 검토 카메라다.
- 이번 확인은 로비 충돌·배치 검증이다. 실제 네트워크 플레이어 생성, 카메라 추적, 일정판 상호작용, 4인 접속, 공연 왕복은 미검증. 다른 방 연결 뒤 별도 확인한다.
- 자동 테스트 모음은 실행하지 않았다. check-work 결과는 log.md에 기록한다.
