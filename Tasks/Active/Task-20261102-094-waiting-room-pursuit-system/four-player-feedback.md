# 4인 테스트 피드백 반영

## 목적
마네킹이 보는 방향과 경계 상태를 읽고 피할 수 있게 한다. 전시 중에는 적이라는 사실을 숨기고, 추격이 시작된 뒤 단원의 흔적과 단계 변화가 드러나게 한다.

## 디자인
- 원화: `_ThirdParty/curtaincall/Pursuit/Concepts/Reclaimed/reclaimed-troupe-turnaround-motion.png`. imagegen으로 먼저 제작한 기본/강화 4방향 외형과 걷기/달리기 앞·옆 키 포즈 시트.
- 낡은 상아색 표면, 봉합선, 검은 마름모 무늬, 황동 보강판, 해진 붉은 목 장식. 원본 FBX와 기존 70개 모션은 유지한다.
- 배치 창에서 소형/중형(외형 1.16배)을 선택한다. 크기와 단계는 독립이며 이동·탐지·포획 수치는 공유한다.
- 기본 3단계부터 더 큰 목 장식과 앞으로 기울인 걷기/달리기. 적용 단계는 단계/연출 탭에서 바꾼다.
- 포획 완료마다 혈흔 0.28씩 누적(최대1). 추격 철회/다음 장소에서 초기화. 유혈 설정을 끄면 피부 혈흔도 숨긴다.

## 전방 표시
- 기존 근접 빨간 외곽선은 제거한다. 실제 추격 대상에게 보이는 화면 테두리 효과는 유지한다.
- 추격 전에는 바닥 신호를 숨긴다. 활성화 뒤 미발견/복귀는 흰색, 경계/조사/수색은 노란색, 발견/추격/포획은 빨간색.
- 기본 길이1.75m/밝기0.32/가장자리 흐림0.65. 표시 각도는 현재 단계의 시야각과 같다. 원색 대신 낮은 채도의 회백색·황토색·적갈색을 쓴다. 실제 시야 범위를 표시하는 기능이 아니라 방향과 행동 상태를 알리는 기능이다.
- 배치 창의 **단계/연출 → 전방 상태 신호 / 외형**에서 길이·밝기·가장자리 흐림·세 가지 상태 색상을 조절한다. 흐림 값이 클수록 가장자리가 넓게 흐려진다.
- 표시 각도는 단계별 시야각 설정에 연동한다. 현재1단계100°/2단계140°/3·4단계180°이며, 위치 무관 최인접 추격 단계의 실제 탐지는 이 각도 밖에서도 가능하다.
- 현재 층의 바닥을 따르고 벽 앞에서 줄어든다. 화면 근처에서만10Hz 계산하며 배열을 재사용한다.

## 통신
- 기존 문제 후보: 10Hz 전체 JSON의 신뢰성 재전송과 3m 차이 즉시 위치 이동. 지연 누적 후 수신이 몰리면 위치가 튈 수 있었다.
- 위치는20Hz 소형 패킷(16체씩 최대540byte), 손실된 과거 위치는 재전송하지 않는다. 150ms 보간 여유와 최대100ms의 짧은 예측 후 멈춘다.
- 이전 시간의 패킷을 버리고, 추격 초기화 번호가 다르면 무시한다. 일반 지연 복귀는 한 프레임 순간이동을 하지 않으며, 명시적 초기화만 원래 배치점으로 옮긴다.
- 포획/대상/단계/혈흔 횟수는 신뢰성 상태 전달을 유지한다. 기본4Hz와 행동 전환 시 갱신한다.

## 관전
- 포획 중인 다른 단원은 관전 대상에서 제외한다. 리타이어/사망 뒤 생존자 선택과 마우스 회전을 사용한다.
- 카메라가 사망자 위치의 방 설정에 묶이지 않고 관전 대상 주위를 돈다. 벽/천장 충돌 기준도 관전 대상이다.
- 관전 대상이 없을 때는 마지막 사망 위치에 카메라를 유지하고 시선만 회전한다. 메뉴 열기/닫기와 복귀 시 입력 차단을 유지한다.

## 검증 범위
- Edit3개: 400ms 손실·지터·역순 도착, 긴 단절과 초기화, 상태별 표시 분류.
- Play: 카메라 고유16개, 바닥 표시/외곽선 제거/혈흔 초기화1개, 포획 후 외팔 복귀2개 통과. 카메라 초기 실패2개는 수정 후 해당 묶음5개 재검사로 통과했다.
- 실제 Unity 화면: `Reclaimed/unity-four-view-review.png`는 4방향 외형 렌더, `Reclaimed/Review/state-cues-play.png`는 대기실 Play에서 세 상태를 비교 배치한 화면이다. 후자는 AI를 정지하고 상태를 고정한 비교용 화면이며 실제 4인 플레이 기록은 아니다.
- 실제 4인 원격 지연·늦은 접속·동시 포획은 팀 실기 검증이 남아 있다.
