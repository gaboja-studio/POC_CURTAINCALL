# Plan

## Context

042는 041 다음 예약 단계다. 폴더·빈 씬(root 0)만 준비됐으며 인간 대포 기능은 구현되지 않았다. 아래는 실행 근거가 아닌 예정 계획이다.

## Activation

1. PM이 041 integrated·실제 4인 공동 테스트 근거·소유권 반납·실제 JIRA URL을 확인한다.
2. 다음 1개인 042에만 Active Task/Allowed를 부여하고 승인된 준비 브랜치에 배정 문서를 Merge commit으로 sync한다.
3. 기존 feat 브랜치는 앞 단계 완료 후 최신 부모 이력을 받는다. 실제 전달 PM 확인 이후만 start-work한다.

## Approach

1. 지상 담당은 시작 이동장치에 트램폴린을 싣고 먼 분리 코스로 간다. 비행자는 대포 3대로 출발해 첫 받기를 연결한다. 대포 무대에서 코스로 걸어가는 길은 만들지 않는다.
2. 쉼터 F 스위치 해제 상태를 유지하되 해제만으로 출발하지 않는다. 모든 생존 비행자 합류 후 담당이 장치를 싣고 F 상승한다.
3. 낮은 손잡이·문턱 없는 진입으로 두 다리 손실/외팔도 접근하도록 한다. 교대는 선택이며 생존 합류 후 다음 구간을 준비·재출발한다.
4. 불꽃은 예고 후 마지막 사람 출발과 무관하게 전진하여 공중/지상 모두 압박한다. 쉼터 경계에서 앞 불꽃 종료, 쿠션 경계에서 종료; 쿠션/최종 대포에는 별도 불꽃·타이머가 없다.

## Files / Risks

- 예정 파일은 setup의 예약 구역만 참조하며 현재 권한은 없다. main_stage.unity는 025 소유, 외줄 원본은 읽기/재사용만 허용.
- 공용 부상·관전·종료 수정은 별도 소유 Task다. 부상 상태는 기존 공용 계약을 읽기/재사용한다.
- 불꽃 접촉 사망은 설계안, 속도/판정 수치는 PM 합의·실제 플레이로 조정한다. 임의의 최종 밸런스로 확정하지 않는다.
- 지상 2명 규칙·중계 대포·호응/보상 수치·2~3인은 미정/후속이며 구현 목표에 넣지 않는다.

## Auto Verification

- 구역: 예약 — 미배정. PM 준비 문서·컴파일·기존 EditMode 결과는 handoff의 Verification 참조.
- 이 단계 기능 자동 테스트·실행 로그·실제 4인 검증: 미실행.
- 활성화 후 `pwsh -File Scripts/check-work.ps1 -Mode PlayMode`로 검사하고 구역→문서→컴파일→PlayMode 테스트→실행 결과를 사실대로 기록한다. 테스트 부재는 NO_PROJECT_TESTS, 실제 플레이 PASS가 아니며 공동 플레이를 대체하지 않는다.
- PM 준비의 기존 EditMode 5/5 검사와 이 단계 PlayMode/실제 4인 검증은 별개다.

## 공동 테스트 항목

합의·실행 전 계획이다. 모든 묶음은 실제 4인 플레이로 수행하며 실제 결과는 handoff에 따로 기록한다.

1. 분리 출발·첫 받기

- 씬: HumanCannon.unity (setup 예약 테스트 씬, 현재 040 소유; 이관 후 실행).
- 인원: 4인(호스트 1·참가자 3). 지상 담당을 호스트→참가자로 교환하고 같은 순서를 반복한다.
- 재현: 지상 담당 장치 싣기/분리 코스 이동→비행 3명 개별 대포 출발→첫 받기; 대포 무대에서 지상 도보 우회도 시도한다.
- 예상: 서로 분리된 출발로 첫 받기에 합류하며 도보 우회가 없다. 장치 위치·비행·받기 상태가 네 클라이언트에서 일치한다.
- 실제 기록 방법: 일시·4인 이름/역할·commit·장치/대포 입력 순서·첫 받기 시각·우회 시도·영상/로그·예상 대비 실제를 handoff에 남긴다. 현재 미실행.

2. 쉼터 합류 게이트·승강·교대

- 씬: HumanCannon.unity (setup 예약 테스트 씬, 현재 040 소유; 이관 후 실행).
- 인원: 4인(호스트 1·참가자 3). 지상 담당 호스트/참가자 교환 후 두 다리 손실·외팔 조건도 반복한다.
- 재현: F 스위치 해제→비행자 1명 미합류 상태에서 상승 시도→생존 비행자 전원 합류→장치 싣기/F 승강→낮은 손잡이 접근→교대/비교대 회차→재출발; 사망자가 있는 회차는 생존자만 합류한다.
- 예상: 해제 상태 유지, 해제만으로 출발 안 함; 모든 생존 비행자 합류 전 상승 불가. 높은 몸 점프 없이 진입·승강 가능, 교대는 선택이며 재출발이 동기화된다.
- 실제 기록 방법: 일시·4인 이름/역할·commit·생존/부상 상태·합류/F/승강 타임라인·교대 여부·영상/로그·실제 차단/진입 결과를 handoff에 남긴다. 현재 미실행.

3. 불꽃 예고·지연 출발·경계 종료

- 씬: HumanCannon.unity (setup 예약 테스트 씬, 현재 040 소유; 이관 후 실행).
- 인원: 4인(호스트 1·참가자 3). 지상 담당 호스트/참가자 교환, 마지막 출발자를 바꿔 반복한다.
- 재현: 마지막 비행자 출발 지연→불꽃 예고/전진 관찰→공중·지상에서 압박 확인→쉼터 경계 통과/생존 합류→다음 구간→쿠션 경계 통과→최종 구간 대기한다.
- 예상: 마지막 출발을 기다리지 않고 불꽃 전진; 쉼터에서 앞 불꽃 종료, 쿠션에서 종료. 쿠션/최종 구간에는 별도 불꽃·타이머 없음; 접촉 판정은 사전 합의안과 대조한다.
- 실제 기록 방법: 일시·4인 이름/역할·commit·합의한 시험 수치/판정·예고/전진/경계/출발 시각·영상/로그·예상 대비 실제를 handoff에 남긴다. 현재 미실행.
