## 1. 치료 중 인간대포 재연습 시작: 조작 잠금·잘못된 복귀

- 장소/기능: 대기실 치료 승강기 → 인간대포 리허설.
- 조건: 한 참가자는 치료 Working 상태, 다른 참가자가 리허설을 시작.
- 확인: 현재 CanStart는 치료 중에도 true. 치료 이용자를 포함한 전체 참가자를 시작 지점으로 옮기지만 치료 점유를 종료하지 않음.
- 결과: 시작 지점에서 의료 workInput 잠금 유지. 치료가 끝나면 승강기 앞 `(0,0,-1.4)`로 다시 이동.
- 결과: 리허설 placed 목록에는 남아 있어 다음 PlaceLocalAtCheckpoint도 시작 지점으로 되돌리지 않음. 연습 참가자가 코스 밖으로 이탈.
- 추가 위험: returnPose가 치료 승강기 내부로 저장됨. 리허설 종료 코드는 그 좌표를 다시 사용함. 내부 좌표 저장은 재현했고 최종 문 닫힘/갇힘은 실제 씬에서 미검증.
- 재현: 같은 상태 순서 3/3. 임시 코스 시작 `(9097,9000.5,8997.4)` → 치료 종료 후 `(0,0,-1.4)` → 재배치 함수 호출 후에도 동일.
- 원인: ExpertRoomView.ReconcileLocalOccupancy는 생존·소유자만 확인하여 다른 시스템으로의 이동을 감지하지 못함. WaitingRoomCannonRehearsal.CanStart/StartPractice에는 치료 상태 인계가 없음.
- 관련: `ExpertRoomView.cs:161`, `ExpertRoomView.cs:230`, `WaitingRoomCannonRehearsal.cs:69`, `:133`, `:374`, `WaitingRoomCannonRehearsal.Ui.cs:47`, `:218`.

## 2. 치료 입장 요청과 트램펄린 운반 겹침: 위치 밀림·조작 잠금

- 장소/기능: 대기실 치료 승강기 + 트램펄린 운반.
- 조건: 입장 요청 처리 시점에 이미 트램펄린 소유가 확정된 상태. 일반 운반 중 F 선택은 운반 대상이 우선이므로 평범한 F 한 번과 구분해야 함. 지연 요청이 겹치는 실제 전송 순서는 별도 실기 검증 대상.
- 확인: 실제 ExpertService.Enter가 요청을 수락하고 승강기 내부로 이동하지만 트램펄린 소유권은 그대로 유지.
- 결과: 다음 FollowCarrier가 이전 위치부터 내부까지 운반 충돌을 검사. 가로막힌 경우 lastSafeCarrierFeet로 플레이어를 밀어내지만 치료 입력 잠금은 유지.
- 재현: GameSettings의 실제 CarryCollisionMesh 사용. 임시 측벽 x=1.6/2.4m 두 배치에서 내부 `(0,0,1.5)` → `(0,0.58,-1.4)`, 약 2.96m 밀림. 기물은 이전 위치에 남음.
- 대조: 측벽 x=0.8m에서는 기존 겹침을 벗어날 수 있어 밀림 없음. 모든 벽/모든 운반 입장에서 발생한다고 일반화하지 않음.
- 원인: 의료 입장은 목마만 해제하고 운반/비행 상태를 인계하지 않음. 트램펄린이 순간이동에 맞춰 마지막 안전 위치를 갱신하거나 운반을 해제하지 않음.
- 관련: `ExpertService.cs:225`, `ExpertRoomView.cs:230`, `HumanCannonTrampoline.cs:270`, `HumanCannonCarry.cs:72`.
