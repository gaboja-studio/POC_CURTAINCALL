## 현재 사용자 결정
- 팝업은 Task 시작 전 원래 C10 환호/야유 UI로 복구한다. 새 숫자 패널과 GPT 스프라이트는 채택하지 않는다. 생성 시안/독립 키트는 기록으로만 보존하며 실제 Feedback 프리팹에서는 제거한다.
- 공연 중 낮은 웅성거림을 유지하고, 본인 또는 현재 관전 대상의 사건에만 환호·야유 4종 중 하나를 일회성 재생한다. 배경음은 반응 때 65%로 살짝 낮추고 복귀한다. 대상 전환/메뉴는 반응음만 중단하고 웅성거림은 유지, 공연 종료/씬 해제 시 배경음도 종료한다.
- 기존 팝업의 이미지·배치·모션은 그대로 사용하되 새 사건은 표시 중인 팝업을 갱신한다. 예전 환호 팝업이 끝나기를 기다리느라 새 야유 소리와 화면 방향이 어긋나지 않게 한다.
- 어두운 배경·밝은 전등·공연 구간 가독성 조정은 유지한다. v6에서 한 구역 시험만 활성화했다.

## 시험 절차와 확장 기준
1. **일반 플레이 시점에서 한 구역만 시험.** 환호는 팔을 들고 상체가 들썩이는 한 번의 파동, 야유는 앞으로 기울었다가 천천히 돌아오는 동작. 가까이 당긴 검사 카메라는 시인성 판정에 쓰지 않는다. 외줄·대포에서 별도 설명 없이 반응 발생과 방향을 구분하는지 확인한다.
2. **개인 반응과 공유 객석을 구분.** 소리/팝업은 본인·관전 대상 기준 유지. 시험 객석은 기존 스냅샷의 공유 사건으로 움직인다. 여러 사람의 반대 반응이 겹칠 때 한 구역이 급하게 왕복하지 않도록 짧은 묶음 시간과 우선순위를 비교한다. 현재 시험 코드는 절댓값이 큰 사건 우선, 동률이면 야유 우선이며 아직 최종 규칙으로 채택한 것은 아니다. 새 점수/벌점 규칙은 추가하지 않는다.
3. **성능 A/B.** 같은 코스·카메라·인원·설정으로 관객 off/on 비교. 우선 기준 PC를 기록하고 1인 빌드, 다음 4인 호스트/클라이언트에서 CPU/GPU p95, draw call, GC, 첫 반응 지연, 초기 로드, 통신량을 측정한다. 현재의 에디터 수치는 기준 비용 판정에 쓰지 않는다.
4. **효과가 비용보다 클 때만 확장.** 이미 구현된 72명 결합 메시 1개/단일 재질/GPU 자세 보간을 사용한다. 사람별 GameObject·Animator·물리·NetworkObject를 추가하지 않는다. 1차 임시 목표는 관객 때문에 추가되는 프레임 시간 0.3ms 이하, 반응 시 관리 힙 할당 0, 추가 네트워크 메시지 0이다. 목표는 실측 결과와 기준 장비에 따라 사용자와 결정한다.
5. **못 알아보면 먼저 축소 또는 대체.** 인원을 늘리지 말고 동작의 실루엣·구역 대비를 먼저 조정한다. v7에서 같은 구역에 그림자 없는 스폿1개의 조명 반응을 적용했다. 그래도 공연 중 체감이 약하면 움직이는 객석을 채택하지 않고 정적인 객석과 현재 사운드만 유지한다.
