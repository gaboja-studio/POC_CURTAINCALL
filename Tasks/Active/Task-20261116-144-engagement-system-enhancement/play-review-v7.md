# 한 구역 어두운 관객 — v7

## 적용
- 관객 자체 금빛/적색 반응 삭제. 몸색 `(0.018,0.016,0.014)` 고정, 안개만 적용한다.
- 환호: 높은 V자 팔을 순서대로 들기 + 넓게 이동하는 객석 조명. 야유: 낮게 앞으로 숙이기 + 좁게 고정된 객석 조명.
- 같은 백열색 Spot1개, 그림자 없음, 반응 약1.8초 후 꺼짐. 기존 좌석을 비추며 몸은 밝아지지 않는다. 원본 배경 씬/재질은 수정하지 않았다.
- 한 구역72명/Renderer1/864삼각형 유지. 사람별 객체·Animator·Collider·NetworkObject·새 메시지 없음. 최초 생성 때 Light를 한 번 캐시하고 프레임마다 각도/강도만 보간한다.
- 광원 local `(95,75,375)`, range40 월드 단위. 환호 cone85/inner45/intensity9000, 야유40/24/6000. 공통 CrowdTrial 설정으로 함께 꺼진다. 기존 사운드/팝업/기본 공연장 조명은 유지했다.

## 실제 화면
- [외줄 약8초](Previews/Runtime/tightrope-crowd-motion-v7.mp4), [대포 약8초](Previews/Runtime/cannon-crowd-motion-v7.mp4): 평상시→환호→야유. 일반 플레이 카메라1920×1080, 확대/색보정 없음, 무음. 이미지 캡처 간 실제 시간을 반영해20fps 영상으로 묶었다.
- 시점 비교 촬영에 한해 로컬 이동과 균형을 멈췄다. 게임 코드/설정에 이 고정을 넣지 않았다. 장애물/공연장 연출은 계속 움직인다. 실제 조작 중 판독성 통과를 뜻하지 않는다.
- 몸이 검게 유지되며 좌석 배경 대비와 V자/낮은 자세 차이를 확인했다. 한 구역은 화면 상단에서 작게 보이고 외줄 기물이 일부 겹친다. 주 피드백은 현재 개인 사운드/기존 UI이며 구역 확대는 보류한다.

## 검증
- 실제 인스턴스: Renderer1, Light1, shadow=None, Clear 후 광원 disabled. `_CheerColor`/`_BooColor` 속성 없음, 몸색 고정, 삼각형864 확인.
- 새 Windows Development 빌드 성공114.887초/오류0/경고32. 임시 진단 define/frame timing을 API로 복원했다.
- 같은 PC에서 호스트+클라이언트3개, Ryzen9700X/RTX5070Ti/31GB, 각1280×720, PC 품질, vSync off. 8초 예열 뒤 off/on/off/on 각4초, 처음0.5초 제외. 4명 연결 및16구간 모두 valid=true, 각 on구간 관객 반응 수신. 테스트 프로세스 전부 정상 종료.
- GPU p95의 on-off 차이8쌍: -0.424~+0.300ms, 중앙값+0.030ms. CPU 주 스레드 p95: -2.683~+0.806ms, 중앙값-1.086ms. 음수는 개선 보장이 아니라 공유 PC/배경 변화의 변동이다. 0.3ms 성능 상한 PASS로 판정하지 않는다.
- 메시163520B/NetworkObject0, 4인 스냅샷 Observe130회 추가 할당0B. 이는 광원 처리나 게임 전체 GC가0이라는 뜻이 아니다. 별도 관객 네트워크 메시지 추가 없음은 코드 구조 확인이며 전체 수신량이 동일하다는 뜻은 아니다.
- 원자료: `Previews/Runtime/four-v7-*-report.json`, [요약](Previews/Runtime/benchmark-v7-summary.json). 실제 조작/다중 PC/인터넷/콜드 로드는 별도 확인 대상. 이번 비용 비교는 기존 진단처럼 이동만 정지했으며 촬영용 균형 고정은 적용하지 않았다.
