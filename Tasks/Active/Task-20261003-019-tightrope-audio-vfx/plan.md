# Plan

## Context

사건 신호는 각 기능의 공개 이벤트로 이미 나온다(예: `TightropeRun.StateChanged`·`PerformanceStarted`, `NetworkPlayer` 상태 변경, 착지 충격).

## Approach

1. `setup.md`의 작업 구역 안에서만 구현.
2. 새 로직은 가능하면 테스트를 함께 남김.
3. 공용 파일이 필요하면 직접 고치지 않고 PM에게 요청.
4. 검사 후 `integration/*`로 제출.
5. 수치는 코드·프리팹에 두지 않고 세팅 파일 칸으로(칸마다 한글 설명·단위).

세부(구현 전에 PM과 합의):

- 사건 신호를 듣는 쪽만 만든다. 판정 코드는 고치지 않는다(필요한 신호가 없으면 PM에게 요청).
- 다른 화면도 같은 공유 상태 변화로 재생하므로 별도 동기화가 거의 필요 없다.
- 볼륨·켜기/끄기·효과 크기는 `BaseGameSettings`(연출·소리 칸).

## Files

- 수정 예정: `Assets/Scripts/Presentation/`(제안), 소리·VFX 에셋 폴더(PM 지정)

## Risks

- 한 사건에 여러 번 재생되지 않게(상태 변경이 여러 번 오는 경우) 확인한다.

## 공동 테스트 항목

PM과 작업자가 구현 전에 합의한다. 최대 3개. 병합 후 공동 테스트에서 이 항목으로 통과 여부를 판단한다.
불필요하면 `불필요 — 이유`. 아래는 후보(PM 합의 전).

1. 톱날·불·추락에 닿는 순간 소리·효과가 모두에게 같은 때에 나온다.
2. 클리어·실패 때 소리가 나온다.
3. 세팅에서 볼륨을 바꾸면 반영된다.
