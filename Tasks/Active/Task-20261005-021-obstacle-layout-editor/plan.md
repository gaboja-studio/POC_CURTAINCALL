# Plan

## Context

012의 장애물 순서(`SawSettings.steps`·`horizontalSaws`)는 숫자 목록이라 뜻과 결과를 플레이해 봐야 안다. 기획자가 씬 뷰에서 보고 고치게 바꾼다. 동작 규칙(`tightrope-course-rules.md` #6~#9)은 바꾸지 않는다.

## Approach

원칙: `setup.md` 작업 구역 안에서만 고친다. 동작 규칙(#6~#9, 7-1)과 012의 판정·절단·발판·공유는 그대로 두고 **입력(배치 데이터)만** 바꾼다. 수치는 세팅 파일 칸(한글 설명·단위)으로 둔다.

### 확인된 근거 (코드 확인 2026-10-05)

- 지금 순서는 `SawSettings.steps`(`ObstacleStep[]`) + `horizontalSaws`(22개 위치·출발 쪽)이고, 실행은 `ObstacleSequence`(호스트)가 한다. 실제 값은 시간 기준 2개만 쓴다: 가로 1~22 게임 시작 0초 작동(정지 없음), 수직 묘기 시작 60초·제거 뒤 20초·끝없이.
- 가로 톱날 속도는 첫·끝 톱날 거리 사이 직선 보간(3.0→4.5m/s)이라 위치를 옮기면 속도도 따라 바뀐다.
- 수직 톱날은 생성 지점이 고정(93m)이라 공유 메시지에 생성 거리가 없다(`sinceSpawn`만 보냄).
- `TightropeCourse.Layout`·`GetLanePosition`은 플레이 전(편집 모드)에도 계산된다 → 씬 뷰에 바로 그릴 수 있다.
- 프로젝트에 테스트 어셈블리가 없다(스크립트가 Assembly-CSharp) → 자동 테스트는 `NO_PROJECT_TESTS`, 계산 확인은 플레이·미리보기로 한다.

### 단계

1. **배치 데이터(`ObstacleLayout`, ScriptableObject)** — `Assets/Scripts/Tightrope/Saws/ObstacleLayout.cs`
   - 가로 톱날 목록: 위치(m)·출발 쪽·**움직이기 시작**(기준 게임 시작/묘기 시작 + ○초)·**멈춤**(○초 뒤 / 안 멈춤).
   - 수직 톱날 규칙: 첫 등장(묘기 시작 후 ○초)·다음 등장까지(사라진 뒤 ○초)·최대 등장 횟수(0 = 계속)·줄(-1 = 진행 중인 플레이어 줄 중 랜덤)·**선두 앞 최소 거리 n m**(임시값 15m).
   - 확장 자리: 불타는 구간(014)용 목록을 같은 파일에 추가할 수 있게 묶음을 나눠 둔다(이번에는 칸 없음).
   - 코드 기본값 = 지금 값 그대로(22개 위치·번갈아 출발, 게임 시작 0초·안 멈춤, 수직 60초·20초·계속).
2. **세팅 연결** — `TightropeSettings`에 배치 파일 칸 추가(`GameSettings.Tightrope.Obstacles`, 연결 없으면 코드 기본값 + 경고). `SawSettings`에서 `steps`·`horizontalSaws`를 빼고 공통 규격(크기·높이·속도·발판·판정)만 남긴다.
   - 에셋: `Assets/Resources/GameSettings/Tricks/TightropeObstacles.asset` 생성·연결(에디터 조작).
3. **실행기 입력 교체** — `ObstacleLayout` → 내부 단계 목록으로 변환해 기존 `ObstacleSequence`가 그대로 실행. 가로는 톱날마다 작동(+정지) 단계, 수직은 반복 단계 1개.
   - 결정(2026-10-05)에 따라 쓰지 않게 된 시작 조건(선두 거리·다른 단계 시작/끝 뒤)과 이름 참조는 코드에서도 지운다(필요해지면 다시 추가).
4. **수직 톱날 등장 위치·낙하(7-1~7-3)** — 고른 줄의 **가장 앞선 진행 중 플레이어 + n m(기본 15)**에 생기고 93m를 넘지 않는다. 그 줄 선두가 93−n m보다 앞이면 그 줄은 후보에서 빼고, 후보 줄이 없으면 미룬다(대기 로그에 이유 표시).
   - 그 지점 **화면 위(목마 4층 고려, 낙하 높이 칸 임시 8m)**에서 생겨 낙하 시간(임시 0.8초) 동안 줄 위로 내려온 뒤 움직이기 시작한다. 낙하 중에도 같은 거리 계산으로 판정한다(앞 n m라 보통 아무도 없음).
   - 생성 거리가 바뀌므로 수직 공유 메시지에 생성 거리 1개를 더한다(판정·발판 동작은 그대로).
5. **씬 뷰 편집** — `Assets/Scripts/Tightrope/Saws/Editor/`
   - 코스가 있는 씬에서 톱날을 그린다: 원판, 왕복 범위 선(±반폭), 공격 높이, 이름표 "#번호 · 거리 m · 속도 m/s".
   - 진행 방향 핸들로 끌어 거리 변경 → 배치 파일에 저장(되돌리기 Ctrl+Z 지원, 0~도착 거리로 제한).
   - 수직 톱날: 생성 한계(93m)·제거(5m) 표시.
6. **쉬운 칸(인스펙터)** — 배치 파일 인스펙터를 쉬운 말 칸으로 그린다. 수직 톱날 아래 "플레이어에게 닿기까지 약 ○초"(= 낙하 시간 + n ÷ (톱날 0.8 + 걷기 0.5 m/s)) 자동 표시. 가로 톱날 여러 개 선택 → 시작·멈춤 한 번에 적용 버튼.
7. **시간 슬라이더 미리보기** — 메뉴 `Tools/CurtainCall/Obstacle Layout` 창: 배치 파일 선택, 시간 슬라이더(0~제한시간), "묘기 시작 시각(가정)" 칸. 씬 뷰에 그 시각의 톱날 위치를 그린다. 가로는 실행 코드와 같은 `HorizontalSawTrack`·`SawMath`, 수직은 "가상 선두가 묘기 시작부터 0.5m/s로 걷는다"고 가정해 등장 위치·시각을 계산(가정은 창에 글로 표시).
8. **검증·문서** — 컴파일, 기존 값으로 플레이해 012와 같은 움직임 비교, 공동 테스트 3개 직접 플레이, 도메인 맵·세팅 안내 갱신(아래 PM 요청).

## Risks

- 씬 뷰 편집이 세팅 에셋을 바로 고친다. 플레이 중에 고친 값도 남는다(ScriptableObject) — 의도대로 "플레이하며 조정" 가능하지만, 실행 중인 판에는 재시작 때 반영됨을 창에 표시한다.
- 기존 `steps`·22개 값이 빠짐없이 옮겨졌는지: 코드 기본값과 에셋 값을 나란히 확인하고 플레이로 비교.
- 수직 공유 메시지 형식 변경 → 호스트·클라이언트가 같은 빌드여야 한다(테스트 MPPM은 같은 코드라 문제 없음).
- 위치를 옮기면 보간 속도도 바뀐다(이름표에 속도를 보여 줘 바로 알 수 있게).
