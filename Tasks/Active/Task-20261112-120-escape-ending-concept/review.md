## 디자인 제안

패널을 화면의 약 44% 폭으로 잡아 오른쪽 캐릭터와 서커스를 가리지 않는다. 짙은 청록 바탕에 아이보리 텍스트, 얇은 금속 프레임, 모서리 작은 황동 리벳을 쓴다. 성공 리본의 민트 포인트와 공용 버튼의 황동 강조를 잇는다. 탭 선택은 밑줄로 명확하게 구분한다.

탈출 상태는 색만으로 표시하지 않고 문 아이콘/텍스트를 함께 사용한다. 플레이어 색상은 초상 옆 독립 동그라미로 유지한다. 예시는 토끼/피에로/소녀 탈출, 곰 미탈출이며 네트워크 슬롯이나 특정 캐릭터의 운명을 고정하는 결정이 아니다. 곰의 빈 소지칸도 예시일 뿐 미탈출자의 소지 기물을 항상 비운다는 규칙이 아니다.

통계와 기물 배정은 전부 가상 값이다. 쉬움/보통/어려움은 제안 표기이며 실제 난이도 명칭과 집계 분모·미시도 표시를 데이터 계약 단계에서 맞춘다. 개인 최고 초상은 해당 플레이어와 연결한다. 기물 그림은 종류 확인용 원화로 기존 정본 아이콘을 대체하지 않는다.

## 피드백 후 기술 작업

1. 프레임/패널 바디/그림자/리본/탭 상태/행/기물 슬롯/상태 아이콘/버튼 상태를 분리하고 9-slice 경계와 PPU를 확정한다. 문구·수치·플레이어 초상·색상은 동적으로 공급하고 글자를 Sprite에 굽지 않는다. 기존 정본 UI 재사용을 먼저 검토한다.
2. 프리팹은 공통 헤더/탭/본문/하단 버튼으로 구성하고 플레이어·통계 본문을 전환한다. 안전 여백, 한글 폰트, 해상도별 가독성, 1~4인 표시를 검증한다.
3. 기존 EscapeCampaignContent의 성공 집계와 EscapeEndingPresentation/SpaceLinkDirector의 전환 대기를 보존하며 결과 스냅샷을 연결한다. 현재 코드에는 방장 권한의 복귀와 참가자 대기 문구가 있다. 원화의 버튼은 권한 동작을 새로 확정하는 것이 아니다.
4. Cinemachine으로 실시간 배경을 먼저 구성한다. 캐릭터와 카메라의 상대 거리를 유지하며 서커스가 원경으로 멀어지고 이후 갈대밭 반복을 유지한다. 최종 부상 상태 캐릭터의 이동 표현은 실제 모델/애니메이션을 확인해 정한다.
5. 로비 버튼 후 입력 차단·카메라·커서·시간/상태 복구와 재시작을 호스트/참가자에서 검사한다. Confluence의 로비 복귀 조작 버그는 이 단계의 별도 검증 항목이다.

## 검토 포인트

패널 밀도와 캐릭터 크기, 밤 장면의 밝기, 서커스 외관/거리감, 두 탭 정보 배치에 대한 피드백을 받는다. 피드백 전에는 스프라이트 키트나 실제 배경 연출 구현을 시작하지 않는다.
