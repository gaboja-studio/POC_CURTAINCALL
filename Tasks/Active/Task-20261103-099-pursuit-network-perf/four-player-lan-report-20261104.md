# 4인 LAN 위치 전송 A/B와 불꽃 접촉 검증

## 환경과 범위

- 2026-11-04, Unity 6000.3.25f1. 메인 Editor + 공식 Multiplayer Play Mode Player 2/3/4, 독립 프로세스 4개, 실제 LAN/UTP 연결.
- 실제 외줄 씬, 동일 플레이어 프리팹·카메라·렌더링. 측정 중 안전 구간 6~24m에서 W/S 합성 입력으로 왕복. 판정과 이동 전송 비용을 분리하기 위해 톱·불꽃과 균형 난수만 일시 비활성화. 저장된 씬/게임 설정은 변경하지 않았다.
- 각 송신측 UTP NetworkSimulatorParameter: SendDelayMS=100, SendJitterMS=30, SendPacketLossPercent=3. 실제 패킷 큐에 적용했다. 클라이언트 RTT 중앙값 238~240ms.
- A: Player NetworkTransform.UseUnreliableDeltas=false, B: true. A→B→B→A 순서, 각 15초. 공통 구간 앞 3초·뒤 0.5초 제외. 실제 유효 공통 구간은 9.36~10.64초.
- 각 프로세스에서 UTC 시각·프레임 시간·RTT·4인 연결 여부·자기/원격 위치 기록. 한 PC의 같은 시계를 사용하여 소유자의 같은 시각 위치를 보간하고 각 화면의 복제 위치와 거리를 비교했다. 지연을 보정하여 오차를 없애지 않았다.
- **4개의 실제 네트워크 프로세스 검사이며, 서로 다른 PC 4대/Relay/출시 빌드 FPS 검사가 아니다.** CPU/GPU를 공유하는 Editor 성능을 출시 성능으로 일반화하지 않는다. GC·대역폭 개선은 측정하지 않았다.

- 프레임 시간은 거의 같고 개선 근거가 없다. 이번 변경을 FPS 최적화라고 보고하지 않는다.
- 최신 위치 델타는 유실된 이전 델타의 재전송을 기다리지 않게 했다. 설치된 NGO의 주기 축 동기화·초기 동기화·텔레포트 신뢰성 경로는 유지된다. 프리팹은 UseUnreliableDeltas 한 값만 변경했다.
- 최초 `reliable-a1`은 이전 실패 후 추락 중인 캐릭터를 측정해 무효. `reliable-a2`는 목표 도착 후 정지가 섞여 최종 비교에서 제외. 최종 분석기는 4인 연결·높이·이동 거리 조건을 검사한다.

## 실제 지연 불꽃 판정

- 접촉 검사에서는 불꽃을 다시 켜고 실행 중 메모리의 추격 불 경계를 8m에 고정했다. 각 소유자는 12m 안전 위치에 배치했다. 테스트 설정 배열 교체 시 기존 FireView 캐시 예외가 발생한 초기 시도는 표시 안정성 통과로 취급하지 않는다. 자동 회귀에서는 새 설정 인스턴스를 사용해 캐시를 정상 재구성했다.
- `fire-contact-valid`: 모든 프로세스의 지연 설정을 새 60초 캡처로 유지하고 검사했다. 호스트의 owner1 복제 위치만 6m로 옮겨 Judge를 호출해도 owner1은 Normal 유지. 피해자 실제 위치는 12m였다.
- owner2의 실제 소유자 위치를 6m로 옮긴 시각: `2026-11-03T16:36:57.1190642Z`. 호스트의 기존 Fire.Hit 확정 이벤트: `16:36:57.2572191Z`. 약 138ms 후 1회 확정.
- 호스트와 피해자 양쪽에서 owner2=Fallen, 안전한 owner0/1=Normal 확인. 앞선 검사에서 접촉한 owner3의 Fallen 상태는 유지됐다. 좌표는 검사 목적으로 지정했으며 사람의 실제 회피 입력 시험은 아니다.

## 실제 지연 톱날 판정

- 새 4인 세션에서도 100ms/30ms/3%와 후보 위치 전송을 함께 적용했다. 시작선 통과·IsPerformanceStarted·4인 연결을 먼저 확인했다.
- 안전한 owner2의 호스트 복제 위치만 가로 톱 중심으로 바꿔 ServerJudgeHits를 호출해도 무부상 유지. 실제 접촉한 owner1은 호스트 확정 부상이 양쪽에 동일하게 반영됐다.
- 움직이는 톱의 최초 순간이동 접촉은 즉시 승인되지 않았고 이후 재통과 때 절단됐다. 이 시도를 짧은 회피/모든 접촉 검출 통과로 보고하지 않는다. 정지 검사의 첫 임시 로컬 트랙 교체도 정기 상태 수신이 덮어써 무효로 제외했다.
- 기존 호스트 StopHorizontal→BroadcastHorizontal 경로로 정지시켜 네 화면에서 같은 좌표·moving=false를 확인했다. 이전 접촉 해제 후 새 지속 접촉은 `2026-11-03T16:55:29.0540960Z` 시작, 호스트 확정 `16:55:29.2266157Z`로 약 173ms였다.
- 30초 뒤 `16:55:59Z` 양쪽 조회에서도 owner1=Normal/LeftLeg 1개 손실, owner0/2/3=Normal/None 유지. 지속 접촉 재전송으로 추가 절단은 발생하지 않았다.
- 이 검사는 일반 가로 톱의 실제 메시지 송수신을 검증한다. 수직 톱/협동·해제 관문의 네트워크 실기, 빠른 경계 통과, 이동 중 점프 회피는 추가 검증 대상이다. 보고 전 75ms 이내 이력이 없거나 접촉이 확인되지 않으면 피해를 보수적으로 거절한다.
