# 커튼과 NGO 씬 전환의 선후 관계

## 언제 읽나

호스트보다 참가자에서 씬 변경이 먼저 보이거나, 로컬 additive 배경이 뜨기 전에 커튼이 열릴 때.

## 확인한 코드 사실

- 기존 SceneCurtainTransition은 전환 UI 컴포넌트가 생긴 뒤 Update에서 NGO OnSceneEvent를 구독했다.
- 참가자 Load 이벤트에서 비동기 Cover를 시작했지만 NGO는 그 코루틴의 닫힘 완료를 기다리지 않는다.
- 호스트의 씬 로드 완료는 참가자별 비네트워크 배경·UI 로드 완료를 뜻하지 않는다.

## 수정 원칙

- 씬 로더 호출 **이전**에 현재 참가자의 닫힘 완료 ACK를 수집한다.
- 전환 표시를 소유한 UI의 존재와 관계없이 메시지 수신기를 먼저 준비한다.
- 각 화면의 NGO 작업·배경·UI 준비가 끝나야 열림을 허용한다.
- 이전 열림 코루틴과 접속 종료의 입력 차단도 함께 정리한다.
- 호출자별 전환 번호를 보존하고, 취소된 요청의 늦은 finally가 새 전환을 열거나 새 닫힘을 자신의 성공으로 쓰지 못하게 한다.

## 한계

전환 도중 새로 접속하는 사람의 최초 NGO 동기화는 별도의 진입 장벽이 필요하다. 현재 참가자의 ACK 장벽으로 보장한다고 보고하지 않는다.
