# Plan

## Context

2026-10-06 승인: 기존 proto_0.0.2.unity에서 4인 입장 → 출발 → 협동/장애물 → 확정 결과 → 재도전을 검증한다. 015·023·016 병합 후 시작한다. 021은 제출 PR만 검토하며 미제출 변경은 복사/체리픽하지 않는다.

## Approach

1. 지정 씬·GUID를 보존하고 Unity 에디터로 기존 코스·목마·톱날·손상·Fire·카메라·게이지·결과·데모 UI·기록을 연결한다. 테스트 IMGUI 방 UI를 제외하고 원본 테스트 씬을 보존한다.
2. P/O 기본 숨김과 각 패널 B/R/M·K/L/착지 명령 gate를 분리한다. RunDebug의 매 프레임 R override를 제거하고 개발 행동을 기록한다. 기존 권한 검사 유지.
3. 모달/입력창에서 이동·점프·균형·F 요청/해제·개발 키(P/O 포함)를 모두 차단한다. 전환에 눌림/예약 입력을 정리하고 닫힌 후 새 입력만 허용한다. 타이머/네트워크는 멈추지 않는다.
4. 최초 시작은 Waiting·최소 인원 유지, 성공 후 Ended→Playing 호스트 전용 retry와 실패 3초 자동 retry를 단일 Run 실행부에 연결한다. 회차·중복 클릭·Leave 후 예약 방어.
5. 성공 시 생존자만 모으되 목마 연결/Follow를 먼저 해제한다. 잔존 팔의 위치·회전을 저장/복구하고 V자 임시 포즈를 적용한다. Slot 균형 회전은 건드리지 않고 손실 복구·사망자 부활 없음.
6. room/session/attempt 호스트 ID 교환·참가자 매핑·누락 행동 hook을 023 adapter에 연결한다. 요청/관측/확정과 unknown 원인 구분, UI와 JSON은 015 결과를 같이 사용한다.
7. PM이 별도로 버전 0.0.2·빌드 시작 씬을 설정한 뒤 macOS 빌드와 통합 검사를 한다. 새 패키지·외부 전송·dev 승격은 제외.
