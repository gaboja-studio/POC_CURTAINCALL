# Plan

## Context

0.0.2 후속 승인: 결과 팝업과 행동 JSON이 같은 호스트 결과를 참조해야 한다. 기존 Run은 성공 시 생존자를 모두 Arrived로 변경하므로 변경 전에 직접 완주·동반 성공을 구분해야 한다. 이탈자는 현재 NetworkPlayer.All에 남지 않는다.

## Approach

1. Run에 종료 직전 호스트 결과 경계와 명시적인 종료 이유를 추가한다. 도착 → 위험 → 실패 판정 순서는 유지한다.
2. Results에 외부 수정 불가능한 스냅샷·직렬화 DTO·참가자 명부를 구현한다. 회차·일시 client ID·slot·사지 상태를 보존하고 이탈자를 분리한다. 영속 ID는 023/022 연결 계약을 사용한다.
3. 호스트가 성공 동반 상태 변경/실패 종료 전에 고정 시간과 결과를 확정한다. 클라이언트는 호스트 결과만 받아 표시하며 승패를 재계산하지 않는다.
4. 신뢰 가능한 호스트 메시지·회차·중복 방어·결과 요청/응답을 구현한다. 지난 결과는 재시작 후 유지하되 방을 떠나면 이전 방 결과를 초기화한다.
5. 전용 테스트 씬에는 기존 코스·공개 결과 컴포넌트를 에디터로 연결한다. 데모 화면·재도전·포즈는 후속 Task에 맡긴다.

## Files

- 수정: setup.md의 Results 폴더·전용 테스트 씬·TightropeRun.cs.
- 읽기 전용: NetworkPlayer, NetworkSessionManager, Fire, GameSettings.
- 보상과 설정 에셋을 수정하지 않는다.

## Risks

- 서로 다른 NGO 메시지 순서와 결과 도착 시점. 결과 자체의 round를 기준으로 저장하고 신규 결과 알림은 중복 없이 처리한다.
- 참가자 이탈/slot 재사용. client ID별 명부를 보존하며 영속 익명 ID는 후속 연결 시 채운다.
- 종료 이후 PerformanceElapsed 증가. 결과에는 종료 순간 값을 고정한다.

1. 한 명 도착 시 네 화면의 고정 완료 시간·직접 도착/동반 성공·사망/이탈·사지 상태가 동일하다.
2. 전원 사망/시간 종료 결과가 3초 자동 재시도 전에 확정되고 다음 시도에도 지난 결과로 보존된다.
3. 이탈/자리 재사용·이전 회차 메시지·중복 종료가 참가자를 덮어쓰거나 새 결과를 중복 생성하지 않는다.
