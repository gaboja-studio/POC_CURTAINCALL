# Plan

## Context

2026-10-05 PM이 0.0.2 4시간 계획을 승인했다. 추격 불과 후반 구간 화재를 구현한다. 발화 당시 구간 위 플레이어도 사망하며, 점프·목마 높이로 화재를 회피하지 않는다. 실제 4인 플레이 검증은 사람이 수행한다.

## Approach

1. FireSettings를 TightropeSettings에 추가한다. 호스트는 시도 시작마다 설정을 복사해 공유하며 플레이 중 편집은 다음 시도에 적용한다.
2. 묘기 시작 10초 후 -6m에서 0.35m/s로 추격, 95m에서 정지한다. 95m 이상은 화재 대상 제외.
3. 묘기 120초에 1·4번 줄 55~95m, 180초에 3번 줄 70~95m 발화한다(끝 제외). 10초 전 경고색과 공개 예고 상태를 제공한다.
4. 호스트 TightropeRun의 도착 확인 뒤, 도착자가 없을 때만 위험 판정 이벤트를 호출한다. Fire는 이 이벤트에서 Normal 플레이어의 수평 접촉을 판정해 ServerSetState(Fallen)을 호출한다.
5. 회차 번호·호스트 기준 경과시간·설정 스냅샷을 NGO 이름 메시지로 공유하고 재시작 초기화 및 재접속 상태 요청을 지원한다. 예전 회차 메시지는 무시한다.
6. 임시 표시 도형에는 콜라이더를 붙이지 않는다. 구간 차단과 피해 경계는 동일한 끝 제외 조건을 쓴다.
7. 불 기능은 독립 프리팹/테스트 씬에 둔다. 최종 HUD·결과·씬 연결은 후속 015·016·022에서 공개 상태/이벤트를 사용한다.

모든 불 수치는 기획 확정값이 아닌 승인된 초기 실험 조건이다.

## Risks

- 호스트가 보는 원격 위치의 지연은 기존 NGO 소유자 이동 구조의 제약이다.
- 블록과 사망은 별개로 처리한다. 높이 검사하는 IsOnRope를 화재 판정에 사용하지 않는다.
- 클라이언트의 로컬 발화 표시가 호스트와 프레임 단위까지 동일하다고 보장하지 않는다. 호스트 일정과 시간 보정으로 맞춘다.
- 021 미제출 변경·배치 에셋은 보존하며 이 작업에서 통합하지 않는다.

## 공동 테스트 항목

1. 실제 4인 화면에서 추격 불 접촉 사망·구간 발화 당시 점유자 사망·10초 예고·끝 95m 안전 경계가 일치한다.
2. 후반 사용 가능한 줄이 2개→1개로 줄고, 불탄 줄 착지 차단 및 점프/목마 높이의 수평 접촉 사망을 확인한다. 같은 판정 시점 도착자는 화재보다 우선한다.
3. 재시작하면 추격 위치·구간 차단·예고가 초기화되고 새 설정만 적용된다. 직전 회차 상태가 다음 회차에 섞이지 않는다.
