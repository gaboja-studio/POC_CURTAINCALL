# Plan

## Context

CC-132 개발 순서의 1단계만 구현한다. 공간과 공연 왕복을 한 루프로 묶어 먼저 검증하고, 그 위에 2~5단계(탐색 제한 시간·상점·밤 정비·전문가 서비스)를 순서대로 쌓는다. 온라인 동기화는 1단계부터 포함한다.
기준: 대기실 2차 기획서 20348931(3.1.2·3.1.3·3.3·3.4.1·4.1), 게임 흐름 15564804(충돌 시 우선), `Harness/Project/Decisions/Waiting-room/space-layout.md`.

## Approach

1. 착수 준비: dev 최신 공용 시스템 수신. 기준 씬은 `WaitingRoomBase.unity`(맵 배치 씬 복사본)이며 원본 waiting_room.unity는 건드리지 않는다.
2. 공간 배치: ①~⑤·⑧ 그레이박스와 대기실 문. ⑧ 문은 닫힘(통과 불가). 스케줄표·수화기·배송구·선반은 위치 표시 도형만. ⑥·⑦은 백스테이지라 만들지 않고, 대기실 문 밖에 ⑥ 대체 통로(집결 판정용, 테스트 전용)만 둔다.
3. 스폰·복귀: ① 로비 스폰 위치 4개. 대기실 진입·공연 종료 후 전원 ①로 이동.
4. 공연 진입: ⑥ 대체 통로의 판정 영역(백스테이지 연결 CC-111 때 실제 ⑥으로 교체). 살아 있는 전원 진입 시에만 동시에 더미 공연(CC-119)으로 전환. 일부 진입은 전환 없음.
5. 복귀·부활: 성공·실패 모두 대기실 복귀, 사망자는 공용 부상 상태로 외팔 부활. 반복 시 이전 진입·전환 상태 초기화.
6. 4인 동기화: 기존 방 생성·참가 재사용. 스폰·⑥ 진입·전환/복귀 시점·부활 결과 동기화.
7. 공용 인터페이스가 부족하면 직접 고치지 않고 PM에게 별도 소유 Task를 요청한다.

## Risks

- 마지막 진입자가 호스트/참가자일 때 전환 시점 불일치, 복귀 후 진입·사망 상태 잔류.
- 복사본과 원본 waiting_room.unity(Task-024 배치 진행 중)가 갈라진다. 원본 반영은 통합에서 PM이 정하며 이 Task는 씬 병합을 하지 않는다.
- ⑥ 대체 통로는 테스트 전용이다. 백스테이지 실제 공간·커튼 방을 만들지 않는다.
- 범위 밖 추가 금지: 타이머·추격자·상점·밤 정비·백스테이지·플레이어 상태/조작.

## 공동 테스트 항목

실행 씬: `Assets/Scenes/Tests/WaitingRoom/Base/WaitingRoomBase.unity` → 공용 더미 공연. 4인(호스트 1·참가자 3). handoff에 일시·참여자·호스트/마지막 진입자·씬·재현·예상·실제를 기록한다. 현재 전부 미실행이다.

1. 접속과 동선: 4명 접속 → 전원 ① 로비의 서로 다른 위치 스폰 → 각자 ①~⑤·⑧과 문 밖 ⑥ 대체 통로까지 이동. 예상: 막히는 곳 없음, ⑧ 문은 통과 불가.
2. 전원 집결 후 공연 진입: 3명만 ⑥ 대체 통로 진입 → 4번째 진입. 예상: 3명일 때 전환 없음, 4번째 진입 순간 전원 동시 더미 공연 전환, 네 화면 시점·결과 일치.
3. 복귀와 반복: 더미 공연에서 1명 사망 처리 → 복귀 → 마지막 진입자를 호스트/참가자로 바꿔 2회 이상 반복. 예상: 전원 ① 스폰, 사망자 외팔 부활, 이전 진입·사망 상태 잔류 없음.
