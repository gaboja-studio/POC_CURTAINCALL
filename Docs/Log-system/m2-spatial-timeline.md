# 0.2.0 공간 로그와 타임라인 — 기획 확인용

2026-11-05 · Task-106 · 담당 @MoHoDu

기준은 현재 구현과 사용자의 이번 지시다. [M2 로그 수집 초안](https://hrjoo122770.atlassian.net/wiki/spaces/bYmkRlnpusng/pages/35553283/M2+--)의 수집 요소를 모두 이미 존재하는 기능으로 간주하지 않는다. 이 문서는 새로 연결한 것과 관측 한계를 구분한다.

## 무엇을 볼 수 있나

런 세션에서 일차와 활동을 고른 뒤 **층별 공간 재생**을 사용한다. 대기실·리허설·공연·탈출로의 실제 X/Z 좌표가 탑뷰로 나온다. 층과 활동 구간을 선택하고 처음/이전 사건/재생·일시정지/다음 사건/마지막, 시간 슬라이더, 재생 속도로 탐색한다. 발자국이나 사건에 마우스를 올리면 설명을 볼 수 있고, 최근 사건을 누르면 해당 시점으로 이동한다.

플레이어는 슬롯별 색상, 추격자는 검정, 장애물은 회색, 오브제는 연갈색이다. 이동은 👣, 사망·잡힘은 💀, 환호·야유는 👏/👎, 발견·해금·일정은 각각의 이모지로 표시한다. 좌표 표본은 읽기용 사건 목록을 채우지 않고 재생에 모두 보존한다. 기존 400개 마커 제한을 새 공간 재생에 적용하지 않는다.

## 제출·시각·평면도

- 기록은 로컬 디스크에 체크포인트로 보존하고 해당 씬/활동이 끝날 때 전송 대상이 된다. 씬 전환, 런 종료, 접속 종료에 해제한다. 같은 씬의 쉬는 시간/공연 구간이 바뀌어도 직전 구간을 제출한다.
- “한 번에 제출”은 **종료 시 묶음 제출**이다. 기존 API 크기 제한 때문에 최대 250건/약 100KB 단위로 나누어 순차 제출한다. 실패하면 재시도하며 원본 eventId와 ACK 중복 방지를 유지한다. 강제 종료는 다음 실행에서 남은 디스크 기록을 재전송한다.
- NGO 서버 시각을 함께 기록하여 여러 PC의 벽시계 차이를 피한다. 같은 서버 시각임을 확인할 수 없는 묶음은 UTC 기준과 ‘시각 미동기화’ 경고를 표시한다. 기록이 없는 구간을 실측 이동으로 채우지 않는다.
- 대기실은 추격자 배치 도구와 같은 층 절단·좌표 투영으로 **실제 씬의 방·복도·바닥·가구를 렌더링한 평면도**를 사용한다. 0m/-5m/-10m 개별 보기와 **모든 층 동시 보기**가 같은 재생 시각을 공유한다. 방 선택·미니맵 클릭·휠 확대·드래그 이동이 가능하다. 최초 검토의 큰 사각형/벽 세 개 예시는 제거했다.
- 공연은 인간 대포 씬의 실제 탑뷰에 동선과 사건을 겹친다. 외줄타기는 플레이 중 코스를 생성하므로 빈 편집 씬의 사진을 쓰지 않고, 실제 생성된 줄의 경로·구조와 장애물 위치를 기록해 도식화한다. 외줄타기까지 미술 텍스처 사진으로 재현한 것은 아니다.
- 탈출로는 **전체 보기 / 구간별 보기**를 제공한다. 합류 계단, 시작홀, 진입 복도·첫 대포, 착지 외줄·하강, 이동 그네·하부 처리장, 소실 외줄·트램폴린, 화염·상승 대포, 첫 반출교·추격 시작, 협동교·방출 구역, 상부 설비, 그네 단절, 마지막 질주, 절단기·출구, 갈대밭의 14구간이다. 실제 씬의 배치 그룹으로 구분하며, 아직 게임 로직에 존재하지 않는 공식 스테이지 번호로 해석하지 않는다. 전체는 경로 파악용이며 높이가 겹치는 구조는 절단 높이가 다른 구간 도면에서 자세히 본다. 보기 전환 시 재생 시각을 유지한다.
- 도면에는 캡처 시점의 정적 구조가 담긴다. 움직이는 물체·추격자·플레이어는 로그를 별도로 겹친다. 일치하는 mapId가 없으면 다른 맵을 임의로 대입하지 않고 ‘원본 도면 미수집’을 표시한다.
- 기록 사이의 이동은 화면상 보간이다. 층 이동, 큰 순간이동, 긴 결측, 사망 이후를 임의로 이어 이동시키지 않는다.

## 이전 배포(v38·v39) 확인 기록

새 수집기는 **이 변경을 포함한 게임 빌드부터** 동작한다. 대시보드만 갱신해도 기존 빌드가 새 위치를 보내지는 않는다. 기존 시트·설문·로그 보관 규칙은 유지한다. 대시보드 v39, 수신기 v38을 기존 배포 URL로 업데이트했다.

서버/재생 Node 검사 134개, Unity 로그 관련 EditMode 검사 92개 통과. 로컬에서 실제 도면 위 합성 데이터로 4색 플레이어·세 층 동시 보기·추격/사망·공연·탈출 전체/14구간 전환과 시각 유지를 확인했다. **검증용 동선은 합성이며 실플레이 자료가 아니다.** 직선 예시는 테스트 좌표 때문이고, 실제 기록에서는 수집 위치를 순서대로 잇는다. 5초 공연 표본 사이의 세밀한 곡선까지 복원하는 것은 아니다.

실제 4인 접속, 빌드→수신→시트의 새 이벤트 전체 왕복, 최종 플레이 감각은 아직 실플레이 검증하지 않았다. 다음 플레이테스트에서 4인의 씬 전환 이후 도착 건수, 잡힘 원인, 층 이동, 공연 환호·야유, 네트워크 종료 후 재전송을 확인해야 한다.

## 맵을 바꾼 뒤 갱신하기

Unity에서 저장되지 않은 씬 변경을 먼저 저장하고 `Tools > Curtain Call > Telemetry > Export dashboard floor maps`를 실행한다. 씬을 저장하거나 기존 에셋을 수정하지 않고 캡처하며 작업 전 씬 구성을 복원한다. 도면 JPEG는 `.harness/local/telemetry-maps/`에만 두고 공개 저장소에 넣지 않는다. 빌드에는 좌표와 mapId만 든 `Assets/Resources/TelemetrySpatialMaps.json`을 포함한다. `node Scripts/Telemetry/prepare-deployment.cjs`로 배포본을 만들고 대시보드 버전을 갱신한다. 도면은 기존 대시보드 멤버 인증을 통과한 조회에만 제공한다. 게임 빌드와 대시보드의 도면 버전을 함께 갱신해야 한다.

운영 확인 범위: v39 배포 성공과 웹 페이지 요청(doGet) 완료를 확인했다. 검증 브라우저의 운영 탭에서는 Google 내부 프레임이 비어 화면 표시까지 확인하지 못했다. 위 도면·재생 조작 검증은 같은 화면 코드의 로컬 미리보기 결과다.
