# 버전 범위와 설문 회차

기획자 조작은 [버전·설문 설정 안내](../../Harness/Project/Guides/Log-system/versioning.md)를 따른다. PM은 원격 변경 대신 새 빌드에 설정을 포함하는 방식을 선택했다(2026-10-26).

## 설정 계약
- `Scripts/Telemetry/playtest-settings.json`: 비밀값 없는 공유 설정. 에디터의 CurtainCall → 로그·설문 설정에서 편집한다. 빌드 시 기존 build-tags manifest에 collection을 넣는다.
- LOGS/SURVEY 태그는 독립이다. 기존 저장값 호환을 위해 내부 태그 키 SURVEY_010은 유지하지만 UI 이름은 설문 사용이다.
- logVersions와 두 설문의 versions는 `숫자.숫자.숫자`, `숫자.숫자.x`, `*` 중 하나. 실제 이벤트/응답 gameVersion은 Application.version 그대로다. 범위별 합산 필터는 아니다.
- night/exit 각각 enabled, id, title, round, versions, formUrl, entry를 저장한다. nightDay는 밤 정비만 사용한다. 자동 시점 추가나 동시 여러 폼 실행은 이 변경에 포함하지 않는다.
- 기본 M1 두 폼은 0.1.x, 회차1. 현재 프로젝트0.2.0에서는 제외한다. 이 PC 태그는 LOGS 켬·설문 끔이다. 다른 PC의 EditorPrefs는 변경하지 않는다.
- ID·회차·시점·PC 사용자 저장공간별 최초 열림. M1 기본 ID/회차/폼은 기존 0.1.0 마커를 존중한다. 새 회차는 별도 해시 마커를 사용하며 옛 마커·로그는 삭제하지 않는다.

## 응답 시트 등록 (관리자)
새 폼 관리자 편집은 사용자가 직접 한다. 기존 M1 두 원본은 유지하며 추가 시트만 Apps Script의 `SURVEY_EXTRA_SOURCES` 스크립트 속성에 JSON 배열로 등록한다.

```json
[{"kind":"NIGHT1","id":"응답_스프레드시트_ID","sheet":"설문지 응답 시트1"}]
```

- `kind`는 NIGHT1(지정 일차 밤) 또는 EXIT(런 퇴장). `id`는 폼 ID가 아니라 응답 스프레드시트 URL의 `/d/` 뒤 값이다. 새 원본을 최대18개 추가할 수 있다.
- 스크립트 소유자가 해당 응답 시트를 읽을 수 있어야 한다. 기존 원본을 속성에서 제거하면 다음 전체 설문 동기화에 빠지므로 기존 항목을 유지하며 추가한다.
- 표시는 번호로 시작하는 질문만 읽는다. M1 질문 해석은 유지한다. 새 폼은 제목의 ‘복수 선택’, ‘자유 응답/서술/자유 의견’으로 차트와 긴 답변을 구분한다. 새 복수 선택 보기의 쉼표는 구분자로 해석되므로 사용하지 않는다.

## 데이터·배포
- 기존 CCS1.0_1_0 코드 유지. 새 CCS2는 실제 버전·설문 ID·회차를 포함한다. 사전 입력 코드는 연결용이며 인증 수단이 아니다.
- 설문 응답/통계 시트 뒤에 surveyId/surveyRound 열을 추가한다. 구형 행은 M1/회차1로 해석한다. 통계는 버전·환경·시점·ID·회차를 모두 분리한다.
- 설문만 켠 새 버전도 Drive 완료 캐시의 버전 목록에 포함한다. 회차 선택은 이미 저장된 결과에서 계산하며 새 적재를 시작하지 않는다.
- **Google 수신/대시보드 서버를 먼저 반영하고 새 게임 빌드 배포.** 2026-10-26 후속 빌드 요청에서 수신v35/대시보드v36 반영 완료. 폼 수정·응답 제출 없음.
