# 대기실·리허설 기록을 읽는 법

[작업자 수집 목록](https://hrjoo122770.atlassian.net/wiki/spaces/bYmkRlnpusng/pages/34799668)과 0.2.0 게임 판정을 비교했다. **런 통계 → 런 선택 → 쉬는 시간 또는 대기실·리허설 → 대기실 탐색 · 리허설 관찰**에서 전체 또는 한 플레이어를 선택한다. 기존 빌드의 기록에는 새 필드가 없다.

| 확인할 내용 | 실제로 기록·표시하는 것 | 해석할 때 주의할 점 |
|---|---|---|
| 이동·방문 | 기존 발자국에 현재 방과 몸 방향을 추가. 연속 표본에서 관측된 방의 변화를 방문으로 집계 | 문턱 통과 트리거가 아니다. 1초 사이에 통과한 방, 방 범위 밖, 정지 중 회전은 누락될 수 있다. 몸 방향은 카메라 시선이 아니다. |
| 단서 공개 | 플레이어별 공개 가능/불가능 상태를 최초 관측 및 변경 시 기록 | 이미 공개된 상태에서 들어왔다면 최초 공개 시각을 알 수 없다. 공개가 곧 발견은 아니다. |
| 단서 조사 | 조작 안내 대상 선택, 직접 열람·재열람, 닫은 사유와 시간, 숨은 면 발견. 팀원 열람은 개인 열람과 분리 | 안내가 선택됐어도 플레이어가 봤는지는 알 수 없다. 같은 앱 실행에서만 첫 안내 대상 선택부터 첫 열람까지 계산한다. 종료 기록이 없는 열람에는 시간을 붙이지 않는다. |
| 탐색 도구·장치 | 사용자의 수락/거절, 거리·도구·키·암호·선행 조건 등 사유, 누적 타격, 개방, 기물 획득·드롭·내구도 변화 | 요청이 호스트에 도달해야 거절 사유를 안다. 비밀번호 원문은 저장하지 않는다. 장치 개방과 개인 통과를 같은 사건으로 세지 않는다. |
| 외줄·인간 대포 리허설 | 회차·단계별 배치, 도착 판정, 낙하·복귀, 대포 중간 발판·반동, 가이드 ID, 투표 변경, 단계 통과·건너뛰기·포기 사유 | 개인 행동과 상태 관측은 따로 표시한다. 그네 학습 조건 달성과 물리적 발판 도착을 구분한다. 팀 과반 통과는 전원 학습 완료가 아니다. |
| 탈출 집결·전환 | 호스트가 정상 상태 플레이어의 구역 진입·이탈·재진입을 관측. 전환 시작, 플레이어별 실제 목적지 배치, 호스트 전환 완료, 출발 위치가 남아 있을 때의 전환 실패 | 사망·연결 종료를 구역 이탈로 간주하지 않는다. 전환 실패에는 임의 좌표나 예외 메시지를 넣지 않는다. |
| 추격·공연 해금·편성 | 기존 추격 시작·해제·잡힘, 오브제 발견, 공연 해금과 스케줄 변경 사건을 같은 런에서 확인 | 대상 해제가 언제나 도망 성공을 뜻하지 않는다. |

문서 제안 중 **독립 대기실 튜토리얼 완료, 가이드별 읽음·이해, 모든 안내의 종료 시각, 설계 경로별 이탈률, 전체 미도착·미조사 명단**은 일괄 산출하지 않는다. 게임에서 확정하지 않는 행동이나 미수집 구간까지 실패로 집계하지 않기 위해서다. 가이드 숨김은 실제 닫힘을 알 수 있는 집결 경로만 기록한다. 탐색 재개 시 전원 소지품·열쇠를 다시 복제하는 전체 스냅샷도 추가하지 않았다.

이동 주기는 기존 지시(대기실·탈출로 1초에 0.5m 이상, 공연 5초, 사건 시 별도 기록)를 유지한다. 이번 보강은 기존 위치 표본과 게임 판정에 연결했다. [실제 디스크 저장 비용과 측정 범위](m2-spatial-timeline.md), [공연·탈출로 항목별 적용표](m2-event-matrix.md).
