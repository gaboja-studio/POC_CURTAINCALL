# 설문 빌드와 통계 사용법

## 새 빌드를 만들 때
1. Unity 상단 **CurtainCall → 테스트 빌드 태그**를 연다.
2. **로그 수집**과 **0.1.0 설문**을 원하는 대로 체크한다. 둘 다 / 로그만 / 설문만 / 모두 끔이 가능하다. 기본은 둘 다 꺼짐이다.
3. **현재 설정 확인**으로 체크 상태와 버전을 확인한 뒤 빌드한다. 체크는 이 PC의 프로젝트별 다음 빌드에 적용된다. 팀원이 빌드한다면 그 PC에서도 체크해야 한다.
4. 설문은 Player Settings Version이 정확히 **0.1.0**일 때만 가능하다. 다른 버전에서 설문 태그를 켜면 빌드를 중단해 잘못된 설문 배포를 막는다.
5. 플레이어는 새 실행 파일로 플레이하면 된다. cmd 실행이나 개인별 로그 설정은 필요 없다. 로그 태그가 꺼져 있으면 기존 대기 로그도 전송하지 않는다.

| 로그 수집 | 0.1.0 설문 | 플레이 시 동작 |
|---|---|---|
| 켬 | 켬 | 로그 수집 + 설문 자동 열기 + 응답/플레이 기록 비교 |
| 켬 | 끔 | 로그 수집만 |
| 끔 | 켬 | 설문만. 응답은 보이지만 행동 로그 비교는 없음 |
| 끔 | 끔 | 둘 다 실행하지 않음 |

## 언제 브라우저가 열리나요?
- 첫날 밤: 본인이 1일차 밤 정비 대기실에 처음 들어왔을 때. 호스트와 참가자 각 PC에서 각자 열린다.
- 게임 종료: 런을 플레이한 뒤 본인이 ESC 메뉴에서 나가거나, 호스트 종료·연결 끊김으로 퇴장되어 시작 화면으로 돌아온 직후. 런을 시작하지 않은 로비 퇴장·창 강제 종료는 대상이 아니다. 각 참가자는 자신의 세션·플레이어 번호로 연결된다.
- **각 설문을 연 적이 있는지** PC의 사용자 캐시에 저장한다. 제출 여부를 게임에서 확인하는 방식은 아니다. 창만 닫아도 다음 런에서 다시 자동으로 열리지 않는다.
- 같은 PC 사용자라면 빌드 폴더·런·익명 로그인 값이 바뀌어도 다시 열리지 않는다. 이전 빌드의 열림 기록도 유지한다. 다른 PC·운영체제 사용자·캐시 초기화 후에는 다시 열릴 수 있다.
- 빌드를 다시 만들거나 같은 PC에서 게임을 재시작하는 것만으로 캐시는 초기화되지 않는다.

## 캐시를 지워 다시 확인하기
Unity에서는 재생을 모두 멈추고 **CurtainCall → 설문 캐시 초기화 → 기본 플레이어만 / MPPM 보조 플레이어 포함**을 사용한다. 0.1.0 두 폼의 열림 표시만 지우고 로그·대기 배치·Google 응답은 보존한다. 같은 PC 저장공간을 공유하는 빌드에도 적용된다. 아래는 수동 방법이다.

1. 게임을 종료한다.
2. 현재 프로젝트는 `%USERPROFILE%\AppData\LocalLow\DefaultCompany\POC_CURTAINCALL\TelemetryPipeline\SurveyCache`다. 회사명·제품명을 바꿨다면 Unity Player Settings 값에 따라 경로도 바뀐다.
3. 이 **SurveyCache 폴더만** 지운다. 옆의 로그 파일은 지우지 않는다.
4. MPPM 보조 플레이어는 `TelemetryPipeline\clients\<구분값>\SurveyCache`에 따로 보관한다.
5. 설문 태그가 켜진 0.1.0 빌드로 다시 해당 시점까지 플레이한다.

## 설문과 플레이 기록은 어떻게 연결되나요?
- 두 폼의 **플레이 기록 연결 코드 (자동입력)** 질문에 게임이 값을 채운다. 버전·TEST/LIVE·세션·플레이어 번호가 들어 있어 색상이나 방코드로 추측하지 않는다.
- 연결 코드는 편집 가능한 단답 질문이므로 응답자가 값을 고칠 수 있다. 이 코드는 분석용 연결이며 본인 인증 수단은 아니다. 고치지 않도록 질문 설명을 유지한다.
- 기존 방코드·색 질문은 그대로다. 자동 연결에는 사용하지 않는다. 제거하거나 선택 질문으로 바꾸는 작업은 설문 소유자가 직접 판단한다.
- 연결 코드가 없는 과거 응답은 원본 응답 시트에 남는다. 버전·환경을 알 수 없으므로 선택 통계에 섞지 않고 동기화 안내에 건수만 표시한다.

## 응답은 어디에 쌓이나요?
1. 플레이어가 Google Forms에서 **제출**하면 각 폼에 연결한 기존 응답 시트에 즉시 저장된다.
2. 대시보드 **지금 갱신** 또는 **30분 자동 갱신** 때 두 응답 시트를 읽는다. 폼이나 원본 응답은 수정하지 않는다.
3. 기존 로그 시트의 **설문 응답 / 설문 통계 / 설문 동기화** 탭을 업데이트한다. 같은 연결 코드가 중복 제출되면 첫 행만 집계한다.
4. 두 원본을 모두 읽은 뒤 중앙 내용을 교체한다. 원본 읽기가 실패하면 이전 스냅샷을 유지하고 화면에 실패 안내를 표시한다.
5. 중앙 설문 응답은 최대 10,000건(폼별 5,000), 화면 응답 목록은 100개씩이다. 한도에 닿으면 실패를 표시한다.

## 대시보드에서 읽는 순서
1. 상단 **환경·게임 버전**을 고르고 맨 아래 **설문 통계**로 내려간다. 에디터/Development Build는 검증용 TEST, 일반 빌드는 실제 LIVE다.
2. **첫날 밤 / 게임 종료** 탭 → 필요하면 세션 검색·드롭다운과 플레이어를 고른다.
3. 문항별 선택 비율을 본다. 분모는 그 문항에 답한 사람 수다. 복수 선택은 합계가 100%를 넘을 수 있다. ‘플레이하지 않음’도 별도 답변으로 표시한다.
4. **응답 보기**로 실제 답변과 설문을 열 때까지 호스트가 기록한 사망 원인·절단·협동 횟수를 비교한다. 서술형은 응답별로 읽는다.
5. ‘플레이 로그 없음’은 아직 로그가 도착하지 않았거나 설문만 켠 빌드일 수 있다. 응답 없음·0점·플레이 성공으로 해석하지 않는다.
6. PC 시계가 다르면 설문 시각 전후 비교가 어긋날 수 있다. 캐릭터 색이나 계정명으로 다른 세션에 억지로 맞추지 않는다.

## 삭제와 권한
- 기존 관리자 인증과 등록 멤버 조회 권한을 그대로 쓴다. 응답 시트 자체를 팀원에게 공유할 필요는 없다.
- 버전 클리어·세션 삭제에는 해당 중앙 설문 응답도 포함되며 미리보기에 건수가 나온다. 원본 Forms 응답은 유지한다.
- 삭제 규칙이 재가져오기를 막으므로 원본 시트에 응답이 남아 있어도 대시보드에서 부활하지 않는다.
- 설문 원본까지 삭제하려면 폼 소유자가 직접 관리한다. 이번 구현은 관리자 폼 2개를 수정하지 않는다.
