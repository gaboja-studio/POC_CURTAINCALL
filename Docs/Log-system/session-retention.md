# 세션 요약·상세 보관

## 운영 기준
- LIVE 상세는 마지막 사건 이후 30일, TEST는 7일 보관한다. 새 기록 수신 후 48시간 동안은 정리하지 않는다.
- 수신 대기 원본이 남았거나 대기 개수를 확정하지 못했으면 기간 정리를 유예한다. 강제 종료처럼 종료 이벤트가 없어도 장기 미활동 세션은 정리 대상이다.
- 세션 전체를 요약한 뒤 상세를 정리한다. 성공/실패·사망 원인·거리·자금·이용률·소요 시간의 표본 수와 평균을 보존한다. 환경·게임 버전을 섞지 않는다.
- 설문 응답은 삭제하지 않는다. 응답 시점의 플레이어별 사망·부상·상호작용 연결에 필요한 최소 요약도 유지한다.
- 상세 기간이 지난 세션을 선택하면 타임라인에 보관 종료를 안내한다. 전체 통계와 자금 그래프·설문은 계속 사용할 수 있다.

## 저장·갱신
- `session-store.gs`: 세션별 상세 JSON과 요약 체크포인트를 기존 비공개 캐시 폴더에 저장한다. `cc-session-*`, `cc-sessions-*` 파일은 대시보드 임시 캐시 정리와 별개다.
- `Events`의 마지막 처리 행 다음부터 읽고, 새 기록을 받은 세션만 재계산한다. 변경 없는 세션은 기존 요약을 합산한다. 원본 중복 검사·설문 동기화까지 전부 증분화한 것은 아니다.
- 첫 전환은 10세션마다 진행 위치를 저장한다. 90초를 넘으면 다음 갱신에서 이어가며, 전환이 끝나기 전에는 이전 완료 화면을 유지한다.
- 원본 적재는 최대 100묶음/90초, 상세 저장본 대조는 30초, 원본 정리는 15초 단위로 나누어 다음 갱신에서 이어간다. 이 수치는 작업 단계의 제한이며 Google 호출 하나의 응답 시간을 보장하지는 않는다.
- `세션 요약` 탭에 환경·버전·런·보관 상태·사건/공연/성공/사망 수와 상세 파일 링크를 표시한다.
- Events가 50,000행을 넘으면 체크포인트에 포함된 앞쪽 최대 25,000행 중 **Drive 저장본을 다시 읽어 전체 행 내용이 정확히 일치한 행만** 시트에서 옮긴다. 상세 파일에는 보관 기간 동안 원래 사건이 남는다. 누락·불일치·새 도착 행은 건드리지 않는다.
- 영수증은 유지하며, 시트에서 옮긴 사건도 세션 파일과 비교하여 중복·충돌을 검사한다. 시트 정리가 중단되면 다음 실행에서 체크포인트와 사건 ID로 복구한다.
- 상세 파일의 이전 판본과 기간이 지난 파일은 휴지통으로 이동한다. 영구 삭제/휴지통 비우기는 하지 않는다.
- 참조되지 않는 이전 상세 저장본도 7분의 보호 시간을 두고 회당 최대 100개씩 휴지통으로 옮긴다. 원본 묶음의 모든 사건이 기간 정리된 경우 해당 원본도 적재 영수증 확인 후 정리한다.

## 처리 상태와 예외
- 화면 상단: 진행 단계, 이번에 반영한 세션 수, 상세/요약 세션 수, 원본 전송 묶음 대기 수, 보관 기간.
- 대기 수는 사건 수나 플레이어 수가 아니다. 제한 시간 안에 폴더 전체를 세지 못하면 ‘최소’ 수량으로 표시한다.
- 보관 종료 후 새로 도착한 사건은 기존 요약에 임의로 더하지 않는다. Events·원본에 남기고 ‘별도 확인 대기’로 표시한다. 상세가 이미 정리된 세션의 완전한 재집계는 원본 확보 후 운영자 복구가 필요하다.
- Google 용량/실행 제한이 사라지는 것은 아니다. 세션 요약·영수증·설문도 장기적으로 증가하므로 대규모 운영에는 추가 분할이 필요하다. 실패 시 이전 완료 화면을 유지한다.

## 타임라인 인원
- 공연에 기록된 참가자 목록을 사건 표시 개수와 분리한다. 진행 거리만 남은 참가자도 목록에 표시한다.
- 최대 400개 도식 사건은 플레이어별로 나누어 선택한다. 시작/마지막 지점과 사망·부상을 우선하며 호스트 사건이 다른 플레이어를 밀어내지 않는다.
- ‘시작 인원’은 해당 공연 시작 이벤트 값이며 ‘기록 확인’은 실제 슬롯이 확인된 인원이다. 둘이 다르면 미수신 가능성을 안내한다. 실제로 없는 참가자·좌표를 만들거나 다른 런의 기록을 합치지 않는다.
