## 사건 정확도
- 부상은 PlayerCondition.Changed를 구독해 같은 프레임의 연속 변경도 보존한다. 초기 상태 동기화는 절단으로 세지 않는다.
- 사망/절단은 원천 콜백 시점의 위치·손실 수를 붙잡고 기록한다. 톱/불 콜백과 같은 프레임일 때 원인을 결합한다.
- 외줄 attemptId는 Results의 공유 UUID를 D 형식으로 정규화한다. 공용 대포는 PerformanceIdentity에서 공유 UUID를 만든다.
- 거리 최댓값은 매 프레임 관측, 5초 간격/종료에 발행한다. 강제 종료·프레임 사이 왕복은 마지막 표본 이후 결손 가능.
- 기물 이동은 복제 스냅샷 차이다. 최초 상태·같은 상태 재수신·사라졌다가 나타난 UID를 입력 사건으로 꾸미지 않는다.
- 실패는 실제 판정 분기의 SHOP_*/CARRY_*/EXPERT_* 코드로 기록한다. 같은 거절을 반복하면 각각 기록하며 UI 안내 문구는 수집하지 않는다. source에 따라 operation·orderId/itemUid를 보존한다.
- 원천의 추가 관측 이벤트는 구독자별 예외를 격리한다. 원래 성공/거절 결과·UI 문구·가격·네트워크 판정은 그대로다.
- 대포 구간 ID는 Departure/First/Shelter/Second/Final의 enum+1이다. 임의 기본 경계를 복제하지 않고 실제 컴포넌트 설정을 조회한다.
- 열기→거래는 screenFlowId, 주문→운반→보관은 roomId+주문 번호의 flowId로 연결한다.
- 미수집을 수치 0/목표 미도달 false로 추정하지 않는다.
- 방별 구역은 CameraViewZone+BoxCollider를 읽기만 한다. Zone_Dormitory/Restroom/PropRoom/JunkStorage/Corridor/ExpertRoom의 기존 이름 계약을 사용하며 회전·스케일·비활성 상태를 반영한다. 시점 유지용 exitPadding은 체류 구역을 확장하지 않는다.
- STORAGE_REACHED는 같은 flowId로 수령→도착→보관을 연결한다. 내려놓기/재줍기는 첫 수령 시각 유지, 다른 플레이어에게 인계/보관/씬 종료는 운반 관측을 닫는다. 재방문은 최초 도착을 중복 기록하지 않는다.
- 공연 시작/이탈·구간·부상·점프·협동·대포·실패 사건에 좌표가 없으면 Emit 시 실제 플레이어 위치와 positionSource=EMIT_OBSERVATION을 추가한다. 원천이 이미 붙인 좌표/명시적 null은 덮지 않는다. 이는 연속 궤적 수집이 아니며 과거 데이터의 좌표를 복원하지 않는다.
