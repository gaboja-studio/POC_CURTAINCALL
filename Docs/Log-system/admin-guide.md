## 멤버 추가·이름 변경·차단
1. 관리자 계정으로 접속 → 상단 ‘관리자 · 보관 / 멤버 / 기록 삭제’를 연다.
2. 새 이메일·표시 이름·사용 허용을 입력하고 ‘멤버 저장’을 누른다.
3. 기존 멤버는 ‘편집’을 누른 뒤 이름을 바꿔 저장한다. 같은 이름을 여러 사람이 써도 이메일은 다르게 구분한다.
4. 접근을 막으려면 편집 → ‘사용 허용’ 해제 → 저장. 그 멤버의 다음 조회부터 차단된다.
5. 소유자를 차단하거나 다른 사람에게 관리자 권한을 주는 기능은 제공하지 않는다. Drive 폴더·원본 시트를 공유할 필요는 없다.

## 원본은 왜, 언제 지우나요?
- 기본 한도: 원본 폴더에 최신 1,000개. 관리자 화면에서 자동 정리 여부와 최대 개수를 1~10,000개로 바꾼다.
- ‘지금 갱신’ 또는 30분 자동 갱신 때 시트 적재가 확인된 파일부터 오래된 순으로 휴지통에 보낸다. 한 번에 최대 100개를 정리한다.
- 시트에 아직 들어오지 않은 파일·내용 검증이 안 된 파일은 보호하므로 일시적으로 한도를 넘을 수 있다.
- 원본을 정리해도 Events와 통계는 유지된다. 다만 원본 재처리·정밀 오류 조사 자료는 줄어든다.
- 휴지통 파일도 용량을 차지하며 30일 뒤 영구 삭제된다. 당장 공간이 필요하면 소유자가 Drive 휴지통을 확인한 뒤 직접 비운다. 자동으로 휴지통을 비우지는 않는다.
- 적재 영수증(Batches)은 보존한다. 이미 처리한 게임 기록이 재전송돼도 원본을 다시 만들지 않는다.

## 버전 전체 클리어
1. 상단 환경과 게임 버전에서 대상을 고른다.
2. 관리자 메뉴 → ‘선택 버전 클리어’를 누른다. **현재 선택한 환경·버전만 대상**이다. TEST를 선택했다면 LIVE 기록은 유지된다.
3. 화면의 버전·사건 수·세션 수·TEST/LIVE 건수를 확인한다. 이 단계에서는 지워지지 않는다.
4. ‘관리자 이메일로 인증번호 받기’ → ourhosu@gmail.com으로 받은 8자리 번호를 입력한다.
5. 확인 문구에 ‘삭제’를 정확히 입력 → ‘확인한 기록 삭제 실행’.

## 특정 세션만 지우기
1. 상단에서 환경과 게임 버전을 고른다.
2. 관리자 메뉴의 세션 목록에서 삭제할 항목을 체크한다. 여러 개를 선택하거나 현재 목록 전체를 선택할 수 있다.
3. ‘선택 세션 삭제’ → 범위와 건수 확인 → 관리자 이메일 인증 → ‘삭제’ 입력 → 실행.
4. 이 경우 선택 환경·버전·세션만 지우며 나머지는 유지된다.

## 삭제 후 알아둘 점
- Events에서 제거하고 통계를 다시 계산한다. 적재가 확인된 관련 원본은 휴지통으로 옮긴다. 여러 세션이 한 파일에 섞여도 다른 세션의 시트 기록은 보존한다.
- 재전송 방지용 삭제 관리 이력과 Batches 영수증은 남긴다. 삭제한 세션의 늦은 기록도 차단한다.
- 버전 클리어는 선택 환경·버전의 확인 시각 이전 사건을 지운다. 같은 버전으로 이후 새 플레이는 다시 쌓인다. 게임 PC의 시계가 맞아야 과거/신규 시각 구분이 정확하다.
- 미적재 원본은 다음 갱신에서 남겨야 할 기록을 적재한 뒤 정리한다. 도중 오류가 나도 삭제 규칙으로 조회를 차단하고 다음 갱신에 정리를 이어간다.
- 잘못 지웠다면 게임과 갱신을 잠시 멈추고 개발자에게 요청한다. 휴지통의 원본만 복원해도 통계가 자동 복원되지는 않는다. 삭제 규칙·영수증까지 고려한 별도 복구가 필요하다.

## 게임 버전 변경
1. Unity에서 Edit → Project Settings → Player를 연다.
2. Version 값을 예를 들어 0.1.0 → 0.1.1로 바꾼다. 숫자 세 덩어리 형식을 사용한다.
3. 새 PC 빌드를 만든 뒤 모든 테스트 PC에 같은 새 빌드를 전달한다. 예전 실행 파일은 예전 버전으로 기록된다.
4. 새 빌드로 방을 만들어 플레이하고 업로드를 기다린다.
5. 대시보드 ‘지금 갱신’ → 새 버전 선택. 서버 코드나 시트 이름을 바꿀 필요는 없다. 과거 기록의 버전도 바뀌지 않는다.

## 개발자용 제한과 근거
- Session.getActiveUser는 execute-as-owner의 외부 Gmail 이메일을 보장하지 않아 등록 메일 OTP를 쓴다. https://developers.google.com/apps-script/reference/base/session
- 메일 전송 권한만 추가하며 메일함 읽기 권한은 사용하지 않는다. https://developers.google.com/apps-script/reference/mail/mail-app
- 휴지통의 용량·30일 정책: https://support.google.com/drive/answer/2375102
- 수신 배포는 dashboardEnabled=false, 웹 화면 배포는 true. 두 버전 모두 새 삭제/영수증 로직 필요. node Scripts/Telemetry/prepare-deployment.cjs로 소스를 준비한다.
