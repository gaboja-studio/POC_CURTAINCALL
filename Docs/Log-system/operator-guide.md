# 기획자용 로그·대시보드 사용 안내

**최신 기획자 안내는 [하네스 운영 안내](../../Harness/Project/Guides/Log-system/index.md)에 있습니다. Windows·Mac 검증/빌드, 관리자/팀원 접속, 새 달력·자금 구간 보기까지 화면 순서로 설명합니다.**

2026-10-22 기준. 현재 게임 버전은 **0.1.0**이다. [통계 읽는 법](reading-guide.md), [로그/설문 빌드 태그와 설문 사용법](survey-guide.md)도 참고한다. 새 빌드는 Unity의 **CurtainCall → 테스트 빌드 태그**에서 로그 수집을 체크해야 로그가 쌓인다. 기본은 꺼짐이다.

## 1. PC를 켜고 대시보드 열기

1. Chrome에서 등록된 계정으로 접속한다. 이메일 인증 화면이 나오면 등록 이메일로 인증번호를 받아 입력한다. 관리자는 **ourhosu@gmail.com**이다.
2. [CURTAINCALL 대시보드](https://script.google.com/macros/s/AKfycby1UfzhOaNl9ycjKYATPF-b32AkSskzupKQ--Zxj3Z_eIKraOqy9Aw1PYYLkqKewJ_wqw/exec)를 연다. 즐겨찾기에 저장하면 다음부터 바로 열 수 있다.
3. 상단에서 **환경**과 **게임 버전 0.1.0**을 고른다.
4. **지금 갱신**을 누르고 ‘갱신 완료’와 최근 갱신 시각을 확인한다.

기존 기록을 볼 때는 브라우저와 인터넷만 필요하다. Unity·Unity Hub·Codex·Pipeline을 켜 둘 필요가 없다.
Google 쪽에서는 30분마다 자동으로 적재·집계한다. PC나 대시보드를 꺼도 이미 Google에 올라간 기록은 처리된다.
‘지금 갱신’은 Google에 도착한 기록을 가져오는 버튼이다. 꺼진 게임 PC의 미전송 기록까지 가져오지는 못한다.

## 2. 환경 선택하기

| 실행한 게임 | 대시보드 환경 |
|---|---|
| Unity에서 재생 버튼을 누른 경우 | 검증용 데이터(TEST) |
| 개발 검사용 빌드(Development Build) | 검증용 데이터(TEST) |
| 일반 빌드 | 실제 플레이(LIVE) |

사람이 직접 플레이했더라도 Unity나 개발 검사용 빌드라면 TEST에 들어간다. 플레이 의도로 구분하는 메뉴가 아니다.
TEST에는 자동 검사로 만든 기록도 섞여 있다. TEST 통계를 실제 이용자의 성적이나 밸런스 근거로 사용하지 않는다.
‘버전 미기록’은 버전 기능을 넣기 전의 과거 기록이다. 0.1.0과 섞지 않는다.

## 3. 새 플레이 기록 쌓기

1. **이번 로그 기능이 들어 있는 게임**을 실행한다. 예전에 받은 실행 파일에는 기능이 없을 수 있으므로 개발자에게 확인한다.
2. 평소처럼 시작 화면에서 방 입장·런 시작·공연·대기실 이용을 진행한다. 기록 버튼을 따로 누를 필요가 없다.
3. 확인할 행동을 한 뒤 게임이 실행되는 상태로 30~60초 정도 기다린다. 이는 확인을 위한 여유 시간이며 도착 시간 보장은 아니다.
4. 대시보드에서 맞는 환경·버전을 고른 뒤 **지금 갱신**을 누른다. 플레이 중 대시보드를 열어 둘 필요는 없다.

이 PC의 현재 Windows 사용자에게는 전송 설정이 이미 저장되어 있다. PC를 다시 켤 때마다 비밀값을 입력하지 않는다.
이번 변경 이후 새로 만든 PC 빌드는 전송 설정을 포함한다. 플레이어는 cmd 실행·비밀값 입력 없이 게임만 실행하면 된다. 빌드 담당 PC에 설정이 없으면 빌드를 중단하므로 설정 없는 빌드를 실수로 배포하지 않는다. Unity 에디터에서 개발할 PC만 최초 전송 설정이 필요하다. 이미 배포된 예전 실행 파일은 새 빌드로 교체해야 한다.
게임 실행 PC는 대시보드 소유자의 Google 계정으로 로그인할 필요가 없다. 게임의 전송 설정과 대시보드 열람 권한은 별개다.

Unity로 확인할 때는 Unity Hub에서 `D:\github\POC_CURTAINCALL`을 열고, Project 창에서 `Assets/Scenes/Start_Lobby/Start.unity`를 열어 상단 ▶ 재생 버튼을 누른다.
관찰이 끝나면 재생을 종료한다. 게임 로그 수집 자체에는 Pipeline 서버가 필요하지 않다. 두 PC 공동 플레이 검증은 현재 보류 중이다.

## 4. 종료·오프라인 때의 동작

기록은 먼저 PC에 저장된다. 방 안에서는 참가자의 기록을 게임 연결로 호스트에게 전달하고, 호스트만 Google Drive로 전송한다. 참가자 PC는 Google 로그 API를 호출하지 않는다. 이후 시트에 누적되어 대시보드에 표시된다.
씬 이동·런 종료 등의 시점과 실행 중 주기적으로 전송할 기록 묶음을 만든다. 모든 사건이 즉시 화면에 뜨는 구조는 아니다.
인터넷이 끊기면 로컬 기록을 보관한다. 인터넷을 복구하고 **게임을 실행해 두거나 다시 실행**하면 재전송한다.
호스트 종료 직전 기록은 다음 실행에서 전송될 수 있다. 참가자가 호스트에게 전달하기 전에 나가면 자기 PC에 남으며, 같은 참가자 환경으로 방에 다시 접속해야 전달된다. 방을 만들지 않은 시작 화면 기록도 방 접속까지 보관한다.
현재 실행의 새 기록을 우선 보내고 예전 미전송 기록도 이어서 보낸다. 전송 실패·많은 기록이 있으면 30~60초보다 오래 걸릴 수 있다. Unity Console에서 `[Telemetry]`로 검색하면 ‘전송 대기 n묶음’과 ‘Drive 저장 확인’을 볼 수 있다. 대기 0을 확인한 뒤 대시보드를 갱신한다. 게임을 끄면 PC→Drive 전송도 멈춘다.
MPPM 보조 플레이어도 별도 큐에서 호스트에게 전달한다. 호스트가 저장 확인을 보내면 참가자 큐에서 지우며, 이후 Google 응답까지 호스트가 보관한다. 미전달 참가자 큐는 같은 MPPM 플레이어로 방에 다시 접속해야 전달된다.
강제 종료는 정상 종료 사건을 보장하지 않는다. 재전송은 같은 기록의 중복 적재를 막지만, 강제 종료 순간의 모든 사건을 복원하는 기능은 아니다.
미전송 기록이 사라질 수 있으므로 로그 폴더·원본 Drive 파일을 임의로 지우지 않는다.

## 5. 한 PC에서 간단히 확인하기

1. 대시보드의 환경·버전을 맞추고 현재 ‘수집 이벤트’ 수를 메모한다.
2. 로그 기능이 포함된 게임에서 시작 화면 진입 등 가능한 행동 몇 가지만 한다. 한 PC에서 불가능한 공동 플레이는 진행하지 않는다.
3. 게임을 켠 채 잠시 기다리고 **지금 갱신**을 누른다. 수집 이벤트 증가를 확인한다.
4. 런을 실제로 시작했다면 새 세션 ID를 선택하고, 타임라인에서 직접 했던 행동·순서·결과를 비교한다.
5. 단계별 시간은 해당 행동을 끝냈을 때 확인한다. 예: 구매 시작→구매 완료, 수령 가능→실제 수령. 대략적인 체감 시간과 대조한다.

시작 화면만 열면 이벤트는 늘어도 ‘총 플레이’는 늘지 않을 수 있다. 총 플레이는 실제 런 ID 수이기 때문이다.
한 사건의 로그를 다시 보내도 한 번만 쌓이는 검사는 이미 한 PC에서 완료했다. 새 플레이·종료 기록이 뒤늦게 도착하면 재갱신 때 총건수는 더 늘 수 있다.
문제가 있으면 **플레이 시각·실행 방식·버전·세션 ID·한 행동·기대한 결과·실제 화면**을 메모해 전달한다. 비밀값은 보내지 않는다.

## 6. 안 보일 때 먼저 확인할 것

| 증상 | 확인 순서 |
|---|---|
| 접근할 수 없음 | Chrome의 Google 계정이 ourhosu@gmail.com인지 확인 |
| 계속 로딩·빈 화면 | 새로고침 또는 Ctrl+F5 → 즐겨찾기로 다시 열기 → 계속되면 화면과 시각 전달 |
| 기록이 없음 | 환경(TEST/LIVE) → 버전 → 로그 기능이 들어 있는 게임인지 확인 |
| 방금 한 행동이 없음 | 게임과 인터넷을 유지하고 잠시 대기 → 지금 갱신. 종료 직전 기록은 게임 재실행 후 재확인 |
| 새 버전이 선택지에 없음 | 그 버전의 첫 로그를 전송하고 지금 갱신. 버전 번호는 개발자가 빌드 전에 설정 |
| 시간·미수령이 미수집 | 시작과 끝이 모두 관측됐는지 확인. 쉬는 시간 종료를 못 봤다면 미이용 확정도 못 함 |

보통은 대시보드만 사용하면 된다. 자세한 원본이 필요할 때만 [로그 시트](https://docs.google.com/spreadsheets/d/1KCLPn1tEW5qsK16jcw8swZ75IeN6p6lG_82zRUOg7I8/edit)와 [Drive 폴더](https://drive.google.com/drive/folders/1zLstjPM44i_aWO6hjvFfBcOSXdClrLAX)를 개발자와 함께 확인한다.
시트의 원본 행·ID를 직접 수정하거나 지워서 수치를 맞추지 않는다. 설치·배포 관련 내용은 [운영·설치](setup.md), 보류 항목은 [남은 작업](remaining-work.md)에 있다.

## 7. 새 타임라인 조작

검색창은 날짜·세션 ID로 목록을 좁히고, 바로 옆 세션 드롭다운은 목록을 열어 선택한다. 선택값을 지울 필요가 없다. 공연은 플레이어별 요약을 먼저 보고, 사망·절단·상호작용 아이콘에 호버해 사건 순서를 살핀다. 숫자는 플레이어별 발생 순서다. 휠 또는 ＋/−로 거리 간격을 늘리고 가로 스크롤로 이동한다. 클릭하면 하단 상세가 열리고 바깥을 클릭하면 닫힌다. 키·일반 버튼·마이크 입력은 분석 타임라인에서 숨기며 원본은 유지한다.
