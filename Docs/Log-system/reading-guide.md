# 기획자용 대시보드 읽는 법

먼저 **환경과 게임 버전**을 맞춘다. 현재 버전은 **0.1.0**이다. 사용 순서는 [사용 안내](operator-guide.md)를 참고한다.

## 1. 맨 위 숫자

| 표시 | 쉬운 뜻 | 해석할 때 주의 |
|---|---|---|
| 총 플레이 | 기록에서 확인한 런의 수 | 실행 횟수·이용자 수가 아님. 끝나지 않은 런도 포함 |
| 수집 이벤트 | 기록된 사건의 수 | 사람 수가 아님. 한 사람이 여러 사건을 만듦 |
| 공연 플레이 | 성공·실패 결과가 확정된 공연 수 | 아직 결과가 없는 공연은 제외 |
| 공연 평균 성공률 | 결과가 확정된 공연 중 성공한 비율 | 10번 중 3번 성공이면 30%. 중도 미확정은 분모에서 제외 |

‘미수집’·‘기록 없음’·‘—’는 판단할 기록이 없다는 뜻이다. 실제 실패 0회·소요 시간 0초와 다르다.
TEST에는 합성 검사 기록이 있으므로 실제 이용자를 분석할 때는 해당 빌드에서 수집한 LIVE 기록을 사용한다.

## 2. 묘기 통계: 어디서 어려워하는가

**외줄 타기 / 인간 대포** 탭을 골라 난이도 별 승률·사망 원인·상세 데이터를 함께 본다.
난이도는 1~3이 항상 표시된다. 아직 플레이하지 않은 난이도의 ‘미수집’은 정상이다.
사망 원인 도넛은 **발생한 사망끼리 비교한 비중**이다. 추락 60%라면 사망 기록 중 60%가 추락이며, 전체 플레이어의 60%가 추락했다는 뜻은 아니다.
평균 최대 거리는 각 플레이어가 각 시도에서 기록한 최대 도달 거리의 평균(m)이다. 왕복 이동량이나 팀원 거리의 합이 아니다.
상호작용 횟수는 확인된 사건을 센다. 버튼을 누른 횟수와 같지 않고, 손잡기를 오래 유지한 시간을 나타내지도 않는다.
승률이 낮고 특정 사망 원인이 많다면 그 구간의 실제 플레이를 먼저 살펴본다. 숫자 하나만으로 장애물 난이도를 바로 바꾸지 않는다.

## 3. 대기실 통계: 어디서 시간이 드는가

**이용 현황**은 공간별 방문·재방문·체류 및 이동·집결 시간을 확인하는 곳이다. 방문 수는 같은 사람의 재방문도 포함하므로 고유 이용자 수와 다르다.
**기물 · 서비스 이용**은 표와 원형 그래프로 전환할 수 있다. 이용 횟수와 이용률은 별개다.
이용률은 해당 환경·버전에서 대기실에 관측된 ‘런별 플레이어’ 중 실제 이용한 비율이다. 같은 사람이 다른 런에 참여하면 별도 표본이다.
**평균 소요 시간**에서 상점·운반 / 편성·준비 / 의료 / 시설 탭을 고른다. 평균과 함께 관측 건수·최소·최대를 본다.
시간은 시작과 끝이 모두 기록된 구간만 집계한다. 중도 포기 등으로 끝이 없으면 평균에서 빠질 수 있으므로 실패·미이용 기록도 함께 확인한다.
예: 수령 가능→실제 수령 시간이 길면 배송구를 못 찾았는지, 공연 준비로 바빴는지 타임라인으로 확인한다. 시간만으로 원인을 단정하지 않는다.
**실패 · 운반 기록**은 구매·수령·보관·서비스 실패 사유와 내려놓기·다시 줍기·인계 등을 보여 준다. 반복 시도는 여러 번 집계될 수 있다.
**미수령 · 의료 미이용**은 쉬는 시간이 끝날 때 남은 물건·입장하지 않은 예약을 확인한다. 취소·중도 이탈은 별도 표시한다.
쉬는 시간 종료를 관측하지 못한 사례는 미이용이라고 추정하지 않는다. 기록 없음이 반드시 전원 수령·전원 치료를 뜻하지 않는다.
치료 후에는 사지·이동·점프·소지 한도 설정의 복구 여부까지 기록한다. 실제 같은 길을 치료 전후로 걸은 속도 비교는 포함하지 않는다.

## 4. 런 통계: 한 판의 흐름을 따라가기

런은 방에서 시작한 한 번의 게임 진행이고, 세션 ID는 그 런을 구별하는 긴 번호다. 자금과 타임라인에서 같은 ID를 고르면 같은 판을 비교할 수 있다.
**일차 별 공동 자금**은 기본적으로 여러 런의 게임 일차별 평균 잔액이다. 현실의 월요일·화요일이 아닌 게임 속 1일차·2일차다.
런 ID를 검색·선택하면 그 런의 자금 변화만 꺾은선으로 표시한다. 점에 마우스를 올려 잔액·리워드·지출을 보고, ‘평균’ 버튼으로 돌아온다.
평균은 팀 자금의 합계가 아니다. 뒤쪽 일차에는 도달한 런만 남아 표본 구성이 달라질 수 있으므로, 이상한 변화는 개별 런으로 확인한다.
**런 세션 타임라인**에서도 세션 ID를 고른 뒤 일차와 공연·쉬는 시간·기타 기록 탭을 선택한다.
자금의 런 선택과 타임라인의 세션 선택은 서로 독립이다. 둘 다 같은 ID로 맞춘다. 선택해도 맨 위 전체 요약 카드까지 그 한 판으로 바뀌지는 않는다.

## 5. 공연 도식 조작하기

1. 타임라인에서 원하는 일차의 공연 탭과 **외줄 타기 / 인간 대포** 공연 카드를 선택한다.
2. 좌측은 출발 방향, 우측은 도착 방향이다. 플레이어마다 색이 다르고, 화면 번호는 플레이어 1~4다.
3. 아이콘에 마우스를 올리면 사건·결과 요약이 뜬다. 그 플레이어의 기록된 위치가 시간순으로 연결되고 다른 플레이어는 흐려진다.
4. 아이콘을 클릭하면 아래에 위치·상태·상호작용·장애물 등 자세한 내용이 고정된다. 다른 점은 선택 변경, 빈 곳 클릭이나 Escape는 해제다.
5. 브라우저가 좁으면 도식 안을 좌우로 스크롤한다. 대기실·기타 기록은 사건 목록 형태로 본다.

이 도식은 중요한 사건이 일어난 좌표를 연결한 것이다. 모든 순간을 촬영한 이동 기록이나 완전한 지도는 아니다.
오른쪽 끝의 점이 반드시 실제 도착점은 아니다. 관측된 좌표 범위로 보여 주며, 좌표 없는 사건은 ‘좌표 미수집’으로 따로 남긴다.
이동·부상·추락/사망·팀원 상호작용·사물 상호작용을 서로 다른 아이콘으로 표시한다. 서로 다른 PC의 아주 근접한 사건 순서까지 단정하지 않는다.

## 6. 처음 분석할 때의 순서

**같은 환경·같은 버전 → 관측 건수 → 전체 경향 → 같은 런의 타임라인 → 실제 플레이 확인** 순서로 본다.
예: 의료 이용률이 낮다 → 예약 자체가 적은지, 예약 후 미이용인지 구분 → 이동/입장 대기 시간과 실패 사유 확인 → 실제 플레이에서 이유 확인.
기록이 적을 때의 0%·100%는 결론이 아니다. 근거가 되는 공연 수·시간 관측 건수와 함께 메모한다.
현재 두 PC 공동 플레이 검증과 기획 결정 2개는 보류 중이다. 이 안내는 모든 실제 플레이 상황의 검증 완료를 의미하지 않는다. [남은 작업](remaining-work.md)을 참고한다.
