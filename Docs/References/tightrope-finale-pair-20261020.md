- 기존 Task 미배정 예외 및 수정 범위는 `tightrope-art-preparation-20261020.md`, `tightrope-art-cleanup-20261020.md`와 같다. 후속 사용자 요청 “저장하고 제출해줘”에 따라 아래 제출 기록을 추가했다.

## 변경

- 출발 표시에서 실제 2~4인 목마를 승인한다. 방에 4명이 있어도 2명이 협동하면 통과 가능하다. 혼자는 승인하지 않는다.
- 도약 전에는 기존 목마에 3·4번째 인원이 합류하면 승인 명부를 확장한다. 누군가 떠난 뒤에는 다른 목마로 명부를 덮거나 줄이지 않는다.
- 승인 당시 2층이 뒤 발판을 밟고, 3·4층이 있는 경우 먼저 건너 버튼을 피해 대기하는 기존 순서를 유지한다.
- 참가자의 관문 스냅샷 검사도 2~4명을 허용한다. 1명·범위 밖 인원·호스트 이외 송신은 거절한다.
- HUD와 조작 안내에서 ‘4명 필수’를 제거한다. 저장된 에셋 참조를 보존하기 위해 `finaleFourStackRequired` 및 공개 FourStack 속성 이름은 호환용으로 유지하고 설명을 수정했다.
- 마지막 관문을 해제하고 톱 도약이 끝나야 완주를 인정하는 검사는 유지한다. 단독 자동 개방, 난이도·톱 크기·화재 수치는 변경하지 않는다.
- 실제 멀티플레이 입력 검사기는 두 캐릭터가 서로 앞을 막고 집결하지 못하지 않도록, 가까우면 먼저 목마를 만든 다음 출발 표시로 이동한다.

## 검증 기록

- 아래 검사 결과는 실제 별도 클라이언트 검사와 합성 위치를 사용하는 회귀 테스트를 구분해 기재한다.
- 신규 회귀 테스트 초기 준비 실패: 공연 시작 직후 아직 줄에 오르지 않아 화재 계획이 준비되지 않았다. 먼저 줄에 올라 공연 타이머가 시작된 뒤 준비하도록 수정했다.
- 신규 PlayMode PASS: 4개 참가 캐릭터가 있는 회귀 환경에서 2인 승인, 3·4층 확장, 2~4인 승인 스냅샷 복원, 1인/비호스트 패킷 거절, 출발 후 명부 유지, 초기화 확인. 위치·접속 대역을 사용하는 검사이며 실제 네 프로세스 통신을 뜻하지 않는다.
- 검사 준비에서 화재 컴포넌트를 비활성화하면 내부 Run 연결도 해제되어 소각 계획 조회가 불가능했다. 컴포넌트는 켜고 해당 검사 회차의 추격 불만 끄는 방식으로 고쳤다. 저장된 화재 에셋은 수정하지 않았다.
- 기존 CooperativeGate 회귀 6개 중 5개 PASS. 나머지 1개는 교체 전 임시 톱의 `Tooth0` 이름을 기대했다. 준비 에셋이 있으면 실제 연결된 원판 메시를 사용하는지 검사하도록 갱신하고 재실행했다. 기존 지름·두께·옆줄 통과·혼자 점프 거절 검사 항목은 유지한다.
- 보정한 기존 관문 검사 1/1 PASS. 관련 PlayMode는 신규 1개 + 기존 6개 모두 PASS(실패했던 항목만 재검사). 컴파일 및 verify-fast PASS. Task 부재로 정식 구역 검사는 PASS로 표기하지 않는다.
- 실제 2인 MPPM `pair1`: 호스트/참가자 별도 프로세스, owner0/1, LAN17921. 출발부터 봉 교대·공중그네·최종 관문까지 가상 키보드로 진행했다. 순간이동, 무적, 강제 승인, 강제 발판 작동, 부상 복구는 사용하지 않았다.
- 호스트에서 약155.73m에 2인 목마 승인 → 위층 도약 → 뒤 발판 → 톱 도약 → 아래층 통과를 기록했다. 양쪽에서 RequiredStackSize=2, 승인 층1/2, AreRequiredGatesCleared=true, Run=Succeeded, 참가2명을 확인했다.
