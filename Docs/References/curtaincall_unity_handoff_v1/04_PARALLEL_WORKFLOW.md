# 병행 작업 규칙

## 작업 소유

리소스 제작 채팅은 원본 PNG·그래픽 토큰·9-slice·리소스 명세·묶음용 에디터 조립 코드를 관리한다. Unity 적용 채팅은 실제 프로젝트의 씬·Prefab·게임 연결 어댑터·입력·상태 전환을 관리한다. 같은 공용 파일을 서로 다른 방향으로 동시에 수정하지 않는다.

적용 채팅은 원본 조립 코드에 오류를 찾으면 파일명·재현 조건·수정 제안을 제작 채팅에 전달한다. 현재 프로젝트에서 필요한 연결 코드는 해당 프로젝트에서 작성할 수 있다. 그래픽 규격을 바꾸는 수정은 제작 버전에 반영한 뒤 공유한다.

## 리소스가 도착할 때마다

1. 제작 채팅: 해당 묶음 ZIP, 신규/수정/재사용 목록, 누적 리소스 표, 적용 변경 요약을 제공한다.
2. 사용자: ZIP과 적용 변경 요약을 Unity 채팅에 첨부하거나 내용을 복사한다.
3. Unity 채팅: 현재 사용하는 파일과 버전·경로를 비교하고 필요한 씬만 갱신한다. `.meta`와 기존 참조를 보존한다.
4. Unity 채팅: 실제 적용 결과와 남은 항목을 기록하고 그래픽 수정이 필요한 경우에만 제작 요청을 돌려준다.
5. 제작 채팅: 한 묶음씩 사용자의 시각 피드백을 받는 기존 절차를 유지한다.

새 채팅이 이전 채팅의 로컬 경로를 자동으로 읽거나 변경을 실시간 수신한다고 가정하지 않는다. 인계 패키지와 묶음별 전달문이 공유 기준이다.

## 상태를 두 축으로 기록

| 축 | 예시 상태 |
|---|---|
| 아트 | 제작 대기 / 전달·검토 중 / 사용자 확정 / 수정본 검토 중 |
| 프로젝트 적용 | 미착수 / 배치 / 데이터 연결 / 컴파일 확인 / Play 확인 / 남은 오류 |

그래픽 확정만으로 씬 적용 완료를 표시하지 않는다. 임시 그래픽으로 연결을 마쳤다고 그 그림을 승인본으로 바꾸지 않는다.

## 현재 출발점

- 아트: 고유 PNG 145개, 확정 137개, 타이틀 신규 8개 검토 중.
- 이 채팅 다음 제작 대상: C14 설정 창 및 탭·슬라이더·토글.
- 적용 채팅 첫 작업: 공통 Canvas 확인 후 공연 C1·C2·C3·P1.
- 실제 프로젝트 버전·씬·입력·네트워크는 새 채팅에서 확인.
- 자동으로 두 채팅이 연결되거나 새 채팅이 생성된 상태는 아니다. 새 채팅에 인계 패키지와 시작 지시문을 전달해야 한다.
