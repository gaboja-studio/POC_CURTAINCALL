# 씬·상태별 적용 계획

아래 이름은 논리 화면명이다. 실제 `.unity` 씬 이름·개수·로드 구조는 프로젝트를 읽은 뒤 대응시킨다. 순서는 이번 병행 작업을 위한 권장 순서이며, 기존 그림의 승인 여부나 개발 완료를 뜻하지 않는다.

## 권장 적용 순서

| 순서 | 화면/상태 | 사용할 UI | 지금 할 일 | 후속 그래픽 의존 |
|---|---|---|---|---|
| 0 | 공통 기반 | 공통 Canvas, TMP, 정렬 그룹 | 기존 구조 확인, 폰트·스케일·레이어·입력 소유 정리 | 없음 |
| 1 | 공연 기본 | C1·C2·C3·P1 | 확정 좌표로 조립, 점수·시간·진행도·균형 연결 | 없음. 시작 ZIP 2개 동봉 |
| 2 | 공연 사건 | C8·C10·C7·C9 | 추락 배너, 환호/야유, 가이드·자막 큐와 우선순위 | 없음. 해당 ZIP 추가 필요 |
| 3 | 공연 메뉴·관전·전환 | C13·확인창·C11·C16 | 메뉴 입력, 관전 전환, 씬 로드/준비 신호 연결 | 없음. 해당 ZIP 추가 필요 |
| 4 | 대기실 | W1·C4·C5·W6·C6·C15·월드 라벨 | 탐색·자금·소지·집결·근접 표시 연결 | W2/W3 전용 판은 추후 추가 |
| 5 | 타이틀·로비 | T1/T2/T3·L1·공용 버튼 | 생성/참가/LAN/설정/종료와 방 정보 연결 | 타이틀 신규 그림 8개 피드백 대기 |
| 6 | 설정 | C14·탭·슬라이더·토글 | 프로젝트 설정 데이터와 저장/적용 정책 확인 | 다음 제작 묶음 수령 후 배치 |
| 7 | 구매·스케줄·결과 | W2·W3·C12 | 품목·일정·결과 데이터 모델과 연결 경계 준비 | 전용 그래픽 도착 후 교체·확인 |

각 단계 안에서도 준비된 부분부터 진행한다. 예를 들어 대기실의 구매 패널 전용 그림이 아직 없더라도 W1·C4·C6 적용은 가능하다. 임시 배치가 필요하면 기존 공용 판과 TMP/Unity 기본 요소를 쓰고 작업 기록에 임시임을 표시한다. 이를 최종 그래픽 리소스로 등록하지 않는다.

## 첫 화면에서 제공할 개발 가이드

1. 실제 씬/Prefab과 논리 화면의 대응.
2. 사용 ZIP 버전, PNG 상대 경로, 누적 목록 기준.
3. Canvas와 각 오브젝트의 부모·Sibling 순서.
4. Anchor min/max, Pivot, anchoredPosition, sizeDelta, Image Type, border, tint/alpha.
5. TMP fontAsset, 굵기, 크기, 정렬, 숫자·문구 바인딩.
6. 표시/숨김 조건, 하단 슬롯 우선순위, 메뉴와 플레이 입력의 관계.
7. 게임 데이터의 원천·단위·주기와 UI View에 연결할 실제 메서드/이벤트.
8. 프로젝트에서 확인한 컴파일·Play·상태 전환 결과, 미실행 항목.

## 공연의 연결 책임

| UI | 게임 쪽이 소유할 값/사건 | UI 쪽 표시 책임 |
|---|---|---|
| C1 | 단원 식별/순서/점수, 공연 정원 최대값, 추락 사건 | 누적 구간 링, 합계 TMP, 사건 직전 구간 강조 |
| C2 | 권위 있는 공연 남은 시간 | 시계/숫자, 마지막 30초 경고 등 전달 규칙 |
| C3 | 경로 길이, 단원별 진행 거리, 추격 불, 추락/최대 도달 위치 | 트랙과 마커 위치·색·경고 |
| P1 | 로컬 플레이어 외줄 여부, 균형값, 위험 체류값 | 외줄 위에서만 표시, 구간/바늘/체류 표시 |
| C8 | 시작·추락·소집 같은 시스템 사건 | 배너/토스트의 큐와 노출 시간 |
| C10 | 단원과 변화량, 환호/야유 사건 | 효과 조각+TMP, 중복/과다 표시 관리 |
| C11 | 로컬 생존/관전 상태, 관전 가능 대상, 선택 대상 | 가장자리 효과, 관전 대상·키 표시 |
| C16 | 씬 로드 상태, 필요한 참가자 준비 여부 | 커튼 닫힘/열림·로딩 표시. 실제 전환 정책은 게임 소유 |

프로젝트가 이미 쓰는 네트워크·이벤트 구조를 먼저 확인한다. 새 네트워크 프레임워크나 임의 RPC를 이 문서만으로 도입하지 않는다. 입력·월드 감지·타이머·점수의 권한은 기존 게임 구조에 맞춰 연결한다.

## 첫 화면 확인 기준

- 2/3/4인 데이터에서 C1 합계와 링 구간이 맞고, 일반 추락 때 capacity가 생존자 수로 축소되지 않는가.
- C2·C3가 가장자리에서 읽히고 중앙 플레이 영역을 가리지 않는가.
- P1이 외줄 밖에서는 숨겨지고, 관전 시 하단 영역을 양보하는가.
- 어두운 무대와 밝은 조명 앞에서 숫자·마커가 읽히는가.
- 실제 연결된 값의 단위와 좌표가 UI가 기대하는 단위와 일치하는가.
- 메뉴·대사·상호작용 추가 뒤에도 상단 핵심 HUD가 유지되는가.

이 목록은 앞으로 프로젝트에서 수행할 확인 기준이다. 인계 파일 작성 시점에 통과한 엔진 테스트 결과가 아니다.
