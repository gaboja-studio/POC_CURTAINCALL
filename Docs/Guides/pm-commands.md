# PM이 AI에게 하는 말

| 단계 | 이렇게 말하면 | AI가 하는 일 |
|---|---|---|
| ① 통합 공간 | "커튼콜 연출 통합 브랜치 만들어줘" | `integration/curtain-call` 브랜치와 통합 기록 폴더 생성 |
| ② 작업 준비 | "커튼 열기 feat Task 만들어줘, 담당은 A" | Task 폴더·작업 브랜치 생성. PM은 Unity에서 테스트 씬·스크립트 폴더를 만들고 `setup.md`에 경로와 **관련 JIRA 번호**를 적음 |
| ③ 인계 | "Task-20260929-001 인계 전 점검해줘" | `setup.md` 체크리스트(씬·`.meta`·브랜치·공동 테스트 항목) 확인 |
| ⑥ 합치기 | "curtain-call 통합 병합 진행해줘" | PR을 순서대로 합치고 공동 테스트 표 작성. 기능 연결 작업도 이 단계에서 |
| ⑦ 마무리 | "curtain-call 통합 마무리해줘" | Task 완료 처리, 이슈 번호 모아 dev로 PR, 브랜치 정리 |

- 테스트 씬을 남길지 지울지는 마무리할 때 **사람이 직접** 정합니다. 결정하지 않으면 마무리 스크립트가 멈춥니다.
- ①②③⑦의 준비·마무리 커밋은 PM이 `integration/*`에 직접 올립니다. GitHub 브랜치 보호에서 `integration/**`의 **우회(bypass) 목록에 PM 계정만** 넣어 주세요.
- 여러 Task를 먼저 모두 준비한 뒤 한꺼번에 인계하면, 작업자의 구역 검사가 서로의 구역을 처음부터 알 수 있어 더 안전합니다.
- 병합 방식: 작업 → 통합은 **Squash**(Task 하나 = 기록 한 줄), 통합 → dev는 **Merge commit**(기능 묶음 단위로 되돌리기 쉬움).
