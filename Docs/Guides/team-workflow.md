# 팀 작업 방법

1. 작업 목적과 담당자를 정하고 Task·작업 브랜치를 만듭니다.
2. AI에게 원하는 결과를 말합니다. 계획과 할 일은 작업하면서 바꿉니다.
3. 기능·수정 묶음이 끝나면 필요한 검사만 한 번 합니다.
4. “저장해줘”, “제출해줘”로 공유합니다. dev에 합칠 때 지정 팀원이 PR을 검토합니다.

## 기억할 것
- plan은 목적·담당·현재 계획, todo는 할 일, log는 문제·결과·다음 할 일입니다.
- PM의 폴더 배정·인계 확인을 기다리지 않아도 됩니다. 다른 기능을 읽고 사용·수정·연결할 수 있습니다.
- 같은 파일을 함께 수정하면 담당자와 겹침을 알립니다. 다른 사람 변경을 덮어쓰지 않습니다.
- integration은 필요할 때만 씁니다. 필요한 작업 브랜치끼리 직접 변경을 받을 수 있습니다.
- 새 에셋 추가·사용은 자유롭고, 큰 수정·삭제는 PM·에셋 관리자가 관리합니다.
- 외부 에셋은 비공개 `_ThirdParty`에 둡니다. 비밀값·Unity 연결 정보는 보존합니다.
- 재미·조작감·게임 방향·최종 플레이 경험은 사람이 확인합니다.
- 진행은 Active, 완료는 Done입니다. 자세한 중간 상태나 인계 승인 표시는 없습니다.
- 이전 작업 원문은 해당 Task의 History/Harness-v1에 있습니다. 그 안의 옛 권한 제한은 적용하지 않습니다.
