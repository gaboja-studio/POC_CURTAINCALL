# 공연 보상·공동 자금 설정 가이드 (기획자용)

마지막 갱신: 2026-10-16 (Task-20261013-031 기준, dev #110 반영 후) · 전체 세팅 사용법: [game-settings-guide.md](game-settings-guide.md)
컨플루언스에 공유할 때는 이 문서를 최신으로 고친 뒤 그대로 옮긴다.

## 한눈에

- 공연 한 번이 끝나면 참가자마다 **호응 몫**이 정해지고, 공연이 **성공**했을 때만 몫의 합이 **공동 자금**에 들어간다.
- 몫을 정하는 수치는 보상 파일 한 개에서 바꾼다: `Assets/Resources/Settings/GameSettings/Tricks/Rewards/temporary-reward`
- 이름처럼 **기획 확정 전 임시값**이다. 수치가 정해지면 이 파일 값을 바꾸고 이 문서의 기본값도 고친다.

## 항목 의미 (기본값)

| Inspector 칸 | 뜻 | 기본값 |
|---|---|---|
| Cheer | 환호 1번에 그 사람 몫이 늘어나는 양 | 10 |
| Jeer | 야유 1번에 그 사람 몫이 줄어드는 양. 0 아래로는 안 내려간다 | 5 |
| Difficulty One / Two / Three Cap | 공연 난이도별 **1인당 몫 상한**. 환호·보너스를 더해도 이 값을 넘지 않는다 | 100 / 150 / 200 |
| All Survived Bonus | 공연 성공 + 참가자 **전원 생존**일 때 정산 직전 각자에게 더하는 양(상한 안에서) | 0 |
| Cut Bonus | 공연 중 팔다리가 **새로** 잘릴 때마다 1개당 더하는 양(상한 안에서). 같은 부위가 다시 잘려도 한 번만 | 0 |

모든 값은 0 이상이다. 음수는 입력되지 않는다.

## 정산 규칙

| 상황 | 그 사람 정산 | 공동 자금 |
|---|---|---|
| 공연 성공, 살아서 끝까지 접속 | 호응 몫(+전원 생존 보너스) | 성공한 사람들 몫의 **합**만큼 증가 |
| 공연 중 사망 또는 접속 끊김 | 0 | — |
| 공연 실패(묘기 실패·제한 시간) | 몫은 기록만 남고 0 | 변화 없음 |
| 생존자가 2명 미만이 되는 순간 | 공연이 **즉시 실패**로 끝남 | 변화 없음 |

- 개발자 모드를 켜면 최소 생존 인원이 2명 → 1명으로 바뀐다(혼자 테스트용).
- 공동 자금은 대기실 지출로 줄어든다. 잔액보다 많이 쓸 수 없다.
- **세대 교체**(탈출 실패) 때 공동 자금은 0으로 초기화된다. 장부에 "세대 교체 초기화"로 남는다.

## 계산 예시 (난이도 1, 2명, 기본값)

1. A가 환호 3번 → 30, 야유 1번 → 25.
2. B가 환호 12번 → 120이지만 상한 100에서 멈춤 → 100.
3. 둘 다 살아서 묘기 성공 → 수입 125, 공동 자금 +125.
4. 같은 상황에서 B가 사망하면 생존 1명 < 2명이라 그 순간 실패 → 수입 0. (개발자 모드면 계속 진행되고, 성공 시 A의 25만 들어간다.)
5. Cut Bonus를 20으로 바꾸고 A의 팔 하나가 잘리면 A 몫 25 → 45. 같은 팔이 복구 후 다시 잘려도 더 오르지 않는다.

## 바꾸는 법: 저장되는 변경 vs 저장 안 되는 변경

| 방법 | 어디서 | 남는가 |
|---|---|---|
| **Inspector에서 파일 값 수정** | Project 창에서 `temporary-reward` 클릭 → Inspector | 파일 자체가 바뀐다. **Play를 멈춰도 남는다.** 팀에 올리려면 Unity 저장 후 AI에게 "저장해줘" |
| **테스트 씬의 런타임 override** | `Assets/Scenes/Tests/Systems/Reward/PerformanceReward.unity` Play → "검증용 수치" 칸 → "런타임 override 적용(에셋 저장 안 함)" | 파일은 안 바뀐다. "에셋 값으로 복귀"를 누르거나 런·접속이 끝나면 사라진다 |

- 공연 도중에 값을 바꿔도 **다음 환호·부상·정산부터** 새 값을 쓴다. 상한을 낮추면 이미 쌓인 몫도 새 상한으로 깎인다.
- 시험 삼아 Inspector 값을 바꿨다면 직접 원래 값(위 표)으로 되돌린다. 숫자만 비교하고 싶을 땐 override를 쓴다.
- 온라인에서는 **호스트의 값**으로 판정한다. 참가자 화면은 호스트가 보낸 결과를 보여 준다.

## 묘기와의 연결 (현재 상태)

- 각 묘기 세팅(예: `Tricks/TightropeSettings`)에 "보상" 칸이 있지만 **아직 비어 있고, 코드도 이 칸을 읽지 않는다.** 지금은 모든 공연이 `temporary-reward` 한 파일을 쓴다.
- 공연 난이도도 지금은 연결 측에서 1로 시작한다. 난이도 2·3 상한은 테스트 씬의 "난이도(새 공연에 적용)"로만 확인할 수 있다.
- 외줄 본편은 아직 보상 시스템과 연결되지 않았다(더미 공연장·테스트 씬에서만 정산). 묘기별 보상 파일·난이도 연결은 묘기 연결 Task에서 한다. 필요하면 PM에게 요청한다.

## 직접 확인해 보기 (테스트 씬)

1. `PerformanceReward.unity`를 열고 Play.
2. "오프라인 런 시작" → "도입 끝 → 공연" → 난이도·더미 참가자 수 선택 → "공연 명부 고정·호응 시작".
3. 자리별 "환호 +", "야유 −", "1곳 절단", "사망"으로 몫이 위 규칙대로 바뀌는지 본다(`호응 현재/상한`).
4. "묘기 성공으로 종료·정산" 또는 "제한 시간 실패로 종료·정산" → "최근 결과"의 수입, 장부의 잔액 변화를 확인한다.
5. 끝나면 Play를 멈춘다. override만 썼다면 파일은 그대로다.
