# 다음 UI 적용 계획

사용자 최신 지시로 dev4d75f7e의 대기실 입력·전환 확인과 기본 HUD를 먼저 적용했다. 백스테이지·탈출로는 생성하지 않는다.

최신 후속: [Dev 시작 지점](dev-start.md)으로 일차·콘텐츠·시간대를 선택해 검증한다. [공통 외곽선·대기실 C6·셔터 정렬](interaction-highlights.md) 확인도 이 경로로 시작할 수 있다.

최신 적용: [대기실 W1/C4/C5/W6·방송·임시 표시 정리](waiting-room-hud.md). 기존 [공연 UI](performance-upgrade.md), [공통 호응 규칙](audience-rules.md), [공연 종료 UI](performance-ending.md)를 유지한다.

## 이후 실행 순서
1. 대기실 기본 HUD·C6·외곽선·셔터의 실제 다인 조작을 확인한 뒤 W4/W5 이름표를 정본 프리팹과 대조해 적용한다. 수화기/스케줄표 등 미대체 UI는 기능을 보존한다.
2. Start: 기존 시작/방 생성·참가 흐름과 준비된 버튼·패널 프리팹을 대조해 적용한다.
3. Lobby: 참가자 명부·준비·호스트 시작 권한을 기존 세션 API에 연결한다.
4. 공통 ESC 메뉴·설정·환호 효과·커튼의 정본 유무를 확인한다. 준비된 부분은 공통 씬에 적용하고 없는 부분은 제작 요청 목록으로 남긴다.
5. WaitingRoomBase: W2 수화기·W3 스케줄표 패널 정본 유무를 확인하고, 준비된 그래픽과 기존 게임 API 범위만 연결한다.
6. Start→Lobby→대기실→두 공연→대기실 전체 흐름, 2~4인·재접속·여러 해상도를 회귀 검증한다.

## 적용 완료: HumanCannon
- 기존 공통 C1/C2/C3 회귀, Assets Guides/Tooltips 정본으로 C7/C15 적용.
- 공간 UI에 구간 표시 유지, 공통 씬 안내는 공간 어댑터가 기존 게임 상태로 제어한다.
- C11 관전 적용 완료. C12는 기존 BasicPanels 인스턴스에 대성공/개인 정산/잔액/자동전환을 표시한다. C13 ESC 및 결과 전용 그래픽/추가 필드는 후속이다.
- 상세 적용/검증: [인간대포](human-cannon.md).

## 1. Start·Lobby 프리팹/기존 기능 대조
- Assets 내부의 완성 프리팹과 제작 Task·독립 테스트 씬을 먼저 확인한다. 전체 화면 프리팹이 없으면 준비된 버튼·패널을 조합할 수 있는지 확인하고 미제작 요소를 목록으로 남긴다.
- StartMenu 등 현재 방 생성/참가/나가기·연결 상태 흐름을 조사한다. UI 화면 목록 T1/T2/T3/L1과 연결점을 정리한다.
- 기존 CommonButtons/BasicPanels 등은 원본 규칙을 유지한다. LobbyHud는 이름만으로 로비용이라고 간주하지 않고 역할을 확인한다.

## 2. 공통 UI 문맥 확장과 화면 적용
- 공간 전환에도 공통으로 쓰는 알림/확인/설정 표시는 공통 UI 씬, 화면 전용 레이아웃은 Start/Lobby의 UI 루트에 둔다.
- 현재 CommonPerformanceUI는 공연 전용이므로 무조건 모든 씬에 띄우지 않는다. 재사용할 공통 계층과 공연 HUD 표시 조건을 분리한다.
- 방 생성/참가 버튼, 입력 검증, 연결 중/오류/취소, 참가자 명부·준비·호스트 시작 권한을 기존 세션 API와 연결한다.
- 인터랙티브 UI 적용 때 EventSystem/InputModule 중복·포커스·키보드/마우스 입력·커서 정책을 확인한다.

## 3. WaitingRoomBase
- W1/C4/C5/W6 기본 적용 완료. C6 근접 안내와 공통 외곽선까지 적용 완료. 다음은 이름표와 미대체 패널이다.
- 상호작용·구매·스케줄 화면은 구현된 데이터/API 범위 안에서 연결하며 게임 규칙과 경제 값을 UI에서 만들지 않는다.

## 4. 연결 검증과 완료 기준
- Start→Lobby→WaitingRoom→공연→WaitingRoom 실제 흐름, UI 씬1개/문맥 갱신/이벤트 해제 확인.
- 호스트·클라이언트 권한, 입장·퇴장·재접속, 실제 키 입력과 여러 해상도 검증.
- 기존 공연 HUD 회귀 및 아직 미실행인 2~4인 C3·불 접촉·관전 전환 검증.
- 각 단계마다 수정 파일·데이터 원천·실행 결과·미실행 항목과 Unity 확인 방법을 가이드에 갱신한다.
