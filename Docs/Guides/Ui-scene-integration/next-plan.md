# 남은 UI 적용·고도화 계획
2026-10-21 · 기준: 연결3ac025f + 제작b5bee0e 수신92effe2. W2 상점·서비스·장부 적용 완료([사용자 확인·검증](waiting-room-shop.md)). 다음 구현은 W3이며 다인 검증은 남아 있다.

## 확정 기준
- 스케줄은 실제 공연이 있는 1~3일차만 배치한다. 4일차는 아침 쉬는 시간 이후 끝나므로 공연 편성/확정 대상이 아니다. 현재 코드의 3일차 밤→4일차 편성 요구도 함께 제거 대상으로 삼는다.
- 결과 완료 시간은 불 타이머가 시작한 시점부터 공연 성공/실패 확정까지 경과 시간이다. 안전 지대에 불이 멈춰도 측정은 계속하며, 남은 불 시간에서 역산하지 않는다. 인간대포는 첫 불 타이머 시작을 기준으로 구간마다 초기화하지 않는다.
- 진행 거리는 각 묘기의 출발→도착 축에 플레이어 위치를 투영한 거리로 계산한다. 0~코스 길이로 제한하고 개인 최대 도달 거리는 공연 중 최댓값을 보존한다. 공중 높이·옆 이동·추락 때문에 직선 변위가 커지는 것을 진척으로 세지 않는다.
- 1인은 Dev 전용이다. 전용 디자인/정본 수정 없이 기존 결과 요약 표시를 재사용하는 간단한 대체 경로를 우선한다. 가짜 두 번째 단원을 만들지 않으며 2~4인 정식 결과와 같은 시간·거리·정산 자료를 사용한다.
- 타이틀은 사용자 첨부 시안: 어두운 서커스 공간 배경, 상단 중앙의 큰 로고, 중앙 세로 메뉴(방 만들기/방 코드로 참가/LAN 접속/설정/종료), 선택 항목의 얇은 장식·밑줄과 밝은 글자. 이전 HTML의 좌측 메뉴보다 최신 시안을 우선한다.

## 현재 상태의 재분류
- 기능 연결 완료: 공연 HUD/호응 규칙/관전·사망, 대기실 HUD/W4·W5/상호작용·커서/Dev 진입. 새 패널과 겹침·수명·실제 데이터 표현은 다시 검증한다.
- W2는 ShopPanel 정본으로 구매·서비스·최근 장부/배송 연결 완료. 기존 상점 IMGUI off·서비스 임시 컴포넌트 제거. UI33/33 통과, 실제2~4인 미실행.
- 임시 대체 상태: BasicPanels 결과 요약, 검은 전환, 스케줄 IMGUI, 기존 시작·로비 메뉴/설정. 새 정본으로 고도화해야 완료다.
- C10은 Assets/_ThirdParty/curtaincall_feedback_v1에 PNG·FeedbackView/Motion·Builder가 있다. 완성 .prefab은 확인되지 않았다. 리소스 없음으로 분류하지 않고 프리팹 조립·검증 준비 항목으로 관리한다. 원본 README의 미실행 기록을 현재 검증 완료로 해석하지 않는다.

## 연결할 데이터·남은 판단
- W2 구매/수령은 WaitingRoomShop, 서비스는 ExpertService, 잔액/장부는 PerformanceRewards. 판매 API는 확인되지 않아 데모 예시만으로 추가하지 않는다. 화면 요청 토큰과 실제 게임 응답 대응/연속 요청 방지를 확인한다.
- W3는 ScheduleBook.EditableDays/LockedOnConfirm/BeginNight 및 ScheduleBoard.CanReady·Campaign 진행을 함께 점검한다. 사용자 최신 결정에 따라4일차 편성을 준비 조건에서 빼되,4일차 아침/최종 진행 상태를 없애거나3일차 밤을 건너뛰지 않는다. 기존 데이터 배열/동기화 형식은 최소 변경을 우선한다.
- C12 시간은 호스트의 불 타이머 시작 신호/동기화 시계 재사용: 외줄 TightropeFire.Elapsed/공연 시작, 인간대포 최초 ArmedAt·Route.Clock 대조. UI를 늦게 열어도 시작점은 변하지 않는다. 시작 전 실패는 시간 미시작 상태로 표시하고 종료 뒤 숫자는 고정한다.
- 거리 기록은 누적 이동거리가 아니다. 외줄 GetDistance/FinishDistance, 인간대포 기존 C3 출발·도착 축을 재사용하며 사망/도착/이탈 직전 종료 위치와 개인 최댓값을 보관한다. 로컬 HUD만 켜져야 기록되는 구조를 피하고 호스트 결과로 전달한다. 정산 공식/실패 판정은 변경하지 않는다.
- 결과 확인 버튼의 팀 진행 의미는 아직 미확정이다. 제안은 개인 결과 닫기만 담당하고 현재 호스트 자동 전환 시점을 유지하는 것. 전원 준비 방식이나 한 명 클릭으로 즉시 공간 전환하는 규칙은 별도 확정 전 추가하지 않는다.
- 타이틀 시안은 화면 구성의 기준이며 배경 원본이 제공됐다는 뜻은 아니다. Assets의 실제 사용 가능한 배경/현재3D 씬을 먼저 확인한다. 로고/메뉴가 합쳐진 시안 전체를 배경으로 쓰지 않는다. 동일 배경이 없으면 별도 배경 자산 필요 여부를 기록하며 기존 아트로 가능한 구성을 우선한다.
- C10 전용 완성 프리팹을 못 찾으면 조립·검증을 먼저 마치고 씬에서 인스턴스로 사용한다. 외부 인계 package의 재추출/원본 변경으로 대체하지 않는다. 새 설정 옵션·새 상품/경제 규칙·미제작 공간은 범위를 늘리지 않는다.

## 구성·수정 범위
- 공통 패널/메뉴/설정/전환은 Assets/Scenes/UI 아래, 공간 전용 진입점과 표시 대상은 각 씬 UI 루트 아래. Start 전용 레이아웃은 Start 씬. Scene View에서 보며 조절하는 편집 방식 유지.
- UI 어댑터/설치/테스트는 SceneIntegration, 기존 ShopPhone/ScheduleBoardView/ExpertRoomView는 기능을 유지하고 표시 전환. 결과는 PerformanceEndingPresentation/PerformanceTransitionUI와 기존 정산·공간 전환 API 연결.
- ScheduleBook/준비 조건, 결과 기록·공유, 전환 진입점에 필요한 정확한 공용 파일은 해당 단계 착수 때 setup에 명시한다. 계획만으로 무관한 공유 코드를 수정하지 않는다. Start/Lobby 빌더 재실행으로 수동 배치를 덮어쓰지 않는다.
- 원본 prefab·PNG·폰트·파일명·GUID·9-slice 보존. 기능 검증 후 대체 임시 오브젝트만 제거. 백스테이지·탈출로 신규 씬은 만들지 않는다.

## 공동 확인 3개와 단계별 검증
1. 대기실 아침/밤: 기물/서비스/배송/장부, 일정 수정/확정/준비,3일차 밤→4일차 아침 진행, 권한·커서·늦은 응답/거절 확인.
2. 두 공연: 타이머 시작부터 시간, 후퇴·점프·추락의 개인 최대 거리, 성공/실패/관전·피드백/결과·커튼·느린 로딩. 1인 Dev와2~4인에서 중복 지급/전환/잔상 없음 확인.
3. 전체: 시안에 맞춘 Start→Lobby→대기실/공연→복귀/나가기, 설정 적용/취소, 재접속·Mac/Windows·16:9/16:10/넓은 화면·빌드. EventSystem 중복·포커스·입력/구독 해제 확인.

단계마다 컴파일·표시/어댑터 테스트·실제 화면 확인 후 인계한다. 기존 카메라2개·확장 SpaceLink6개 실패는 별도 추적하며 통과로 기록하지 않는다. 신규 패널의 실게임 검증과 제작 검증은 구분하고 미실행은 명시한다. 완료는 배치뿐 아니라 실제 데이터/입력·예외 처리·임시 표시 정리까지 포함한다.
