# PR·이슈 직접 쓰기

AI에게 "제출해줘", "버그 제보해줘"라고 하면 자동으로 이 형식이 됩니다. GitHub 웹에서 직접 쓸 때도 똑같이 맞춰 주세요.

## 제목

| 종류 | 형식 | 예시 |
|---|---|---|
| PR | `[종류] Task번호 한 줄 요약` | `[feat] Task-20260929-001 커튼 열기` |
| 버그 이슈 | `[BUG] 한 줄 요약` | `[BUG] 커튼이 두 번째부터 안 열림` |
| QA 요청 이슈 | `[QA] 한 줄 요약` | `[QA] 커튼 열기 연출 확인 요청` |

## PR 본문

| 칸 | 쓰는 법 |
|---|---|
| 작업 내용 요약 | 무엇이 달라졌는지 1~3줄. 예) "커튼이 3초 동안 천천히 열립니다." |
| 관련 JIRA 이슈 | 선택 사항. plan에 관련 번호가 있으면 옮기기 |
| Issue 번호 | 해결되는 이슈를 `closed #12`처럼. 없으면 "없음" |
| 검사 결과 | 해 본 것만 결과를 쓰고, 안 해 본 것은 "미실행" |

검사 결과 칸 채우는 법:

- **안전성**: 미해결 충돌·비밀 파일·Unity `.meta` 누락 검사 결과를 적습니다. 작업 폴더 제한은 없습니다.
- **컴파일**: 실제 컴파일 결과를 적습니다. Unity 변경이 없으면 생략하며 Console 경고만으로 성공을 판단하지 않습니다.
- **테스트**: 필요한 테스트만 선택해 실제 결과를 적습니다. 테스트가 없으면 `NO_PROJECT_TESTS`, 미실행이면 이유를 적습니다.
- **직접 플레이 확인**: Play로 확인한 내용. 예) "커튼 열림 5회 반복 확인"

## 이슈

GitHub **Issues → New issue**에서 BUG 또는 QA REQUEST 양식을 고르면 칸이 나옵니다. 제목 앞의 `[BUG]`, `[QA]`는 미리 채워져 있습니다.
